## What actually happens

Agents are records on the Allternit API ([Agents API](/api/agents)). When you pair a node ([BYOC Overview](/byoc/overview)), the Cloud API relays agent-session, office and beta calls to that node over an outbound WebSocket, so the agent runs on your data plane against its SQLite state and the local Gizzi runtime (`:4096`).

```
Browser / SDK  --HTTPS-->  Cloud API  --WSS relay-->  agent-daemon --> allternit-api :8013 --> gizzi-code :4096
```

There is no per-agent binding to a deployment. Routing is per paired runtime: relayed routes go to your paired, online node, and return HTTP 428 if none is available.

## Before a device is paired

Until a node is paired, the Cloud API has nowhere to run agents, sessions, vaults, memory or deployments. These calls answer `428 PRECONDITION_REQUIRED` with the message "No data-plane node registered for this account". In the console, those pages show a "Managed Agents run on a computer you connect" card with **Connect a device** and **Docs** instead of an error. Pair your Mac, PC or a cloud computer and the pages fill in.

## Steps

1. [Install](/byoc/installation) `allternit-api` and `agent-daemon`.
2. Approve the pairing at `https://platform.allternit.com/pair`.
3. Create and run agents through the normal API; they execute on your node.

## Runtime and brain

Each agent has two picks, and the console's agent form (**Agents › New** or **Edit**) shows both:

- **Runtime** is how the agent works: Allternit, or another agent program such as Claude Code, Codex or Hermes. Allternit is the default. Each runtime shows its category and, where it applies, a status such as "API key or Enterprise only". A runtime other than Allternit runs on a computer that has that program installed.
- **Brain** is the model the agent thinks with, from the Cloud model list. Leave it on **Cloud default** to use the model Cloud recommends.
- **Access** is how the brain is paid for: Allternit credits, your API key, or a plan (for example a Claude or ChatGPT plan).

Some runtimes run only their own company's models; the form greys out brains a runtime can't run. Most companies don't allow their plan sign-in inside another company's agent, so a plan works only with Allternit or with that company's own runtime (a Claude plan with Claude Code, a ChatGPT plan with Codex). When you pick a runtime that can't use the current brain or plan, the form switches to one it can use and says what changed.

The agent record keeps `model` (the brain) and `provider` at the top level and stores the runtime the same way bots do, inside `config`: `config.botBrain = { runtime, access, modelRef }` plus `config.agentView` (see [Agents API](/api/agents)). The console merges these into the existing config instead of replacing it. Records saved before runtimes existed read as `runtime: "allternit"`. When the runtime's program is not installed on the computer the agent runs on, the save still succeeds and the agent page shows the warning. If a save breaks a rule, the API answers `422` with one of these codes, and the console shows the message under the field:

| Code | Message |
|---|---|
| `runtime_unknown` | No runtime called `<id>`. |
| `brain_not_fit` | `<Runtime>` runs `<Provider>` models only. |
| `plan_not_allowed_on_runtime` | `<Provider>`'s plan can't be used inside `<Runtime>`. Use an API key, or pick `<own runtime>`. |

## Security

- The daemon authenticates with a device token obtained from `POST /api/v1/runtime-pairings/exchange`, after signing a challenge with its device identity.
- Revoke a device with `/api/v1/runtime-devices/:id`.

## How this relates to the Agency Kernel

BYOC is where the Allternit API data plane and Gizzi runtime run on hardware you control. The [Agency Kernel](/architecture) contracts are served through the Cloud API. Nothing on this page changes them.
