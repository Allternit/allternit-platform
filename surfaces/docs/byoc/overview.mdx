## What is BYOC?

BYOC (Bring Your Own Compute) means **your data plane stays on infrastructure you control** — or on an isolated instance Allternit provisions for your subscription. The public [Cloud API](/api/cloud-api) at `https://api.allternit.com` is the control plane for every mode. The [Allternit API](/api/allternit-api) binary is the data plane. It is never a second public hostname.

You get:

- **Data stays on the node** — sessions, files, and Office bindings live in per-instance SQLite
- **No inbound ports** — the node opens an outbound WebSocket to the Cloud API
- **One public origin** — browsers talk only to `api.allternit.com`
- **Same binary everywhere** — local desktop, your VPS, or a provisioned instance

<Note>
**Status:** Implementation IMPLEMENTED × Exposure PUBLIC PREVIEW. `allternit-api` binds `0.0.0.0` on `ALLTERNIT_API_PORT` (default dev `18013`; pin `8013` in production), not loopback. Firewall it.
</Note>

## Architecture

```
┌─────────────────────────────┐         ┌──────────────────────────────┐
│  Control plane              │         │  Data plane                  │
│  Cloud API                  │◄───────►│  Allternit API               │
│  api.allternit.com          │  WSS    │  :8013, firewalled           │
│                             │  relay  │                              │
│  • Auth (Clerk)             │         │  • allternit-api             │
│  • Pairing & device tokens  │         │  • Per-instance SQLite       │
│  • Billing & model router   │         │  • Gizzi runtime             │
│  • Fleet / hosted runtimes  │         │  • agent-daemon (outbound)   │
└─────────────────────────────┘         └──────────────────────────────┘
         ▲                                          ▲
         │ HTTPS + Clerk JWT                        │
         └──────────── Browser / SDK ───────────────┘
                   (never hits :8013 directly)
```

Mode 3 is the hosted data-plane lane (provisioned instances), distinct from [Fly hosted runtimes](/byoc/hosted-runtime) which bundle a Gizzi gateway and agent-daemon as a managed machine.

## Pair a node (mode 2)

1. Start Allternit API and `agent-daemon` on the box (firewall the API port; only the daemon needs it).
2. The daemon creates a pairing: `POST https://api.allternit.com/api/v1/runtime-pairings`.
3. Approve the user code at `https://platform.allternit.com/pair`.
4. The node exchanges the pairing for a device token and connects:

```
wss://api.allternit.com/api/v1/runtime-relay/connect/:runtimeId
```

5. From then on, agent-sessions / office / beta calls to `https://api.allternit.com` relay to this node.

If nothing is paired and online, those routes return **HTTP 428**.

Full protocol: [Cloud API — runtime pairing](/api/cloud-api#runtime-pairing).

## System requirements

| Resource | Minimum | Recommended |
|----------|---------|-------------|
| CPU | 2 cores | 4+ cores |
| RAM | 2 GB | 4+ GB |
| Disk | 10 GB | 50+ GB SSD |
| OS | Ubuntu 22.04 LTS | Ubuntu 24.04 LTS |

Supported: Linux (x86_64, ARM64), macOS 12+ (desktop). Provisioned fleet images are Linux x86_64.

## Release channel

Provisioned instances and operators pull:

```
https://api.allternit.com/releases/allternit-api/latest/linux-x86_64.tar.gz
```

Desktop ships its own bundled Allternit API. Do not publish port 8013.
