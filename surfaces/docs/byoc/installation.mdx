The data plane is `allternit-api` (`cmd/allternit-api`). Pairing is done by `agent-daemon` (`cmd/agent-daemon`, `@allternit/agent-daemon`). See [BYOC Overview](/byoc/overview).

## Get the binary

Provisioned and fleet instances pull the release tarball:

```bash
curl -fsSL https://api.allternit.com/releases/allternit-api/latest/linux-x86_64.tar.gz -o allternit-api.tar.gz
```

Only `linux-x86_64` is referenced by the provisioning code. Desktop bundles its own `allternit-api` build. To build from source: `cargo build --release -p allternit-api`.

## Run allternit-api

```bash
ALLTERNIT_API_PORT=8013 \
ALLTERNIT_DATA_DIR=/var/lib/allternit \
./allternit-api
```

- `ALLTERNIT_API_PORT` sets the listen port. If unset it defaults to the dev port `18013`; production owners pin `8013`.
- The listener binds `0.0.0.0:<port>`, not loopback. Firewall the port or put it behind a private interface. Do not publish it.
- Health: `GET /health`, `GET /health/live`, `GET /health/ready`.

## Pair with the Cloud API

```bash
cd cmd/agent-daemon && npm install && npm run build
ALLTERNIT_RUNTIME_NAME="my-vps" \
ALLTERNIT_GATEWAY_URL=http://127.0.0.1:8013 \
npm start
```

| Variable | Default | Purpose |
|---|---|---|
| `ALLTERNIT_CLOUD_API_URL` | `https://api.allternit.com` | Control plane |
| `ALLTERNIT_RUNTIME_NAME` | `<hostname> VPS` | Display name |
| `ALLTERNIT_GATEWAY_URL` | `http://127.0.0.1:8013` | Local data plane |
| `ALLTERNIT_RUNTIME_IDENTITY_PATH` | daemon default | Where the device identity is stored |
| `ALLTERNIT_PAIRING_MODE=hosted_auto` | unset | Auto-pair; also needs `ALLTERNIT_HOSTED_INSTANCE_ID` and `ALLTERNIT_HOSTED_BOOTSTRAP_TOKEN` |

The daemon prints a verification URL and a user code. Approve it at `https://platform.allternit.com/pair`. It then exchanges the pairing (`POST /api/v1/runtime-pairings/exchange`) and connects to `wss://api.allternit.com/api/v1/runtime-relay/connect/:runtimeId`.

Alternatively the [Deploy Wizard](/byoc/deploy-wizard) provisions and bootstraps a VPS for you.

## Process supervision

Run both processes under your service manager (systemd, launchd). Neither ships a unit file; write your own with the environment above.

## How this relates to the Agency Kernel

BYOC is where the Allternit API data plane and Gizzi runtime run on hardware you control. The [Agency Kernel](/architecture) contracts are served through the Cloud API. Nothing on this page changes them.
