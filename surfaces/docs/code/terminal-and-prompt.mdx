Code has two kinds of session. A **Code session** is a conversation with an agent: messages, tool steps, approvals and the files it made. A **terminal** is a live shell (or a Terminal bot's CLI) on your computer or cloud computer. Both live in Code mode.

## Terminal mode

Terminal mode is the regular Code view with a terminal session where the thread was. Turn it on with **Terminal** in the status row under the prompt. While it is on, that button reads **Thread**: press it to go back to the thread. A terminal session's card in the Code overview, and the session panel's **Terminal** row, turn it on too.

- **The session line** at the top shows the session's name, then `zsh` and the repo and branch for a shell, or the bot's address for a Terminal bot. With the left rail collapsed, it starts after the window's back, forward and sidebar buttons.
- **The session** fills the rest of the view. On Desktop it is always dark, in light and dark mode, like the terminal cards in the Code overview. The prompt and status row sit on the same dark surface, and the prompt's dashed frame stays visible on it.
- **The prompt types into the session.** What you run goes to the shell (or the bot's CLI) as a line, followed by Enter. You can also click the session and type in it directly.
- **A Terminal bot** opened from the overview is shown as the session. **Shell** on the session line goes back to your own shell.
- **The same panes and session panel as the thread.** Terminal, Changes, Browser, Computer, Files, Artifacts, Transcript, Tasks, Code map (with local gizzi) and the project's own panels open beside the terminal session from the same toolbar, and **Session details** docks on the right. As in thread mode, panes need a session: the new-thread screen has none.
- **No computer connected** (for example ai.allternit.com with no computer paired) shows **Not connected** with a **Connect** button instead of an error.
- **On a cloud computer** terminals work the same way as on your Mac when its image has the Factory pane engine: they keep running when the computer's `allternit-node` restarts, and they show titles and previews. On an older image they still work, but they end when `allternit-node` restarts ([details](/api/terminal#cloud-computers)).

## Switching sessions

The session switcher sits at the top right of the Code view, in the session header (or, before the first message, in the tools at the top right). It follows the mode:

| Mode | Button | Lists |
| --- | --- | --- |
| Thread | **Threads** and the count | Your recent thread sessions. Pick one to open it. |
| Terminal | **Terminals** and the count | **Your shell** and your Terminal bots. Pick one to show it as the session. |

**See all** at the bottom opens the Code overview on that kind, in **List**, **Grid** or **Deck**. See [Session overview](/guides/session-overview).

On a phone, the count button in the header does the same: in the terminal it opens the overview on **Terminal sessions**.

On a phone, the terminal is always one shell at a time with a strip of tabs. See [Code on a phone](/code/on-a-phone#terminal).

## Coding agents in the terminal

When a coding agent runs in a Code terminal, Allternit hides the agent's own input box and its composer drives the agent instead. This covers Claude Code, Codex, Kimi, Antigravity (`agy`), opencode and Gizzi. Grok and Qwen show the full screen. See [which tools work how](#harness-support).

- **The composer reads "Message &lt;agent&gt;…"** (for example "Message Claude Code…"). What you send is typed into the agent and submitted.
- **A chip on the composer's top edge** shows the agent and its state: **Idle**, **Working** or **Needs you**. While it works, **Stop** (Esc) interrupts the turn.
- **Permission and choice prompts become buttons.** **Yes**, **No** or the numbered options replace the agent's dialog, and a click presses that key (or moves the selection) in the agent.
- **A mode button** in the bottom bar shows the agent's own mode (such as **Bypass permissions** or **Plan mode**). A click cycles it, the same as Shift+Tab in the agent.
- **Slash and @ menus still open**, just above the composer, because what you type is mirrored into the agent as you type.
- **A screen Allternit does not recognise shows the full terminal**, including the agent's own box. Nothing is hidden when Allternit cannot tell where the input box is.
- **`exit` brings the full shell back.** When the agent quits, the composer returns to the normal terminal prompt.

On a phone, the same state shows as question buttons and **Stop** above the keys strip. See [Code on a phone](/code/on-a-phone#terminal).

### Tabs, the Terminals menu and live cards

- **Tabs (Desktop).** Each terminal is a tab. **New** opens another terminal and **Close** ends one. A tab takes the agent's name once it runs, for example "Claude Code".
- **The Terminals menu** (the switcher at the top right in Terminal mode) lists **Your shell**, your Terminal bots and every terminal, each with its title, folder and status (**Working**, **Needs you** or **Idle**), such as `claude · allternit-platform · Working`. A row opens that exact terminal, with its history. The menu is fully opaque.
- **Live cards.** In the Code overview, every terminal, plain shells included, is a live card in **List**, **Grid** or **Deck**: its title, folder, the agent and its state, and the last lines of the screen above the agent's input box. A runtime that cannot list terminals still shows "Terminal session". The cards update only while the overview is open.
- **On this Mac.** The menu, the overview and the phone sessions sheet also list every agent session running outside Allternit (Terminal, iTerm2, Ghostty), with **Move here**, **Open a copy** and **New session here**. See [Move a session into Allternit](/guides/live-sessions#move-a-session-into-allternit).

## Prompt

In Code, the prompt is one input line in a dashed frame across the whole width of the Code view. On the line: **+** (attach), `❯`, the text you type, voice and run. On the frame's top edge, the prompt cache's state (**cache warm**, **cache expiring** or **cache cold**) is at the left, and the model with its status dot is at the right. The cache state shows only when the provider reports it. As you type more, the line grows upward (up to about ten lines). Press **Enter** to run, **Shift+Enter** for a new line.

Directly under the line is the status row:

| Side | What it shows |
| --- | --- |
| Left | The computer, the repo, the branch, **Worktree** (on `main` before a session starts) and the permission mode (**Manual**, **Auto**…). |
| Right | How much of the context is used, and **Terminal**. |

Under the status row, a usage line shows the last run: tokens in and out, the cached share and the cost, such as `52.8k in · 152 out · 88% cached · $0.03`. A phone leaves out tokens out. It shows only what the provider reported, and it hides when there is no run yet.

**Context bar position.** Click the context meter to open the usage panel, then set **Context bar** to **Bottom** (the blocks in the status row, the default) or **Above** (a thin bar on its own line just above the prompt, with the percent at its end). The bar turns amber at 75% and red at 90%, and a plan limit near its end also colors it. Click the bar to open the same panel. The choice is kept on this device.

Before a session starts, the computer and repo open pickers. In a running session the repo and branch are plain text, because the session's folder is fixed. Chat and other modes keep the rounded composer.

## Console drawer replaced

The old bottom Console drawer is gone (2026-10-28). Its shell tab is Terminal mode above. In its place is the [system drawer](/guides/system-drawer), a developer tool turned on in **Settings → Developer**: **Needs you**, **Bots**, **Running** and **Problems** across every session and mode, opened with ⌘J, the dot on Gizzi or the menu bar menu. The preview pane's **View session activity** link went with the old drawer.

## Background

Code mode can show the same moving background as bot chats. Each workspace can have its own: the brush button in the session toolbar lists the looks, and on phones it is **Background** in the pane menu. In the iPhone app, tap the session name at the top and pick **Background**. A look picked there applies to that workspace only. **Same as Settings** follows **Settings → Appearance → Background**, which shows in Code only when **Show on → Code mode** is on (off until you turn it on). It plays behind the session view, but not on the canvas board or while Terminal mode is on, and the shell rail beside it wears the same background. ASCII looks sit under a stronger veil here so code and text stay easy to read. See [Stage backgrounds](/surfaces/bots#stage-backgrounds) for the looks and options.

## For developers

- Terminal mode: `src/views/code/CodeTerminalCanvas.tsx` and `code-terminal.css` (`.code-terminal-dark`, `.code-terminal-session-line`). On Desktop it renders the session line, then one `TerminalSurface` (dark scheme), or `BotSession` (the bot's `PaneMirrorView`) after a `factory-attach-pane` request. CodeCanvas renders it in place of the thread and keeps the session header, prompt and status row; the prompt dock gets `.code-terminal-dark` while it is open. With no runtime (`useRuntimeAvailable`) it shows **Not connected**.
- Open state and input: `useCodeTerminalStore` in `src/views/code/code-terminal.store.ts` (`open`, `toggle`, `openCodeTerminal()`, `sendInput`). The open session sets `sendInput`; `handleSend` in `CodeCanvas.tsx` hands the prompt to it (shell: `sendTerminalInput(id, text + "\r")`; bot: `sendPaneInput` via `terminalDataToPaneInput`). The status row's `code-bottom-status-terminal` button (`CodeTerminalButton`) toggles it and reads **Thread** while open. Factory bot attach (`src/components/factory/pane/attach.ts`) and `MultiTabTerminal` call `openCodeTerminal()`.
- Session switcher: `src/views/code/CodeSessionSwitcher.tsx` (`code-session-switcher`). It reads `useCodeTerminalStore.open` for the kind, lists `useModeOverview("code")` rows, sets `useCodeTerminalStore.botId` for a Terminal bot with a live pane (else `openOverviewItem`), and **See all** calls `rememberOverviewLayout("desktop:code", layout)`, sets `useCodeOverviewKind` and opens `code-threads`. It sits in `CodeSessionHeader` and, before the header shows, in `CodeTopRightTools` (`code-top-right-tools`, `CodeThreadView.tsx`) with the session toolbar (`CodeSessionLauncher placement="inline"`) or the canvas toggle. `CodeTopRightTools` publishes its width as `--code-floating-tools-w`, which the session line uses as right padding. Phone: `PhoneOverviewButton kind`.
- Collapsed rail: `.code-terminal-session-line[data-at-top]` (launchpad) and `CodeSessionHeader` pad by `--titlebar-controls-w` under `[data-rail-collapsed=true]`.
- Dashed frame: `.code-terminal-dark` sets `--polish-hairline` / `--polish-hairline-strong` for `composer-terminal-input`.
- The shown Terminal bot is `useCodeTerminalStore.botId` (null = your shell). The Gizzi companion sits above the prompt line (`bottom: 100%`) and hides in Terminal mode.
- The `<ConsoleDrawer />` mount in `src/shell/ShellApp.tsx` is commented out, not deleted.
- Mounts: `src/views/code/CodeCanvas.tsx` (launchpad and conversation). Both drop their padding while `terminalCanvasOpen` is true; the docked `CodeSessionPanel` stays available.
- iPhone app: `surfaces/allternit-mobile/ios/Features/Code/CodeComposer.swift` (`CodePromptEdge`, `CodeContextBar`, `CodeRunUsage`). Usage comes from the chat stream's finish frame, so the app shows it only for runs in the open session, not for threads loaded from history. The preference is `allternit-code-composer-context-bar`.
- Prompt: `src/views/chat/ChatComposer.tsx`, `codeTerminal` branch. `composer-terminal-line` stacks `composer-terminal-edge` (the frame's top edge, drawn in segments so a background shows through: `composer-terminal-cache`, then `model-picker-trigger`), `composer-terminal-input` (attach, text, voice, run), `composer-compact-controls` (the status row) and `composer-terminal-usage`.
