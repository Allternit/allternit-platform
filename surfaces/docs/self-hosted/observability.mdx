## Traces (OpenTelemetry)

Trace export is set with the standard OpenTelemetry environment variables, not in the settings file:

| Variable | Example | What it does |
|---|---|---|
| `OTEL_EXPORTER_OTLP_ENDPOINT` | `http://otel-collector:4318` | Where spans are sent. Unset means no export. |
| `OTEL_SERVICE_NAME` | `allternit-agents-server` | The service name on every span. |
| `OTEL_TRACES_SAMPLER` | `parentbased_traceidratio` | Which traces are kept. |

Other standard `OTEL_*` variables follow the OpenTelemetry SDK conventions.

A trace links the session, each turn and each tool call, so you can follow one turn from the client request through the model call and the worker's tool run.

The collector is something you run. The server sends spans only to the endpoint you set.

## Metrics (Prometheus)

Metrics are off by default. Turn them on in the settings file:

```yaml
observability:
  prometheus:
    enabled: true
    listen: 127.0.0.1:9464
```

- Metrics are served on their own listener, `127.0.0.1:9464` by default.
- The main API port never serves `/metrics`. A request for it there gets `404`.
- Outbound requests are counted per host, so you can see exactly which hosts the server called.

To scrape from another machine, change `listen` or put a proxy in front, and limit who can reach it.

## Logs

- Logs go to stderr.
- The format is JSON by default. Set `observability.log_format: text` for plain lines.
- The server is built to keep secrets out of logs: API keys, environment keys, session secrets and provider credentials. Check your own log pipeline too.

With Docker Compose, read them with `docker compose logs server` and `docker compose logs worker`.

## Health

- `GET /v1/server/info` answers without a key and is a simple liveness check.
- The server runs its own health checks every `health.check_interval` (default `60s`).
- `allternit-agents-server admin doctor` runs checks on demand. See [Operations](/self-hosted/operations#doctor).
