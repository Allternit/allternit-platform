`gizzi agents` is the crew: which agents exist, which harness each one runs on, and which machine it's on.

Every agent in the Factory is a **Bot**: one record with a stable id. The Factory doesn't add a second kind of agent. Bots differ in two separate ways: **how a bot runs** (its execution binding) and **how people reach it** (its channels).

## Three ways a bot runs

| Binding | What it is | Examples | Status |
|---|---|---|---|
| **Hosted** (`type: hosted`) | Runs on Gizzi's session loop, locally or on a cloud computer | Al (the Coordinator), bots you create in Bot Mode | Live |
| **Terminal** (`type: terminal`) | A CLI harness running in an engine pane | Claude Code, Codex, Kimi CLI, Grok CLI, agy, and `gizzi` itself | New with the Factory. Every pane belongs to a bot |
| **Vendor** (`type: vendor`, mode `linked` or `mirror`) | A vendor's own agent or app, reached through the agent gateway | ChatGPT, Claude, Gemini, Copilot, Grok, Kimi, Hermes | Live. See [Vendor bots](/guides/vendor-bots) |

Vendor bots carry a **lane** (`official`, `channel`, `ui_bridge` or `local`) and a **guarantee** (`exact`, `best_effort` or `read_only`), and they're directed by another bot. The guarantee decides what "delivered" means for that bot. See [delivery states](/factory/orchestration#delivery-states).

## Reach is separate from running

Telegram, Slack, SMS, phone calls, email and push are how **people** talk to a bot. They're not a way for the bot to run. A Hosted bot can be on Telegram. A Terminal bot's Telegram messages arrive as turns in its pane. A Vendor bot stays inside its directing bot's phone. Channels belong to [orchestration](/factory/orchestration).

## A Terminal bot is a full Bot

Everything that comes with a bot comes with a Terminal bot. Server-side pieces work the same for every binding. Pieces that have to live inside the harness are delivered by the engine when the pane starts, and again on re-entry (after compaction or a restart). Each one is labeled with what actually happens.

| What a bot has | Hosted (Gizzi) | Terminal (Claude Code, Codex, …) | Vendor |
|---|---|---|---|
| Identity, name, avatar | Full | Full. The pane header and wall tile show the avatar | Full |
| Threads, Needs you inbox, bot phone | Full | Full | Shares its directing bot's phone |
| Reach: channels, phone number, email | Full | Full. Messages arrive as turns in the pane | Through the directing bot |
| Live voice calls | Full | Routed: the bot's Hosted front (or its directing bot) answers, and the request lands in the pane as a turn. A CLI can't hold a live call | Through the directing bot |
| Persona and role instructions | System prompt | **Guidance**: written as a managed block in the harness's own instruction file (`CLAUDE.md`, `AGENTS.md` or `GIZZI.md`) and re-sent on re-entry. Labeled guidance, because the harness's built-in prompt still applies | Through the connector, where the lane allows |
| Memory (bot memory and active twin memory) | Injected | A context pack written at pickup, plus `LEARNED.md`. What the bot learns comes back as `proposed`, and only your accept makes it active | Connector read |
| Skills | Loaded | Copied into the harness's skills folder at spawn (for example `.claude/skills`) | Not available |
| Tools, connectors, computer, browser | Native | The Allternit MCP connector is registered in the harness config. Computer control goes through leases | Connector |
| Vault and credentials | Leased | Never written into the pane. Reached only through a connector tool with a lease, and every use is audited | Connector, with a lease |
| Model | Setting | Passed as the harness's own flag (`--model`, a Codex profile, …) | The vendor's |
| Permissions and autonomy | Gate | A Gate hook in the harness (`PreToolUse` for Claude, Codex and Qwen) plus the bot's [autonomy policy](/guides/bot-autonomy) (`draft` / `ask` / `tell` / `limits`) | Lane and policy |

Each field reports one of `delivered`, `guidance`, `partial` or `unavailable`, so a screen never claims more than the harness actually got.

## `team.yaml`

A team is a file. `gizzi agents up <team>` reads it, spawns a pane for each Terminal bot, binds the Hosted and Vendor bots, and registers everyone. Teams can mix all three bindings.

```yaml
bots:
  - { bot: al,       role: coordinator, binding: hosted }
  - { bot: builder,  role: build,       binding: terminal, harness: claude }
  - { bot: checker,  role: check,       binding: terminal, harness: codex }
  - { bot: research, role: research,    binding: vendor,   vendor: chatgpt, lane: official, directed_by: al }
reach:
  al: [telegram, push]
```

Each bot is addressed as `bot@team` (for example `builder@product-build`). The pane, the thread and the node all point at the same bot id.

### Presets

A preset swaps which harness or binding fills a role, without editing the team. For example, one preset can run the `build` role on Terminal Claude Code and another on Vendor ChatGPT.

```bash
gizzi agents up product-build --preset codex-heavy --dry-run
```

`--dry-run` prints the plan: one step per bot (`spawn`, `bind`, `skip` or `stop`), with the harness, machine and reason. Run it again without `--dry-run` to do exactly that.

### `--on <computer>`

```bash
gizzi agents up product-build --on build-box
```

`--on` boots the team's panes on another machine you've connected (a Mac, a Linux box or a cloud computer). This is also how Gizzi on Windows runs a team, because the pane engine is Unix-only.

## Harnesses

`gizzi agents harness list` shows the agent CLIs found on a machine (Claude Code, Codex, Kimi, Grok, agy, Gizzi) with their path and version. `gizzi agents harness sync` rescans. Discovery is local: it resolves the known CLI names on `PATH` and reads their `--version`. No network calls are made. This replaces `gizzi runtime`.

## Watching and attaching

- `gizzi agents ps` lists every bot with its binding, state, current node and proof count. Running sessions are checked against the live panes on every `ps`, so a dead process shows as dead, never as running.
- `gizzi agents wall [<team>]` opens the live wall of terminals in the engine's pane view. `ctrl+b q` returns you to Gizzi.
- `gizzi agents attach <bot@team>` depends on the binding. A Terminal bot opens its pane. A Hosted bot opens its session right in Gizzi's TUI. A Vendor bot shows its thread and ticket status, because it has no terminal.
- `gizzi agents recover` shows what it would restart after a crash. `--apply` does it.

On Desktop, Code mode's terminal wall shows the same panes as xterm tiles, so a keystroke in either shows up in both.
