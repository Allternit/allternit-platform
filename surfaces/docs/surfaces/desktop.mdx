## Overview

`allternit-desktop` (`@allternit/desktop`, in `surfaces/allternit-desktop`) is the Electron shell that bundles the whole stack so it runs locally out of the box: the workspace web UI, the Rust `allternit-api` server, `gizzi-code`, and supporting services (mux, voice, connector sidecar, office engine, computer-use driver). You can also point it at your own Allternit instance. See [BYOC overview](/byoc/overview).

The workspace UI is a Vite + React app built from the separate `allternit-ai` repository. `scripts/prepare-platform-static.cjs` packages its static export into the app; set `ALLTERNIT_AI_PATH` to build against a specific checkout.

## Global hotkeys

| Action | Shortcut |
|---|---|
| Toggle Quick Chat mini-window | `Cmd/Ctrl+Shift+A` |
| Toggle HUD window | `Cmd/Ctrl+Shift+H` (fallback `Alt+Shift+H`) |

The Quick Chat window loads the workspace UI with `/?mini=1`.

## Local development

```bash
cd surfaces/allternit-desktop
npm run dev      # builds the auth renderer, then `electron .` with NODE_ENV=development
```

## Build and package

```bash
npm run build:electron       # full packaged build (stages platform static, office add-ins, api binary, sidecars)
npm run build:electron:dmg   # same, DMG target
```

`build:electron` runs `prepare:*` steps first (platform static, computer-use driver, ACU gateway, Lima, Lume, mux, mesh node, office engine, API binary, connector catalog and sidecar) and `verify:packaged-resources`.

| Channel | Direction | Purpose |
|---|---|---|

## Allternit Factory views

<Note>
Shipping with the Allternit Factory build. These views are the approved design and are not live yet.
</Note>

Desktop is the graphical product for the [Allternit Factory](/factory/overview). There's no new mode: the Factory's four parts show up in places Desktop already has, and every view reads the same engine as Gizzi.

| Part | Where it shows |
|---|---|
| Front door | Bot Mode's launch screen: "What should the team work on?" starts a Campaign |
| [Agents](/factory/agents) | The team strip on the launch screen and the project page. Each card shows the avatar, `bot@team`, a binding badge (Hosted · Gizzi, Terminal · harness name, Vendor · vendor name · official · exact), state, current node, proof `k/n` and reach. A Team graph shows who delegates to and checks whom |
| [Orchestration](/factory/orchestration) | Threads, with `standing` and `task` labeled differently. Task threads carry a node strip. Every message shows its delivery state |
| [Workflows](/factory/workflows) | A template picker in the composer ("Run as: Build, check, prove") and a Flow graph tab on the project page, with live node status, the fail route and the human gate |
| [Workspace](/factory/workspace) | Project = Campaign. A Board tab on the project page, and the Node page in the shared pane: intent, plan and delivered, `PROGRESS.md` to the side, proof paired to each contract line, and [Approve](/factory/approvals) |
| Live terminals | Code mode's terminal wall shows every Terminal bot's pane with a `bot@team` and node header. These are the same panes as `gizzi agents wall`, so a keystroke in either shows up in both. Hosted bots open their Gizzi session, and Vendor bots open their thread |
| Per-bot device | The bot phone gets a Work app: that bot's nodes and approvals |

The views draw the same picture for the same input (no random layout), show "—" when empty, and take counts from the judge, never from narrative. Desktop ships `allternit-factory` and `gizzi` in `resources/bin` and puts `gizzi` on your PATH at first run.

## How this relates to the Agency Kernel

Desktop hosts the Allternit API and Gizzi runtime locally. It is not part of the [Agency Kernel](/architecture); the kernel's Agency API is a Cloud API surface. See [Architecture](/architecture).

## Prompt-cache countdown

After a cache-bearing response, Gizzi Code shows a separate cache row under
its model/context footer. Desktop and the web/phone/PWA workspace show the
same indicator inside the latest reply's post-run orb telemetry, alongside
time, tokens, and cost. Clicking the telemetry also includes a Cache row in
the details. Existing custom
status-line commands are preserved.

The row updates every 30 seconds without sending a model request. Green means
warm, amber means less than 20% of the TTL remains, and red means the estimated
TTL has elapsed. The block bar shows time remaining. `last hit` is the share
of the latest request's input read from cache, not a session-wide hit rate.
When cold, `may re-cache` shows the latest reported input footprint.

Expiry is an estimate from the request TTL, not a guarantee that the provider
still holds the cache. Changes to model, tools, or context may invalidate it
earlier. Unknown provider TTLs have no countdown. Native requests with a known TTL
currently use five-minute ephemeral markers; Gizzi's interactive cache path
uses its configured five-minute or one-hour TTL. No keepalive requests
are sent. Miss counts and causes are omitted when not reported.
