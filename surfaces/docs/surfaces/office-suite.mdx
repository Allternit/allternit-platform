## Overview

The **Allternit Office Suite** is a family of document surfaces built on the `@allternit/office-*` engine and editor packages. Every editor runs inside the platform shell as a first-class ACI view, delivered to the desktop app's main window for "Open with" workflows, and inside the iOS read-only viewer. A single artifact contract stores the real file bytes, so the same `.docx`, `.xlsx`, `.pptx`, or `.pdf` can move between web, desktop, and mobile without conversion.

All surfaces are reachable from the **Allternit Office** window — the popped-out desktop window the ACI rail's bottom tab opens (route `/office`, same window pattern as `/design`). The ACI **Extensions** tab (`browser-extensions` view) hosts only the extensions manager; the suite itself was extracted from it into the office window.

## Routes and shell view types

| Surface | Route | Shell view type | What it accepts |
|---|---|---|---|
| **Allternit Docs** | `/docs/:artifactId?` | `docs` | Blank document, artifact ID, or file handoff |
| **Allternit Sheets** | `/sheets/:artifactId?` | `sheets` | Blank workbook, artifact ID, or file handoff |
| **Allternit Slides** | `/slides/:artifactId?` | `slides` | Blank deck, artifact ID, or file handoff |
| **Allternit PDF** | `/pdf/:artifactId?` | `pdf` | Artifact ID or file handoff (viewer only) |
| **Allternit Sign** | `/sign` | `sign` | Upload a PDF or receive a handoff from the PDF viewer |
| **Allternit Office window** | `/office` | — (popped-out window) | Create-new cards and "Open a file" for any supported format — the ACI rail's bottom tab (replaces the Design button in ACI mode) |

Each route is optional-`artifactId`, so `/docs` opens a blank document and `/docs/art_018f3a7c...` loads that artifact directly.

## Artifact section kinds

Every editor persists (or reads) the same artifact payload, regardless of whether it is opened from the shell, a desktop window, or the iOS viewer.

| Editor | Binary section kind | Plaintext section kind | Notes |
|---|---|---|---|
| **Allternit Docs** | `docs-editor/binary` | `docs-editor/plaintext` | Base64-encoded `.docx` bytes are the source of truth; plaintext is extracted for search and iOS |
| **Allternit Sheets** | `sheets-editor/binary` | `sheets-editor/plaintext` | Base64-encoded `.xlsx` bytes; plaintext extracted for search and iOS |
| **Allternit Slides** | `slides-editor/binary` | `slides-editor/plaintext` | Base64-encoded `.pptx` bytes; plaintext extracted for search and iOS |
| **Allternit PDF** | `pdf-viewer/binary` | — | Viewer only; the original PDF bytes are read but not written back |
| **Allternit Sign** | `pdf` | — | The signed output is saved as a `pdf` data-URL section in a document artifact |

<Note>
  Legacy section kinds such as `docs-editor/<block>`, `sheets-editor/sheet`, `slides-editor/slide`, and `pdf-viewer/page` are upgraded on load where needed; new saves write the binary/plaintext pair above.
</Note>

## Desktop integration

On the Electron desktop app (`surfaces/allternit-desktop`), the suite follows a **shell-first, single-window** model. Docs, Sheets, Slides, and PDF always open as ACI shell views in the app's main window, using the same `docs`/`sheets`/`slides`/`pdf` view types as the web platform. The suite launcher itself lives in the popped-out **Allternit Office** window — the ACI rail's bottom tab (it replaces the Design button in ACI mode) — which reuses the single `OfficeSuiteSection` component to launch in-shell editors.

**"Open with Allternit"** file associations route into the same main window — there are no separate per-program office windows. The desktop registers `fileAssociations` for `.docx`, `.xlsx`, `.pptx`, and `.pdf`; macOS `open-file`, Windows `second-instance`, cold-start argv, the app menu, and `shell:open-office` IPC are all routed through the main window over the `office:open-file` / `office:open-target` preload channels (queued until the window has loaded). The platform's `desktop-bridge.ts` stashes file bytes in the one-shot file handoff and opens the editor as an in-shell view, falling back to the editor route when the shell isn't mounted.

Because the same artifact section contract drives routes, shell views, desktop windows, and mobile, a document saved on the web opens byte-for-byte identically on desktop and iOS.

## iOS read-only viewer

Editing on iOS is deferred until the web editor fully stabilizes; the current mobile surface is a **read-only viewer**. The iOS feature lives in `surfaces/allternit-mobile/ios/Features/Office/` and includes:

- `OfficeArtifactClient` — artifact-service client for fetching documents.
- `OfficeDocumentsView` — list presented from the Artifacts library toolbar.
- `OfficeDocumentView` — native read-only rendering of every editor's section mapping (doc blocks, slide cards, sheet TSV grid, and PDF pages).
- `OfficeEditorWebView` — `WKWebView` to the platform editor route with a Bearer-signed initial navigation.

DEBUG builds support `-open-office-documents` and `-open-office-document-id <id>` regression arguments. The flow is verified end-to-end in the iPhone simulator: a live artifact from the gateway is listed, and the native read-only view renders its heading and paragraphs.

## Office AI assistant

The suite includes an Allternit-backed AI assistant via the **`@allternit/office-ai`** package. It replaces the upstream editor's chat transport with one that streams from the platform's own agent runtime:

- `streamOfficeAi()` POSTs `/api/agent-chat` and normalizes the platform SSE `{chunk_type, chunk}` stream into `delta`, `tool-call`, `tool-result`, `done`, and `error` chunks.
- `OfficeAgentLoop` exposes the same `AgentLoop` interface (`busy`, `run`, `cancel`, `reset`, `restore`, and the usual events) so the vendored AI panels work unchanged.
- The Docs editor uses a real `AiPanel.tsx` implementation that streams document blocks as context. Sheets, Slides, and PDF re-export the loop through their agent stubs so their existing panels connect immediately.
- A settings gate returns provider `allternit` with a platform-managed key, satisfying the panel's configuration check without shipping real credentials to the client.

The E2E suite at `surfaces/ai.allternit.com/tests/office-ai.spec.ts` streams answers into all four editor assistant panels from a mocked SSE endpoint.

## Opening editors from code

### Shell view registry

Inside the platform shell, use the registry's `open` helper with a view type and optional context:

```typescript
// Open an existing artifact
open('docs', { artifactId: 'art_018f3a7c...' });
open('sheets', { artifactId: 'art_018f3a7c...' });
open('slides', { artifactId: 'art_018f3a7c...' });
open('pdf', { artifactId: 'art_018f3a7c...' });

// Open a blank editor
open('docs');
open('sign');
```

### File handoff

For files that do not already live as artifacts, stash the bytes and pass the handoff ID:

```typescript
import { stashFile } from '@/views/office/file-handoff';

const handoffId = stashFile({ name: 'report.docx', bytes: docxUint8Array });
open('docs', { handoffId });
```

The hub's suite section uses the same `stashFile`/`takeFile` one-shot handoff, so desktop file associations and the **Open a file** button flow through the exact same path.

### Direct route navigation

If you are outside the shell (for example, in a standalone page or a test), navigate to the route directly:

```typescript
navigate('/docs/art_018f3a7c...');
navigate('/sheets', { state: { handoffId } });
```

<Note>
  `/office` is the popped-out Allternit Office window's content route (the ACI rail's bottom tab) — on the desktop, open it via the rail entry or the app menu's **Allternit Office** item rather than navigating directly.
</Note>
