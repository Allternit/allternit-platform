## Overview

**Native Agent** is the primary chat surface for running autonomous agents inside the Allternit platform. It combines a conversational message stream with a live execution canvas so you can watch an agent think, plan, call tools, and report progress in real time.

Unlike the general chat view, Native Agent sessions are isolated by origin surface (`chat`), load agent workspace context, and surface structured agent output such as milestone roadmaps and tool execution traces.

## How to access it

Native Agent runs inside the platform shell. Open it from the shell navigation or programmatically:

```text
https://app.allternit.com/shell?view=native-agent
```

From shell code:

```typescript
open('native-agent');
```

The surface is registered as a singleton view (`native-agent`), so only one instance can be open at a time.

## Layout modes

Use the control bar in the header to change how the chat and canvas are arranged.

| Mode | Behavior |
|---|---|
| **Split** | Chat panel on the left (40% width) and canvas on the right |
| **Chat only** | Full-width conversation stream |
| **Canvas only** | Full-width execution canvas with milestones and tool calls |

## Key concepts

### Session

A Native Agent session is a persistent conversation tied to the `chat` origin surface. Sessions are stored through the backend at `/api/v1/agent-sessions` and can operate in either `regular` or `agent` mode. Agent-mode sessions load an agent workspace and attach its context pack to every message.

### Context pack

When a session runs in `agent` mode, the platform builds a context pack from the agent's workspace files:

| File | Purpose |
|---|---|
| `IDENTITY.md` | Agent identity and role |
| `VOICE.md` | Voice and tone guidelines |
| `POLICY.md` | Behavior policies |
| `SOUL.md` | Trust tiers and permissions |
| `PLAYBOOK.md` | Operational playbooks |
| `TOOLS.md` | Available tools and usage |

The pack is cached by content hash and refreshed automatically when workspace files change.

### Canvas

The right-hand canvas visualizes the agent's execution state. It renders two primary components:

- **MilestoneProgress** — a linear roadmap of milestones plus the active mission's task path.
- **ToolCallVisualization** — a list of tool calls with arguments, results, execution times, and retry actions.

### Tool calls

Tool calls are rendered as collapsible cards grouped by category (File System, System, Code, Automation, Interactive). Each card shows:

- Tool name and category
- Live execution status
- Arguments
- Result or error output
- Execution time

### Runtime Ops

The **Runtime Ops** button in the header opens the runtime operations view, where you can inspect execution mode, backend health, and active sessions.

## Endpoints

Native Agent uses the N20 Native Agent API client (`native-agent-api`). Key routes:

| Method | Path | Description |
|---|---|---|
| `GET` | `/api/v1/agent-sessions` | List sessions |
| `POST` | `/api/v1/agent-sessions` | Create a session |
| `PATCH` | `/api/v1/agent-sessions/:id` | Update a session |
| `DELETE` | `/api/v1/agent-sessions/:id` | Delete a session |
| `POST` | `/api/v1/agent-sessions/:id/messages` | Append a message |
| `POST` | `/api/agent-chat` | Stream a chat response |
| `GET` | `/api/v1/agent-sessions/sync` | SSE session sync channel |
| `GET` | `/api/v1/tools` | List available tools |
| `POST` | `/api/v1/tools/execute` | Execute a tool |

## Session modes

| Mode | Description |
|---|---|
| `regular` | Standard chat session without an agent workspace |
| `agent` | Loads an agent workspace, trust tiers, and context pack |

Set the mode when creating a session via `session_mode` in the request payload, or programmatically through the mode session store.

## Runtime execution modes

The runtime API supports three execution modes that control how aggressively the agent acts:

| Mode | Behavior |
|---|---|
| `plan` | Ask before executing tools |
| `safe` | Run safe tools automatically, prompt for destructive ones |
| `auto` | Execute tools automatically within policy boundaries |

Change the mode through Runtime Ops or by calling `PUT /api/v1/runtime/execution-mode`.

## Code session panes

Use **Panes** in the Code session header to open or close Terminal, Changes,
Browser, Computer, Files, Artifacts, Transcript, and Tasks. A check marks each
open pane; the menu stays open while you select multiple panes. Escape closes
it. The header shows the number of open panes and any running tasks.

Each pane can be resized, docked, expanded, or opened in a separate window.
On phones, the pane menu opens one pane full screen. Code tools use the same
shell surfaces as Browser and Computer, with light and dark appearance support.

The terminal has independent shell tabs, a folder path and branch context.
Use **+** for another shell. Switching tabs keeps shells mounted; closing a
shell tab disposes its session. The final tab stays open. The workspace button
starts a fresh terminal in the same folder in the console workspace.

### Watch background tasks

Open **Panes → Tasks** in a Code session to see **Running** and **Finished**
work. Each row shows its state and elapsed time. Open a shell task for its
latest output; native subagent tasks can also open their child-session
transcript. The Panes control keeps a running-task count when the pane is closed.

Claude CLI background tasks appear in this same list, including tasks that
continue after the chat reply finishes. Their output and terminal outcome come
from the CLI, rather than from the assistant saying a task is running. CLI-owned
agents show the progress/result the provider reports; they do not gain a Gizzi
child-session transcript merely by being mirrored into the list.

**Stop** targets the selected background task. A rejected or unacknowledged CLI
stop remains an error; it is not shown as a successful cancellation. If the CLI
connection disappears without a terminal outcome, its active tasks become
**interrupted**. A finished chat reply does not imply all background work finished.

With Claude CLI, a resumed conversation can prepend an old task notification
and its automated-message reminder to the next request. The provider may then
ignore that request and the app shows **turn produced no model output**. Retry
with a clear new request, or start a new thread. This is a provider conversation
limitation; the Tasks pane still shows the task's observed outcome.

### Browse, preview and edit files

The Files pane keeps the folder tree beside your open files. Click a file to
preview it. Hover over its row and select **Edit**, or use **Edit** in the
preview toolbar. The same controls appear when a row has keyboard focus;
on touch screens the Edit button stays visible.

Search the tree, expand or collapse folders, and refresh its listing without
leaving your editor. Open files appear in tabs. Use arrow keys in the tab bar
to switch files. Drag the divider to resize the tree, or use the tree toggle
to hide it. On narrow panes and phones, the tree sits above the editor.

Use **Save** or **Cmd/Ctrl+S** to write your changes. Unsaved edits stay in
memory when you switch files or close and reopen the pane. Closing an edited
file offers **Save and close**, **Discard**, and **Cancel**. A failed save keeps
the file open. Refreshing or leaving the app with unsaved changes prompts you;
drafts are not stored across an app restart.

The Changes pane has a folder-grouped file list and an **All changes** view.
Search for a changed file, collapse its diff, or open it directly in the
editor with its Edit button. The options menu includes **Show files**,
**Group files by folder**, **Collapse all files**, **Expand all files**,
**Word wrap**, and **Refresh**. Each expanded file shows all of its diff hunks.
