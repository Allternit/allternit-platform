## Before sign-in

Allternit opens on a dark welcome screen. Sign-in is available immediately; the animation never blocks access.

The 24-second illustration assembles every piece of the A://TERNIT wordmark. Gizzi arrives, the website's bot cast joins, the other bots leave, and Gizzi catches a spark. Gizzi and the wordmark dissolve before the loop starts again. The earlier Home, Bots, Code and ACI product-demo sequence is no longer the sign-in illustration.

| Surface | Authentication |
| --- | --- |
| m.allternit.com and the phone web layout | The real Clerk form below the illustration, including Apple, Google, GitHub, email, verification and recovery |
| ai.allternit.com and terminal login | The same animation beside the real Clerk form; narrow windows stack it above the form |
| Allternit Desktop | The same shared sign-in layout with the existing **Continue in browser** handoff |
| Native iPhone app | Bundled offline illustration above native social sign-in and **Continue with email**; email opens the dark Clerk sheet |

Sign in with Apple is available alongside the other providers. Existing account creation, password, verification and recovery behavior is preserved. The illustration contains no form and never receives account credentials.

## Motion and accessibility

- Authentication controls remain stationary and usable from the first frame.
- Focusing the web authentication form pauses the illustration. Opening native email sign-in, starting social sign-in or backgrounding the app pauses it too.
- The animation pauses offscreen and in hidden pages. It resumes from its current position.
- Reduce Motion shows the settled wordmark and Gizzi instead of the loop.
- The illustration is not keyboard-focusable. The actual sign-in controls keep their normal labels and keyboard behavior.
- Small screens can scroll; forms remain accessible when the keyboard is open.

## Shared asset and security

The canonical source is `surfaces/allternit-mobile/shared/login-arrival` in allternit-platform. `scene.js` contains the reviewed wordmark geometry, original website character rigs and embedded art. `player.js` owns lifecycle and a 30-fps paint limit. Run `python3 build.py --web /path/to/allternit-ai` there to generate identical `login-arrival.html` files for both repositories.

The web loads `/brand/login-arrival.html` in a sandbox with only `allow-scripts`. Its own hash-locked Content Security Policy blocks all network requests. A narrowly scoped hosting rule permits this illustration to be embedded only by its own site; other application pages retain their existing framing restrictions.

iOS bundles the same HTML through `project.yml`. `LoginArrivalView` loads only that document in a nonpersistent, noninteractive WKWebView; navigation away is rejected. No remote site, model endpoint, JavaScript library or external video is needed to play the illustration. The native view passes only pause and Reduce Motion state.

The wrappers and static poster ensure that sign-in remains available if the illustration cannot load. Native password, verification and recovery steps remain ClerkKitUI views themed to match the welcome screen.

## Release verification

Verify HTML SHA256 parity across repositories, a full wordmark/cast/solo/disappear/restart cycle, form focus and sheet pausing, background/foreground behavior, Reduce Motion and phone/desktop layout. Check real Clerk sign-in separately from the illustration. A web deployment does not update an installed native iPhone app; the app needs a new TestFlight or App Store build.
