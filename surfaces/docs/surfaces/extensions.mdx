## Overview

`allternit-extensions` ships the **Allternit Chrome extension** (`allternit-extension`) and its companion **native host** (`native-host`). Together they bring Allternit into the browser: agents can see the current page, drive it programmatically, and — through native messaging — reach the local Allternit runtime for file-system and system-level work.

<Note>
  For the Microsoft Office integration, see the dedicated [Allternit Office Add-in](/surfaces/office-addin) page.
</Note>

## Chrome Extension (`allternit-extension`)

A unified Chrome extension built with [WXT](https://wxt.dev/). It exposes Allternit agents directly inside the browser and on every webpage.

### Features

- **Browser automation** — Allternit agents can click, type, navigate, scroll, and extract data from the active tab using the same computer-use protocol as the rest of the platform.
- **Page agent** — A floating chat panel is injected into any page so users can ask Allternit to act on what they are looking at.
- **Assist only.** The page agent reads and explains. Page text is data: it never follows orders written inside a page, it says what a page asks for, and its answer cites what it read.
- **Native messaging** — The extension talks to the `native-host` bridge to forward actions to the local Allternit Desktop bridge on TCP `127.0.0.1:3011`.

### Development

```bash
cd surfaces/allternit-extensions/allternit-extension

pnpm dev    # launches Chrome with the extension loaded
pnpm build  # builds to dist/
pnpm zip    # packages for Chrome Web Store submission
pnpm test   # run the Vitest suite
```

## Native Host (`native-host`)

The native messaging host bridges the Chrome extension to the local system and the Allternit runtime. It is required for file system access and local agent execution from the browser.

The host uses the single native messaging name:

```text
com.allternit.desktop
```

### Register the host

Chrome native messaging manifests require exact extension origins; wildcards are not allowed.

```bash
# From the workspace root
ALLTERNIT_EXTENSION_ID=<32-character-chrome-extension-id> pnpm --filter @allternit/desktop-native-host register

# Register against a custom Chromium profile
pnpm --filter @allternit/desktop-native-host register -- --extension-id <id> --profile-dir <browser-user-data-dir>

# Dry-run / doctor check
pnpm --filter @allternit/desktop-native-host run doctor -- --extension-id <32-character-chrome-extension-id>
```

For direct shell usage you can also use the bundled script:

```bash
cd surfaces/allternit-extensions/native-host
./register.sh --extension-id <32-character-chrome-extension-id>
./register.sh --doctor --extension-id <32-character-chrome-extension-id>
./register.sh --uninstall
```

### What the installer does

1. Builds an executable wrapper at `dist/allternit-native-host-wrapper`.
2. Writes `com.allternit.desktop.json` into supported Chromium native messaging host directories.
3. Points the manifest `path` to the wrapper executable.
4. Sets `allowed_origins` to the concrete `chrome-extension://<id>/` origin.

### Supported browsers

On macOS and Linux the installer registers the host for:

- Google Chrome
- Google Chrome for Testing
- Microsoft Edge
- Brave
- Chromium

On macOS it also registers Arc. Windows registry wiring is handled separately.

### Validation

```bash
pnpm --filter @allternit/desktop-native-host test
pnpm --filter @allternit/desktop-native-host smoke:browser-mode
pnpm --filter @allternit/extension test
pnpm --filter @allternit/extension build
```

`smoke:browser-mode` launches Chrome for Testing with the development extension, stages the native-host manifest into the temporary profile, starts a TCP `3011` bridge, and verifies that `chrome.runtime.connectNative('com.allternit.desktop')` reaches the host and returns `pong`.

## Self-hosted install on cloud computers

Cloud computers run their own Chrome for the agent browser, and the agent needs the extension in it. The extension is not on the Chrome Web Store, and Chrome 137 and later ignore `--load-extension`, so the only way in is a **managed policy** that force-installs it from a self-hosted update manifest.

<Warning>
  **Status: packaging is built, hosting is not live until the files are published.** Until `update.xml` and the CRX exist at the URL below, Chrome on a cloud computer cannot fetch the extension and the agent browser runs without it. Check with `curl -sI https://runtime.allternit.com/chrome-extension/update.xml` before relying on it.
</Warning>

### How it fits together

| Piece | Where | What it does |
|---|---|---|
| Workflow | `.github/workflows/extension-crx.yml` | Builds the extension with WXT, packs a CRX3 signed with the stable extension key, writes `update.xml` (gupdate format: app id, `codebase`, `version`). Runs on manual dispatch and on a tag `extension/v<version>` (the tag must match `package.json`). Never deploys. |
| Packer | `scripts/pack-crx3.mjs` | Dependency-free CRX3 writer. Prints the extension id the key gives; the workflow fails if it is not `chheieepkpbhkiimdmbdjmnhcooclpok`. |
| Host | `https://runtime.allternit.com/chrome-extension/` | The R2 bucket `allternit-runtime` (the same one that serves Desktop runtime files, see [Owned downloads](/operations/owned-downloads)). Holds `update.xml` and `allternit-extension-<version>.crx`. |
| Policy | `install-browser-policy.sh` (Linux guest image) | Writes `/etc/opt/chrome/policies/managed/allternit.json` with `ExtensionSettings` set to `force_installed` for the extension id and `update_url` set to the `update.xml` above. |

The default update URL is `https://runtime.allternit.com/chrome-extension/update.xml`. Set `ALLTERNIT_EXTENSION_UPDATE_URL` to use another host, or to `none` to remove the policy and install nothing.

### Release steps

1. Bump `version` in `surfaces/allternit-extensions/allternit-extension/package.json`. Chrome only updates when the version in `update.xml` is higher than the installed one.
2. Tag and push `extension/v<version>`, or run the workflow by hand. The run's summary prints the two upload commands. The CRX and `update.xml` are also attached to the tag's GitHub release and the run's artifacts.
3. After approval, run the printed `r2-upload.py` commands (CRX first, then `update.xml`). The workflow does not run them.
4. Cloud computers pick up the new version through Chrome's normal extension update check (a few hours), or at once from `chrome://extensions` with **Update**.

### The signing key

The extension id comes from the public `key` field in `wxt.config.ts`. A CRX is accepted for that id only if it is signed with the matching **private** key. The private key is not in the repository. It must be added as the Actions secret **`ALLTERNIT_EXTENSION_PRIVATE_KEY`** (PEM). The workflow packs the CRX, derives the id from the key and fails if it differs, so a wrong key can never produce a published file. If the original private key is lost, the id cannot be kept: a new key means a new id, a new `key` in `wxt.config.ts`, and an updated id in the policy and in Gizzi Code. Do not use the secret name `ALLTERNIT_EXTENSION_KEY`; `wxt.config.ts` reads that name as the public key.

### Windows cloud computers

Chrome and Edge on Windows only force-install an extension that is not from their own store on a machine that is **managed**: joined to an Active Directory domain, enrolled in Microsoft Entra ID / device management (MDM), or enrolled in Chrome Browser Cloud Management. On an unmanaged machine the `ExtensionInstallForcelist` / `ExtensionSettings` policy is ignored for off-store extensions, and the extension shows as unsupported. Chrome 137 and later also ignore `--load-extension` there.

Our Windows cloud VMs are not domain joined and are not MDM enrolled, so **we do not expect the force-install to work on them**, and we have not tested it. This section does not promise it. Options to decide later: enrol the VMs in Chrome Browser Cloud Management (free, needs an enrolment token per organization), or publish the extension to the Chrome Web Store (unlisted) so the store accepts it. Until one of those is done, the Windows agent browser works without the extension (the existing computer driver path).
