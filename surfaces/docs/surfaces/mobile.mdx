## Overview

The **Allternit iOS** client is a native SwiftUI application that brings the Allternit platform to iPhone. It supports chat with agents, cowork project tracking, cloud-instance management, BYOC monitoring, agent hub management, and push-driven live activities.

The mobile surface uses the same backend APIs as the web and desktop surfaces: Clerk authentication, `agent-sessions`, `agent-chat`, and the full platform REST API.

## Base URL

The iOS client connects to the Allternit platform API:

```
https://api.allternit.com/api
```

Local development targets:

```
http://127.0.0.1:8013/api
```

Authentication is performed with the Clerk iOS SDK. The backend receives `Authorization: Bearer <Clerk JWT>`.

## Key platform endpoints

The mobile client consumes these live platform endpoints.

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/api/v1/agent-sessions` | Create a chat session |
| `GET` | `/api/v1/agent-sessions` | List sessions / history |
| `GET` | `/api/v1/agent-sessions/:id/messages` | Fetch session messages |
| `POST` | `/api/agent-chat` | Send a message and stream the reply |
| `POST` | `/api/v1/agent-sessions/:id/abort` | Stop an in-flight reply |
| `GET` | `/api/v1/agent-preferences` | Read user response-style preferences |
| `PUT` | `/api/v1/agent-preferences` | Update response-style preferences |
| `POST` | `/api/v1/agent-preferences/writing-style/learn` | Learn the user's writing style for Write in my style |
| `GET` | `/agents/:id/workspace/file` | Read an agent workspace file |
| `PUT` | `/agents/:id/workspace/files` | Write an agent workspace file |

## Request / response examples

### Create a session

```bash
curl -X POST https://api.allternit.com/api/v1/agent-sessions \
  -H "Authorization: Bearer $CLERK_JWT" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Mobile chat",
    "origin_surface": "chat",
    "session_mode": "regular",
    "metadata": { "device": "ios" }
  }'
```

```json
{
  "id": "ses_abc123",
  "name": "Mobile chat",
  "origin_surface": "chat",
  "session_mode": "regular",
  "created_at": "2026-08-13T19:50:00Z"
}
```

### Stream a chat reply

```bash
curl -X POST https://api.allternit.com/api/agent-chat \
  -H "Authorization: Bearer $CLERK_JWT" \
  -H "Content-Type: application/json" \
  -d '{
    "chatId": "ses_abc123",
    "message": "Explain this code",
    "runtimeModelId": "default"
  }'
```

Response body is SSE-style `data: {json}` lines:

```text
data: {"type":"message_start","messageId":"msg_1","modelId":"default","runtimeModelId":"default"}
data: {"type":"content_block_delta","messageId":"msg_1","partId":"p1","delta":{"type":"text_delta","text":"This function..."}}
data: {"type":"finish","status":"complete"}
```

### Read agent preferences

```bash
curl https://api.allternit.com/api/v1/agent-preferences \
  -H "Authorization: Bearer $CLERK_JWT"
```

```json
{
  "response_style": "concise",
  "custom_instructions": "Prefer TypeScript examples."
}
```

### Update agent preferences

```bash
curl -X PUT https://api.allternit.com/api/v1/agent-preferences \
  -H "Authorization: Bearer $CLERK_JWT" \
  -H "Content-Type: application/json" \
  -d '{
    "response_style": "verbose",
    "custom_instructions": "Include unit tests in answers."
  }'
```

```json
{
  "updated": true,
  "style_md_synced": true
}
```

### Abort a session

```bash
curl -X POST https://api.allternit.com/api/v1/agent-sessions/ses_abc123/abort \
  -H "Authorization: Bearer $CLERK_JWT"
```

```json
{
  "aborted": true
}
```

## Capabilities

- **Chat** — streaming conversations with agents, markdown rendering, syntax highlighting, and artifact cards.
- **Agent Hub** — browse, create, edit, and template agents; switch agents from the composer.
- **Artifacts** — your Artifacts v2 library (see [Artifacts in the iOS app](#artifacts-in-the-ios-app)).
- **Cowork** — view and manage cowork projects and tasks.
- **Cloud instances** — monitor and operate cloud and BYOC deployments.
- **IntelliSchedule** — time-aware agent scheduling from the device.
- **Live Activities** — keep a long-running loop visible on the lock screen.
- **Push notifications** — background refresh and push-driven alerts.

## Error codes

The iOS client surfaces API errors through the standard HTTP status codes:

| Status | Meaning |
|---|---|
| `200 OK` | Success |
| `400 Bad Request` | Invalid request payload |
| `401 Unauthorized` | Clerk JWT missing, expired, or invalid |
| `404 Not Found` | Session or agent not found |
| `429 Too Many Requests` | Rate limited |
| `500 Internal Server Error` | Backend error |

Client-side errors are reported as device alerts and logged to the in-app diagnostics view.

## Updates and recovery (m.allternit.com)

The m.allternit.com app runs a service worker (`fabric-session-service-worker.js`). It loads the page from the network first, so a new deploy shows up the next time you open the app. Every merge to allternit-ai main deploys m.allternit.com (Cloudflare Pages project `allternit-m`). Offline, it opens the last copy it saved. Build files (`/assets/...`) have the build hash in their names, so the worker keeps them and serves them from its cache.

Cloudflare Pages answers a request for a missing file with the app page (`index.html`) and status 200. The worker never stores a response of type `text/html` under a build file's name. If it finds one already stored, it deletes it and downloads the file again. Before that rule (cache `allternit-fabric-session-v140` and earlier), one such response could leave the app blank on every launch.

If a build file still fails to load before the app starts, a small script in the page deletes the app's caches and its service worker, then reloads once. The downloaded on-device voice models are kept. It runs at most once per session. ai.allternit.com does the same in `boot.js`, and its worker (`sw.js`) also never stores HTML under a build file's name.

## Error reports from phones

The m.allternit.com app sends errors to `/client-errors` on its own host. A Cloudflare Pages Function there writes them to the Function log and stores nothing. The path is outside `/api/` because a zone route sends all of m.allternit.com `/api/*` to cloud-api. The report carries:

- uncaught errors and rejected promises
- errors the app's error screen catches
- build files that fail to load before the app starts
- a snapshot (what is on screen, viewport, Home Screen or Safari) when the screen is still nearly empty 20 seconds after launch

Read them live with `wrangler pages deployment tail <deployment-id> --project-name allternit-m` (the full deployment id from `wrangler pages deployment list`).

## Artifact import on phones

Artifacts made before Artifacts v2 are copied into the cloud once per device. Desktop copies the stores that live on the computer. The web app and the phone copy only what is in their own browser storage. Before this, a phone read every record from the paired computer and re-sent it on every launch.

## Artifacts in the iOS app

The native app's Artifacts tab reads the same Artifacts v2 library as Desktop, ai.allternit.com and m.allternit.com (`GET /api/v2/artifacts`, sent straight to the cloud API with the Clerk token).

- **Filters.** **Everything**, **Mine** and **Shared with me**, a kind filter, and a search box that searches titles on the server. Pull down to refresh; more rows load as you scroll.
- **Opening an artifact.** Tap a row. Pages, docs, HTML designs and diagrams render in a web view that can load the page's own scripts and fonts but can't navigate away (links open in Safari). Sheets show as a grid, decks as slide cards, code as text, PDFs in a PDF view with **Sign this PDF**, and images and videos play in place. Cards, dashboards, ops sheets, motion and canvas designs run only in the web app, so the phone offers **Open Allternit on the web**. Office files copied from the old document store also show **Open in editor**.
- **Archive and delete.** **Archive** moves an artifact out of your saved work (it's per person, like the web's Archive). **Delete** is for the owner and removes it for everyone.
- **Make something new.** Dashboards, Motion, Page, Build, Image, Video and Deep Research start an artifact session: a new Cowork agent session whose standing instructions say what to make. The studio opens full screen with **Chat** and the kind's pane; the pane lists what the session saved (artifacts whose `origin.session_id` is the session) and refreshes every few seconds. Templates your organization turned off aren't shown.
- **Artifacts from chats.** An artifact that arrives in a chat stream (HTML, a document, a diagram, a sheet, code or an image) is saved to Artifacts v2 with the same id the web gives it (`art_t` + a stable hash of the session, kind, title and body), so it shows in the library on every surface and replaying a chat never makes a copy.

Developer notes: the client is `Core/API/ArtifactsV2Client.swift`; the library store is `Features/Artifacts/ArtifactLibraryStore.swift` (no local file; the old canvas mirror is gone). Studio sessions keep their instructions in `ArtifactStudioLauncher` and send them as the agent-chat `systemPrompt` on every turn. The Office editor web view signs the page's own `fetch` and XHR calls to its origin and the cloud API with a fresh token from the app (`AuthenticatedWebBridge`).

## Phone drawer and modes

On ai.allternit.com on a phone and in the m.allternit.com app, the menu (tap **☰** or swipe from the left edge) is the desktop rail for the mode you are in, laid out as a phone drawer. It covers 92% of the screen (at most 440 px on a tablet). Tap the strip of chat on the right, or swipe the menu left, to close it.

- **Top line.** The mode dial, the wordmark, **Inbox** and **Search**. The dial is the current mode as a round icon. Tap it and all four modes (**Home**, **Bots**, **Code**, **ACI**, the same as the desktop mode dial) fan out in a labelled arc with the current one filled. Tap one to switch, or tap outside or press Escape to close. Switching modes keeps the menu open on that mode's rail. Bots shows the same unread count as on Desktop. **Search** opens a full-screen search of chats, code threads, agent runs, projects and bots.
- **Wordmark.** Home shows the A://TERNIT wordmark. Bots shows A://TERNIT BOTS and ACI shows A://TERNIT ACI, set a little smaller so they fit beside the mode icon. Code shows the gizzi code wordmark.
- **One mode's rail at a time:**
  - **Home:** Projects, Artifacts, Automation Tasks, Customize and **More** (choose which tabs show; the choice is shared with Desktop). Then **Teammates** (your bots, with how many need you), **Pinned**, and **Recents** with a filter, a preview line, the time and a working marker.
  - **Code:** Projects, Artifacts, Automation Tasks and More, then your recent code threads grouped by repository.
  - **ACI:** MCP Apps, ACI Extensions, Computers, Teach and More, then your pinned apps and recent agent runs.
  - **Bots:** the Desktop Bots rail, sized for touch. **Home** (the Bots home) and **⋯** at the top, your main bot as a big tile with a crown (tap it for its main chat), the **Promote** row, **Projects**, **Bots** (each with what it is doing; amber means it needs you) and **Group chats** pinned at the bottom above the New button.
- **Bottom of the menu.** Your avatar with a ring that shows your cloud usage (tap it for Settings), **Phones**, and a floating **New** button: New chat in Home, New thread in Code and Bots, New session in ACI. Press and hold **New** for the other ways to start and **Quick task**.

Developer notes: the mode list is shared with Desktop through `src/shell/mode-buttons.ts`. The phone keeps the active mode in `usePhoneNav().mode`. Opening a mode's own section (Chats, Bots, Code or ACI) sets the mode. Shared sections (Projects, Artifacts, Automation Tasks, Settings) keep the current mode. `setMode` switches modes from the dial (`PhoneModeWheel.tsx`). The drawer has no visible title bar; its title stays for screen readers. The Bots rail is the Desktop one: `PhoneDrawer` renders `ShellRail` with `embedded` and `mode="bot"` (`BotModeRail` reads `usePhoneSurface()` for touch sizes and turns off drag-to-promote). `phone.css` `.phone-bot-rail` scales its type and keeps **Group chats** above the floating footer.

## Bot Mode in the iOS app

The native iPhone app (`surfaces/allternit-mobile/ios`, `Features/Bots/`) has the same Bot Mode as the PWA.

- **Rail.** The quick bot strip across the top (tap a bot to open its main chat), then **Threads** with the count of threads waiting on you, **Groups**, **Computers**, your bot **Projects**, pinned bots, group chats and every bot. A green dot means the bot is working and an amber dot means it needs you. Swipe a bot to pin it or open its profile.
- **Main chat.** Tapping a bot opens its main chat. The app finds the existing one first (this phone's pin, then the bot's `canonicalThreadId`, then its newest Main chat thread) and only creates a new one when there is none.
- **Bot page.** Tap the bot's name in a chat. The page shows the profile card with **Edit** and **Stage**, then rows for Threads, Tasks, Routines, Artifacts, Memory, Computer and Channels.
- **Threads.** Threads are grouped into Waiting on you, Working, Queued, Idle and Resolved, and the list refreshes every 15 seconds. Waiting threads have **Approve** and **Decline** buttons.
- **Group chats.** Make a room with 2 to 6 bots. Every member answers, or only the members you @mention. A bot can @mention another bot to bring it into the next round. The stage strip shows who is talking.
- **Live stage.** Give the bot files, photos or links, then choose **Plan first**, **Do it** or **Ask me first**. The bot's main chat stays open under the stage.
- **Computers.** Open any computer to see its screen. **Take control** gets the control lease for this phone. The screen reconnects with full control, and with view-only access when someone else takes over. A bot's own desktop uses the bot desktop routes: observe, take over and hand back.

Developer notes: endpoints are `/api/v1/agents`, `/api/v1/threads` (with `approve` and `decline`), `/api/v1/bot-projects`, `/api/v1/bot-groups`, `/api/v1/cowork/memory?bot=`, `/api/v1/gateway/bots/:id/channels`, `/api/v1/computers` (`status`, `control`, `control/take`, `control/release`, `ws-token`) and `/ws/computers/:id/vnc`. Group chat turns run on the device the same way as the web's `group-chat-turn-runner.ts`: each bot answers in an ephemeral agent session. The VNC client supports only the RFB "None" security type, so a computer that asks for a VNC password shows the connection error.

## Quick bot strip

Jump into a bot's chat without opening the menu.

- **Desktop:** collapse the rail, then hover over (or tab to) the widget at the top left. Your bots appear in a column under it, each with a green dot while it works and an amber dot when it needs you. Click one to open its main chat. The column hides a moment after the pointer leaves, and **Escape** closes it.
- **Phone:** press and hold **☰**. Tap a bot to open its main chat. A normal tap on **☰** still opens the menu.

## Sheets on the phone

On the phone, everything you open from a chat, from the icons at the top right, or from the composer rises from the bottom of the screen as a sheet. There are three sizes:

- **Menu sheet**, as tall as its contents: the **⋯** menus, the panes menu, **Agent mode**, **Plugins**, **Artifacts**, the design system menu and the **+** menu in a bot thread. A submenu opens in the same sheet with a **Back** row at the top. A menu too long for half the screen (a filter list, say) works like a list sheet.
- **List sheet**: the model picker, **Switch thread** and long menus. It opens at about half the screen. Drag it up for full height, down for half, and down again to close it.
- **Full screen**: an open artifact or file, the thread panel, **Computer**, the sessions overview, search and mini-apps. They slide up over the screen and back down when you leave.

Drag a sheet anywhere on it, not only by its handle. On the content, the sheet moves until it is at full height; there the content scrolls, and pulling down from the top of the content moves the sheet again. A tap on the handle switches between half and full height. To close a sheet, drag it down or flick it, tap the dimmed area, or pick an item. Full-screen views close with **Back**. With Reduce Motion turned on, sheets fade in and out instead of sliding. The menu (**☰**) still slides in from the left, Settings pages still push in from the right, and photos still zoom from their thumbnail.

Developer notes: the phone sheet lives in `src/components/ui/phone-sheet.tsx` and `phone-sheet.css`. `QuietMenu`, `DropdownMenu` and `Popover` switch to it when `usePhoneSurface()` is true, so call sites need no changes. `CascadeMenu`, `ModelPickerPopover` and `ThreadSwitcher` use it directly. Full-screen covers (`.phone-desktop-overlay`, `.phone-cover`) are wrapped in `SheetPresence`, which keeps them mounted while they slide out. Motion: in 340 ms with `cubic-bezier(.16,1,.3,1)`, out 220 ms with `cubic-bezier(.4,0,1,1)`. `PhoneSheetGrabber` calls `attachSheetDrag(sheet, grabber, close)`: a sheet taller than 55% of the screen plus 48 px rests at 55% and at full height (`100dvh - 48px`); a shorter one keeps its own height. The height follows the finger (up past the tallest resists), a release coasts 0.2 s of its speed, then settles on the nearer height in 280 ms; ending below three quarters of the lowest height, or a flick down from it, closes the sheet. The phone's own gesture sheets (`useSheetGestures`: **+** in the composer, the bot picker, Install, nudges, ACI pairing) take the same content drag; inside them `useEdgeResistance` stretches only the bottom edge, since a pull down at the top moves the sheet. `phone-sheet.css` must not share class or keyframe names with `phone.css` (`phone-sheet-css.test.ts` checks): a shared `.phone-sheet-scrim` once drew the dim over every gesture sheet, so they could not be dragged or tapped.

## Composer on the phone

The phone composer is the Desktop composer: the top deck, the message box and the bottom deck (**Agent mode**, **Plugins**, **Artifacts**) read as one unit, and on Home and the launch screens it rests at the bottom of the screen. Its controls always fit on one row, down to a 375 px wide phone. The model name shortens first. **Incognito ask** in a bot thread shows as an eye icon. The Chat | Cowork switch shows icons only, and **Output** moves into the **+** sheet. In Code, the computer, folder and worktree chips above the box wrap to a second line instead of running off the screen.

## Bots on the phone

- **Bot chat.** The top line is **Back**, the bot (name and what it is doing) and **⋯**. Back leaves the thread for the Bots home. Your messages wear the bot's own colour. Tap the bot for its page.
- **Bot page.** The same banner as the Desktop bot page (the bot's banner colour, with your stage background from Settings → Appearance moving behind it, running up under the top line), with the bot's avatar, role and **Edit** on it, then its Threads, Tasks, Routines, Artifacts, Memory, Computer and Channels, each with a live count, and each opening that part. There is no composer on the bot page; the deck at the bottom switches back to the chat.
- **Create bot.** A short sheet: pick an avatar pack and look, a colour, and a name, then **Create**. Role, instructions, brain and computer are under **More options**.
- **Connections.** The apps button at the top of the Bots home opens the apps your bots can use: what is connected (with **Sign in** where a sign-in expired), apps by category with **Add**, and your subscriptions.
- A bot's main chat is found again on every phone instead of being made again, so a bot has one **Main chat**.

## Section screens and Settings

- **Projects, Artifacts, Automation Tasks** and the sessions overview have **☰**, the title and a filter button at the top, and a floating search box and **New** button at the bottom. Artifacts show as thumbnail cards.
- **Settings** is a full sheet: your account card (plan and how much is left), then **Account**, **Assistant**, **Appearance** (Light, Dark, System), **Bots & agents**, **Computers** and **Advanced**, with simple on/off settings as switches. Pages open full width with a back button. **Log out** is at the bottom. Every settings page has a place on the phone: `settings.config.ts` gives each page a `phone: { group, order }`, and a test checks that every page is reachable.

## The ACI screen

ACI on the phone has no view tabs. Switch views from the menu's ACI rail: **MCP Apps**, **ACI Extensions** and **Computers**, or tap the ACI mode button or **New session** for the agent. The top bar holds only **☰**. MCP Apps, ACI Extensions and Computers show their name with the same page header as Desktop: the serif title (and MCP Apps' one-line description) at the top of the view.

Apps and Extensions each have one row under the top bar instead of a title, a search box and a row of filters. The row holds the view's own tabs or categories (Installed, Discover and Build in Apps; All, Productivity and the other categories in Extensions), a search button that opens into a search box, and icon buttons: **+** for Add by URL in Apps, and Marketplace and Upload in Extensions. The Agent view adds one row with the computer picker only when you have paired computers.

Desktop keeps the full headers. Developer notes: the phone screen is `src/fabric-session/phone/screens/AciScreen.tsx`. It passes `compact` to `McpAppsView` and `BrowserExtensionsView`, which then render the shared `CompactViewBar` (`src/components/ui/polish/CompactViewBar.tsx`).

## Navigation appearance

Mode controls and shell rail tabs share the desktop glass selection style. The Chat/Cowork control uses the same glass highlight on ai.allternit.com and the installed PWA. Touch targets keep their phone sizing, and motion and transparency follow system accessibility preferences.

Bot avatar packs, expression rendering, visible sizing and category controls are shared with Desktop. The same assets and renderer ship in both the web phone layout and the PWA.
