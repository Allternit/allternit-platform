This quickstart builds a weather MCP App directly with the open MCP packages. The [Apps SDK](/plugins/sdk/overview) (preview) will shorten this to one file. The server it builds has three parts:

- `get_temperature`: a data tool with no UI.
- `show_weather`: a render tool whose result is displayed in a View.
- `ui://weather/card.html`: the View, served as an MCP resource.

The server runs over streamable HTTP and is written in TypeScript with the official MCP SDK v2 ([`@modelcontextprotocol/server`](https://www.npmjs.com/package/@modelcontextprotocol/server), [`@modelcontextprotocol/client`](https://www.npmjs.com/package/@modelcontextprotocol/client)) and [`@modelcontextprotocol/ext-apps`](https://www.npmjs.com/package/@modelcontextprotocol/ext-apps). SDK v2 speaks MCP `2026-07-28` (stateless: `server/discover`, a `_meta` envelope on every request) and still answers clients that open with the older `initialize` handshake, so one server works with both. Allternit pins `@modelcontextprotocol/server` and `@modelcontextprotocol/client` at `2.3.1` and `@modelcontextprotocol/ext-apps` at `2.0.3`.

<Note>
This server has no authentication so the example stays short. A server that reads or changes user data must require OAuth. See [Authentication](/plugins/develop/authentication).
</Note>

## 1. Create the project

```bash
mkdir weather-app && cd weather-app
npm init -y
npm pkg set type=module
npm install @modelcontextprotocol/server@2.3.1 @modelcontextprotocol/client@2.3.1 @modelcontextprotocol/ext-apps@2.0.3 zod@^4.2.0
npm install --save-dev tsx typescript
```

`"type": "module"` is required because the sample uses ES module imports. SDK v2 needs Node.js 20 or later and Zod 4.2 or later.

## 2. Write the server

Save this as `server.ts`:

```ts server.ts
import { createServer } from "node:http";
import { Readable } from "node:stream";
import { createMcpHandler, McpServer } from "@modelcontextprotocol/server";
import {
  registerAppResource,
  registerAppTool,
  RESOURCE_MIME_TYPE,
} from "@modelcontextprotocol/ext-apps/server";
import { z } from "zod";

const VIEW_URI = "ui://weather/card.html";

const TEMPS: Record<string, number> = { london: 14, tokyo: 22, austin: 31 };

// The View: one HTML document, no build step. It speaks the MCP Apps bridge
// (JSON-RPC over postMessage) directly, so it has no dependencies.
const VIEW_HTML = `<!doctype html>
<html>
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<style>
  body { margin: 0; padding: 16px; font-family: system-ui, sans-serif;
         background: var(--color-background-primary, #fff);
         color: var(--color-text-primary, #1f1e1d); }
  .card { border: 1px solid var(--color-border-secondary, #ddd); border-radius: 12px; padding: 16px; }
  .temp { font-size: 40px; font-weight: 600; }
  .muted { color: var(--color-text-secondary, #666); }
</style>
</head>
<body>
<div class="card">
  <div id="city" class="muted">Waiting for data…</div>
  <div id="temp" class="temp"></div>
</div>
<script>
  let nextId = 1;
  const pending = new Map();

  function send(msg) { window.parent.postMessage({ jsonrpc: "2.0", ...msg }, "*"); }
  function request(method, params) {
    const id = nextId++;
    return new Promise((resolve, reject) => {
      pending.set(id, { resolve, reject });
      send({ id, method, params });
    });
  }
  function notify(method, params) { send({ method, params }); }

  function applyTheme(ctx) {
    const vars = (ctx && ctx.styles && ctx.styles.variables) || {};
    for (const [k, v] of Object.entries(vars)) if (v) document.documentElement.style.setProperty(k, v);
  }

  function render(result) {
    const data = result && result.structuredContent;
    if (!data) return;
    document.getElementById("city").textContent = data.city;
    document.getElementById("temp").textContent = data.temperatureC + " °C";
  }

  function reportSize() {
    notify("ui/notifications/size-changed", { height: document.documentElement.scrollHeight });
  }

  window.addEventListener("message", (event) => {
    if (event.source !== window.parent) return;
    const msg = event.data;
    if (!msg || msg.jsonrpc !== "2.0") return;
    if (msg.id !== undefined && (msg.result !== undefined || msg.error)) {
      const p = pending.get(msg.id);
      if (!p) return;
      pending.delete(msg.id);
      msg.error ? p.reject(new Error(msg.error.message)) : p.resolve(msg.result);
    } else if (msg.method === "ui/notifications/tool-result") {
      render(msg.params); reportSize();
    } else if (msg.method === "ui/notifications/host-context-changed") {
      applyTheme(msg.params);
    } else if (msg.method === "ui/resource-teardown" && msg.id !== undefined) {
      send({ id: msg.id, result: {} });
    }
  });

  // 2026-01-26 is the MCP Apps (ext-apps) bridge revision, separate from the
  // MCP protocol revision (2026-07-28) the server speaks.
  request("ui/initialize", {
    protocolVersion: "2026-01-26",
    appInfo: { name: "weather-card", version: "1.0.0" },
    appCapabilities: {},
  }).then((result) => {
    applyTheme(result.hostContext);
    notify("ui/notifications/initialized", {});
    reportSize();
  });
</script>
</body>
</html>`;

function buildServer(): McpServer {
  const server = new McpServer(
    { name: "weather-demo", version: "1.0.0" },
    {
      instructions:
        "Look up the current temperature for a city. Use get_temperature to read data; " +
        "use show_weather only when the user wants a weather card displayed.",
    },
  );

  // Data tool: no UI, safe to call repeatedly.
  server.registerTool(
    "get_temperature",
    {
      title: "Get temperature",
      description: "Get the current temperature in Celsius for london, tokyo or austin.",
      inputSchema: z.object({ city: z.string().describe("City name, e.g. london") }),
      annotations: { readOnlyHint: true, destructiveHint: false, openWorldHint: false },
    },
    async ({ city }) => {
      const t = TEMPS[city.toLowerCase()];
      if (t === undefined) {
        return { isError: true, content: [{ type: "text", text: `Unknown city: ${city}` }] };
      }
      return { content: [{ type: "text", text: `${city}: ${t} °C` }] };
    },
  );

  // Render tool: its result is delivered to the View.
  registerAppTool(
    server,
    "show_weather",
    {
      title: "Show weather card",
      description: "Display a weather card for a city. Call only when the user wants to see it.",
      inputSchema: z.object({ city: z.string() }),
      annotations: { readOnlyHint: true, destructiveHint: false, openWorldHint: false },
      _meta: { ui: { resourceUri: VIEW_URI } },
    },
    async ({ city }) => {
      const t = TEMPS[city.toLowerCase()];
      if (t === undefined) {
        return { isError: true, content: [{ type: "text", text: `Unknown city: ${city}` }] };
      }
      return {
        content: [{ type: "text", text: `Showing weather for ${city}: ${t} °C` }],
        structuredContent: { city, temperatureC: t },
      };
    },
  );

  // The ui:// resource that holds the View.
  registerAppResource(
    server,
    "Weather card",
    VIEW_URI,
    { mimeType: RESOURCE_MIME_TYPE },
    async () => ({
      contents: [
        {
          uri: VIEW_URI,
          mimeType: RESOURCE_MIME_TYPE,
          text: VIEW_HTML,
          // No network access needed, so declare no domains.
          _meta: { ui: { csp: { connectDomains: [], resourceDomains: [] }, prefersBorder: true } },
        },
      ],
    }),
  );

  return server;
}

// Streamable HTTP, stateless and dual-era: a fresh server per request.
// 2026-07-28 clients (server/discover) and legacy initialize clients are both served.
const mcp = createMcpHandler(() => buildServer());

const http = createServer(async (req, res) => {
  if (req.url !== "/mcp") {
    res.writeHead(404).end();
    return;
  }
  // createMcpHandler is web-standard (Request -> Response); adapt node:http.
  const hasBody = req.method !== "GET" && req.method !== "HEAD";
  const request = new Request(`http://${req.headers.host}${req.url}`, {
    method: req.method,
    headers: req.headers as Record<string, string>,
    ...(hasBody ? { body: Readable.toWeb(req) as ReadableStream, duplex: "half" } : {}),
  } as RequestInit);
  const response = await mcp.fetch(request);
  res.writeHead(response.status, Object.fromEntries(response.headers));
  if (response.body) for await (const chunk of response.body) res.write(chunk);
  res.end();
});

const port = Number(process.env.PORT ?? 3000);
http.listen(port, () => console.log(`MCP server listening on http://localhost:${port}/mcp`));
```

Things to notice:

- `createMcpHandler` makes the server dual-era: a `2026-07-28` client gets `server/discover` and stateless requests, an older client gets the `initialize` handshake, from the same `buildServer()`.
- Tools are listed in registration order, so `tools/list` is the same on every request.
- `registerAppTool` copies `_meta.ui.resourceUri` to the older flat key `_meta["ui/resourceUri"]`, so hosts that only read the older key still find the View.
- The render tool returns both `content` (text the model reads) and `structuredContent` (data the View reads).
- The View uses only the standard bridge: `ui/initialize`, `ui/notifications/initialized`, `ui/notifications/tool-result`, and `ui/notifications/size-changed`. It has no dependencies.
- The resource declares an empty `csp`, so the View gets no network access. See [Build: MCP App UI](/plugins/develop/mcp-app-ui#content-security-policy).

## 3. Run it

```bash
npx tsx server.ts
# MCP server listening on http://localhost:3000/mcp
```

Check it with any MCP client. This script uses the SDK client to list the tools, call the render tool, and read the View:

```ts client.ts
import { Client, StreamableHTTPClientTransport } from "@modelcontextprotocol/client";

// "auto" probes server/discover (MCP 2026-07-28) and falls back to initialize.
const client = new Client({ name: "check", version: "1.0.0" }, { versionNegotiation: { mode: "auto" } });
await client.connect(new StreamableHTTPClientTransport(new URL("http://localhost:3000/mcp")));

const { tools } = await client.listTools();
console.log(client.getNegotiatedProtocolVersion()); // 2026-07-28
console.log(tools.map((t) => [t.name, t._meta]));

console.log(await client.callTool({ name: "show_weather", arguments: { city: "Tokyo" } }));

const view = await client.readResource({ uri: "ui://weather/card.html" });
console.log(view.contents[0].mimeType); // text/html;profile=mcp-app

await client.close();
```

```bash
npx tsx client.ts
```

You should see `show_weather` listed with `_meta.ui.resourceUri` set, a result whose `structuredContent` is `{ city: "Tokyo", temperatureC: 22 }`, and the MIME type `text/html;profile=mcp-app`.

## 4. Make the server reachable

Allternit connects to your server from its own infrastructure, so the URL must be public and use `https`. Connector URLs that resolve to loopback, private, or link-local addresses are refused. During development, expose your local port through a tunnel and use the tunnel's `https` URL, for example `https://<your-tunnel-host>/mcp`.

<Tip>
If you run your own Allternit API for development, set `ALLTERNIT_MCP_ALLOW_PRIVATE_CONNECTORS=1` on it to allow connectors that resolve to a local address.
</Tip>

## 5. Connect it in Allternit

Add the server as a connector. This request uses the [connector API](/tools/mcp#create-a-connector):

```bash
curl -X POST https://api.allternit.com/mcp/connectors \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "name": "Weather demo",
    "name_id": "weather-demo",
    "url": "https://<your-tunnel-host>/mcp",
    "type": "http"
  }'
```

## 6. See it render

Start a chat and ask: "Show me the weather in Tokyo." The model calls `show_weather`. When the call completes, Allternit reads `ui://weather/card.html`, loads it into the sandbox, and shows the card in the conversation. Change the theme between light and dark and the card follows, because the View applies the `styles.variables` the host sends.

If the card does not appear, see [Troubleshooting](/plugins/guides/troubleshooting).
