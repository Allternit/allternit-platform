Gizzi Code reads the same data Allternit Desktop shows. Nothing here is a copy: answer a decision, pause a routine or start a computer in the terminal and Desktop, the web app and the phone apps see it at once.

## Footer chips

Two chips show in the footer when there is something to show:

- `⚑ 3`, next to the context meter, means agents in three places are waiting on you. Open `/decisions`.
- `PR #123 ✓4 ✗1 ●2`, on the mode line, is this branch's pull request: 4 checks passed, 1 failed, 2 are running. The number's color is the review state. Open `/pr`.

- `bots paused`, left of the others, means all bots are paused (see Pause all bots below).

The chips stay hidden when nothing is waiting, the branch has no PR, or the source isn't there (Desktop's engine isn't running, `gh` isn't installed or signed in).

## /decisions

One queue for every question and approval an agent is waiting on, across all sessions on this machine: other terminal sessions, Desktop chats, bot chats and Factory workers. It is the same queue as **Tasks → Decisions** in Desktop.

| Key | Does |
|---|---|
| `↑` `↓` | choose a decision |
| `1`–`9` | pick that option (a decision with several questions asks them in turn) |
| `x` | dismiss a question |
| `y` or `enter` | allow an approval once |
| `a` | always allow |
| `n` | deny |

The answer goes to the asking session through the engine, so it continues wherever it runs. The list refreshes every 5 seconds.

## /pr

The pull request for the current branch and its checks, refreshed every 20 seconds while open. `enter` opens the selected check in the browser and `o` opens the PR. It uses the GitHub CLI (`gh pr view`), the same source Desktop uses for linked PRs on code sessions, so `gh` must be installed and signed in.

## /projects

Your projects with the status chip Desktop shows (**On track**, **At risk**, **Blocked**, **Needs decision**, **Done**, or **Closed**) and the next action from the project's status page. Active projects come first.

## /routines

Your routines (Desktop's **Automation Tasks**) with when each runs next, when it last ran and its schedule, soonest first. Press `p` to pause or resume the selected routine.

<Note>
Routines that live on your cloud computer are listed by that computer's runtime. In the terminal, `/routines` lists the ones on this machine's runtime.
</Note>

## Computers

```bash
gizzi computers ls             # your computers and paired runtimes
gizzi computers start "Mail VPS"
gizzi computers stop cmp_7fe9…
```

`ls` shows two lists:

- **Computers**: the ones in Desktop's Computers view (this machine, paired machines, cloud desktops). `start` and `stop` take a name or an id from this list.
- **Paired runtimes**: every runtime signed in to your account (Desktops, cloud computers, VPSs, phones), online first.

### Run a session on another computer

```bash
gizzi run --on "Allternit cloud computer" "fix the failing test in api/"
```

`--on` starts the session on that runtime through the Allternit relay, sends your message, and prints the web and phone links to follow it. The turn runs on that computer, with its files and its signed-in CLI tools. A sleeping cloud computer is woken first, which can take a minute. Add `--model <brain>` (any model id from `gizzi models`) to pick the model there.

The relay needs an Allternit API key with the `compute` scope in `ALLTERNIT_API_TOKEN` (**Settings → API keys**). The device token from `gizzi pair` only identifies this machine and can't drive another one.

## Phone tasks

```bash
gizzi phone task "open Settings and turn on Do Not Disturb"
gizzi phone task "order my usual" --phone "Joe's Pixel"
gizzi phone runs                  # recent runs and their status
```

`task` sends your goal to a linked phone and prints each step as the run moves. `--phone` takes a serial or a name; with one phone linked, or only one online, you can leave it out. Inside a session, `$GIZZI_THREAD_ID` and `$GIZZI_SESSION_ID` (or `--thread` and `--session`) tie the task to that conversation, so its card shows there.

When the run reaches a sensitive step (a payment, a delete, a text, a call, a password), it stops and the terminal shows what it wants: the effect, the app, the button and how long you have. Then:

- `o` opens the screen image (in the terminal itself on iTerm2 and WezTerm, otherwise in your image viewer).
- `a` approves. It only works after the image has been shown. If the image can't load, you can still deny.
- `d` denies.

Approving is the same act as in the app, by you, signed in. Nothing in the terminal approves for you: with no terminal to ask (a pipe or a script), the hold is left for the app, and the run ends as timed out if nobody answers. API keys can't approve.

A refusal is printed as it comes: your bots are paused, or the conversation's latest message didn't come from you. With no phone linked, an offline phone or a signed-out terminal you get one plain line saying so. See [Phone approval holds](/api/phone-holds).

## Share an artifact

```bash
gizzi artifact share art_e969…          # publish and print the link
gizzi artifact share art_e969… --at 3   # publish version 3
gizzi artifact share art_e969… --status # is it shared, and where
gizzi artifact share art_e969… --off    # stop sharing
```

Sharing publishes a snapshot of the version, so later edits don't change the shared page until you share again. Artifacts have no comments yet, so there is no comments view.

## Pause all bots

```bash
gizzi agents bot pause
gizzi agents bot resume
gizzi agents bot pause --status
```

`gizzi bot pause` and `gizzi bot resume` work as a short form.

`pause` prints `All bots are paused. Routines and automatic replies are on hold; your own messages still run.` `resume` prints `Bots resumed.` `--status` shows the current state with when it was paused and from which surface. Add `--json` to print the runtime's object, `{"paused": true, "since": 1762700000, "by": "gizzi"}`.

While paused, routines and loops do not start, and bots send no proactive turns or channel auto-replies. Messages that arrive are kept and show as unanswered. Your own direct messages to a bot still run. Gizzi's own loops and scheduled agent routines obey the switch too: a paused computer starts no new scheduled run and no further loop iteration. A scheduled run keeps its place in the schedule (the next slot, no burst after resume). A run or iteration already in progress finishes. A loop you start by hand while paused runs its first iteration, because starting it is your own action. Its next iterations wait until you resume. If the runtime cannot be reached, nothing is held. Resume starts everything again. The switch is shared: pausing from the terminal pauses the same bots in Desktop and the phone apps. `gizzi status` shows a `Bots: paused since ...` line while it is on.

If the runtime on this computer is too old, the command prints `This computer's Allternit runtime is too old for pause. Update it.` and exits with an error.

## Messages tools in a session

When a session sends a text message through the Messages tools, the terminal shows what happens to it.

- A send is held, not sent. The result reads `Waiting for your approval, here or on your phone`, with the recipient and the exact text that is held. Approve it in the Needs-you inbox on your phone, the web app or Desktop.
- A draft shows the recipient, their name and the text, with `Draft only. Send it from your phone.`
- A search shows a short list: sender, time and the first line of each message, capped, marked as outside content. Treat that text as untrusted.

## Where the data comes from

These views read Allternit Desktop's gateway on this machine (`127.0.0.1:8013`, or `ALLTERNIT_API_URL`) with this machine's sign-in from `gizzi pair`, and the engine at `127.0.0.1:4096` (`GIZZI_ENGINE_URL`). If Desktop isn't running, they say so. Open Desktop or run `gizzi serve`.
