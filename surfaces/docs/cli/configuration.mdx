## Configuration sources

Gizzi Code reads configuration from three sources, in order of precedence:

1. **Command-line flags** — highest priority
2. **Environment variables** — e.g. `ALLTERNIT_API_KEY`
3. **`config.toml`** — `~/.config/gizzi-code/config.toml`

## config.toml reference

```toml
# ~/.config/gizzi-code/config.toml

[model]
provider = "allternit"         # Provider identifier
model = "gizzi-pro"            # Default model alias
temperature = 0.7

[auth]
credential_store = "auto"      # "file" | "keyring" | "auto"
default_profile = "work"

[permissions]
default_mode = "suggest"       # "suggest" | "ask" | "dontAsk"
allow = ["read", "web_search"]
deny = ["rm -rf"]

[ui]
theme = "auto"                 # "auto" | "dark" | "light"
syntax_highlighting = true
code_wrap = true

[telemetry]
enabled = true
otel_endpoint = "http://localhost:4318"
```

## Named profiles

`gizzi config profile` manages named **permission profiles** that bundle approval rules. Profiles are merged into the active permission set on startup.

```bash
# List profiles
gizzi config profile list

# Create a strict profile
gizzi config profile add strict --rule bash=ask --rule edit=ask

# Activate it
gizzi config profile set-active strict

# Remove
gizzi config profile remove strict
```

## Models for each job

Pick a model per job in `models.jobs` (project `config.json`), or in the Allternit app: open the model pill in a Code session and choose **Models for each job…** (also in **Settings → Gizzi Code**). The sheet lists Explorers, Coders, Reviewer, Goal escalation and Summarizer, each with **Same as chat** to follow the session's model; **Done** saves for the active project. A job left out follows the session's model. Values are `provider/model` ids, the same as the top-level `model` setting.

```json
{
  "models": {
    "jobs": {
      "explorer": "<provider>/<fast-model>",
      "coder": "<provider>/<balanced-model>",
      "review": "<provider>/<strongest-model>",
      "goalEscalate": "<provider>/<strongest-model>",
      "summarizer": "<provider>/<fast-model>"
    }
  }
}
```

| Job | Used for |
|---|---|
| `explorer` | Explorer subagents (`explorer`, and the older `explore`) |
| `coder` | Builder subagents (`builder`, and the older `general`) |
| `review` | The reviewer (`/review`, `gizzi run --review`, goal rounds) and Code Reviewer subagents |
| `goalEscalate` | The model a goal switches to after two rounds with the same failures |
| `summarizer` | Compacting long sessions, and Scribe subagents |
| `webResearch` | Web Researcher subagents |
| `chat`, `goalJudge` | Accepted and stored; not used yet |

## Subagents

gizzi ships 15 built-in subagent types. The full list is in [Subagents](/guides/subagents). Each type has a model class:

| `model` value | Model used |
|---|---|
| `small` | `small_model` when set, else the cheapest model on the session's provider (on `auto`, the simple tier) |
| `standard` | The parent agent's model |
| `deep` | The strongest model on the session's provider (on `auto`, the reasoning tier) |
| `inherit` | The parent agent's model |

A subagent's model comes from, in order: its own `model`, the matching `models.jobs` entry, then its class. A type with no class uses `small`. If the class has no model on the provider, the parent's model is used.

Agent files (`.gizzi/agents/*.md`) accept `model: small`, `model: standard`, `model: deep` and `model: inherit`, plus `title` and `face` (a character in the Office Professionals avatar pack).

Your custom subagents from Settings → Subagents are written to `~/.gizzi/agents/allternit/` when gizzi starts, and every ten minutes after. They load at the next config reload. A file whose subagent you deleted is removed.

| Variable | Effect |
|---|---|
| `GIZZI_SUBAGENT_SYNC_OFF` | Do not fetch your custom subagents from Allternit |
| `GIZZI_NO_BRAIN_AGENTS` | Do not pass the subagents to the Claude Code and Codex brains |
| `GIZZI_CODEX_SMALL_MODEL` | Model written for Small subagents in `~/.codex/agents/allternit-*.toml` |

The Claude Code brain gets the subagents with `--agents` (Small runs on Haiku, Standard on Sonnet, Deep on Opus). The Codex brain gets them as `~/.codex/agents/allternit-<id>.toml` files.

## Goal rounds

While a `/goal` runs, each round ends with the project's checks and a review: `goal.checks` when set (a list of commands), else the `typecheck` and `test` scripts in `package.json`, else `cargo check` for Rust. Failures and the reviewer's findings go into the next round. Turn off the review with `"goal": { "review": false }`, or the checks with `"goal": { "checks": [] }`. Reviewer tokens are not counted against the goal's token budget.

## Environment variables

| Variable | Purpose |
|----------|---------|
| `ALLTERNIT_API_KEY` | API key for the LLM gateway |
| `ALLTERNIT_ENDPOINT` | Override the default API endpoint |
| `GIZZI_CONFIG_PATH` | Override the `config.toml` location |
| `GIZZI_CREDENTIAL_STORE` | Override `auth.credential_store` |
| `ALLTERNIT_FACTORY_PEER` | Register the session as a peer in the [Allternit Factory](/factory/agents) engine. On by default; set `0` to opt out. Replaces an older variable named on the [migration page](/factory/migration#environment-variables) |

## File permissions

The `config.toml` file is created with `0o600` permissions when auth profiles containing secrets are written.
