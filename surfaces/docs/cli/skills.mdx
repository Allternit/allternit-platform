## Overview

The `gizzi skills` command manages the agents and skills available to the Allternit runtime. It can create new agents from a description, list all registered agents, and generate new skills with AI assistance.

Use it to:

- Bootstrap agents for specific workflows or code-review roles
- Inspect the agents currently available to Gizzi Code
- Generate reusable skills from a plain-language description

## Command reference

| Command | Description |
|---------|-------------|
| `gizzi skills create` | Create a new agent from a description |
| `gizzi skills list` | List all available agents |
| `gizzi skills create-skill` | Generate a new skill with AI assistance |

`gizzi skills` requires a subcommand. Run `gizzi skills --help` to see the available options.

## Agent modes

When creating an agent with `gizzi skills create`, choose how the agent can be used:

| Mode | Description |
|------|-------------|
| `all` | Can function as either a primary or subagent |
| `primary` | Acts as the main agent in a session |
| `subagent` | Called by other agents for delegated tasks |

## Available tools

Agents created with `gizzi skills create` can be granted access to a subset of the runtime tool belt. Pass a comma-separated list to `--tools`:

- `bash` — shell command execution
- `read` — read files
- `write` — write files
- `edit` — edit files
- `list` — list directories
- `glob` — file globbing
- `grep` — search file contents
- `webfetch` — fetch web pages
- `task` — spawn subagent tasks
- `todowrite` — write todo lists
- `todoread` — read todo lists

Omit `--tools` entirely to enable every tool.

## Usage examples

### List agents

```bash
gizzi skills list
```

### Create an agent interactively

```bash
gizzi skills create
```

### Create an agent non-interactively

```bash
gizzi skills create \
  --description "Review pull requests for security issues" \
  --mode subagent \
  --tools read,grep,webfetch \
  --model allternit/gizzi-pro
```

### Create an agent in a custom directory

```bash
gizzi skills create \
  --path ./my-agents \
  --description "Generate JSDoc for exported functions" \
  --mode all \
  --tools read,write,edit
```

### Generate a skill

```bash
gizzi skills create-skill \
  --description "Summarize the current git diff for a standup update"
```

### Generate a skill in a specific directory

```bash
gizzi skills create-skill \
  --path ./.gizzi/skills \
  --description "Draft release notes from CHANGELOG.md" \
  --model allternit/gizzi-pro
```

## Where agents and skills are stored

- **Agents** created without `--path` are written to `.gizzi/agent/` in the current project, or to the global Gizzi Code config directory when global scope is selected interactively.
- **Skills** created without `--path` are written to `./.gizzi/skills/`.

## Where skills are loaded from

Gizzi Code builds one skill catalog per session. When two skills share a name, the higher source wins and the other is kept as shadowed (`gizzi debug skill` lists the winners).

| Priority | Source | Locations |
|----------|--------|-----------|
| Highest | Project | `.claude/skills`, `.agents/skills`, `.openclaw/skills`, `.allternit/skills` in the project and its parent folders |
| | User | `~/.claude/skills`, `~/.agents/skills`, `~/.openclaw/skills`, `~/.allternit/skills` |
| | Configured | Extra skill paths and remote skills from your config |
| Lowest | Built-in | Shipped inside Gizzi Code |

To change how a built-in skill behaves, put a skill with the same name in a user or project folder. Yours is used, and the built-in stays available as shadowed. Set `GIZZI_DISABLE_BUILTIN_SKILLS=1` to turn every built-in skill off.

## Built-in skills

Workflow skills:

| Skill | Use |
|-------|-----|
| `agent-orchestrator` | Delegate work to other CLI agents and review what they produce |
| `steer-parallel-agent` | Steer an agent session that is already running |
| `artifacts` | Make or change an Allternit artifact |
| `import-from-claude-codex` | Preview and import instructions, skills and MCP servers from Claude Code and Codex |
| `skill-inventory` | Review skill sources and collisions |

Craft skills for visual work. Each one carries its own scripts and templates, so any model on Gizzi Code works the same way: build in code, render frames, look at them, fix, then export.

| Skill | Makes |
|-------|-------|
| `motion-reel` | Motion-graphics videos: promos, logo reveals, kinetic type, with a beat-synced synthesized score |
| `brush-film` | Hand-painted animated shorts drawn in code with p5.brush |
| `film-studio` | The review and packaging contract over any video job: brief, style guide, shot list, scored contact-sheet review |
| `ui-motion` | Product UI motion (transitions, panels, toasts), with a frame-strip tool to check it frame by frame |
| `visual-design` | Distinctive, finished web and app UI, with a desktop and phone screenshot review loop |
| `generative-art` | Seeded generative art with a parameter viewer and PNG export |

The craft skills are brand-neutral. They start from your own brand material (colors, logo, voice) or ask for it.

The first time a session loads the catalog, the craft skills' files are extracted to `skills-builtin/<skill>/<version>/` inside Gizzi Code's data directory (`~/.local/share/gizzi-code` on macOS and Linux). A new Gizzi Code release with changed files extracts to a new folder. The old folder is left in place, so projects that link to it keep working.

What they need on your machine: Node.js, Google Chrome or Chromium (set `CHROME` to use another browser), and ffmpeg for video export. `motion-reel` also needs Python 3 with NumPy for the score. Each skill installs its own npm packages (for example `playwright-core` or `p5.brush`) into the project on first use.

## Common flags

### `gizzi skills create`

| Flag | Description |
|------|-------------|
| `--path` | Directory path to generate the agent file in |
| `--description` | What the agent should do |
| `--mode` | Agent mode: `all`, `primary`, or `subagent` |
| `--tools` | Comma-separated list of tools to enable (default: all) |
| `-m`, `--model` | Model to use in `provider/model` format |

### `gizzi skills create-skill`

| Flag | Description |
|------|-------------|
| `-d`, `--description` | What the skill should do |
| `--path` | Directory to create the skill in |
| `-m`, `--model` | Model to use for generation |

### Global options

| Flag | Description |
|------|-------------|
| `--ci` | Run in non-interactive mode with structured output |
| `--ci-format` | CI output format: `ndjson`, `text`, or `markdown` |
| `--log-level` | Log level: `DEBUG`, `INFO`, `WARN`, or `ERROR` |
| `--print-logs` | Print logs to stderr |
| `-h`, `--help` | Show help |
| `-v`, `--version` | Show version number |
