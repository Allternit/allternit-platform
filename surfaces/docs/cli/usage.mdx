## Overview

The `/usage` command is an inline command available inside an interactive Gizzi Code session. It prints your Allternit plan (Free, Plus, Max or Ultra, named as Allternit Desktop names them), your credits and Cloud balance, the plan limits of each CLI brain you are signed in to, and a live summary of the current session: the active model, context-window use, cost, duration and tokens.

The footer shows your credit balance next to the context meter, for example `credits $41.20 · context: 12% (24k/200k)`. It is hidden when you are not signed in. **Settings › Usage** shows the same plan and limits.

Use it when you want to:

- Check how much of the model's context window is occupied
- See the running cost and duration of the current session
- Verify which model and directory the session is using
- Diagnose rate-limit or context-overflow warnings

<Note>
  `/usage` is a session-local command, not a top-level shell command. Run it from the Gizzi Code REPL/TUI prompt by typing `/usage` and pressing Enter.
</Note>

## Command reference

| Command | Description |
|---------|-------------|
| `/usage` | Show your Allternit plan, credits and CLI-brain limits, plus this session's tokens and cost |

`/usage` works in both interactive and non-interactive sessions. It does not modify session state and can be run any number of times.

## Output sections

Running `/usage` produces a small inline panel with the following sections.

### Session context

| Field | Description |
|-------|-------------|
| `Model` | The active model for the current session |
| `Directory` | The working directory the session is running in |
| `Session` | The unique session identifier |

### Context window

A progress bar shows the percentage of the active model's context window currently consumed. The bar changes color based on utilization:

| Color | Threshold | Meaning |
|-------|-----------|---------|
| Green | `< 75%` | Healthy context headroom |
| Yellow | `75% – 89%` | Context window is filling up |
| Red | `≥ 90%` | Critical — consider starting a new session or compacting context |

The count includes input tokens, cache-read tokens, and cache-creation tokens.

### Session totals

| Field | Description |
|-------|-------------|
| `Cost` | Total estimated cost of the session in USD |
| `Duration` | Wall-clock time since the session started |
| `Tokens` | Total tokens consumed (input + output) |
| `Cache read / Cache write` | Breakdown of cached input tokens, when applicable |

### Allternit account

Read from Allternit Cloud (`GET /api/v1/me/usage`, the route Desktop's plan meter uses). It costs nothing and runs no model. Gizzi signs in with `ALLTERNIT_API_TOKEN`, `ALLTERNIT_API_KEY`, or the device token from `gizzi login`, in that order.

| Field | Description |
|-------|-------------|
| `Plan` | Free, Plus, Max or Ultra |
| `Credits` | Your Cloud credit balance in USD |
| `Monthly` / `Free monthly` | Used of the plan's monthly grant (or the free allowance), and when it resets |
| `This month` | What you spent from credits this month |

Not signed in: the section says so and names `gizzi login`. Nothing is made up.

### CLI brains

The plan limits that Claude Code, Codex and Kimi report for your own subscription (5-hour and weekly windows, with reset times). A CLI you are not signed in to is left out.

### Check usage mid-session

```text
/usage
```

Example output:

```text

│  Usage                                 │

  Directory: ~/projects/my-app

  ████████████████░░░░░░░░░░░░  42% (12.3k / 200k)
  Color: green

  Cost:      $0.0234
  Duration:  4m 12s
  Tokens:    28.5k
             12.3k in / 16.2k out
             3.1k cache read / 0 cache write
```

### Use in non-interactive mode

`/usage` is also available in non-interactive sessions, making it useful in scripts or remote/attached sessions where you want a quick consumption snapshot without leaving the terminal.

```text
/usage
```

## Common flags

`/usage` does not accept any flags or arguments. All displayed values are derived automatically from the current session state.

## Interpreting context-window color

If the context bar is yellow or red, consider one of the following:

- Start a fresh session for a new task
- Use `gizzi run --continue` or `gizzi run --session` to fork or switch sessions
- Compact the conversation with `/compact` if available
- Reduce the amount of attached context or file attachments
