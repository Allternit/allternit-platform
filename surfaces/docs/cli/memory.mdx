Gizzi keeps a copy of your [Memory Drive](/guides/memory-drive) on your computer and reads
its `MEMORY.md` at the start of every session. Memories saved during a session are
committed and synced at the end of the turn.

## Commands

| Command | What it does |
| --- | --- |
| `gizzi memory` / `gizzi memory status` | Drive location, sync state, pending changes, last error. |
| `gizzi memory list [--source twin\|facts] [--json]` | Your memories: twin items and learned facts. See the [Memory page](/guides/memory). |
| `gizzi memory edit <id> "<text>"` | Change one memory. Editing a learned fact replaces it, so it gets a new id. |
| `gizzi memory forget <id>` | Delete one memory. |
| `gizzi memory sync` | Sync now. `--dismiss` clears the notice about edits that were refused. |
| `gizzi memory log [-n N]` | Recent changes. |
| `gizzi memory view <path>` | Print a file, e.g. `facts.md`. |
| `gizzi memory search <words>` | Search every drive you have mounted. |
| `gizzi memory import` | Preview moving memories from the old per-project memory folder into the drive. Nothing changes. |
| `gizzi memory import --apply` | Do the import as one change. Running it again does nothing. |
| `gizzi memory dreams` | Recent nightly Dreams and their reports. |
| `gizzi memory undo-dream <id>` | Undo one Dream. |
| `gizzi memory questions --drive <ref>` | A shared drive's questions board. |
| `gizzi memory ask <text> --drive <ref>` | Ask the team a question. |
| `gizzi memory answer <id> [text] --drive <ref> [--resolve]` | Answer a question, or mark it resolved. |

Add `--drive <ref>` (for example `team:ws_42`) to work with a shared drive, and `--json`
where you need machine-readable output.

Gizzi adds a dated **From past chats** block to every turn, drawn from your stored turns, unless
**Settings, Memory, Search and reference chats** or the `memory_search` setting is off. The
`memory_recall` tool also searches past chats and takes `from`, `to`, `session`, `skip_sessions`
and `neighbors_of`. See [Memory tools](/tools/memory#past-chats-in-recall). To review what agents
want to learn, see [gizzi knowledge](/cli/knowledge).

In the terminal UI: `/memory` (overview), `/memory view <path>`, `/memory log`, `/memory sync`,
`/memory-search <words>`.

## Where it lives

- Signed in: `<gizzi data>/memory-drive/<account>/personal`, plus one folder per mounted drive.
- Signed out: a local drive for that computer. The first time you sign in, its history is
  merged into your account's drive. Nothing is reset or overwritten.
- Each account has its own folder; switching accounts never mixes memories.

Agents with **user** memory (`memory: user` in the agent definition) keep it in your drive
at `agents/<agent>/memory.md`. **Project** memory stays in the project's
`.claude/agent-memory/` (shared through that project's own git) and **local** memory stays on
your computer.

## Saving and syncing

- One line per memory: Gizzi adds the source (`gizzi:session/<id>`), the date and an id.
- If someone else saved first, Gizzi re-reads the drive, re-applies your change once and pushes
  again. It never force-pushes.
- Offline, changes are kept and pushed the next time you're online, each as its own change.
- If the drive refuses a change (for example, a line that looks like a password), the reason is
  shown, the edit is moved to `<drive>.rejected/` and nothing else is lost.
- Gizzi's own local dream stays off while the nightly Dream is on for your drive.
- If a memory was deleted forever on the server, Gizzi replays only changes made since its
  last sync and clears the old history from its local copy, so the memory doesn't come back.

## Sent to your Memory Drive

When you're signed in, Gizzi also sends each turn to your Memory Drive's capture intake: what you
type, the assistant's reply and the tool calls, so the nightly Dream can learn from your terminal
sessions and Gizzi can search past chats. This happens with Sleep on or off. Gizzi skips slash
commands, and credentials in tool input and output are replaced with `[redacted]` before storing.
Incognito sessions send nothing. Turn it off in Settings → Memory → **Where your memories come from** →
**Gizzi in the terminal**. Scripted `--bare` runs never send anything.

## Sleep and memory conflicts

`gizzi memory sleep` talks to Allternit Sleep on your account. Add `--json` to print the runtime's answer unchanged.

| Command | What it does |
| --- | --- |
| `gizzi memory sleep status [--json]` | Sleep on or off, sleeping now, debt, last sleep, spend today against the daily cap, and how many conflicts need you |
| `gizzi memory sleep run [--kind nap\|daydream]` | Start a sleep now |
| `gizzi memory sleep report [id] [--json]` | What a sleep did; the latest one by default |
| `gizzi memory sleep undo <id>` | Undo one sleep |
| `gizzi memory sleep on` / `off` | Turn Sleep on or off |
| `gizzi memory disputes [--json]` | List memory conflicts Sleep found |
| `gizzi memory disputes resolve <id> a\|b\|both_scoped\|neither` | Settle one conflict |
| `gizzi memory pages [topic] [--json]` | List the pages Sleep wrote, or show one topic |

When Sleep is off, or the stage a command needs is not built yet, Gizzi says so plainly
("Sleep is off. Turn it on with `gizzi memory sleep on`." or "Not built yet: disputes.") and exits with code 2.
On a runtime without Sleep it prints "This runtime has no Sleep yet. Update Allternit." and exits 2.

In the terminal app, `/memory` shows the same Sleep status line, "N memory conflicts need you" when there are any,
and the switch (`/memory sleep on` or `/memory sleep off`).
