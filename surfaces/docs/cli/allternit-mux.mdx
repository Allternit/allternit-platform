## Overview

`allternit-mux` was the terminal multiplexer daemon behind Code Mode terminals, Gizzi's PTYs, workspace panes and bot desktops. It has been folded into the [Allternit Factory](/factory/architecture) pane engine (`factory/pane`, run as `allternit-factory pane`). The `cmd/allternit-mux` crate and binary no longer exist.

A Desktop terminal tile, a Gizzi PTY and a Factory agent pane are now the same thing: a pane in the pane engine. A terminal shows in the agent wall as a workspace labeled `term-<id>`, and an agent you start in one is detected like any other agent pane.

<Note>
Allternit Desktop builds released before this change keep using the `allternit-mux` they bundle, so nothing needs migrating on those machines. The hosted runtime image and cloud computer images pick up `allternit-factory` on their next build.
</Note>

## What replaced what

| allternit-mux | Now |
|---|---|
| `allternit-mux serve` (daemon) | `allternit-factory pane server`. Clients start it on demand with `allternit-factory pane tty ensure` |
| Socket `~/.allternit/mux/mux.sock` | The pane engine's socket for the Factory's agent session (`ao`), reported by `allternit-factory pane tty ensure` |
| `ALLTERNIT_MUX_SOCKET` | `ALLTERNIT_FACTORY_PANE_SOCKET` (skips `ensure`) |
| `ALLTERNIT_MUX_BIN` | `ALLTERNIT_FACTORY_BIN` |
| `session.create` + `pane.create` | `factory.terminal.create` |
| `pane.send_input` | `factory.terminal.write` (raw bytes, not a paste) |
| `pane.resize` | `factory.terminal.resize` |
| `pane.read` (scrollback) | `factory.terminal.output` with `follow: false` |
| `events.subscribe` `pane.output` / `pane.exited` | `factory.terminal.output` with `follow: true` |
| `session.close` | `factory.terminal.close` |
| `/opt/allternit-mux/allternit-mux` and `allternit-mux.service` in guest images | `/opt/allternit-factory/allternit-factory` and `allternit-factory-pane.service` |

## `allternit-factory pane tty`

The terminal commands, for shells, scripts and guest images. Every command prints JSON and exits 1 on an error. Every command except `help` starts the pane engine first when it isn't running.

```bash
allternit-factory pane tty ensure
# {"socket":"/Users/you/.config/…/sessions/ao/herdr.sock"}

allternit-factory pane tty create build-1 --cwd ~/repo --cols 120 --rows 40 -- /bin/zsh -l
allternit-factory pane tty write build-1 "make test" --enter
allternit-factory pane tty read build-1        # the kept output, raw
allternit-factory pane tty resize build-1 100 30
allternit-factory pane tty attach build-1      # take it over here; ctrl+b q detaches
allternit-factory pane tty get build-1
allternit-factory pane tty list
allternit-factory pane tty close build-1
```

| Command | What it does |
|---|---|
| `ensure` | Starts the pane engine if needed and prints `{"socket": …}` |
| `create <id> [--cwd DIR] [--cols N] [--rows N] [--label L] [--env K=V]… [-- argv…]` | Opens a terminal. With no argv it runs the pane engine's default shell. Ids are 1 to 64 of `A-Z a-z 0-9 _ -` |
| `write <id> <data> [--enter]` | Types raw bytes (`--enter` adds a carriage return) |
| `read <id>` | Prints the kept output and exits |
| `resize <id> <cols> <rows>` | Sets the terminal's size |
| `attach <id>` | Takes the terminal over in your own terminal. `ctrl+b q` detaches and the shell keeps running |
| `close <id>` | Closes the terminal |
| `get <id>`, `list` | Terminal facts: `terminal_id`, `pane_id`, `workspace_id`, `engine_terminal`, `running`, `exit_code`, `pid`, `output_bytes` |

## Socket methods

Clients that draw the terminal themselves (allternit-api's [Terminal API](/api/terminal), Gizzi's PTY websocket, workspace-service) speak to the pane engine's socket directly. The socket takes one JSON request per connection: `{"id", "method", "params"}` on one line, then one response line `{"id", "result"}` or `{"id", "error": {"code", "message"}}`. These methods are Allternit additions and are not in the published Herdr schema.

| Method | Params | Result |
|---|---|---|
| `factory.terminal.create` | `terminal_id`, `cwd?`, `command?` (argv), `env?`, `cols?` (80), `rows?` (24), `label?` | `{ terminal }` |
| `factory.terminal.write` | `terminal_id`, `data` | `{}` |
| `factory.terminal.resize` | `terminal_id`, `cols`, `rows` | `{}` |
| `factory.terminal.close` | `terminal_id` | `{}` |
| `factory.terminal.get` | `terminal_id` | `{ terminal }` |
| `factory.terminal.list` | — | `{ terminals }` |
| `factory.terminal.output` | `terminal_id`, `replay?` (true), `follow?` (true) | A stream, below |

`factory.terminal.output` answers `{"id", "result": {"terminal_id", "replay_bytes"}}`, then sends lines on the same connection:

- `{"type":"output","data":"…"}`: terminal output as UTF-8 text. A character split across reads is never split across frames.
- `{"type":"live"}`: once, with `follow`, when the replay is done and live output starts.
- `{"type":"exit","exit_code":0}`: once, when the shell exits and its output is drained. `exit_code` is `null` if it couldn't be read.

Error codes: `terminal_not_found`, `terminal_exists`, `invalid_terminal_id`, `invalid_size`, `terminal_exited`, `terminal_write_failed`, `terminal_create_failed`.

## Behavior

- **Scrollback.** The pane engine keeps the last 2 MiB of each terminal's raw output for replay. An exited terminal's output and exit code are kept for 10 minutes, or until it's closed.
- **Size.** The client owns a terminal's size: a resize holds even when the agent wall lays the pane out differently.
- **Terminal replies.** While a client is streaming a terminal, that client answers the program's terminal queries (cursor position, device attributes) and the pane engine's own emulator stays quiet, so programs never read two replies. With nobody attached, the pane engine answers.
- **Lifetime.** Terminals live in the pane engine daemon. They survive UI reconnects and restarts of allternit-api or `gizzi serve`, and end when the shell exits, the terminal is closed, or the pane engine stops.
- **Windows.** The pane engine's terminals need its Unix socket, and Windows Desktop doesn't ship `allternit-factory` yet, so Windows Desktop has no terminals. That's unchanged: `allternit-mux` was macOS and Linux only too.
