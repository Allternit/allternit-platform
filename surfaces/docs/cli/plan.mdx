## Overview

Plan mode is a read-only planning phase for complex tasks. In plan mode, the agent explores the codebase, considers approaches, and writes a concrete implementation plan before any files are edited. The `/plan` slash command toggles plan mode from inside the Gizzi Code TUI, or displays the current session plan when already in plan mode.

Use plan mode when you want to review a strategy before the agent starts writing code, running tests, or making destructive changes.

## Command reference

| Command | Description |
|---------|-------------|
| `/plan` | Enter plan mode if not already active. If already in plan mode, display the current plan. |
| `/plan <description>` | Enter plan mode and immediately ask the agent to start planning for `<description>`. |
| `/plan open` | Open the current session plan in your configured external editor. Only works when already in plan mode. |

## Basic usage

Enter plan mode from the Gizzi Code TUI:

```bash
/plan
```

Enter plan mode with a specific task:

```bash
/plan Refactor the auth module to use JWT-based sessions
```

View the plan that the agent has written so far:

```bash
/plan
```

Edit the plan in your default external editor:

```bash
/plan open
```

## How plan mode works

When you enter plan mode, the agent switches to a read-only stance:

- It explores the codebase and existing patterns.
- It asks clarifying questions if the approach is ambiguous.
- It writes a design and implementation plan to the session plan file.
- It does **not** create, edit, or delete files except the plan file itself.

When the plan is ready, the agent exits plan mode and presents the plan for your approval. After approval, the agent implements the plan using the normal permission rules.

On the approval prompt in the terminal, press `e` (or `ctrl+g`) to open the plan in `$EDITOR`. Change, add, remove or reorder steps, save and close: the prompt shows the edited plan, and the edited plan is what runs when you approve. `e` types into the feedback box instead while **No, keep planning** is selected.

## Plan file

Each session in plan mode writes its plan to a Markdown file under the Gizzi Code configuration directory:

```
~/.gizzi/plans/<word-slug>.md
```

For subagent sessions, the file name includes the agent ID:

```
~/.gizzi/plans/<word-slug>-agent-<agentId>.md
```

You can override the plans directory with the `plansDirectory` setting, but it must remain within the project root for safety. Plans are persisted across session resumes and forks.

## Starting in plan mode from the CLI

You can also start a session directly in plan mode without using the TUI slash command:

```bash
# Interactive session
gizzi run --permission-mode plan

# Non-interactive, print-only session
gizzi exec --permission-mode plan "Plan a refactor of the checkout flow"
```

In these cases the agent behaves the same way as if `/plan` had been invoked: it explores, designs, and writes a plan before making any changes.

## Saved plans

When the agent finishes a plan and you have an Allternit account, Gizzi saves the plan to it as one artifact for the session (id `art_plan_<session id>`). A changed plan is a new version of the same artifact. Offline or signed out, nothing is saved and the prompt works as before.

Plans stay out of the normal artifact list. To list them:

```bash
gizzi artifact list --plans
```

Each plan prints like any other artifact: its id, version, type, title and last update. The plan's status (`open`, `approved` or `done`) shows in the app's Plans list. Without `--plans`, `gizzi artifact list` doesn't show plans.

### Open in Allternit

When the plan is saved to your account, the approval prompt shows the plan's title and steps with the hint **Press o to open in Allternit**. Press `o` to open the plan in the app, where you can approve, revise or ask a question:

- With Allternit Desktop installed, it opens `allternit://artifact/<id>` in the Desktop window, and the hint changes to "Opened in Allternit".
- Without Desktop, it opens `https://ai.allternit.com/?artifact=<id>` in your browser ("Opened in your browser").
- If neither works, the hint says "Could not open the plan".

The prompt still works in the terminal. Whichever place answers first counts.

## Exiting plan mode

Plan mode ends when:

- The agent calls the `ExitPlanMode` tool and presents the plan for approval.
- You run `/exit` to leave plan mode manually.
- The session ends.

After exiting, the session returns to its previous permission mode and the agent can proceed with implementation.

## Plan mode with an installed CLI model

When the session's model is an installed coding CLI (one you connected under **Providers**), that CLI runs its own tools, so Gizzi carries plan mode over to it:

- **A CLI with its own plan mode** runs in that mode. Anything the mode would ask about goes to Gizzi: edits to the session plan file are allowed, everything else is refused. When the CLI presents its plan, Gizzi saves it as the session plan file and asks the usual **Build Agent** question.
- **A CLI with a sandbox** plans in a read-only sandbox and hands the plan over with Gizzi's `plan_exit` tool, which takes the whole plan as Markdown.
- **Other CLIs** get the same `plan_exit` tool and plan-mode instructions.

The CLI ends its turn as soon as the question is asked, so you can take as long as you need to review. Answer **Yes** and Gizzi starts a build turn that carries the plan out. Answer **No** and reply with notes to revise it. If the plan is presented again before you answer, the newer plan replaces the open question.

In headless runs (`gizzi run`, `gizzi exec`) nobody can answer, so the CLI gives the plan as its final reply instead.

In the Allternit apps, a plan with two or more numbered steps shows as an editable card: you can change, add, remove or reorder steps before you answer, and the agent runs your list. See [Edit and approve an agent's plan](/guides/plan-approval).
