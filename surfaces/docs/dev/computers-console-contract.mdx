This is the developer contract for the Computers console: one screen that shows every computer you own (cloud, paired, and this machine) with live health, services, ports, updates, findings and logs. It is the reference all surfaces build against (web, phone layout, PWA, Desktop, iOS, Android, Gizzi Code, `cmd/cli`).

Status: contract agreed 2026-11-20. Routes are being built in lanes and are not compiled yet. A route marked "planned (step N)" has no code yet (N is the step in the build plan). Migrations 153, 154 and 155 are named here; the SQL files do not exist yet.

## Decisions (D1 to D10)

| Id | Decision |
|---|---|
| D1 | The collector is a new Rust crate, `host-probe`, mounted at loopback `/v1/host/*` by allternit-api and the ao shim. Rejected: the gizzi fabric-worker, a Node server, pushed Python scripts. |
| D2 | Node routes are a fixed set under `/v1/host/*` (below). |
| D3 | Cloud serves a list route, a relay proxy and a metrics route. The cloud never polls computers. |
| D4 | Each node adds a 60 second sample to its heartbeat. The cloud keeps 48 hours of samples with a 5 minute rollup. |
| D5 | The probe is unprivileged and read-only. Changes need an approval id and write a change record first. |
| D6 | A restore point comes before a fix (rule below). |
| D7 | One pairing path: runtime pairing. See [Computer pairing](/dev/computer-pairing). |
| D8 | Cloud computer settings (below). |
| D9 | SSH uses per-computer keys plus short-lived agent keys. |
| D10 | Web sheets are ConnectSheet panels, drawn with the neutral scale (no tan Space palette). |

## Node routes (loopback `/v1/host/*`)

Served by the shared `host_probe::http` router (feature `http`). **Shipped in allternit-api** (step 1.8); the ao shim mounts the same router in a follow-up. Read routes need no approval. The one write route is `POST /v1/host/actions`.

| Route | Returns |
|---|---|
| `GET /v1/host/snapshot` | `HostSnapshot` |
| `GET /v1/host/services` | `{ services: HostService[], providers }` |
| `GET /v1/host/ports` | `{ ports: HostPort[], sources }` |
| `GET /v1/host/updates` | `{ updates: HostUpdate[], sources, lastRefreshed?, stale? }` |
| `GET /v1/host/findings` | `{ findings: HostFinding[], sources?, generatedAt, ageSec, refreshing }` (cached, see below) |
| `GET /v1/host/logs/stream?unit=&provider?=` | Server-sent events, one `LogLine` JSON object per `data:` line |
| `GET /v1/host/logs/tail?unit=&lines=` | `{ lines: LogLine[] }` (default 100, at most 1000) |
| `POST /v1/host/actions` | `HostActionResult` |
| `GET /v1/host/elevation` | `ElevationStatus` (installed, outdated, missing, notNeeded, unsupported) |
| `GET /v1/host/elevation/plan` | `SetupPlan`: every file, command and allowed action, shown before approval |
| `POST /v1/host/elevation/setup` | `ElevationStatus` after one OS admin prompt. 409 `{ error: "needs_terminal", command }` on a headless Linux server, 409 `cancelled`, 503 `helper_missing` |
| `GET /v1/host/forward?port=N` | WebSocket bridged to TCP `127.0.0.1:N` (see port forward below) |

**Who may call.** A call that came over the relay (`x-allternit-relayed`) must carry the cloud's relay signature (`x-allternit-runtime-sig`, `-ts`, `x-allternit-owner`, keyed by the runtime's relay key, path without query). The cloud adds it only after its caller check and the pairing's `runtime:execute` check, so an unsigned or badly signed relayed call gets 401 `relay_unauthorized`, and an unpaired runtime 503 `not_paired`. A local call (the Desktop UI on loopback) passes the same auth as every other protected local route. The forward socket is the exception: the relay opens it with no headers, and the cloud's single-use ticket is its gate.

**Findings cache.** The updates read alone takes 45 to 60 s on dnf and Windows, so findings are never computed inside a request. The node serves its cached report with `generatedAt` (ISO time of the scan) and `ageSec`, and starts a background rescan when the report is older than 10 minutes or an action ran (`refreshing: true`). Before the first scan finishes the answer is **202** with `findings: []` and `generatedAt: null`. Clients show that as "checking", never as "no problems".

### HostSnapshot

| Field | Type |
|---|---|
| `sampledAt` | ISO 8601 string |
| `uptimeSec` | number |
| `os` | `{ name: string, version: string, family: 'linux' \| 'macos' \| 'windows', arch: string }` |
| `cpu` | `{ percent: number, cores: number, load1?: number }` |
| `memory` | `{ usedBytes: number, totalBytes: number }` |
| `disk` | `{ mount: string, usedBytes: number, totalBytes: number }[]` |
| `net` | `{ rxBytesPerSec: number, txBytesPerSec: number }` |

### HostService

`{ name: string, unit: string, state: 'running' | 'stopped' | 'failed' | 'unknown', enabled: boolean, description?: string, pid?: number, memoryBytes?: number }`

Linux uses systemd units, macOS uses launchd jobs, Windows uses services.

### HostPort

`{ port: number, protocol: 'tcp' | 'udp', address: string, process?: string, pid?: number, exposure: 'loopback' | 'lan' | 'public' }`

### HostUpdate

`{ id: string, name: string, current?: string, available: string, security: boolean, kind: 'package' | 'os' }`

### HostFinding

`{ id: string, severity: 'info' | 'warning' | 'critical', category: 'disk' | 'security' | 'service' | 'update' | 'config', title: string, detail: string, suggestedAction?: HostAction, reclaimBytes?: number }`

`reclaimBytes` is set on `space.clean` findings (`disk-full:<mount>` and `space-clean:<item>`): the estimated bytes the suggested clean-up frees. It is only sent when there is an estimate.

### LogLine

`{ ts: string, unit: string, level: 'debug' | 'info' | 'warn' | 'error', message: string }`

Logs are masked at the node (tokens, keys, passwords, and email local parts are replaced before the line leaves the machine). Retention is **off by default**: the cloud never stores log lines unless the user turns retention on for that computer.

### Actions

`POST /v1/host/actions` body: `{ type, target, approval_id }`. Response: `{ changeId: string, undo?: { type: string, target: string, label: string }, note?: string }`. `note` is a short plain message for the user, for example when nothing needed to change.

The action list is fixed:

| `type` | `target` |
|---|---|
| `service.start` | service unit name |
| `service.stop` | service unit name |
| `service.restart` | service unit name |
| `port.free` | port number (stops the owning process; when the port belongs to a known service, it **stops that service**, and the approval sheet must say so) |
| `updates.install` | update id, or `all-security` |
| `space.clean` | clean-up item id from a finding |
| `snippet.run` | saved snippet id |

An unknown `type` returns 400. A missing or unapproved `approval_id` returns 403 `{ error: "not_approved" }` and changes nothing. The node accepts only the cloud's `ap1.<jti>.<exp>.<utag>.<sig>` ids: it recomputes the HMAC with its relay key, its runtime id and the request's `type` and `target`, rejects an expired id, and claims the id once in its change store, so a replay is 403. An unpaired node refuses every action. An action that needs admin rights the node does not have returns 403 `{ error: "needs_elevation" }` (set up admin access with `/v1/host/elevation/setup`).

The runtime presence heartbeat (every 60 s) and the paired report carry the `/v1/host/snapshot` body as `hostSample`.

## Cloud routes (allternit-cloud-api)

| Route | Behaviour |
|---|---|
| `GET /api/v1/computers/console` | One list of `ConsoleComputer` rows: kind `cloud` \| `paired` \| `desktop`, group, provider, region, os, address, last sample, services count, last backup. |
| `GET /api/v1/computers/:id/host/*` and `POST` | Relay proxy to the node's `/v1/host/*`, after an access-tier check (owner or organization member, same rule as `paired_computers.rs` `may_use`). |
| `GET /api/v1/computers/:id/metrics?window=24h` | `MetricSeries[]` from `computer_metric_samples`. |

Rules:

- An asleep cloud computer answers the relay with **409** `{ error: 'asleep', lastSample }`. The console never wakes a computer to read it.
- The relay allow-list on the cloud side is `is_allowed_runtime_path` in `cmd/allternit-cloud-api/src/routes/runtime_relay.rs:1686-1709`. The prefix `/v1` is already allowed, so `/v1/host/*` needs no new entry. The capability strings at `relay.rs:42-47` in the node are capability names, not paths.
- Offline, CPU and disk alert rules push to the phone and Desktop.

## Console list (`GET /api/v1/computers/console`)

Response: `{ "computers": [ConsoleComputer, ...] }`. Web, CLI and iOS accept this shape.

| Field | Meaning |
|---|---|
| `id` | Console row id. Cloud = `provisioned_instances.id`, paired = `paired_computers.id`, desktop = `runtime_devices.id`. Every `/computers/:id/*` route takes this id. |
| `runtimeId` | The `runtime_devices.id` the relay is keyed by. Always sent, null when there is none. Terminals use `row.runtimeId ?? row.id` for `allternit-relay://`. |
| `kind` | `cloud`, `paired` or `desktop` |
| `name`, `group`, `provider`, `region`, `os`, `address` | Display fields |
| `status` | One of the values below |
| `lastSample` | Newest `HostSnapshot`, or null |
| `servicesCount`, `lastBackup` | Summary fields |

Status values:

| Status | Meaning |
|---|---|
| `online` | Live relay, recent heartbeat |
| `offline` | No live relay |
| `asleep` | Cloud computer sleeping (never woken by the console) |
| `starting` | Cloud computer booting |
| `stopped` | Cloud computer stopped |
| `suspended` | Cloud computer suspended |
| `error` | Provider or runtime error |

Group names, in this order: `Allternit Cloud`, `On your desk`, `Your servers`, `Shared with you`.

Provider labels (#2757): `Allternit Cloud` for cloud computers (logo key `allternit`; Orgo is never shown), `Paired` for paired computers, `Allternit Desktop` for Desktop runtimes. Clients show the label the cloud sends and do not guess one.

### Needs attention (one rule for every client)

A computer needs attention when any of these is true. Every client uses this rule and no other.

| Condition | Source |
|---|---|
| `status` is `offline` or `error` | Row status |
| CPU at 90% or more | `lastSample.cpu.percent` |
| Memory at 90% or more | `lastSample` memory |
| Any disk at 90% or more full | `lastSample.disk` |

Findings (`/host/findings`) show in the detail card's Health tab; they are not part of this list rule.

`asleep`, `stopped` and `suspended` never need attention on their own: the user chose that state.

## Metrics (`GET /api/v1/computers/:id/metrics?window=24h`)

Response: `{ "series": MetricSeries[] }`. Each series is `{ metric, unit, points: [{ t, v }] }` with `t` an ISO 8601 string.

| Metric | Unit |
|---|---|
| `cpu` | percent, 0 to 100 |
| `memory` | percent, 0 to 100 |
| `disk` | percent, 0 to 100 |
| `net_rx`, `net_tx` | bytes per second |

Windows: `1h`, `24h`, `7d`, `30d`. Retention: 48 hours of raw 60 second samples, then 5 minute rollups kept for 30 days. Each node sends a `hostSample` (the `/v1/host/snapshot` body) in its 60 second presence heartbeat, and paired computers send it in their report. Without it a series stays empty.

## Approval flow (two steps, no shortcut)

| Step | Route | Returns |
|---|---|---|
| 1 | `POST /api/v1/computers/:id/approvals` with `{ type, target }` | `{ approvalId, expiresAt }` |
| 2 | `POST /api/v1/computers/:id/host/actions` with `{ type, target, approval_id }` | `{ changeId, undo?, note? }` |

The action route never mints an approval. Minting does not touch the computer, so an asleep computer can be approved. `target` is 1 to 256 characters with no control characters.

Approval id format: `ap1.<jti>.<exp>.<utag>.<sig>`, at most 129 characters, all `[a-z0-9.]`.

| Part | Meaning |
|---|---|
| `jti` | 32 lowercase hex, random, single use |
| `exp` | Unix seconds, issued plus 120 |
| `utag` | First 16 hex characters of `sha256_hex(user_id)`. Only the cloud checks it. |
| `sig` | Lowercase hex `HMAC-SHA256(key, "ap1\n<jti>\n<exp>\n<utag>\n<runtime_id>\n<type>\n<target>")` |

The key is the per-runtime relay key (`runtime_devices.credential_hash`, lowercase `sha256_hex(device_token)`, used as ASCII bytes). The node already holds it. The node splits on `.`, recomputes `sig` with its own runtime id and the request type and target, compares in constant time, rejects an expired `exp`, then claims the whole id once. Full detail is in PR #2772.

Errors:

| Status | Body | Meaning |
|---|---|---|
| 400 | | Approval id missing |
| 403 | `{ "error": "needs_elevation" }` | The change needs the one-time privileged helper (see below) |
| 403 | `{ "error": "approval_invalid", "reason": "format\|signature\|expired\|binding" }` | Bad approval. Nothing is relayed. |
| 409 | `{ "error": "asleep", "lastSample" }` | Computer is asleep or stopped. A 409 without `error: "asleep"` is the node refusing the action. |
| 503 | `{ "error": "offline", "lastSample" }` | No live relay |
| 404, 405, 501 | | Not available on this computer. Clients show "not available", not an error. |

## Port forward

`POST /api/v1/computers/:id/forward` with `{ remotePort }` returns `{ url, ticket, expiresInSeconds }` (30 seconds). Connect to `url?ticket=`. The ticket is single use. One WebSocket carries one raw TCP stream: binary frames both ways, no ready text frame. Mint one ticket per TCP connection. The node side is `/v1/host/forward?port=N` (1 to 65535): it dials `127.0.0.1:N`, replies `socket_ready` (or `socket_close` code 1011), then pumps bytes as base64 `socket_data`. The relay connection is the authentication and no approval is needed.

|---|---|

## Approval, change record and undo

1. The user approves one concrete action in the console. The cloud issues an `approval_id` bound to that action, that computer and that user.
2. The node writes a change record first (runtime home, not the platform database), then runs the action, then logs to audit.
3. `change_id` points at the record. If the action can be reversed, the response carries `undo`, which is itself an action that needs its own approval.

## Restore point rule

- Cloud computer: the latest Orgo daily backup is recorded with the change record. If no backup is newer than 24 hours the console says so before the user approves.
- Paired computer: the change record only.
- On-demand Orgo disk snapshots are unsupported and show a plain message.

## Privileged helper model

The probe never runs as root and no password is stored. Changes that need elevation use a one-time setup that the user approves:

| OS | Helper |
|---|---|
| Linux | A sudoers drop-in that allows one helper binary only. |
| macOS | A privileged launchd helper, installed once. |
| Windows | An elevated service, installed once. |
| Orgo cloud | Already root, no setup. |

## SSH key model

Each computer gets its own key. Agents get short-lived keys. The probe writes a marked `authorized_keys` block and only edits inside the markers. Paired computers are reached over their mesh IP (the mesh `autogroup:self` rule is untouched). Cloud computers use the Orgo SSH endpoint. Mesh stays off for cloud computers.

## Cloud computer settings (Orgo)

`CloudComputerSettings`: `{ location, sizeId, diskGb, sleepAfterMin, wakePolicy, image }`.

- Location is chosen on create: `nyc`, `chi`, `lon` or `syd`. Move, restart, resize, grow disk, clone and rebuild are supported.
- Rebuild is delete, create and first boot in the same location. It is held until a backup check passes, because it destroys the only disk copy.
- Daily backups are on.
- Image is Ubuntu only (`image: 'ubuntu'`). Starter templates ship only if their `setup.sh` passes.
- Public URLs are out of scope.
- Resize, grow, clone and region prices are read from one real request before the UI ships (Eoj gate G3).
