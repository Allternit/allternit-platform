**Status: DESIGN — NOT YET IMPLEMENTED (router and ModelPool); AVAILABLE (contract).** See [status labels](/architecture#status-labels).

A provider is described by what it can do, not by its name.

## Architecture contract

Produce a `ModelCapabilityProfileV1` and a `ModelPoolEntryV1`. Requests come as `CapabilityRequestV1`; the router returns an `ExecutionPlanV1`. Eligibility by sensitivity and trust is a policy check applied before any utility scoring. If no entry qualifies, the answer is an alternate implementation or a failure, never an invented model name.

Validate against the schema in `spec/Contracts/kernel/v1/schemas/` before anything else. Receivers fail closed, so a document that does not validate is rejected, not repaired.

## Current implementation

The router and ModelPool are on main as library code, but nothing calls the router in production yet, so a provider profile is not selected by live runs today.
