## Overview

The **Allternit Self-Improve** crate provides scaffolding for an evolutionary self-improvement loop in the agents-as-diffs pattern. A meta-agent rewrites a task-agent's code, and every generation is stored as a diff from its parent. A protected evaluation surface can never appear in a produced diff, and a staged evaluation gate runs a cheap subset before paying for a full evaluation.

## Base URL

The crate is consumed as a Rust library. It does not expose HTTP endpoints directly.

## Components

| Module | Purpose |
|--------|---------|
| `lineage` | Agents-as-diffs archive, parent selection, and patch-chain reconstruction |
| `working_copy` | Scratch-copy lifecycle, patch application, and protected-path filtering |
| `eval` | Staged evaluation gate traits and orchestration |

## The pattern

1. `LineageArchive::record` stores each generation as `{ id, parent_id, patches, valid, score }`.
2. `ParentSelection` chooses the next breeding parent:
   - `Latest`
   - `Best` (highest score)
   - `ScoreProportional` (sigmoid-weighted sampling with an over-use penalty)
3. `WorkingCopy::create` scratch-copies a target repo, excluding protected paths.
4. `WorkingCopy::apply_patches` runs `git apply` over the reconstructed patch chain.
5. `WorkingCopy::finalize_diff` force-resets protected paths and filters the resulting diff.
6. `StagedGate` runs a `ValidityCheck`, then a subset `Evaluator::eval_subset`, then the full evaluation if all staged scores are positive.

## Safety rules

- **Protected paths can never appear in a produced diff.** Filtering is verified by re-scanning the diff for the protected path string.
- **No network assumptions.** The crate only invokes local `git apply` and `git diff`.
- **Validity before evaluation.** A generation that does not compile or typecheck never reaches an evaluator.
- **Staged before full.** Full evaluation only runs after every staged score clears the `> 0` bar.

## JSON examples

### Record a generation

```rust
use allternit_self_improve::lineage::{LineageArchive, Generation, ParentSelection};

let mut archive = LineageArchive::new("./archive")?;
archive.record(Generation {
    id: "gen_2".to_string(),
    parent_id: Some("gen_1".to_string()),
    patches: vec!["gen_2.patch".to_string()],
    valid: true,
    score: 0.85,
})?;
```

### Reconstruct a working copy

```rust
use allternit_self_improve::working_copy::WorkingCopy;

let protected = vec!["tests/golden".to_string(), "eval/harness".to_string()];
let mut wc = WorkingCopy::create(
    "/path/to/repo",
    "./scratch",
    &protected,
)?;

wc.apply_patches(&archive.patch_chain("gen_2")?)?;
let diff = wc.finalize_diff()?;
```

### Run staged evaluation

```rust
use allternit_self_improve::eval::{StagedGate, Evaluator, ValidityCheck};

let gate = StagedGate::new(
    Box::new(MyValidityCheck),
    Box::new(MyEvaluator),
    0.2, // subset fraction
);

let report = gate.evaluate(&wc).await?;
```

## Error codes

| Error | Meaning |
|-------|---------|
| `ProtectedPathLeak` | A protected path string was found in the produced diff |
| `PatchApplyFailed` | `git apply` failed for a patch in the chain |
| `InvalidGeneration` | Generation ID or parent chain is invalid |
| `EvaluationFailed` | Staged or full evaluation failed |

## Harness improve loop

<Note>
**Coming in the next release.** `harness-improve` is a repo tool, not part of an installed app.
</Note>

`harness-improve` (crate `services/self-improve-gizzi`) uses this scaffolding to propose changes to Gizzi's own prompts and limits. It runs on your own model access. A person approves every change.

### Harness view

Only the editable files are copied into a temp dir:

- `session/prompt/*.txt`
- `tools/builtins/*.txt`
- `session/limit.ts`
- `session/guardrail-defaults.ts`

The suite, the graders and the tests are never in the view. The proposer sees the failed dev cases, not hidden tests.

### Allowlist and protected suite

A patch is valid only if it passes all of these:

- It touches only allowlisted files.
- The two `.ts` files change numbers only, within bounds.
- The guard tests pass: byte caps, vendor ban, injection wording, context breakdown and guardrails.

The shared suite in `domains/agent-evals/gizzi/` is protected. See [Gizzi evals](/guides/gizzi-evals).

### Staged gate, then full gate

The candidate runs the protected suite live. The staged gate runs a fraction of the dev split. The full gate adds the holdout split. Staged results are cached.

| Result | Score |
|---|---|
| A case passes | +1 |
| A case fails and also failed in the baseline | +0.5 |
| A case that passed in the baseline now fails | −1 |

### Accept rule

A candidate is accepted when the gate is valid, the report comparison is ok, and at least one more case passes than in the baseline.

The tool shows the price first. `--max-usd` is a hard stop. `--max-generations` defaults to 1.

### Output

The output is a patch, `report.md` and a lineage record. `--open-pr` opens a draft pull request and is opt-in. The tool never merges.
