## Overview

Gizzi is Allternit's agent runtime. It ships as `gizzi-code` (source: `cmd/gizzi-code`), a TypeScript program that runs either as an interactive terminal app or as a local HTTP server with `gizzi-code serve`. The server holds sessions, runs tools, calls models through its provider layer, and manages MCP servers, skills, memory, sandboxes and PTYs.

**Status:** Implementation IMPLEMENTED × Exposure PUBLIC (shipped in the gizzi CLI and bundled with Allternit Desktop as a sidecar).

## How the platform uses it

The platform API (`allternit-api`) does not call model providers directly. It calls the Gizzi runtime over HTTP. The runtime URL comes from the API's terminal-server setting and defaults to `http://127.0.0.1:4096`. For example:

- `POST /api/agents/:id/runs` sends the agent's input through a Gizzi session using the agent's system prompt, `model` and `provider`. See [Agents API](/api/agents).
- The [Page Agents API](/api/page-agents) proxies page-agent runs to the same local runtime (`ALLTERNIT_PAGE_AGENT_URL`, default `http://127.0.0.1:4096`).
- The [Providers API](/api/providers) relays provider sign-in, connect flows and quota windows from the runtime, which stores provider credentials.

## Runtime HTTP surface

`gizzi-code serve` mounts route groups including:

| Prefix | Purpose |
|--------|---------|
| `/session` | Create sessions, send prompts, stream and read messages. |
| `/provider`, `/model-pool` | Provider auth, model discovery, model pool. |
| `/mcp` | MCP server management. |
| `/skill` | Skill discovery. |
| `/memory`, `/brain` | Runtime memory and local model surfaces. |
| `/sandbox` | Per-session sandbox state. |
| `/pty` | Terminal sessions. |
| `/permission`, `/question` | Approval and question prompts raised during a run. |
| `/automations`, `/cron` | Scheduled and triggered runs. |
| `/peers` | Peer sessions (see [Allternit Factory agents](/factory/agents)). |
| `/pane-browser`, `/pane-artifact`, `/pane-render` | Desktop pane integrations. |

The route list lives in `cmd/gizzi-code/src/runtime/server/server.ts`. The runtime publishes an OpenAPI description of these routes; treat that, not this table, as the full reference.

## Models and providers

Gizzi resolves the model and provider it is given (for example `ollama` / `qwen2.5:0.5b` for the local Companion fallback). Local models run through Ollama; see [Local Brains](/api/local-brains). Subscription and API-key providers are connected through the runtime; see [Providers](/api/providers).

## How this relates to the Agency Kernel

Gizzi is the runtime that executes sessions today. The Agency Kernel is the separate, capability-based execution layer behind the Agency API; where a kernel step needs a model or a harness, it may call into this runtime. See [Architecture](/architecture).
