## Audit log

`GET /api/v1/platform/audit-log` returns `{ "data": [{ "id", "action", "actor_email", "resource", "ip", "created_at" }] }`. Filters are `project_id`, `action`, `from`, `to`, `after` (cursor) and `format` (for CSV). It needs an organization admin or the project owner. Key, project and policy changes write entries.

## Key expiry and IP allowlist

Project keys accept two optional fields when created:

- `expires_at`: after this time the key returns 401 and the console shows it as Expired.
- `allowed_cidrs`: a list of CIDR ranges. Calls from other addresses are refused. The client address is read from the trusted proxy header only. Console sessions are exempt.

`PATCH /api/v1/platform/projects/:id/keys/:key_id` changes a key after creation. Both fields apply to project keys, not to the user-level keys in Settings.

## Roles

Organization roles map to console access: `org:developer`, billing and viewer. Members are managed on the Members page.

## Organization policy

`GET` and `PUT /api/v1/platform/org/policy` (organization admin) read and set:

| Field | Effect |
|---|---|
| `require_key_expiry` | New keys must have an expiry |
| `max_key_ttl_days` | Longest allowed key lifetime |
| `live_keys_admin_only` | Only admins create live keys |
| `ip_allowlist` | Organization-wide CIDR allowlist |
| `spend_alert_email` | Address for spend alerts |

## Off by default

- SSO, SCIM and custom roles are behind the console flag `VITE_ORG_SSO`.
- Spend alert emails are sent only when `PLATFORM_SPEND_ALERT_EMAILS` and `ALLTERNIT_CUSTOMER_EMAILS` are set.
- Request body logging needs `log_bodies` and `PLATFORM_LOG_BODIES` (see [usage and logs](/console/usage-and-logs)).
