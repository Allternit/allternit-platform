<Note>
**Status:** Implementation SHADOW (feature-gated, stubbed in the runtime build) × Exposure —. Earlier versions of this page documented a `gizzi --computer-use-mcp` flag, paths under `cmd/gizzi-code/src/shared/utils/computerUse/`, and a set of tools (`left_click`, `right_click`, `double_click`). On main there is no `--computer-use-mcp` CLI flag, that directory does not exist, and the server is not available as a standalone stdio process.
</Note>

## What exists on main

- The TUI carries a Computer Use MCP implementation under `cmd/gizzi-code/src/cli/ui/ink-app/utils/computerUse/` (`mcpServer.ts`, `hostAdapter.ts`, `wrapper.tsx`, `executor.ts`, `gates.ts`). Its tool builder (`engine/tools.ts`) defines: `screenshot`, `key`, `hold_key`, `type`, `scroll`, `left_click_drag`, `zoom`, `open_application`, `switch_display`, `request_access`.
- The MCP client attaches it in-process only when the `CHICAGO_MCP` feature flag is on and a server named `computer-use` is configured (`services/mcp/client.ts`).
- In the runtime build (`cmd/gizzi-code/src/runtime/utils/computerUse/mcpServer.ts`) `createComputerUseMcpServerForCli()` is a stub that throws `Computer Use MCP server is not available in this build`.

## What to use instead

- Browser and desktop automation with approvals: the ACI routes, see [Computer Use](/tools/computer-use) and [ACI API](/api/aci).
- Desktop packaging embeds a pinned Cua Driver 0.34.0 (`surfaces/allternit-desktop/resources/computer-use/`; see [Cua Driver and the agent cursor](/tools/computer-use#cua-driver-and-the-agent-cursor)), launched by Allternit Desktop so that macOS Accessibility and Screen Recording permissions attach to the app.
- Design contract: [Canonical Computer Use](/core/canonical-computer-use).

## How this relates to the Agency Kernel

Computer use is an execution environment under kernel policy and receipts, not part of the kernel contracts. See [Architecture](/architecture).
