## Overview

Allternit Cloud Sandboxes run untrusted code in isolated virtual machines instead of the host process. Organization admins define **sandbox templates** that describe the runtime, source code, environment, and resource limits. A template can then be launched as a **sandbox instance**.

A separate lower-level `/sandbox/*` execution API is also available for ad-hoc code execution. It can stage uploads in and return files out; see [Sandbox API](/api/sandbox).

## run_code in chat

The Gizzi agent has a built-in `run_code` tool that analyzes attached files with Python. It does not use these VM sandboxes. It runs on the computer where the agent runs, inside the operating system sandbox (bubblewrap on Linux, sandbox-exec on macOS), with the network off and a clean environment. The script can read only its input files and the Python environment (not the home folder, other users, mounted volumes or Keychains) and can write only its run folder. Windows, Linux without bubblewrap, and computers where the sandbox can't start (Allternit cloud computers today) refuse to run it; it never runs unsandboxed.

- Attachments are staged only from `data:` URLs or allternit-api upload paths (`/api/v1/uploads/<id>`). `file:` paths and other URLs are refused.
- Python 3.12 with pandas, numpy, openpyxl and matplotlib, set up once with a pinned uv (0.11.19, checksum verified).
- 60 seconds by default, 120 at most. Output is capped at 64 KB each for stdout and stderr, and files it saves at 20 files and 20 MB.
- The permission is `run_code`: Auto runs it, Ask shows an approval card with the script (up to 4 KB of it), Read-only hides it.
- Files it saves are stored as uploads and listed on the result. Clients draw the result from `files` and `run`. Do not parse the tool's text `result`.

The live `tool_result` event and the reloaded transcript carry the same payload. When a chat is loaded with `GET /api/v1/agent-sessions/:id/messages`, the `run_code` tool part in `metadata.parts` has the same `files` and `run` as the live event, plus its `callID`:

```json
{
  "type": "tool_result",
  "toolCallId": "toolu_01",
  "toolName": "run_code",
  "result": "{ … }",
  "files": [
    {
      "name": "chart.png",
      "mediaType": "image/png",
      "uploadId": "3f2a9c0e8b7d4e1f9a6b5c4d3e2f1a0b",
      "size": 48213,
      "url": "/api/v1/uploads/3f2a9c0e8b7d4e1f9a6b5c4d3e2f1a0b"
    }
  ],
  "run": {
    "stdout": "rows 120\n",
    "stderr": "",
    "exit_code": 0,
    "timed_out": false,
    "skipped": [{ "name": "big.parquet", "reason": "over_limit" }]
  }
}
```

| Field | Meaning |
|-------|---------|
| `files[].uploadId` | A random upload id, the same kind `POST /api/v1/uploads` returns. It stays the same for every later read of this call. |
| `files[].url` | Where to fetch the bytes. See [Uploads API](/api/uploads) for the download headers. |
| `files[].size` | Bytes stored. |
| `run.exit_code` | The script's exit code. It is `null` when the run timed out. |
| `run.timed_out` | `true` when the run was stopped at its time limit. |
| `run.skipped` | Files the script saved that were not returned, each with a `reason`. |

`run.skipped[].reason` values:

| Reason | Meaning |
|--------|---------|
| `over_limit` | `run_code` left the file out: it went over 20 files or 20 MB. |
| `over_file_limit` | The API received more than 20 files and left out the rest. |
| `too_large` | The file did not fit in the 20 MB left for this result. It was not read. |
| `not_regular_file` | A symlink, folder, pipe or device, or the file was missing. |
| `hard_link` | The file has more than one hard link. |
| `outside_run_folder` | The path is not inside this run's `out/` folder. |
| `changed` | The file changed size while it was read. |
| `unreadable`, `store_failed` | A read or write error. |
| `unsupported_platform` | The API runs on a system without the needed file checks (Windows). |

The API reads only regular files with one link inside `<gizzi data>/runs/<session>/<call>/out/`. It does not follow symlinks at any level, and it checks the size before it reads a file. The first time it sees a finished call, it stores the files and writes one record for the call. Every later read, live or reloaded, uses that record and never stores the files again. The files stay available after Gizzi deletes run folders older than 7 days.

For the user view, see [Analyze files](/guides/analyze-files).

## Base URLs

Templates and instances are managed under the organization-scoped admin prefix:

```text
https://api.allternit.com/api/v1/admin
```

The ad-hoc execution API is mounted at:

```text
https://api.allternit.com/sandbox
```

Local development:

```text
http://127.0.0.1:8013/api/v1/admin
http://127.0.0.1:8013/sandbox
```

## Sandbox templates

Sandbox templates are scoped to an organization and can only be managed by organization owners or admins.

### Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/v1/admin/sandbox-templates` | List templates for the organization |
| POST | `/api/v1/admin/sandbox-templates` | Create a template |
| GET | `/api/v1/admin/sandbox-templates/:id` | Get a template |
| PUT | `/api/v1/admin/sandbox-templates/:id` | Update a template |
| DELETE | `/api/v1/admin/sandbox-templates/:id` | Delete a template |

### Template schema

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | yes | 1-64 lowercase alphanumeric characters, dots, dashes, or underscores |
| `description` | string | no | Human-readable description |
| `runtime` | string | yes | One of `bash`, `python`, `node`, `rust` |
| `image` | string | no | VM image; defaults to `ubuntu-22.04-minimal` |
| `source` | string | no | Source code or script to execute |
| `resources` | object | no | Resource limits (driver-specific) |
| `network_enabled` | boolean | no | Whether the sandbox may access the network; defaults to `false` |
| `env` | object | no | Environment variables as key/value strings |
| `timeout_secs` | integer | no | Timeout in seconds; defaults to 300, max 3600 |

### Create a template

```bash
curl -X POST http://127.0.0.1:8013/api/v1/admin/sandbox-templates \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -H "x-allternit-organization-id: org_456" \
  -d '{
    "name": "python-base",
    "description": "Base Python sandbox",
    "runtime": "python",
    "source": "print('sandbox ready')",
    "env": { "PYTHONUNBUFFERED": "1" },
    "timeout_secs": 120
  }'
```

Response (HTTP 201):

```json
{
  "id": "tpl_123",
  "org_id": "org_456",
  "name": "python-base",
  "description": "Base Python sandbox",
  "runtime": "python",
  "image": "ubuntu-22.04-minimal",
  "source": "print('sandbox ready')",
  "resources": {},
  "network_enabled": false,
  "env": { "PYTHONUNBUFFERED": "1" },
  "timeout_secs": 120,
  "created_at": "2026-04-01T12:00:00Z",
  "updated_at": "2026-04-01T12:00:00Z"
}
```

### List templates

```bash
curl -X GET http://127.0.0.1:8013/api/v1/admin/sandbox-templates \
  -H "Authorization: Bearer <token>" \
  -H "x-allternit-organization-id: org_456"
```

Response:

```json
{
  "items": [
    {
      "id": "tpl_123",
      "org_id": "org_456",
      "name": "python-base",
      "runtime": "python",
      "image": "ubuntu-22.04-minimal",
      "source": "print('sandbox ready')",
      "resources": {},
      "network_enabled": false,
      "env": { "PYTHONUNBUFFERED": "1" },
      "timeout_secs": 120,
      "created_at": "2026-04-01T12:00:00Z",
      "updated_at": "2026-04-01T12:00:00Z"
    }
  ]
}
```

## Sandbox instances

Launching an instance runs the template source inside the sandbox runtime and records the result.

### Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/v1/admin/sandbox-instances` | List instances for the organization |
| POST | `/api/v1/admin/sandbox-instances` | Launch an instance from a template |
| GET | `/api/v1/admin/sandbox-instances/:id` | Get an instance |
| POST | `/api/v1/admin/sandbox-instances/:id/stop` | Mark an instance as stopped |

### Launch an instance

```bash
curl -X POST http://127.0.0.1:8013/api/v1/admin/sandbox-instances \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -H "x-allternit-organization-id: org_456" \
  -d '{
    "template_id": "tpl_123",
    "name": "daily-report-run"
  }'
```

Response (HTTP 201):

```json
{
  "id": "inst_789",
  "status": "running",
  "session_id": "sess_abc",
  "exit_code": 0,
  "stdout": "sandbox ready\n",
  "stderr": ""
}
```

### Instance schema

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Instance ID |
| `org_id` | string | Owning organization |
| `template_id` | string | Source template ID |
| `name` | string | Optional display name |
| `status` | string | `running`, `error`, `stopped`, etc. |
| `session_id` | string | Sandbox session ID if available |
| `exit_code` | integer | Process exit code |
| `stdout` | string | Captured standard output |
| `stderr` | string | Captured standard error |
| `started_at` | string | ISO 8601 start time |
| `stopped_at` | string | ISO 8601 stop time |
| `created_at` | string | ISO 8601 creation time |

### Stop an instance

```bash
curl -X POST http://127.0.0.1:8013/api/v1/admin/sandbox-instances/inst_789/stop \
  -H "Authorization: Bearer <token>" \
  -H "x-allternit-organization-id: org_456"
```

Response:

```json
{
  "id": "inst_789",
  "status": "stopped",
  "stopped_at": "2026-04-01T12:05:00Z"
}
```

## Sandbox execution API

For ad-hoc execution, the `/sandbox/*` routes run code directly without creating a template or instance.

### Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/sandbox/` | Service status |
| POST | `/sandbox/execute` | Execute code synchronously |
| POST | `/sandbox/execute/stream` | Execute code with streaming output |
| GET | `/sandbox/capabilities` | Driver capabilities |
| GET | `/sandbox/health` | Driver health |
| GET | `/sandbox/pool` | Pool status for operators: warm counts, limits, state-file location |

### Execute code

```bash
curl -X POST http://127.0.0.1:8013/sandbox/execute \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "code": "print(21 + 21)",
    "language": "python",
    "timeout_secs": 60,
    "env": { "FOO": "bar" },
    "network_enabled": false
  }'
```

Response:

```json
{
  "exit_code": 0,
  "stdout": "42\n",
  "stderr": "",
  "duration_ms": 340,
  "session_id": "sess_xyz"
}
```

### Streaming execution

```bash
curl -N -X POST http://127.0.0.1:8013/sandbox/execute/stream \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "code": "for i in range(3): print(i)",
    "language": "python"
  }'
```

The stream emits one SSE event per output line and ends with a `done` event:

```
data: {"type":"stdout","line":"0"}

data: {"type":"stdout","line":"1"}

data: {"type":"stdout","line":"2"}

data: {"type":"done","exit_code":0}
```

## Error codes

| HTTP | Code / Message | Meaning |
|------|----------------|---------|
| 200 | — | Success |
| 201 | — | Template or instance created |
| 400 | `invalid_runtime` | Runtime not in `bash`, `python`, `node`, `rust` |
| 400 | `invalid_name` | Template/instance name does not match the allowed pattern |
| 400 | `invalid_timeout` | `timeout_secs` is not between 1 and 3600 |
| 400 | `missing_source` | Server tool source is empty |
| 403 | `organization_required` | No active organization in the session |
| 403 | `insufficient_role` | Caller is not an organization owner/admin |
| 404 | `not_found` | Template or instance not found |
| 409 | `duplicate_name` | A template with this name already exists |
| 503 | `VM driver not available` | No VM driver is initialized |
