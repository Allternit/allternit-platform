## Overview

The computer toolset is how every agent in Allternit uses a screen. There is one contract, one executor and one adapter per model family:

1. **Contract.** `allternit.computer.v2` (23 members: the 17 pixel members of `allternit.computer.v1` — byte-identical names and input fields to Anthropic's `computer_toolset_20260801` — plus 6 structured members backed by the Allternit Driver) and `allternit.browser.v1` (31 members, identical to Anthropic's `browser_toolset_20260801`). v2 is additive: every v1 call is a valid v2 call.
2. **Executor.** `POST /api/v1/computers/:id/toolset` in allternit-api. It validates the call, checks the control lease and approvals, writes the audit row, scales coordinates and dispatches the action.
3. **Adapters.** gizzi turns each model's tool calls into contract calls. gizzi is the only agent loop. No adapter runs a loop of its own.

`:id` is a computer id or `this-device`. In gizzi, set the target with `GIZZI_COMPUTER_ID`. The default is `this-device`.

## Members

### Computer (`allternit.computer.v1`)

| Member | Risk | Approval | Fields |
|---|---|---|---|
| `screenshot` | reversible | no | none |
| `zoom` | reversible | no | `region: [x0, y0, x1, y1]` |
| `left_click`, `right_click`, `middle_click`, `double_click`, `triple_click` | risky | no | `coordinate?: [x, y]`, `text?` (modifier keys to hold, such as `ctrl+shift`) |
| `mouse_move` | reversible | no | `coordinate` |
| `left_click_drag` | risky | no | `start_coordinate`, `coordinate`, `text?` |
| `left_mouse_down`, `left_mouse_up` | risky | no | none |
| `scroll` | reversible | no | `scroll_direction`, `scroll_amount`, `coordinate?`, `text?` |
| `type` | risky | on non-sandbox targets | `text` |
| `key` | risky | on non-sandbox targets | `text` (xdotool syntax, such as `ctrl+a` or `Return`), `repeat?` |
| `hold_key` | risky | on non-sandbox targets | `text`, `duration` |
| `wait` | reversible | no | `duration` (seconds) |
| `cursor_position` | reversible | no | none |

### Computer v2 (`allternit.computer.v2`)

The structured members. They read and drive the UI through the [Allternit Driver](/tools/allternit-driver) sidecar — no screenshots for reads — and every model family gets them as the `computer_v2` function tool (Claude gets them next to its native toolset). Prompt guidance in both tools steers models to prefer `read_ui` + `run_batch` over screenshot + pixel loops.

| Member | Risk | Approval | Fields |
|---|---|---|---|
| `read_ui` | reversible | no | `app?` / `pid?` / `window_id?` (default: frontmost), `query?`, `max_elements?` (default 200), `since?` (a version: returns only the diff) |
| `act` | risky | on non-sandbox targets for `set_value` / `select` / `press` (same rule as `type`) | `id` (element id from `read_ui`), `op` (`click`, `set_value`, `select`, `press`, `menu`, `focus`), `value?`, `key?`, `path?` (menu path), `version?` |
| `run_batch` | risky | on non-sandbox targets, when any `act` step enters text | `steps` (1–50): `{act? {id, op, value?, key?}, menu?, pixel? {tool, args}, wait? ms, wait_for?, expect?, timeout_ms?}`; `version?` |
| `verify` | reversible | no | `checks` (1–20): `{id?, role?, name?, text?, gone?, value?, enabled?}`, `timeout_ms?` |
| `request_human` | reversible | no | `reason?`, `timeout_ms?` (default 5 min) |
| `use_credential` | risky | on non-sandbox targets | `name`, `kind?` (`secret` or `totp`), `source?` (`vault`, `keychain`, `bitwarden`, `onepassword`), `domain?` (must match the credential's binding) |
| `run_subtask` | risky | on non-sandbox targets, **once per subtask** (its steps carry that grant) | `goal`, `inputs?` (`[{name, value}]`, the only text it may type), `success?` (1–10 `verify` checks, or `{ask}` for a fuzzy yes/no), `constraints?` (`ops?`, `avoid?`, `allow_irreversible?`), `max_steps?` (default 12, max 40), `budget_ms?` (default 60 000), `app?` / `pid?` / `window_id?`, `query?`, `max_elements?` (default 300) |

`run_batch` runs ordered steps in one window. Each step may check `wait_for` (precondition) and `expect` (postcondition); the batch stops at the first failed check and returns one observe read (the fresh element map). `verify` checks bounded conditions — role, name, text, gone, value, enabled — on a fresh read. `request_human` pauses the lease, opens the live view with input enabled, and resumes the same session when the person signals done (`POST /api/v1/computers/:id/human-done`) or the timeout elapses. `use_credential` types a vault secret or a fresh TOTP code into the focused field; the value never enters the model context, the prompts or the logs. See [Computer credentials](/tools/computer-credentials).

`run_subtask` hands a bounded step sequence (fill a form, search and pick a result, toggle settings) to the decision loop instead of the planner model. Each step reads the element map, picks one option from the visible elements × allowed ops with a typed decision (`POST /v1/decisions`, about 100–150 ms on a local scorer), runs it through the same lease → policy → audit path as every other call, and checks `success` with `verify`. It returns a step trace (decision, backend, latency, confidence per step) and a status: `done`, `escalated` (with the reason and a compact current screen, so the planner continues from there) or `failed`. A decision under its confidence threshold hands control back instead of guessing. Elements named like send, pay, buy, delete or publish are never options unless `constraints.allow_irreversible` is set. Secrets never go in `inputs`: use `use_credential`. See [How computer use decides](/tools/computer-use-decisions) for the loop and measured numbers.

```json
{
  "member": "run_subtask",
  "input": {
    "goal": "Fill the sign-up form and submit it",
    "inputs": [{ "name": "full name", "value": "Ada Lovelace" }, { "name": "email", "value": "ada@example.com" }],
    "success": [{ "text": "Thanks, Ada" }],
    "max_steps": 8
  }
}
```

Structured members need the Allternit Driver on the computer: today that is this-device (macOS, Linux); cloud guests gain them with the guest driver image. The [schema endpoint](#schema) reports each member's availability per target.

### Browser (`allternit.browser.v1`)

Targets are either `{ "type": "coordinate", "x": 640, "y": 380 }` or `{ "type": "ref", "ref": "ref_2" }`.

| Member | Risk | Default | Approval |
|---|---|---|---|
| `navigate`, `left_click`, `right_click`, `middle_click`, `double_click`, `triple_click`, `left_click_drag`, `left_mouse_down`, `left_mouse_up`, `close_tab` | risky | on | no |
| `screenshot`, `zoom`, `hover`, `mouse_move`, `scroll`, `scroll_to`, `wait`, `read_page`, `find`, `get_page_text`, `new_tab`, `list_tabs`, `switch_tab` | reversible | on | no |
| `type`, `key`, `hold_key`, `form_input` | risky | on | on non-sandbox targets |
| `read_console`, `read_network` | reversible | **off** | no |
| `javascript_exec`, `file_upload` | irreversible | **off** | always |

The executor reports what a target can run (see [Schema](#schema)). A member that a target can't run returns `is_error` with a plain reason. It is never silently skipped.

| Target | What runs |
|---|---|
| Cloud and bot computers (Linux) | All 17 pixel members, through xdotool and scrot in the guest. The v2 structured members return `unimplemented` until the guest driver image ships (D1b). |
| Cloud computers (Windows) | All 17 pixel members, through PowerShell and user32 (`SetCursorPos`, `mouse_event`, `keybd_event`, SendKeys for `type`) run by the VM driver's guest exec. The v2 structured members return `unimplemented` until the guest driver image ships. |
| This device (macOS, [Allternit Driver](/tools/allternit-driver) over Cua Driver 0.34) | All 17 pixel members and all 7 v2 structured members (the sidecar must be running — the schema endpoint says when it isn't). Pointer and keyboard members go through the Allternit Driver sidecar's `pixel_*` ops, which run Cua Driver's desktop scope, own input per window and log each op. Cua Driver has no press-and-hold key call on macOS, so `hold_key` posts the key-down and key-up events through CoreGraphics itself (keys go to the frontmost app; it uses the Accessibility permission Allternit Desktop already has). Held modifiers (`text`) work on clicks and drags, not on `scroll`. `cursor_position` uses `get_cursor_position`. Cua Driver has no separate press and release on macOS, so `left_mouse_down` is held by the executor and sent with `left_mouse_up` as one click (same spot) or one press-drag-release gesture. |
| This device (Windows) | All 17 pixel members and the v2 structured members through the same sidecar over loopback TCP (the sidecar picks the port and gates every request with a launch token), replacing the Cua CLI fallback. |
| Browser (ACU gateway, Playwright) | All 31 browser members, including element refs, tabs, console, network, JavaScript and uploads. The four optional members stay off until the caller turns them on (see [Optional members](#optional-members)). |
| Paired computers (mesh) | Nothing. They take no agent input. View them live instead. |

## Executor

```http
POST /api/v1/computers/:id/toolset
```

```json
{
  "toolset": "computer",
  "member": "left_click",
  "input": { "coordinate": [640, 400] },
  "run_id": "ses_123",
  "turn_id": "msg_456",
  "call_index": 0,
  "model_frame": { "width": 1280, "height": 800 },
  "coordinate_space": "pixels",
  "approval_grant": null,
  "browser_session_id": null
}
```

`model_frame` is the size of the last screenshot the model saw. Leave it out and the executor uses the default frame for the screen. `coordinate_space` is `pixels` (the default) or `normalized_1000`.

The checks run in this order:

1. **Contract validation.** The member must exist and its input must match the member schema. The batch rule applies (see below). A bad request returns `400`.
2. **Control lease.** On a cloud computer the agent takes or renews the lease, so viewers can see who is driving and a person can take over. If someone else holds control, the call returns `423 computer_controlled_elsewhere`. On this device the owner must have taken control first, otherwise the call returns `423 take_control_first`.
3. **Policy and approval.** A declarative policy denial returns `403 policy_denied`. A member that needs approval returns `409 approval_required` with an `approval_id`. Approve it with `POST /api/aci/handoff/:approval_id/approve`, then resend the same call with `approval_grant` set to that id. A grant works once, and only for the exact action it was issued for.
4. **Audit row.** A row is written to the policy audit log and fsynced before the action runs. If the row can't be written, the action doesn't run.
5. **Dispatch.** The action is sent to the [Allternit Driver](/tools/allternit-driver) on this device, the guest or the browser gateway. The v2 structured members answer from the driver's element map (or the human gate, or the credential backends): no screenshot is taken, no coordinates are scaled, and the result is a text block with the driver's JSON (element tree, batch result or verify rows).

Every call returns this result shape:

```json
{
  "is_error": false,
  "content": [{ "type": "image", "media_type": "image/png", "data": "iVBOR..." }],
  "screen": { "width": 2560, "height": 1440, "scale": 1.633, "frame_width": 1568, "frame_height": 882 }
}
```

Refusals add an `error` code.

### Human hand-off

`request_human` opens a human window on the computer: `computer.human_requested` and `computer.human_resumed` events on the events stream carry `{ reason, live_view: true, input_enabled: true }` for the UI, and on cloud computers the agent's lease is released for the window (on this-device the person already is the controller). The person signals done with:

```http
POST /api/v1/computers/:id/human-done
```

which wakes the waiting call; it re-takes the lease (a person still driving keeps control — agents never preempt a person) and returns "The session has control again."

### Browser results

Every dispatched browser result, success or failure, carries `browser_state`:

```json
{
  "tabs": [
    { "tab_id": "tab_1", "title": "Shop", "url": "https://example.com/", "active": false },
    { "tab_id": "tab_2", "title": "", "url": "about:blank", "active": true }
  ],
  "state_changes": [
    { "type": "tab_opened", "tab_id": "tab_2", "url": "about:blank" },
    { "type": "active_tab_changed", "tab_id": "tab_2" }
  ]
}
```

- **Tabs.** Every page in the session is a tab with a stable `tab_N` id. Exactly one tab is active, and a session always has at least one. Closing the active tab makes the most recent remaining tab active. Closing the last tab opens a blank one.
- **`state_changes`** lists what this call changed, in order: `tab_opened`, `tab_closed`, `active_tab_changed` and `navigated` (a tab's URL changed). Popups and `target=_blank` links show up as `tab_opened`.
- **`tab_id` input.** Members that take `tab_id` act on that tab without switching to it. Leave it out to act on the active tab.
- **Element refs.** `read_page` and `find` return elements with refs such as `ref_7`. Every member that takes a `target` accepts `{ "type": "ref", "ref": "ref_7" }` as well as a coordinate. A ref belongs to its tab. It goes stale after a navigation or a re-render that removes the element. A stale ref returns `is_error` and asks for a fresh `read_page` or `find`.
- **`find`** matches the query's words against each visible element's role, accessible name, placeholder, name and id, and returns the 20 best matches with their refs and centre points. It doesn't call a model.

### URL policy

- Only `http`, `https` and `about:blank` can be opened. `file:`, `data:`, `javascript:`, `chrome:` and every other scheme are refused on every target.
- A browser that runs for a cloud computer refuses hosts that are loopback, private, CGNAT or mesh (`100.64.0.0/10`), link-local (including the `169.254.169.254` metadata address), `metadata.google.internal`, `*.internal`, `*.local` or `localhost`, or a host that resolves to any of those. The executor checks `navigate` first. The gateway then checks every request the page makes, including redirects and subresources.
- A browser that runs on your own machine (this device, not a cloud computer) can open local and private addresses.
- The workspace host policy (`aci_safety`) still applies on top.

### Optional members

`file_upload`, `read_console`, `read_network` and `javascript_exec` are off by default. A call to one of them returns `403 member_disabled` unless the request lists it in `enable`:

```json
{ "toolset": "browser", "member": "read_console", "input": {}, "enable": ["read_console"] }
```

`GET …/toolset/schema?toolset=browser&enable=read_console,read_network` reports those members as enabled. `@allternit/computer-driver` and `allternit-computer-driver` send `enable` for the member being called, because the Anthropic SDK only calls the members its toolset config turned on. `javascript_exec` and `file_upload` still need an approval grant on every call.

- `read_console` and `read_network` return the last 150 console messages or responses recorded on the tab. Recording starts the first time the tab is used through the toolset.
- `javascript_exec` evaluates the text in the page and returns the result as JSON.
- `file_upload` sets files on an `<input type=file>` ref. `paths` are on the browser's computer. A cloud browser only uploads files under its upload folder (`ALLTERNIT_BROWSER_UPLOAD_ROOT`, default `<tmp>/allternit-browser-uploads`). `document_ids` aren't supported.

### Batch rule

The calls in one turn (`turn_id`) run in `call_index` order. After a call fails, or while it waits on an approval nobody has given, each later call in the turn returns `is_error` with exactly:

- computer: `Not executed: an earlier computer action in this turn failed.`
- browser: `Not executed: an earlier action in this turn failed.`

A retry of the failed call itself, for example with an approval grant, is allowed.

### Model frame and scaling

Screenshots are downscaled so the long edge is at most 1568 px and the area is at most 1.15 MP. They are never upscaled, and the aspect ratio is kept. The model sees the screen in that frame and answers in it. The executor maps coordinates back to screen pixels, and the executor is the only place this happens.

On this device the screen size is the native screenshot size in pixels, because Cua Driver 0.34's desktop scope takes native screenshot pixels on a Retina Mac too. `cursor_position` converts Cua Driver's points to pixels. `zoom` crops the region at full resolution and fits it to the frame.

Grid-trained GUI models such as UI-TARS and Qwen-VL send `coordinate_space: "normalized_1000"`, a 0–1000 grid over the whole screen.

### Schema

```http
GET /api/v1/computers/:id/toolset/schema?toolset=computer
```

This returns the target (`this_device`, `guest_linux`, `guest_windows` or `browser_gateway`), whether it is sandboxed, and every member with `enabled`, a `reason` when it is disabled, `risk`, `needs_approval`, a description and its input schema.

### Events

Every action that runs emits this event:

```json
{ "type": "computer.action", "ts": "2026-10-07T21:00:00Z",
  "data": { "toolset": "computer", "member": "left_click", "x": 1280, "y": 720,
            "screen_w": 2560, "screen_h": 1440, "run_id": "ses_123", "ok": true } }
```

`x` and `y` are screen pixels. The event goes out on the computer's events websocket (`/computers/:id/events`) and on `GET /api/v1/computers/:id/toolset/events`, a server-sent event stream that works for every target, including this device. The agent-cursor overlay uses these events.

## Adapters

| Model family | How it calls the toolset | Why |
|---|---|---|
| Claude (Anthropic API) | Native `computer_toolset_20260801` / `browser_toolset_20260801` for the 17 pixel members, plus the `computer_v2` function tool for the 7 structured members | The AI SDK has no toolset type, so the provider fetch hook replaces gizzi's function tool with the native entry on the wire. It maps Claude's toolset `tool_use` blocks back, and returns `tool_result` with `toolset_name` and `browser_state`. If a model rejects the native entry, the same request is resent with the function tool. The wire hook only rewrites the v1 pixel marker, so `computer_v2` passes through as a plain function tool. |
| Claude via other providers | Function tool | No wire hook outside `@ai-sdk/anthropic` |
| OpenAI | Function tool | `@ai-sdk/openai` 2.0.89 can't turn Responses `computer_call` items into loop tool calls |
| Gemini | Function tool | `@ai-sdk/google` 2.0.54 has no `computer_use` tool |
| Kimi, Qwen, GLM, local and open models | Function tool, with optional 0–1000 grid | Generated from the contract. Grid mode switches on for UI-TARS, Qwen-VL and similar models, or when `GIZZI_COMPUTER_TOOLSET_GRID=1`. |

The function tools are one per toolset, named `computer` (pixel members), `computer_v2` (structured members) or `browser`. Each takes an `action` (the member name) plus that member's fields. The fields have the same names and types as the contract. A tool only lists members the target reports as enabled. Both computer tools carry the steering guidance: prefer `read_ui` + `run_batch` over screenshot + pixel loops, and give each bounded step sequence to `run_subtask`, keeping the planner's own calls for planning and for what a subtask hands back.

When the executor answers `approval_required`, gizzi asks the person through its normal permission prompt, records the approval and retries once with the grant.

## What it replaced

- **gizzi `browser` tool** (ACU gateway, goal-driven `execute`). It is replaced by the toolset `browser` tool under the same `GIZZI_DISABLE_BROWSER_TOOL` switch. Goal-driven browsing was a second agent loop, so it is gone.
- **gizzi `desktop` tool.** Removed on 2026-10-09. Screen input is the `computer` tool; provisioning and files are the `computers` tool, which calls allternit-api's `computer_*` tools. Both are on with `GIZZI_ENABLE_COMPUTER_TOOL`.
- **`pane_browser`** is unchanged. It drives the page the person can see in the app's browser pane. That pane is a different target from the headless gateway session, so the two stay separate.
- **allternit-api `computer_screenshot` / `computer_mouse` / `computer_keyboard` tools** (`/tools/execute`). These stay as compatibility aliases on the shared control plane. New work uses the toolset.
