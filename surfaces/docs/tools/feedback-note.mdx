title: 'feedback_note'
description: 'A diagnostic note kept on your device'
---

## Overview

`feedback_note` lets the assistant write down a problem it ran into: a bug, a confusing step or a missing feature. The note stays on your device.

## Parameters

| Parameter | Type | Meaning |
|---|---|---|
| `kind` | `bug`, `confusion`, `missing` or `other` | What sort of problem this is |
| `summary` | string | One line, up to 300 characters |
| `details` | string, optional | Steps, errors and context, up to 4,000 characters, with no secrets |

## Result

A local note id and the kind. The note goes to `feedback-notes.json` in the data folder, at most 200 notes, with file mode 0600. Nothing leaves the device until you send the note with a tap through the report flow. There is no cloud route for notes.

## Permission

It writes only a local note, so it is allowed in every mode. It never sends anything.

## Surfaces

Desktop, web, phone layout, PWA and iOS keep the note on the device. Android follows the PWA. Family: `session`.

## Reviewing notes

- Settings, Diagnostics on web and Desktop lists the notes. Send passes a note to the report flow. Delete removes it.
- The terminal lists them with `/feedback notes` and removes one with `/feedback notes delete` with a number or an id.
- The local routes are `GET /memory/feedback-notes` and `DELETE /memory/feedback-notes/:id`.
