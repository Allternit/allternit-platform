The projects in the table below connect through each vendor's own authenticated API or supported inbox. Others connect through your browser sign-in or through Messages; see the sections after the table. Most run on your connected Sessions computer; Rakazo and FrockBot connect to a server origin you configure. They connect to the vendor's existing agents, rather than selecting a model from Brains. Each adapter follows the vendor's source at a pinned commit, noted in its README. OpenMausBot, Codync, Hivekeep, Invisible Dots and CopilotKit OpenDots have source-based transport tests; the others have static checks only. Live vendor-account verification is pending for all of them.

## Before connecting

Run the vendor app on the same computer as the subscription gateway. In Settings → Connections, choose the vendor, review permissions, and enter its own credential. Credentials are stored encrypted. Never paste credentials into a chat or support report.

On Desktop, the website phone layout, and the PWA, the same connection flow uses your connected computer. A cloud-only runtime cannot reach an app on your laptop's loopback address. If the adapter is unavailable on your chosen runtime, finish Sessions setup first.

## Use your bot

After the credential check succeeds, pick an agent returned by that vendor instance. Allternit retains its vendor identity and uses the normal bot chat flow. Replies are matched to the accepted vendor request or turn. An accepted message alone is never shown as a completed response.

OpenMausBot and Codync can forward explicit human approval decisions. Hivekeep's external API does not expose approval controls. Invisible Dots approvals are not forwarded by this adapter because a conversation message cannot safely claim ownership of a task approval; review them in the vendor app. Closing an Allternit connection does not stop a shared vendor bot.

## When a request fails

An uncertain send or a wait timeout can mean the vendor received your message. Check its conversation before sending a new message. Retrying the same send ID within the running gateway reuses the prior result. Gateway restarts do not restore these in-memory send records or contexts.

Authentication failures require reconnecting with the correct credential or restoring its scope. Schema changes fail explicitly instead of interpreting an unrelated reply as your bot's answer.

## Browser sign-in projects

Gemini Spark, Claude Duet, Slashy and AbacusAI Bot have no developer API. Connect them like ChatGPT or Gemini: in Settings → Connections choose the project and sign in to your own account in Allternit's login browser. The gateway then chats in that signed-in web app for you. Gemini Spark needs a Google AI Pro or Ultra plan with Spark (US beta). Claude Duet needs a Claude Pro or Max plan with Duet (US research preview, waitlist). Their page selectors are first versions and are checked on the first real sign-in.

## Messages projects

Iris, Poke, Instinct, Flip, Cue and Pally are assistants you text. Allternit texts them from your own number through Messages on your Sessions computer, which must be a Mac signed in to Messages:

1. Set `SUBS_GATEWAY_MESSAGES_ENABLED=1` for the gateway.
2. Give the gateway process Full Disk Access (System Settings → Privacy & Security), so it can read replies from Messages, and allow it to control Messages when macOS asks.
3. In Settings → Connections choose the assistant and enter JSON `{"handle":"+1…"}` with the number or iMessage address you text it at. Flip's published number is filled in for you.

Replies are the assistant's next texts after yours. If you text the same assistant by hand while Allternit is waiting, that text can be taken as the reply.

## Any AG-UI agent

Any agent that speaks the [AG-UI protocol](https://docs.ag-ui.com) over HTTP can be connected without a vendor-specific adapter. Examples are agents built with LangGraph, CrewAI, Mastra, Pydantic AI or CopilotKit runtimes that expose an AG-UI endpoint.

1. In Settings → Connections choose **Any AG-UI agent**.
2. Enter the **Agent run URL**: the address the agent accepts AG-UI runs on (a POST that streams Server-Sent Events). Use `https` for an agent on a public host, or `http://127.0.0.1:PORT/...` (or `localhost`, `::1`) for an agent on the computer that runs the gateway.
3. Add a **Token** if the agent asks for a bearer token, then save and start the check.

Allternit stores the URL and token together as one encrypted credential, JSON `{"url":"…","token":"…"}`. Agents that need another header can be given `"headers":{"X-Api-Key":"…"}` in that JSON through the gateway API. Each connection is one agent, named after its host.

What the connection checks:

- The URL must not contain a user name, password or `#fragment`, and plain `http` is accepted only for loopback addresses.
- For a public host, every address the name resolves to must be public. Private networks, link-local and cloud metadata addresses (`169.254.169.254`), carrier-grade NAT (`100.64.0.0/10`), IPv6 unique-local addresses and other reserved ranges are refused. The request then goes to the address that was checked, so a DNS answer that changes later cannot send it elsewhere. Redirects are not followed.
- The first check sends a GET with your token: a 401 or 403 means the token was refused, a 5xx or no answer means the agent is unavailable. Most AG-UI endpoints answer 405 to a GET, which counts as reachable.

Each message starts an AG-UI run in a new isolated thread with the conversation so far. A reply is shown only after the agent reports the run started and finished successfully for that exact thread and run. Tool calls, state updates and reasoning events are read but not shown or answered, and a run that pauses for input is reported as unsupported. History lasts while the gateway runs; there is no resume, approval forwarding or cancellation.
