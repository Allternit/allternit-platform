title: Connected subscriptions
description: Connect subscription accounts with your phone, a desktop app or a browser sign-in, and use them from this computer or a Sessions computer.
---

Connected subscriptions let the workspace use supported capabilities from your own ChatGPT, Claude, Kimi, Gemini, or Copilot account through Subscription Fabric. This is separate from a provider API key, an Allternit Cloud model, or a CLI harness login. The subscription account's plan, observed capabilities, quotas, and session health determine availability.

For bot login assignment, gateway sign-in, and the account status reference, see the [Subscriptions surface guide](/surfaces/subscriptions).

Subscriptions are managed in **Settings → Connections**, which replaced Settings → Subscriptions. See [Connections](/guides/connections) for its tabs, the order bots use to reach an app, and the connect wizard.

## Connect with your phone first

The quickest way to connect is **Settings → Connections › Setup › Link a phone**: your bots then use the apps already signed in on your phone, with no password and no Sessions computer. See [Phone Link](/guides/phone-link). Settings → Connections › **Apps** lists one row per app with how bots reach it (on your phone, a desktop app, or a browser sign-in) and which route they use. A browser sign-in, below, is the fallback for an app that isn't on your phone.

## Which computer runs your subscriptions

Allternit Desktop runs its own subscription gateway. **Settings → Connections › Setup › Runs on** shows which computer answers:

- **A Sessions computer, when one is bound and running.** It answers first, for every route.
- **This computer, otherwise.** Phone and desktop-app connections work from the computer you use Allternit Desktop on, with no Sessions computer. **Add a Sessions computer** binds an always-on computer that keeps your subscriptions working while this one is off. When a bound Sessions computer is stopped, the page names it and this computer answers until it runs again.

Chats with a subscription model from the model picker and bot turns use the same routes: the app on your phone first, then a desktop app, then a browser sign-in. See [the subscription gateway API](/api/subscription-gateway).

### Browser sign-ins on this computer

On the computer you work on, browser sign-ins are off until you turn on **Browser sign-ins on this computer** under Runs on. When it is on:

- They run in the Google Chrome you already have installed, on a separate Allternit profile. Your own Chrome profile is never opened or changed. They don't use Chrome for Testing, because some vendors block it.
- They run hidden: no window, no Dock icon, and nothing takes focus.
- A window opens only when you click: to sign in, or to clear a vendor's check.
- Without Google Chrome installed, the switch stays off and says to install it.

Turning the switch off closes every running browser sign-in on this computer. A Sessions computer always runs browser sign-ins in its own windows; it has no switch.

## Connect an account in a browser

1. Open Settings → Connections (**Sign in with a browser**), the subscription connection flow in the model picker, or **Use your subscription** in [first-run setup](/guides/first-run-setup).
2. Make sure a Sessions computer is running, or that **Browser sign-ins on this computer** is on.
3. Choose a supported provider and open its sign-in window. Sign in yourself: in the window that opens on this computer, or in the live computer view of your Sessions computer.
4. Wait for sign-in detection, or use the sign-in check offered by an older gateway.
5. Read and acknowledge the provider-terms disclosure before selecting the subscription model.
6. Select an available subscription model and send your request.

The gateway runs inside Allternit Desktop on your computer, and on a single-tenant Sessions computer (hosted, BYOC, or locally contained) when you bind one. The workspace reaches it through the runtime's subscription proxy; gateway credentials stay server-side.

## Bring your memory from a login

A connected ChatGPT, Claude, Kimi, Gemini or Copilot login can also bring what that account remembers about you into
your Memory Drive with one tap. See [Memory Drive](/guides/memory-drive#bring-your-memory-from-your-logins-in-one-tap). Memory Drive also reads your logins' saved memories and new
chats every few hours to keep itself current. Those reads never send a message and wait when a login is busy;
turn them off in Memory Drive. See [Keep it current by itself](/guides/memory-drive#keep-it-current-by-itself).

## Several logins

You can connect several logins for a subscription provider, label them, choose a preferred login, and switch from Settings or the model picker. The preferred login is tried first. This does not create extra entitlement or remove provider usage limits.

## Health

Your Sessions computer re-checks each signed-in login every 3 minutes. A login that stops working shows on **Settings → Status** and opens a **Lane down** item in Needs you. See [Lane status](/guides/lane-status).

## What is available

The picker exposes the live provider catalog rather than a fixed list of every capability a vendor offers. Chat and streaming replies use the selected lane. Longer tasks can report progress and need-user states, and return files or artifacts when the adapter supports them.

A provider's native features are not automatically implemented in its Allternit adapter. Check the connected catalog and task result before relying on research, media, office, website, or agent-task capabilities. ChatGPT dots have an adapter on main, but their selectors and approval controls still require a consented live validation; they are not a verified general-purpose automation lane.

## Files in a reply

When a subscription reply makes a file (an image, a deck, a document, a spreadsheet), the file appears in the chat as an artifact card under the reply text. Allternit downloads it from your Sessions computer and checks it against the checksum the gateway recorded. A file that does not match is not shown; the reply says which file could not be downloaded intact, and it stays on your Sessions computer. Files over 24 MB are not copied into the chat: the card opens them from your Sessions computer instead. Reloading the chat shows the same cards.

## Pick a specific GPT, Project, Gem or bot

After connecting a vendor login, use the bot connection's agent picker to choose
its default chat or a specific account entry. Available entries carry labels such
as **GPT**, **Project**, **Gem**, **Agent**, **Page**, **Bot**, or **Profile**, and a
vendor avatar when one is exposed. ChatGPT Projects/GPTs and Gemini Gems start
chat on the selected entry's vendor page; Claude Projects keep their existing
Project routing. The selection stays with the conversation across gateway restarts.

The list comes from the connected account's last probe. New web discovery is
**inferred and not live-verified**. It reads rendered account navigation, so hidden
or unpinned entries may not appear. To refresh, expose the account sidebar (or My
GPTs on ChatGPT) on the Sessions computer and reconnect/check the account. Kimi
and Copilot show saved agents/pages only if their page exposes supported links;
otherwise the picker contains default chat only. Copilot page chat support still
needs human validation. Hermes profiles and Grok's Bot picker use their existing
list readers.

Choosing an entry does not create or modify a vendor bot or grant extra quota.
Send the first turn yourself, and check that the vendor opened the intended bot
before relying on its knowledge or instructions. Complete sign-in, verification
checks, questions and approvals yourself.

## Human initiation and limits

Subscription sends require a human-initiated request and the applicable disclosure acknowledgement. When an agent prepares a task, you approve it on a card, and that approval can run only the task the card shows: if anything else were sent with it, Allternit refuses it. A card from an older version of Allternit can't be approved; reject it and ask again after Allternit updates. Bots and schedules can prepare work; do not assume that a connected consumer subscription can execute unattended bot turns. Provider-side questions and approvals can require your intervention.

The disclosure explains provider-terms risk. Acknowledgement is not provider authorization. Availability and quotas remain controlled by the provider.

## When a usage limit pauses a session

Your own subscription has its own usage limits, for example a 5-hour or weekly limit. As a session gets close, the strip above the composer says **Approaching usage limit**. When the limit is reached, the agent finishes its current step (**Usage limit reached · Wrapping up**), then the session pauses: **Wrapped up past your usage limit** or **Paused until 7:40 PM · … · resumes on its own**. At the reset, the session continues by itself on the same model.

### Keep going on Allternit Cloud

If you don't want to wait, a paused session on your own subscription shows **Keep going on Allternit Cloud**, with the Cloud model it will use and what you have to spend, for example "DeepSeek V4 Pro · $4.20 Cloud balance" or "$1.50 free left this month".

- **Nothing changes until you tap it.** Allternit never moves a session to Cloud by itself, and nothing is charged without the tap.
- **Which model:** the same model when Allternit Cloud offers it, otherwise Allternit Cloud's default model. Open models are never picked for you.
- **What happens:** the same session continues on that Cloud model, paid from your Cloud credits (or your plan's or free monthly allowance). The transcript shows "Continued on Allternit Cloud (DeepSeek V4 Pro) after the 5-hour limit was reached.", and the model picker shows the Cloud model.
- **No credits left:** the button reads **Add Cloud credits** and opens **Settings → Billing**. When you come back, the button changes to **Keep going on Allternit Cloud**. See [Credits and auto top-up](/guides/credits-and-auto-top-up).
- **Signed out of Allternit Cloud:** the button doesn't show.
- **When your subscription resets:** the session stays on Cloud. To go back, pick your subscription's model in the model picker.

It works the same on Desktop, ai.allternit.com, the phone layout and the m.allternit.com app. In the gizzi terminal, the paused line says `/keep-going on Allternit Cloud (…)`; type `/keep-going` to do the same thing (with no credits left, it opens billing in your browser).

A session paused on Allternit Cloud's own monthly limit, or on a bot's spending budget, doesn't offer this.

## When a subscription needs you

Your subscriptions run in their own browser on your Sessions computer. If a vendor stops one until a person steps in (a bot check, an expired sign-in, a restricted account, or a browser profile busy in another window), Allternit tells you wherever you are:

- **Desktop:** a small notice at the top of the window, for example "ChatGPT on your Sessions computer needs you: Finish the check", with **Fix** and **×**.
- **Phone and the m.allternit.com app:** a banner under the header.
- **More than one:** a single notice ("2 subscriptions need you") with a list and a **Fix** for each.

**Fix** opens the vendor's own page on your Sessions computer, shown live in Allternit (full screen on a phone). You finish the check or sign in yourself. Allternit never answers a vendor prompt or solves a check for you. When you close it, Allternit re-checks the account without using your subscription, and the notice goes away once it's ready.

A slower-than-usual service, a vendor outage, or a change to a vendor's page shows as a quieter notice without **Fix**. These clear on their own.

**×** hides the notice until that subscription's state changes, or for 24 hours. **Settings → Connections** always shows each account's state and its **Log in** or **Finish the check** button.

## Coding tools on any computer

Settings → Connections › Coding tools sets up CLI brains (Claude Code, Codex, Grok and others) on the computer it names: this Mac, or the computer your phone and the web are using, such as your always-on Allternit cloud computer. Anything set up on a cloud computer keeps working while your own computer is closed.

1. **Install.** Tap Install. Some tools (Claude Code, for example) come with their maker's own terms, and you accept those first. Allternit installs a pinned, tested version and shows its progress. If the computer has no Node.js, Allternit installs a private copy for these tools only.
2. **Sign in.** Tap Sign in. Allternit shows a link, and sometimes a short code. Open the link on any device (your phone works) and sign in with your own account.
   - **Codex and Grok:** enter the code shown. Sign-in finishes by itself.
   - **Claude Code:** after you sign in, the page shows a code. Paste it into the box in Allternit.
   - **OpenCode:** a normal vendor like the others. Sign-in runs `opencode auth login`, which signs OpenCode in to the model providers you pick.
3. When it says **Connected**, the tool is available as a brain in the model picker.

A bot can also bring up this setup in chat: see [Connect a vendor from chat](/guides/connect-vendor-from-chat).

If OpenAI rejects a Codex code, turn on "device code authorization for Codex" in ChatGPT Settings → Security, then try again. One-click install isn't available on Windows yet; install the tool yourself there, then sign in.

## Troubleshooting

| State | Next action |
| --- | --- |
| Authentication required | Reopen sign-in on the Sessions computer. |
| Verification challenge | Complete the provider's check yourself. |
| Profile locked | Close the conflicting use of that profile before reconnecting. |
| Usage limit | Wait for the provider's reset, select another entitled lane, or tap **Keep going on Allternit Cloud** ([details](#keep-going-on-allternit-cloud)). |
| UI drift / degraded / provider down | Inspect the status and update or repair the adapter before retrying. |
| Missing Sessions computer | Bind or restore the computer and gateway connection. |

For observation and control, see [Computers and ACI](/guides/computers-and-apps). For deliverables, see [Artifact modes](/guides/artifact-modes).

## Gemini and Copilot preview

Gemini and Copilot are carried vendors with thread looks and connection setup in **Settings → Connections**. Choose Add account, select the provider, read the provider-terms warning, and sign in yourself on the Sessions computer. On the phone, open Settings → Connections and use the live computer sign-in view.

These connections use the `ui_bridge` lane and are **best effort**. Gemini and Copilot are new and **not yet verified against the live services**. A look, seeded vendor entry, or signed-in account does not prove that every provider capability works. Provider page changes can interrupt a connection. The terms warning describes account and provider-terms risk; acknowledging it does not grant permission from the provider or remove the human-initiation requirement.
