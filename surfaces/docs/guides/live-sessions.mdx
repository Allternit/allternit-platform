A live session is an agent running in a terminal on your computer: Claude Code, Codex, Kimi, Grok, Antigravity (`agy`), Gizzi, OpenCode, Qwen, Gemini, Cursor, Copilot, Pi, or a Factory pane. Allternit lists them with a one-line status that costs no tokens, so you can tell what each one is working on without opening it.

## List your sessions

```bash
gizzi agents sessions
```

Each row shows the address, `busy` or `idle`, the delivery tier, whether it can move into Allternit (`movable`), how many live processes hold it, the repo and branch, and what the session is doing. Add `--json` for the full record.

```
eoj/allternit-claude   busy    push  busy           1 holder  Allternit/allternit-platform@main  · Auth refresh rework · Running tests
eoj/joe-claude         idle    pull  now            1 holder  joe
eoj/web-codex          idle    push  open_elsewhere 2 holders Allternit/allternit-ai@main
```

If nothing is running, the command says so. It never invents a session.

## Move a session into Allternit

A session running in macOS Terminal (or iTerm2, Ghostty) can move into an Allternit terminal, so you can drive it from the composer, watch it on a live card and reach it from your phone. You have three choices for each session:

- **Move** stops the old process once the agent is idle and resumes the same session in Allternit.
- **Open a copy** forks the session into Allternit. The old one keeps running and nothing is signalled.
- **New session here** starts a fresh session of the same tool in the same folder. The old one is untouched.

Not every tool can do all three. See [Harness support](/code/terminal-and-prompt#harness-support).

### On Desktop and ai.allternit.com

1. Open **Code** and look under **On this Mac** in the Terminals menu (or at the bottom of the Code overview).
2. Pick **Move here**, **Open a copy** or **New session here** on the session's row.
3. For a move, check the command and the flags it keeps (for example `--dangerously-skip-permissions`), then confirm. The row follows the move: **Waiting** for the agent to go idle, **Stopping**, **Starting**. You can cancel while it waits.
4. The session opens as a tab. The old Terminal window stays open and shows the exit.

### On a phone

On the iPhone app, Android app and the phone layout, open the Code session list. **On your computer** (the iPhone and Android apps) or **On this Mac** (the phone layout and PWA) lists the same sessions with the same three choices. A move always asks in a sheet first, and the moved session opens as a terminal tab. The phone must reach your computer through the relay. See [Code on a phone](/code/on-a-phone).

### From the command line

`gizzi agents adopt` does the same from a shell.

```bash
gizzi agents adopt <session> [--copy | --new] [--cancel] [--yes] [--json]
```

`<session>` is a session id, an address, or a name or prefix from `gizzi agents sessions`. If more than one session matches, the command lists them and stops.

| Flag | What it does |
|---|---|
| (none) | Move: wait for the agent to go idle, stop the old process, resume the same session in Allternit. |
| `--copy` | Open a copy in Allternit. The old session keeps running and nothing is signalled. |
| `--new` | Start a fresh session in the same folder. The old one is untouched. |
| `--cancel` | Cancel a move that is still waiting for the agent to go idle. Ctrl-C does the same. |
| `--yes` | Don't ask first. Needed when there is no terminal to ask on. |
| `--json` | Print the raw result. |

Before a move, the command shows who holds the session and what it will resume with, and asks first:

```
$ gizzi agents adopt adopt-probe
adopt-probe (claude) is open in Terminal pid 48211 on ttys004.
It will resume in Allternit with: claude --resume 7f3c0e1a-... --model opus
The old Terminal window stays open and shows the exit.
Move? [y/N] y
Move started (job 5d2e...).
Waiting for adopt-probe to go idle…
Stopping pid 48211…
Starting in Allternit…
Done: terminal term-31
```

The command refuses without asking when the session is already in Allternit, when it is open in more than one place (it lists every holder; close the others first), or when its tool can't resume (use `--new`). A runtime without the adopt route says: "This Allternit runtime is too old for adopt; update Allternit Desktop." The command exits non-zero on any failure.

## What each field means

| Field | Meaning |
|---|---|
| `address` | `person/session`. `person` is your username. `session` is the folder name plus the harness (`allternit-claude`); a second session in the same folder gets `-2`. |
| `status` | `busy`, `idle` or `offline`. Claude Code's own status comes first, then the Factory pane's, then the harness hooks. |
| `doing` | `title · task`, at most 120 characters. |
| `tier` | How a message reaches it: `push` (into the running turn), `turn` (at its next hook) or `pull` (when it checks its inbox). |
| `repo`, `branch` | Read from git in the session's folder. |
| `cwd` | The folder name only. |
| `holders` | Every live process holding this session id: `pid`, `app` (`Terminal`, `iTerm2`, `Allternit`, `Ghostty` or `other`, read from the process's parent chain; a Factory pane is `Allternit`), and when known `paneId`, `tty` and `startedAt` (the OS start time of the process). Two holders means the session is open in two places. |
| `movable` | Whether it can move into Allternit: `now` (one holder outside Allternit, idle, and the harness can resume it by id), `busy` (mid-turn: wait for it), `open_elsewhere` (more than one live holder, so it is refused: only one process may write to a session), `no_resume` (the harness cannot resume by id, or no session id was found; it can still open a new session here), `here` (already in an Allternit pane). |
| `carriedFlags` | The flags the outside holder was started with that a move keeps, such as `--dangerously-skip-permissions` or `--model opus`. Resume, continue, session, fork and one-shot print flags, ids and prompt text are left out. Never sent to the cloud. |
| `canCopy` | The harness can fork this session into a new one. |
| `external` | A holder runs outside Allternit. |

## Holders and moving a session

One session id should have one writer. Allternit groups every live process by harness and session id, so a session opened in Terminal and again in a pane shows once, with two holders, as `open_elsewhere`.

How each harness's processes map to a session id, cheapest reliable source first (the id on its command line always wins):

| Harness | Process | Session id from | Move command | Copy command |
|---|---|---|---|---|
| Claude Code | `claude` | `~/.claude/sessions/<pid>.json` | `claude --resume <id>` | `+ --fork-session` |
| Codex | `codex` | the rollout file it holds open, else the newest rollout for its folder (`~/.codex/sessions`) | `codex resume <id>` | `codex fork <id>` |
| Kimi | `kimi-code` | `~/.kimi-code/locks/sessions/<id>.lock` (holds the pid) | `kimi --session <id>` | `kimi fork <id>` |
| Grok | `grok` | `~/.grok/active_sessions.json`, else the newest in `~/.grok/sessions/<folder>` | `grok --resume <id>` | `+ --fork-session` |
| Antigravity | `agy` | the `presence/<id>.lock` it holds open | `agy --conversation <id>` | none |
| Gizzi | `gizzi-code` | the transcript it holds open, else the newest in `~/.gizzi/projects/<folder>` | `gizzi --session <id>` | `+ --fork` |
| OpenCode | `opencode` | the newest session for its folder in `opencode.db` | `opencode --session <id>` | `+ --fork` |
| Qwen | `qwen` | the id on its command line only (`--resume`, `--session-id`); a qwen started without one is `no_resume` | `qwen --resume <id>` | `+ --fork-session` |

Carried flags go right after the command name. The table lives in one place, `factory/engine/src/agents/harness_table.rs`; clients read only `movable`, `carriedFlags` and `canCopy`. Listing sessions never signals, writes to or types into a process: it reads the process table (`ps`), each process's argv and folder, and for Codex, Gizzi and Antigravity the files it holds open (`lsof`), each with a short timeout.

## How `doing` is worked out

Allternit reads what the agent already records, and never asks the agent to report:

- **Claude Code:** the latest session title, then the in-progress item with the highest id in `~/.claude/tasks/<session>/`, then the in-progress item on its latest todo list.
- **Codex:** the thread name from `session_index.jsonl`, then the in-progress step of its latest plan.
- **Other harnesses:** the in-progress item on the latest todo list in the transcript their hooks report.

Transcripts are read from the end: up to 2 MiB the first time, then only what was appended.

## Privacy

Only the folder name leaves your computer, not the full path. To share full paths, set `ALLTERNIT_SHARE_PATHS=1` before starting Allternit.

## For developers

- Engine: `GET /api/factory/sessions` returns the array of sessions. allternit-api serves the same list at `GET /api/v1/live-sessions` behind your sign-in. If the Factory engine is not running, allternit-api runs the same discovery itself (session files and the process table), so every session and its holders still show; only pane-only entries (a pane with no agent process found) need the engine. It answers `502` with a `transport` error only if that fails too.
- The new fields (`holders`, `carriedFlags`, `canCopy`, `movable`, `external`, `move`) are additive. An older runtime leaves them out; treat a missing `movable` as "this runtime cannot move sessions" and hide the move controls.
- Heartbeat: the 60-second runtime presence heartbeat carries `sessions` (up to 100), so the cloud can show your sessions to your team. `carriedFlags` is removed first.
- Adopt: `factory/engine/src/agents/adopt.rs` holds the decision, the stop-and-wait and the job registry; allternit-api (`cmd/allternit-api/src/netops/presence.rs`) passes it the terminal create, because the create path lives in allternit-api, which depends on the engine.
- Hooks: sessions that only report through Gizzi hooks are read from `~/.allternit/live-sessions/hooks.json` and listed while their last hook is under 10 minutes old.

### Move, copy or open a new session (API)

`POST /api/v1/live-sessions/adopt` (behind your sign-in, like the list) moves a session from Terminal, iTerm2 or Ghostty into an Allternit terminal, opens a copy of it, or opens a new session of the same CLI in its folder. allternit-api runs it as a library, so it works while the Factory engine is down (Desktop quit).

```bash
curl -X POST http://127.0.0.1:<api port>/api/v1/live-sessions/adopt \
  -H 'content-type: application/json' \
  -d '{"sessionId":"<id>","harness":"claude","mode":"move","cols":120,"rows":40}'
```

The request names only the session (`harness` + `sessionId`) and the terminal size. The folder, the terminal's name and the carried flags come from the live session itself, so a client cannot add its own command line. `new` can name the session by `address` instead of `sessionId` (a process whose session id was not found still has an address).

| `mode` | What it does | Answer |
|---|---|---|
| `move` | Stops the old process, then resumes the same session id in a new Allternit terminal (the Move command above, with the carried flags) | `202 {jobId, state}`; the job runs on |
| `copy` | Opens a fork of the session in a new terminal (the Copy command). No signal. Needs `canCopy` | `200 {terminalId}` |
| `new` | Opens a new session of the same CLI with the carried flags in the session's folder. No signal | `200 {terminalId}` |
| `cancel` | Cancels a Move that is still `waiting_idle` | `200 {jobId, state: "failed", code: "cancelled"}` |

#### How a Move runs

1. It takes a per-session lock. A second adopt for the same session while one runs gets `409 adopt_in_progress`.
2. Right before it acts, it runs discovery again for that session: exactly one holder, outside Allternit, with the same pid and start time it first saw, and `movable` is `now`.
3. `busy`: state `waiting_idle`. It looks again every 2 s for up to 5 minutes (cancelable), then fails with `still_busy`.
4. State `stopping`: it checks the pid's start time once more and sends **SIGTERM** to that pid only. It waits up to 15 s for the process to exit; a start time that changes means the pid now belongs to another process, so pid reuse can't fool it.
5. Not exited after 15 s: failed `did_not_exit`, and **nothing is started**. There is no SIGKILL, ever. Quit the CLI in its own window and try again.
6. Exited: state `starting`. It creates the Allternit terminal with the Move command in the session's folder (through your login shell, so the CLI gets the PATH your own terminal has), then `done` with `terminalId`. If that create fails, the job fails with `start_failed` and `error` holds the exact command to run by hand.

The old Terminal window stays open, showing that the CLI exited. Allternit never closes or types into another app's window.

The job shows on the session as `move: {jobId, state, terminalId?, code?, error?}` (`state` is `waiting_idle`, `stopping`, `starting`, `done` or `failed`) in `GET /api/v1/live-sessions`, and at `GET /api/v1/live-sessions/adopt/<jobId>` (useful when the session left the list). Both are kept for 10 minutes after the job ends.

#### Error codes

Errors are JSON: `{"error": "<code>", "message": "…"}`. On a running Move the same codes land in `move.code`.

| Status | Code | Meaning |
|---|---|---|
| 400 | `bad_request` | The body is not `{sessionId, harness, mode, cols, rows}`, or `sessionId` is not a plain id |
| 400 | `unknown_harness` | Not a harness in the table above |
| 404 | `not_found` | No live session with that harness and id on this computer |
| 404 | `no_job` | Cancel, or a job lookup, with no Move job |
| 409 | `adopt_in_progress` | Another adopt for this session is running |
| 409 | `session_open_elsewhere` | More than one process holds the session (or an unidentified process of the same CLI may); only one writer per session id |
| 409 | `already_here` | It already runs in an Allternit terminal |
| 409 | `no_holder` | No running process holds it, so there is nothing to move |
| 409 | `holder_unverified` | The holder's start time could not be read, so it is not stopped |
| 409 | `holder_changed` | The holder's pid or start time changed since the job began; nothing was stopped |
| 409 | `still_busy` | Still working after 5 minutes; nothing was stopped |
| 409 | `did_not_exit` | Still running 15 s after SIGTERM; nothing was started |
| 409 | `session_gone` | The session stopped by itself before it was moved |
| 409 | `too_late` | Cancel after the Move left `waiting_idle` |
| 422 | `no_resume` | The harness can't resume this session by id (use `new`) |
| 422 | `no_copy` | The harness can't fork a session |
| 422 | `no_cwd` | The session's folder is not known |
| 502 | `start_failed` | The terminal did not start; `message` has the command to run by hand |

A runtime older than this answers `404` for the route: keep today's behavior and hide Move, Copy and New.
