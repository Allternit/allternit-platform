---
title: "System drawer"
description: "See what needs you, what is running and what broke across every session and mode, and approve requests without opening each session."
---

The system drawer shows what is happening across the whole app: every session, every mode, this computer and the cloud. Use it when several agents or bots work at once. You can answer their requests, see what is running, and find what broke without opening each session.

The drawer never opens by itself. You open it.

## Open it

| Where | How |
| --- | --- |
| Desktop | The indicator at the bottom of the left rail, above the usage meter. It reads like **2 need you · 5 running · 1 problem**. Each part opens the drawer on its own tab. Click the part again to close it. With nothing going on it reads **Nothing running**. |
| Desktop, any mode | **⌘J** (Ctrl+J on Windows and Linux) opens and closes it. |
| Phone and PWA | The round pulse button in the menu's footer, next to Phones. Its badge shows the most urgent count. The drawer opens as a sheet; tap outside it to close. |

On Desktop the drawer sits along the bottom, beside the rail. Drag its tab row to make it taller or shorter.

## Tabs

| Tab | What it holds |
| --- | --- |
| **Needs you** | Every approval and question waiting on you: agent permission requests from any chat, code session or bot, and Factory approvals. Each one shows where it came from and how long it has waited, with **Approve** and **Deny**. Agent requests also have **Open session**. The longest wait is first. |
| **Running** | Sessions with a reply streaming, Terminal bots, and dev servers on this computer, each with **Open** and **Stop**. **Stop** ends a session's reply. For a Terminal bot, it sends Ctrl-C to its terminal. For a dev server, it ends the process (Desktop app only). **List / Graph** switches to the Factory graph, which shows a campaign's steps and the bot working each one. **Next up** at the bottom lists the next three scheduled routines this week. |
| **Runs** | Agent turns, commands (tests, builds, checks, dev servers, shell) and Factory runs from the code sessions active in the last day. Each run shows its session, status, time and facts such as the model and tokens. Select a run to see its output, its tool calls and a replay. |
| **Problems** | Typecheck, lint, test and build failures from the code sessions active in the last day, grouped by session and then file. A row opens the file at that line. Above them, **Stuck and failed** lists routines that keep failing and Terminal bots that stopped with an error. |

The tab row also shows your plan usage (Allternit Cloud, or your model's account when it nears its limit) and how many Terminal bots are working. Click the usage to open **Settings → Usage**.

## On a phone

The phone and the PWA have the same four tabs in a sheet. **Graph** draws as an indented list, because a wide graph does not fit. Approve and Deny are full-width buttons. Dev servers show **Preview** and **Stop** only.

Approval notifications still arrive as push notifications when they are turned on in **Settings → Notifications**.

## For developers

- **Mount:** `ConsoleDrawer` (`src/drawers/ConsoleDrawer.tsx`) wraps `DrawerRoot` and binds ⌘J. `ShellApp` mounts it in every mode, and `PhoneShell` mounts it lazily inside `.phone-root`. Open state, height and tab live in `useDrawerStore` (`allternit-drawer-storage`). `toggleConsole(tab)` opens it on a tab, or closes it when it is already open on that tab.
- **Placement:** `ShellFrame` writes the rail column width to `--shell-rail-col` on the document root. The drawer uses it as its left inset.
- **Tabs:** the console registry (`src/views/code/console/console-registry.ts`) holds them. The built-ins are `needs-you`, `running`, `runs` and `problems` (`builtin-tabs.tsx`). An unknown saved id, such as one from the retired console, falls back to the first tab.
- **Data:** `system-model.ts` reads it. `useNeedsYou` merges `usePermissionStore` pending requests with Factory pending approvals. `useSystemCodeSessions` derives runs, problems and ports for code sessions that are streaming or updated in the last 24 hours, up to 12. Each is derived again only when its messages change. `useSystemCounts` feeds the rail indicator and the phone button.
- **Graph:** `CampaignFlowView` in `src/components/factory/views/connected.tsx` draws one campaign's flow. `ProjectFlowView` now uses it too.
- **Retired with the old Console:** the Output, Plan, Terminals, Ports, Changes, Factory (Mission Control), Tasks, Usage and Artifacts tabs. Dev servers moved into Running (`DevServers` in `PortsTab.tsx`). The Terminals tab's workspace (`TerminalWorkspace`, `terminal-workspace.store`) was removed. Code's shell is [Terminal mode](/code/terminal-and-prompt).
