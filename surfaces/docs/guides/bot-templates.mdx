---
title: Bot and team templates
description: Launch reusable workers and coordinated projects from recipes you can inspect and save.
---

A **bot template** describes one worker's instructions, tools, skills, routines, and first task. A **team template** adds roles and a plan of dependent tasks. Templates are recipes; instantiated bots and threads are the running work.

## Marketplace

**Bots rail ⋯ → Marketplace** (it was called Templates) opens everything you can add to your bots, in three tabs:

| Tab | What it shows |
| --- | --- |
| **Agents** | Bot and team templates: the same gallery as the Bots launch surface. |
| **Apps** | The connector directory. Your connected apps come first, then the rest. Selecting a card or **+** opens the connector's page, where you connect it, sign in or enter an API key. |
| **Skills** | The skill directory. **+** installs a skill into `~/.agents/skills`; every bot can use it from its next turn. Turn skills on or off in Customize → Skills. |

Apps and Skills have a search box. Cards show only what the directory knows (maker, category, tools); there are no ratings or install counts. If the app directory cannot load, the Apps tab says why and offers **Try again**. The Marketplace is the same on Desktop, the ai.allternit.com phone layout and the m.allternit.com app (bot drawer **⋯ → Marketplace**).

## Use a template

Browse templates from the Bots launch surface or the Marketplace **Agents** tab. Open a recipe to inspect its roles, required setup, planned outputs, and approval points. For a team, enter the project brief and review which existing bots it will reuse and which it will add, then start the project.

The team flow matches each role to an existing bot where possible and creates missing bots. It creates the project, lays out task threads and their dependencies, and starts the root threads through Al. Downstream work follows the [coordinator's dependency rules](/guides/project-coordination).

Each built-in template has a default character (its `look`, one of the Gizzi YouTube cast) shown on the template's colour; a bot made from it wears that look until you change it.

A bot template creates one bot and opens its main chat with the bot's greeting (the template's `welcome`). Nothing is sent for you: the template's first task is the first suggestion chip under the greeting, followed by its starter prompts, so the bot only starts work when you tap or type. See [Bots greet you first](/surfaces/bots#bots-greet-you-first). If the chat cannot open, the bot is still created; open its bot screen and check the connected runtime before retrying.

## Routines

Template routines are installed paused unless you explicitly enable them during setup. Review the schedule and required tools in bot home before enabling recurring work. A recipe's written approval points must also be reviewed before using it for consequential actions.

## Save and reuse

Save as template stores a reusable bot or team recipe. Saved templates can be private or organization-visible and can record which template they were forked from. The recipe excludes credentials, memory, and live threads; reconnect the required tools and accounts for each new use. The API additionally strips secret-looking fields before storage.

| Method | Private runtime path | Purpose |
| --- | --- | --- |
| GET | `/api/v1/templates` | List accessible saved recipes. |
| POST | `/api/v1/templates` | Save a bot or team recipe. |
| DELETE | `/api/v1/templates/:id` | Delete a saved recipe. |

The create body contains `kind` (`bot` or `team`), `visibility` (`private` or `org`), optional `forkedFrom`, and the `template` object. These routes are part of the Allternit API data plane.
