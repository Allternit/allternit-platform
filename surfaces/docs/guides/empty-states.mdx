A screen with nothing in it does not show a blank page. It shows a small line drawing that loops gently, a headline, one quiet line under it and, where there is something to do, one button.

## The drawings

| Drawing | Where it shows |
| --- | --- |
| **Stack of sheets** | Projects, project files, Explorer, and a connector search with no match |
| **Bell** | Inbox, Needs you, Files requests, scheduled tasks and routines |
| **Envelope** | Chats in the phone drawer, a bot's threads, and Meetings with no calls coming up |
| **Coins** | Billing transactions and the usage ledger |
| **Gizzi walking** | Code sessions, the bot picker and bot rail with no bots, and computers |

The drawing is one colour, the text colour, so it works in light and dark. With reduced motion it is a still picture.

## Buttons

A button shows only where the action already existed on that screen.

- **Projects:** "No projects yet." and "Start your first one." with **New project**.
- **Code sessions:** **New session**.
- **Project files:** **Add files**.
- **Routines:** **New routine**.
- **Bot rail with no bots:** **Create a bot**.
- **Computers:** **Open settings**.

A search with no match, and an error, keep a plain text look with no drawing. The words on every screen are the same as before.

## Where it works

Web, the phone layout and the m.allternit.com app use the drawings. The iPhone app and the Android app have them too. Each app lists below only the screens it really draws.

### iPhone

| Drawing | Screens |
| --- | --- |
| **Stack of sheets** | Projects (with **New project**), a code project with no sessions (with **New session**), a folder in Files, the Artifacts library, a computer's drive with no computers, the screen picker with no computers, Connectors with none available, and the first run of MCP Apps |
| **Bell** | Files requests, Decisions, Agent activity, Replays (only when no filter is on), Routines, Loops, the routines and goals lists in the automation hub, and Code scheduled tasks |
| **Envelope** | The agent hub with no agents, the history drawer, and group chats with none yet |
| **Gizzi walking** | The Code overview with no sessions (with **New session**) |

A search or filter that finds nothing, an error and an offline screen keep their old look with no drawing.

The connect-a-computer panel also shows a small scene that follows what is really happening. Gizzi sleeps until the panel is waiting for a computer, the cables pulse while "Waiting for your computer" shows, and the cables go solid with a check once a computer is online. If the list cannot be read, Gizzi goes back to sleep. With Reduce Motion each state is a still picture.

The Computers pane with no paired computers shows the same scene, asleep and still. Pairing happens in its own sheet, so the pane never shows the connecting or connected states.

### Android

| Drawing | Screens |
| --- | --- |
| **Stack of sheets** | Projects, a project with no sessions, a Code folder with no files, the Artifacts library (none, and archived), the Meetings artifacts panel, the Connections list under More, bot templates and memory, the impact map, and the empty lists in Settings (Customize, Manage, Memory, Operator, Resources) |
| **Bell** | Inbox, Files requests, automation routines, loops and calendar, Code scheduled tasks, Decisions, agent activity, Meetings approvals, bot tasks and webhooks |
| **Envelope** | Bot sessions and threads, bot channels, and the Meetings transcript |
| **Coins** | Code usage |
| **Gizzi walking** | The "No bots yet" strip, Code diffs and the dev server |

The Artifacts library keeps its **New artifact** button inside the block, and the automation screens keep their existing **New** buttons. A search with no match ("No matches") and an error look as before, and Settings notes that only inform are left alone.

## Badge pop

When a step is finished, a grey badge turns to colour: one colour fills in, a ring settles and the mark draws. You see it on a connected app and on completed milestones. It plays once. With reduced motion it shows the final badge.
