Artifact modes tell the agent what deliverable to create and which capabilities it needs. Choose a mode in the workspace, describe the result, and inspect the output in its artifact or editor pane. A completion message alone is not the deliverable.

## Choose the format

Where the inline mode selector appears, its tabs stay on one horizontally scrollable row. The selected mode uses neutral glass with no accent color. Keyboard focus remains visible; reduced transparency and increased contrast use a solid selection surface.

| Mode | Expected result |
| --- | --- |
| Artifact | The agent chooses a useful format and explains that choice briefly before creating it. |
| Build | A runnable website or app artifact. |
| Docs | An editable structured document. |
| Sheets | An editable spreadsheet with typed data and formulas where needed. |
| Slides | An editable presentation. |
| Deep Research | A structured research report with sources and citations. |
| Image | A generated image checked against the request. |
| Video | A playable video with the requested duration and format. |
| PDF | An editable PDF, opened in the PDF editor pane. |
| Code | Real file changes and runnable code, with appropriate verification. |
| Agent Swarm | A coordinated run with named roles, ownership, and a synthesized deliverable. |

A missing tool, provider, or editor capability can block a mode. Choose an available runtime/provider or connect the required capability, then retry. The mode contract requires real output and tool evidence instead of simulated success.

## Editor panes and bot threads

Docs, Sheets, Slides and PDFs work through artifact sessions with an editor pane. Subsequent turns edit the document already open in that pane. These sessions differ from a one-shot generation that emits a new artifact each time.

PDFs open in the [PDF editor](/guides/pdf-editor): you change text in the PDF's own font, move and add content, sign, fill forms and rearrange pages, and each change saves back as a new version of the same artifact. A read-only preview opens when you don't have edit access. Uploading a `.pdf` file to the workspace library also creates a PDF artifact.

Images open in the embedded PhotoCraft editor: the layered source (`.pcraft`/PSD) is kept in the artifact's runtime storage so edits keep their layers across sessions, and every save also writes a flattened image as a new artifact version — that flat image is what previews, shares and downloads show by default. "Download PSD" exports the layered source for use in other tools. Uploading an image file (PNG, JPEG, WebP, PSD, …) to the workspace library creates an editable image artifact.

Videos open in the embedded FilmCraft editor: the footage is referenced from Allternit's media storage (never copied into the artifact), the project source (`.fcproj`) is kept in the artifact's runtime storage so edits keep their timeline across sessions, and every save also exports an MP4 that becomes the new artifact version — the export is what previews, shares and downloads play. Generated videos (`media_generate`) and uploaded video files (MP4, MOV, WebM) both land as editable video artifacts. On phones and the m.allternit.com PWA, a video artifact opens as the playable view first, with **Edit video** mounting the full editor for trimming and exports. Image artifacts work the same way: the picture shows first, and **Edit image** opens the image editor.

## Studio panes

Every tile under **Make something new** on the Artifacts page (and the rail's **+** menu) opens an artifact session: the chat on the left and the artifact's pane on the right. Docs, Sheets, Slides and Design open their editor. **Dashboards**, **Motion**, **Page**, **Build**, **Image**, **Video** and **Deep Research** open a studio pane, which goes through three states:

1. **Before anything is made**, the pane says what the session makes and how it works. Describe what you want in the chat.
2. **While the agent works on it**, the pane shows a card shaped like the result (an image, a 16:9 clip, a dashboard grid, a browser page, a motion timeline, a report) with a moving fill. Under the card are the agent's current thought, how long it has been working, and its latest tool steps, so a long render never looks stalled. Images and videos use a frame the shape of the requested size (square or 16:9 when none was given) with small squares pulsing out from the middle until the result arrives; with reduced motion turned on, the squares stay still.
3. **When the result exists**, it opens in its own artifact window in the pane, using the kind's editor where it has one: dashboard tiles, the motion timeline, PhotoCraft for images, FilmCraft for videos, a live preview for pages and builds. Later turns change that same artifact. A status strip at the bottom of the pane shows the agent's steps while it updates it.

A Dashboard, Motion or Page session is bound to the artifact its agent makes, so reopening the session shows it again and new requests update it instead of making a second one. Dashboards and Motion are plan-gated, the same as their templates in the Output menu.

When an image or video is generated in any chat (`media_generate`), the same rendering frame appears inline in the conversation until the file is ready, then the picture itself shows in the chat with **Download**, **Open** and **Copy prompt**. See [Agent steps in replies](/guides/agent-steps#when-the-agent-makes-an-image-or-a-video).

On phones (ai.allternit.com and the m.allternit.com app), Docs, Sheets, Slides and Design open their editor full screen when you start or open one; go back to reach the chat. Studio panes keep the chat in front, since you start them with a prompt. **Open** on the artifact card under the chat opens the pane full screen, and the header's pane menu lists it alongside Browser and the session's outputs.

Bot threads do not offer these three editor-pane modes. Use the workspace artifact session for the editable Office flow. A bot can still produce file deliverables through tools available to its thread; that is a different path from editing an open pane.

## Inspect and continue

Keep the conversation for instructions and steering, and the artifact pane for the resulting work. Open a supported output to preview or edit it, check the contents, and ask for a specific revision. Available export formats depend on the artifact kind and the tool that created it.

A thread's artifact list and context checkpoint serve different purposes: the list collects outputs; the checkpoint preserves enough working context to continue. Review both when resuming a long task.
