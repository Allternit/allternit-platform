## Overview

The Orchestrator API is a stateless passthrough to the canonical Gizzi orchestrator running in Gizzi Runtime. The platform API preserves the HTTP method, path suffix, query string, request body, and response status so the orchestrator remains the single source of orchestration state. Live executor sessions belong to the Gizzi Node process, not the platform API.

## Base URL

```text
https://api.allternit.com/api/v1/orchestrator
```

For local development:

```text
http://127.0.0.1:8013/api/v1/orchestrator
```

The upstream target is the configured terminal server at `/v1/orchestrator`.

## Authentication

All requests require a valid bearer token in the `Authorization` header. The platform also forwards Gizzi basic-auth credentials when `GIZZI_PASSWORD` or `GIZZI_SERVER_PASSWORD` is configured. See [Authentication](/api/authentication) for details.

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `ANY` | `/orchestrator` | Proxy root to the Gizzi orchestrator. |
| `ANY` | `/orchestrator/*path` | Proxy any orchestrator sub-resource. |

## Proxy example

```bash
curl -X GET https://api.allternit.com/api/v1/orchestrator/status \
  -H "Authorization: Bearer $TOKEN"
```

The platform forwards this to:

```text
https://terminal-server.internal/v1/orchestrator/status
```

## Streaming responses

If the upstream returns `text/event-stream`, the platform proxies the byte stream without buffering and sets the appropriate SSE headers:

```bash
curl -N https://api.allternit.com/api/v1/orchestrator/sessions/sess_123/events \
  -H "Authorization: Bearer $TOKEN"
```

## Request body forwarding

JSON bodies are forwarded verbatim:

```bash
curl -X POST https://api.allternit.com/api/v1/orchestrator/execute \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "session_id": "sess_01hqx8x7x7x7x7x7x7x7x7x",
    "plan": [...]
  }'
```

## Response

Responses are proxied with the same status code and `Content-Type` returned by Gizzi Runtime. A successful request returns whatever the orchestrator returns; the platform does not reshape the body.

## Error codes

| Status | Code | Description |
|--------|------|-------------|
| `400` | `invalid orchestrator proxy path` | Path did not contain `/orchestrator`. |
| `401` | `Unauthorized` | Missing or invalid bearer token. |
| `502` | `orchestrator_unavailable` | Upstream Gizzi orchestrator is unreachable. |
| `502` | `invalid_orchestrator_response` | Upstream response body could not be read. |
