## Overview

The Allternit Cloud API is the **only public API**. It is the hosted control plane that binds user accounts to self-hosted and managed data-plane nodes. It provides the runtime pairing protocol, the browser-to-runtime relay, hosted runtime lifecycle, Allternit-provisioned instances, the BYO-VPS deploy wizard, the Cowork Runtime execution API, and the `/v1` model gateway.

The API is built from `cmd/allternit-cloud-api` and runs at `https://api.allternit.com` in production (Postgres). The [Allternit API](/api/allternit-api) (`:8013`, SQLite) is the private data plane — never a public hostname. See [API Overview](/api/overview). The `/v1/chat/completions` model gateway is on this origin.

## Base URL

```
https://api.allternit.com
```

Public health endpoints require no authentication. Runtime pairing creation and exchange are public (like an OAuth device flow). All other endpoints require either a Clerk session JWT or a runtime device token in the `Authorization: Bearer <token>` header.

## Runtime pairing

First-party device pairing binds a desktop or VPS runtime to a human account without giving the runtime the human's Clerk session token. The runtime generates an Ed25519 keypair, polls for approval, and exchanges the pairing for a revocable device credential.

### Pairing endpoints

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| POST | `/api/v1/runtime-pairings` | Public | Create a pairing request. |
| POST | `/api/v1/runtime-pairings/exchange` | Public | Exchange an approved pairing for a device token. |
| GET | `/api/v1/runtime-pairings/code/:code` | Clerk / device | Inspect a pairing by user code. |
| POST | `/api/v1/runtime-pairings/code/:code/approve` | Clerk / device | Approve a pairing request. |
| POST | `/api/v1/runtime-pairings/code/:code/deny` | Clerk / device | Deny a pairing request. |
| GET | `/api/v1/runtime-devices` | Clerk / device | List paired runtimes. |
| POST | `/api/v1/runtime-devices/verify-token` | Device token | Introspect a device token. |
| DELETE | `/api/v1/runtime-devices/:id` | Clerk | Revoke a runtime. |
| POST | `/api/v1/runtime-devices/:id/heartbeat` | Device token | Runtime heartbeat. |
| POST | `/api/v1/runtime-devices/:id/rotate` | Device token | Rotate device credential. |
| POST | `/api/v1/runtime-devices/:id/revoke-self` | Device token | Self-revoke a runtime. |

### Create a pairing

```bash
curl -X POST https://api.allternit.com/api/v1/runtime-pairings \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Production VPS",
    "runtimeType": "vps",
    "hostname": "prod-01",
    "platform": "linux-amd64",
    "version": "0.1.0",
    "publicKey": "base64url-encoded-32-byte-public-key",
    "capabilities": [
      "runtime:connect",
      "runtime:execute",
      "runtime:files",
      "runtime:terminal",
      "providers:connect",
      "providers:use"
    ]
  }'
```

### Response

```json
{
  "pairingId": "pair_abc123",
  "deviceCode": "secret",
  "userCode": "ABCD-2345",
  "challenge": "secret",
  "verificationUrl": "https://platform.allternit.com/pair?code=ABCD-2345",
  "expiresAt": "2026-08-13T20:00:00Z",
  "pollIntervalSeconds": 2
}
```

### Exchange a pairing

The runtime signs the challenge with its Ed25519 private key and polls the exchange endpoint.

```bash
curl -X POST https://api.allternit.com/api/v1/runtime-pairings/exchange \
  -H "Content-Type: application/json" \
  -d '{
    "pairingId": "pair_abc123",
    "deviceCode": "secret",
    "signature": "base64url-ed25519-signature-of-allternit-runtime-pairing:pairingId:challenge"
  }'
```

### Response

```json
{
  "runtimeId": "rt_xyz789",
  "userId": "user_123",
  "userEmail": "ops@example.com",
  "organizationId": "org_456",
  "deviceToken": "allternit_runtime_...",
  "tokenType": "Bearer",
```

## Runtime relay

Once paired, a runtime opens an outbound WebSocket to the cloud API. A Clerk-authenticated browser can then proxy HTTP requests and WebSocket traffic to that runtime without exposing the runtime's loopback API publicly.

### Relay endpoints

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| WS | `/api/v1/runtime-relay/connect/:id` | Device token | Runtime relay WebSocket. |
| POST | `/api/v1/runtime-devices/:id/proxy` | Clerk | Proxy an HTTP request to the runtime. |
| POST | `/api/v1/runtime-devices/:id/socket-ticket` | Clerk | Create a one-time WebSocket ticket. |
| WS | `/api/v1/runtime-devices/:id/socket?ticket=...` | Ticket | Browser WebSocket to the runtime. |
| POST | `/api/v1/runtime-devices/:id/viewer-token` | Clerk | Mint a live desktop (VNC) viewer token for a cloud computer. |
| GET | `/api/v1/runtime-devices/:id/viewer-check` | Clerk or `compute` token | Automated self-check of the live desktop path: is the cloud computer's VNC socket reachable? |

### Proxy a request to a runtime

```bash
curl -X POST https://api.allternit.com/api/v1/runtime-devices/rt_xyz789/proxy \
  -H "Authorization: Bearer <clerk-session-token>" \
  -H "Content-Type: application/json" \
  -d '{
    "method": "GET",
    "path": "/api/v1/health",
    "headers": {},
    "body": "",
    "bodyEncoding": "utf8"
  }'
```

The cloud API verifies ownership and capability, forwards the request over the runtime WebSocket, and streams the response back.

### WebSocket ticket

For streaming endpoints, request a ticket first:

```bash
curl -X POST https://api.allternit.com/api/v1/runtime-devices/rt_xyz789/socket-ticket \
  -H "Authorization: Bearer <clerk-session-token>" \
  -H "Content-Type: application/json" \
  -d '{"path": "/api/v1/runs/run_123/events/stream"}'
```

### Response

```json
{
  "ticket": "ticket_uuid",
  "expiresInSeconds": 30
}
```

Connect to the ticketed WebSocket:

```bash
wscat -c "wss://api.allternit.com/api/v1/runtime-devices/rt_xyz789/socket?ticket=ticket_uuid"
```

### Live desktop viewer token

"Sign in on the cloud computer" opens the computer's desktop in the browser. The desktop is served by the cloud computer itself and tunnelled through its outbound relay connection, so no Sessions computer record and no shared secret are involved. The viewer token uses the same signed format as the Sessions `computers` ws-token (purpose `vnc`, `computer_id` set to the runtime id), is signed with that runtime's own relay key (the digest cloud-api already stores for it, `credential_hash`), and lives 300 seconds. The runtime's allternit-api checks it at `GET /api/v1/runtime-viewer/vnc?token=…` and proxies to its local VNC server (`ALLTERNIT_RUNTIME_VNC_ADDR`, default `127.0.0.1:5900`). `wsUrl` carries a 30-second relay socket ticket: connect right away, and ask again to reconnect.

```bash
curl -X POST https://api.allternit.com/api/v1/runtime-devices/rt_xyz789/viewer-token \
  -H "Authorization: Bearer $CLERK_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "readOnly": false }'
```

```json
{
  "token": "<signed token>",
  "expiresAt": "2026-10-03T12:05:00+00:00",
  "wsUrl": "wss://api.allternit.com/api/v1/runtime-devices/rt_xyz789/socket?ticket=<30 s ticket>",
  "runtimeId": "rt_xyz789"
}
```

`readOnly` is optional and defaults to `false` (signing in needs keyboard and mouse). Errors: `401` unauthenticated; `404` for an unknown, revoked, or someone else's runtime (the same answer for all three); `409 not_a_cloud_computer` for a Desktop or BYO runtime; `503 runtime_warming` or `runtime_offline` when the computer is still waking or unreachable (a sleeping computer is woken the same way the relay proxy wakes it); `400 no_host` when the request carries no host to build the public address from. No environment variable is required; `ALLTERNIT_VIEWER_WS_BASE` optionally overrides the public ws base (default: the request's own host over `wss://`).

#### Checking the live desktop without a browser

`GET /api/v1/runtime-devices/:id/viewer-check` verifies the whole path a person would use, so it can be tested against any real cloud computer by a script or an orchestrator. It does the same ownership, cloud-computer and wake steps as `viewer-token`, then asks the runtime, over the relay with a 60-second view-only token, to connect to its VNC socket and read the RFB banner (`GET /api/v1/runtime-viewer/vnc-check?token=…` on the runtime, same token rules as the viewer). Nothing is opened or sent to the VNC server, and no session is created.

```bash
curl -s https://api.allternit.com/api/v1/runtime-devices/rt_xyz789/viewer-check \
  -H "Authorization: Bearer $ALLTERNIT_API_TOKEN"
```

```json
{ "ok": true, "runtimeId": "rt_xyz789", "relay": "connected",
  "vnc": { "reachable": true, "rfb": "RFB 003.008", "latencyMs": 4 }, "checkedAt": "2026-10-04T12:00:00+00:00" }
```

On failure the body is `{ "ok": false, "runtimeId", "stage", "reason" }` and the status says where it stopped:

| Status | `stage` / `reason` | Meaning |
| --- | --- | --- |
| 401 / 404 / 409 | none | Same as `viewer-token`: not signed in; unknown, revoked or someone else's runtime; `not_a_cloud_computer`. |
| 503 | `wake` / `runtime_warming`, `runtime_offline` | The computer is still waking or can't be reached. Retry in a minute. |
| 504 | `relay` / `runtime_timeout` | The runtime didn't answer through the relay. |
| 502 | `relay` / `runtime_has_no_viewer`, `runtime_rejected_token`, `runtime_answered_<status>` | The runtime is too old to have the viewer route, or its relay key is out of date. |
| 502 | `vnc` / `vnc_unreachable`, `vnc_timeout`, `not_rfb` | The runtime is up but nothing (or something other than VNC) answers on `ALLTERNIT_RUNTIME_VNC_ADDR`. |

A green check proves the relay, the token and the VNC server; it can't prove a human can see pixels, so the first real "Sign in on the cloud computer" on a new image is still worth one look. Run it after provisioning a cloud computer and after changing the desktop image.

### Allowed relay paths

The runtime proxy only accepts paths under the following prefixes:

```
/api, /viz, /sandbox, /vm-session, /rails, /stream, /terminal, /mcp,
/platform, /metrics, /alabs, /cowork, /webhooks, /ws, /panes, /status,
/health, /v1
```

## Relayed data-plane namespaces

These Cloud API routes authenticate with a Clerk session, resolve the caller's default healthy node, and **relay** the request to Allternit API on that node. They do not store a second copy of the resource in Cloud API Postgres.

| Namespace | Paths | Docs |
|-----------|-------|------|
| Agent sessions | `/api/v1/agent-sessions` | [Agent Sessions](/api/agent-sessions) |
| Office | `/api/v1/office/bindings`, `/bootstrap`, `/runtime/state` | [Office](/api/office) |
| Beta research | `/api/v1/beta/research`, `/api/v1/beta/sessions` | [Beta](/api/beta) |

HTTP **428** means the account has no healthy node (pair a desktop/VPS or start a provisioned instance). The original `Authorization` header is forwarded. SSE is not buffered.

## Provisioned instances

Paid subscriptions can get an Allternit-provisioned data-plane instance (isolated container, per-instance SQLite, auto-pair). These routes are control-plane only: they create/start/stop the instance. Traffic to Allternit API inside the instance still goes through the runtime relay.

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | `/api/v1/provisioned-instances` | Clerk | List your instances. |
| POST | `/api/v1/provisioned-instances` | Clerk + subscription | Create an instance. |
| GET | `/api/v1/provisioned-instances/:id` | Clerk | Instance status. |
| POST | `/api/v1/provisioned-instances/:id/start` | Clerk | Start a stopped instance. |
| POST | `/api/v1/provisioned-instances/:id/stop` | Clerk | Stop an instance. |
| GET | `/api/v1/provisioned-instances/:id/usage` | Clerk | Metering sessions. |
| DELETE | `/api/v1/provisioned-instances/:id` | Clerk | Destroy an instance. |

Host registration (`/api/v1/provisioned-hosts`) is operator-only.

```bash
curl https://api.allternit.com/api/v1/provisioned-instances \
  -H "Authorization: Bearer <clerk-session-token>"
```

This is mode 3 in [BYOC Overview](/byoc/overview). It is separate from Fly [hosted runtimes](/byoc/hosted-runtime).

## BYO-VPS deploy wizard

The wizard provisions a self-hosted runtime on Hetzner, DigitalOcean, AWS, or a manual SSH target. It runs idempotent bootstrap over SSH, joins the box to the mesh, registers it as a gizzi instance, and mints a one-time pairing token.

### Wizard endpoints

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| POST | `/api/v1/cloud/wizard/deployments` | Clerk | Start a wizard deployment. |
| GET | `/api/v1/cloud/wizard/deployments` | Clerk | List wizard sessions. |
| GET | `/api/v1/cloud/wizard/deployments/:id` | Clerk | Get wizard state. |
| POST | `/api/v1/cloud/wizard/deployments/:id/advance` | Clerk | Advance to the next step. |
| POST | `/api/v1/cloud/wizard/deployments/:id/resume` | Clerk | Resume after a human checkpoint. |
| POST | `/api/v1/cloud/wizard/deployments/:id/cancel` | Clerk | Cancel the wizard. |
| DELETE | `/api/v1/cloud/wizard/deployments/:id` | Clerk | Delete a terminal wizard session. |
| POST | `/api/v1/cloud/wizard/deployments/:id/bootstrap` | Clerk | Run or retry the bootstrap step. |

### Start a wizard

```bash
curl -X POST https://api.allternit.com/api/v1/cloud/wizard/deployments \
  -H "Authorization: Bearer <clerk-session-token>" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "hetzner",
    "apiToken": "hetzner-api-token",
    "instanceName": "allternit-prod-01",
    "region": "fsn1",
    "instanceType": "cx21",
    "storageGb": 50
  }'
```

### Response

```json
{
  "deploymentId": "dep_abc123",
```

## Error codes

| Status | Code | Meaning |
|--------|------|---------|
| 200 | `ok` | Success. |
| 201 | `created` | Resource created. |
| 204 | `no_content` | Resource deleted. |
| 400 | `bad_request` | Invalid request parameters. |

| 403 | `forbidden` | Permission denied or plan limit reached. |

| 409 | `conflict` | Resource conflict, non-retryable bootstrap, or terminal state mismatch. |

| 428 | `authorization_pending` | Pairing waiting for approval. |
| 429 | `rate_limited` | Too many requests. |

| 503 | `service_unavailable` | Service not configured or runtime warming/offline. |
| 504 | `gateway_timeout` | Runtime did not respond in time. |

## Rate limits

- Authenticated API routes: 60 requests per minute by default (`RATE_LIMIT_RPM`).
- Public pairing and relay routes: 30 requests per minute by default (`PUBLIC_RATE_LIMIT_RPM`).

Rate limit headers are included on responses:

```http
X-RateLimit-Limit: 60
X-RateLimit-Remaining: 59
X-RateLimit-Reset: 1723575600
```
