Scope `phones`. These routes drive the **project owner's own phones**: the Android phones and iPhones linked to their Allternit Desktop (Phone Link, adb or a USB Agent). Nothing about a phone is stored in the cloud. Each call is relayed, signed as the owner, to the Desktop that serves the phone, and runs through the same phone gateway a bot uses.

- Use a key that is **not bound to an account**. Phones belong to the owner, not to one of your end customers, so an account-bound key gets `403 account_bound_key`.
- Errors use the usual `{ "error": { "type", "code", "message", "param" } }` shape ([Errors](/api/platform/errors)). Every `POST` honors `Idempotency-Key`.
- Serials look like `link:…`, `usb:…` or `host:port`, so URL-encode them in paths. Use `-` for the only connected phone.

## Safety

- **Texts and calls need a person.** `phone.sms.send` and `phone.call.dial` open the approval dialog on the owner's Desktop, the same as when a bot asks. The API can't skip it. A refusal comes back as a result with `ok: false` and `error: "approval_denied"`.
- **Tasks and skills never text or call.** The phone task loop and skill replays only tap, type, swipe and read.
- **Nothing personal leaves the Desktop.** History redacts typed text, numbers and message bodies. Frames and screen text stay on the Desktop. Webhooks carry no screenshots.

## Errors when a phone isn't reachable

| Status | Code | Meaning |
|---|---|---|
| `503` | `phone_desktop_offline` | The owner's Allternit Desktop is offline. Open it, signed in, and retry. |
| `503` | `phone_gateway_unavailable` | The Desktop is online, but its phone gateway isn't running. |
| `503` | `phone_timeout` | The phone didn't answer in time. A text or call may still be waiting for approval. |
| `409` | `phone_offline` | That phone isn't connected to the Desktop right now. |
| `409` | `phone_required` | More than one phone is connected. Name a serial instead of `-`. |
| `404` | `no_desktop` | The owner has never paired an Allternit Desktop. |

## The phone object

```json
{
  "object": "phone",
  "serial": "link:7f3a",
  "name": "Joe's Pixel",
  "model": "Pixel 8",
  "online": true,
  "desktop_online": true,
  "last_seen_at": null,
  "call_bridge": { "enabled": true, "botName": "Raven" }
}
```

```http
GET /v1/phones
```

Returns `{ data, has_more: false, next_cursor: null }`. While the Desktop is offline, this lists the phones the cloud last saw, with `online: false` and `desktop_online: false`.

## Run one phone tool

```http
POST /v1/phones/{serial}/tool
```

| Field | Type | Notes |
|---|---|---|
| `name` | string | Required. One of `phone.devices`, `phone.screenshot`, `phone.read_ui`, `phone.screen_text`, `phone.tap`, `phone.type`, `phone.find_and_tap`, `phone.swipe`, `phone.home`, `phone.back`, `phone.key`, `phone.open_app`, `phone.sms.read`, `phone.sms.send` or `phone.call.dial`. The `phone.` prefix is optional. |
| `arguments` | object | The tool's arguments, as the phone tools take them (for example `{ "x": 540, "y": 1200 }` for `phone.tap`). |
| `run_id` | string | Optional. Groups several calls into one run in the history. By default each call starts a new `api-…` run. |

`phone.sms.send`, `phone.call.dial` and `phone.sms.read` wait for the phone owner to approve the call on their computer, every time, before the tool runs.

A `200` is the tool's result, even when the tool failed:

```json
{ "object": "phone.tool_result", "ok": true, "run_id": "api-4be1…", "tool": "phone.tap" }
```

A failed tool answers `ok: false` with an `error` such as `approval_denied`, `approval_timeout`, `rate_limited`, `not_found` or `accessibility_off`, plus a `message`. A text or call waits up to 80 seconds for the owner's approval.

## Give a phone a goal

```http
POST /v1/phones/{serial}/task
```

`{ "goal": "Open Settings and turn on Wi-Fi", "max_steps": 15, "bot_id": "…", "brain": "provider/model" }`. `goal` is required (up to 2000 characters). `max_steps` is 1 to 40 (default 15). The model is `bot_id`'s brain, else `brain`, else the default.

The task runs on the Desktop: it reads the screen, takes one action, and repeats until the goal is met, it fails, it runs out of steps, or 5 minutes pass. The call answers `202` at once:

```json
{ "object": "phone.run", "run_id": "task-9c2e…", "serial": "link:7f3a", "skill": null, "status": "running" }
```

Follow it with the `phone.step` and `phone.run.completed` webhooks, or read its steps with `GET /v1/phones/{serial}/history?run_id=`.

## Run many phones at once

```http
POST /v1/phones/runs
GET  /v1/phones/runs/{id}
```

A fleet run starts one background run per phone: the same task on every phone (`goal`), or the same saved skill (`skill`, with `inputs`).

```json
{ "serials": ["link:7f3a", "usb:R5C1"], "goal": "Open the store app and check today's orders", "max_steps": 20 }
```

It answers `202` with the fleet run:

```json
{
  "object": "phone.fleet_run",
  "id": "pfr_3b1c…",
  "kind": "task",
  "status": "running",
  "counts": { "runs": 2, "running": 2, "succeeded": 0, "failed": 0, "not_started": 0 },
  "runs": [{ "object": "phone.run", "run_id": "task-9c2e…", "serial": "link:7f3a", "status": "running", "ok": null }],
  "not_started": []
}
```

- List 1 to 100 phones by serial (not `-`), each once. Give `goal` or `skill`, not both.
- A phone whose run can't start (offline, unknown skill) is listed in `not_started` with its error code; the others still run.
- Each run ends with `phone.run.completed`. When the last one ends, the project gets `phone.fleet_run.completed`, and `GET /v1/phones/runs/{id}` shows `status: "completed"`.

## Concurrent run limits

Task and skill runs started through the API (single, fleet or MCP) count against the plan's limit while they run:

| Plan | Phone runs at once |
|---|---|
| Sandbox | 1 |
| Pay as you go | 5 |
| Growth | 25 |
| Enterprise | Set in the contract |

A run that would go over the limit gets `429 phone_run_limit` and nothing starts (a fleet run is checked as a whole). A run frees its slot when `phone.run.completed` arrives. Single tool calls are not limited by this, only by the [rate limit](/api/platform/idempotency-and-limits).

## Watch a phone live

```http
POST /v1/phones/{serial}/live
```

Returns a **view-only** live view of the phone's screen for 10 minutes:

```json
{
  "object": "phone.live_view",
  "id": "4c1f…",
  "serial": "link:7f3a",
  "view_only": true,
  "expires_in": 600,
  "expires_at": "2026-10-29T15:10:00Z",
  "viewer_url": "https://api.allternit.com/phone-live/4c1f…",
  "stream_url": "wss://api.allternit.com/phone-live/4c1f…/socket"
}
```

- Open `viewer_url` in a browser or put it in an `iframe`. It needs a browser with WebCodecs (current Chrome, Edge, Safari or Firefox).
- `stream_url` is the raw stream for your own player: a JSON `{ "type": "meta", "width", "height", "codec": "h264" }` frame, then one H.264 Annex-B access unit per binary frame. iPhones on the Allternit app send their own framing; use `viewer_url` for those.
- The stream is relayed from the owner's Desktop and can't send taps or typing. After 10 minutes both URLs stop working (`404 live_view_expired`, or a close with code `4401` mid-stream); ask for a new live view.
- `409 phone_offline` means the phone isn't connected to the Desktop. Treat both URLs like a password while they're valid: anyone with one can watch the screen until it expires.

## MCP tools

The same operations are MCP tools on the Allternit MCP server (`https://mcp.allternit.com/mcp`). Connect with a project key that has the `phones` scope as the bearer token. A key with only `phones` gets just the phone tools; a key with `agents` and `phones` gets the agent tools as well.

| Tool | Does |
|---|---|
| `phones_list` | The owner's linked phones |
| `phone_screenshot` | A screenshot (returned as an image) |
| `phone_tap` | Tap at `x`, `y` |
| `phone_type` | Type `text` |
| `phone_open_app` | Open `app` |
| `phone_tool` | Any phone tool by `name`, with `arguments` |
| `phone_task` | Start a task (`goal`); returns the `run_id` |
| `phone_run_status` | A run's status and latest steps (`serial`, `run_id`) |
| `phone_skill_run` | Replay a saved `skill`; returns the `run_id` |
| `phone_history` | A phone's recent steps and runs |
| `phone_live_url` | A view-only live view, as above |

Each tool takes `serial` (or `-` for the only connected phone). `phone.sms.send`, `phone.sms.read` and `phone.call.dial` through `phone_tool` behave exactly as on `/v1`: texts and calls wait for the owner to approve on their Desktop. Tool calls and runs are metered the same way.

## Metering

| Meter | Counts | Price |
|---|---|---|
| `phone_minutes` | Time an agent drives a phone. A task or skill run counts its length, rounded up to the minute. Tool calls count one minute for each phone and clock minute that has calls in it. | $0.02 a minute |
| `linked_phone` | Each phone a live project drives in a calendar month | $5 a phone a month |

Growth includes 3,000 phone minutes and 25 linked phones each month. See [Pricing](/api/platform/pricing) and [Usage](/api/platform/usage).

## Phone skills

A skill is a phone run that was saved once and replays with no model. Typed text is never stored, so each run passes it as `inputs`. Skills are saved in Allternit Desktop.

| Method and path | Body | Returns |
|---|---|---|
| `GET /v1/phones/skills` | | `{ data: [{ object: "phone.skill", name, inputs, … }] }` |
| `POST /v1/phones/skills/{name}/run` | `{ serial?, inputs?, bot_id?, brain? }` | `202` `{ object: "phone.run", run_id, skill, status: "running" }` |

A run needs a value for each of the skill's `inputs` (`400` otherwise). If a step's element has moved, that step gets one re-decision on `bot_id`'s brain (or `brain`).

## History

```http
GET /v1/phones/{serial}/history?run_id=
```

Every phone tool call on this phone, from bots, skills, tasks, routines and this API. History keeps 500 steps or 30 days per phone.

```json
{
  "object": "phone.history",
  "serial": "link:7f3a",
  "steps": [
    {
      "object": "phone.step",
      "id": "0b6c…",
      "run_id": "task-9c2e…",
      "at": "2026-10-20T15:01:02Z",
      "tool": "phone.type",
      "label": "type",
      "args": { "text": { "redacted": true, "len": 12 } },
      "ok": true,
      "error": null,
      "duration_ms": 412,
      "source": "task",
      "snapshot": true
    }
  ],
  "runs": [
    { "object": "phone.run", "run_id": "task-9c2e…", "started_at": "…", "ended_at": "…", "steps": 7, "failed": 0, "source": "task" }
  ],
  "retention_days": 30,
  "max_steps": 500
}
```

`snapshot: true` means a frame was kept on the Desktop. Frames aren't served through the API.

## Webhooks

Subscribe an endpoint ([Webhooks](/api/platform/webhooks)) to these events. They're sent to every project the owner owns that has an endpoint subscribed. `account_id` is always `null`.

| Event | When | `data` |
|---|---|---|
| `phone.step` | A phone tool call finished, from any source | `step_id`, `run_id`, `serial`, `tool`, `label`, `ok`, `error`, `duration_ms`, `source` (`bot`, `skill`, `task`, `routine` or `api`), `snapshot` |
| `phone.run.completed` | A phone task or skill run ended | `run_id`, `serial`, `ok`, `status` (task: `done`, `failed`, `max_steps`, `timeout`; skill: `succeeded`, `diverged`, `failed`), `skill`, `source`, `steps`, `failed`, `model_calls`, `duration_ms` |
| `phone.fleet_run.completed` | Every run of a fleet run ended, or none could start. Sent only to the project that started it | `fleet_run_id`, `kind`, `runs`, `succeeded`, `failed`, `not_started` |

Events come from the Desktop's event forwarder, so they arrive a few seconds after the step. If the Desktop was offline, they arrive when it reconnects.
