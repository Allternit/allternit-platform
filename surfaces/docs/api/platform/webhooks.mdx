Scope `webhooks`. Endpoints are project-wide, so account-bound keys can't manage them.

| Method | Path | |
|---|---|---|
| `POST` | `/v1/webhooks` | Create: `{ "url", "events", "description"?, "signer"? }` (the response includes `secret` once) |
| `GET` | `/v1/webhooks` | List |
| `GET` / `DELETE` | `/v1/webhooks/{id}` | Retrieve / delete (pending deliveries stop) |
| `POST` | `/v1/webhooks/{id}/test` | Send a `webhook.test` event to this endpoint |
| `GET` | `/v1/webhooks/{id}/deliveries` | Delivery log |
| `POST` | `/v1/webhooks/{id}/deliveries/{delivery_id}/redeliver` | Try again now |

`url` must be public `https` (not a private, loopback or link-local address). `signer` is `allternit` (the default, below) or `standard_webhooks` ([Standard Webhooks](#standard-webhooks)); endpoint objects show which one they use. `events` lists what you want, or `["*"]` for everything:

| Event | When |
|---|---|
| `message.received` | A text arrived on one of your numbers (`data.message`). |
| `message.status` | A text you sent was recorded (`data.message`). |
| `registration.updated` | A number's carrier registration changed (`data.number_id`, `data.state`, `data.rejection_reason`, `data.sms_state`). |
| `call.started` | A call with one of your agents started (`data.call`). See [Voice](/api/platform/voice). |
| `call.ended` | A call ended (`data.call`, with `status`, `duration_seconds`, `end_reason`). |
| `call.transcript.ready` | A call's transcript is complete (`data.transcript`), sent right after `call.ended`. |
| `usage.threshold` | The project's spend this month reached 50, 80 or 100% of its spend cap, once each per month (`data.meter` = `spend`, `data.percent`, `data.used` and `data.limit` in USD, `data.period` like `2026-10`). See [Billing and spend caps](/api/platform/billing). |

```json
{ "id": "evt_3b1…", "object": "event", "type": "message.received", "created": 1759601822,
  "project_id": "proj_…", "account_id": "acct_7Hq…", "data": { "message": { "id": "msg_…", "body": "Do you have time Tuesday?" } } }
```

## Delivery and retries

We POST each event to each matching endpoint. Any `2xx` answer within 10 seconds counts as delivered. Anything else is retried after 30 s, 2 min, 10 min, 30 min, 1 h, then every 2 h, for 24 hours; after that the delivery is marked `failed` (redeliver it from the log). Redirects aren't followed. Events can arrive more than once and out of order: deduplicate on `id`.

## Verify the signature

Every request carries:

```http
allternit-signature: t=1759601822,v1=5f2b…
```

`v1` is the hex HMAC-SHA256 of `"<t>.<raw request body>"` with your endpoint's `secret`. Check it against the raw body, before parsing, and reject requests whose `t` is more than five minutes old.

<CodeGroup>
```js Node
import crypto from "node:crypto";

export function verify(rawBody, header, secret, toleranceSec = 300) {
  const parts = Object.fromEntries(header.split(",").map((p) => p.split("=")));
  const t = Number(parts.t);
  if (!t || Math.abs(Date.now() / 1000 - t) > toleranceSec) return false;
  const expected = crypto.createHmac("sha256", secret).update(`${t}.${rawBody}`).digest("hex");
  const given = Buffer.from(parts.v1 ?? "", "hex");
  const want = Buffer.from(expected, "hex");
  return given.length === want.length && crypto.timingSafeEqual(given, want);
}
```

```python Python
import hashlib, hmac, time

def verify(raw_body: bytes, header: str, secret: str, tolerance_sec: int = 300) -> bool:
    parts = dict(p.split("=", 1) for p in header.split(","))
    t = int(parts.get("t", "0"))
    if not t or abs(time.time() - t) > tolerance_sec:
        return False
    expected = hmac.new(secret.encode(), f"{t}.".encode() + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, parts.get("v1", ""))
```
</CodeGroup>

## Standard Webhooks

Create the endpoint with `"signer": "standard_webhooks"` to get [Standard Webhooks](https://www.standardwebhooks.com) signatures instead, so any Standard Webhooks library (Svix, `standardwebhooks` on npm/PyPI) can verify them. The body is the same event object. The `secret` is then `whsec_` followed by base64 of 32 random bytes, and every request carries:

```http
webhook-id: evt_3b1…
webhook-timestamp: 1759601822
webhook-signature: v1,K5oZfzN95Z9UVu1EsfQmfVNQhnkZ2pj9o9NDN/H/pI4=
```

`webhook-id` is the event `id` (the same on every retry, so deduplicate on it). The signature is base64 HMAC-SHA256 of `"<webhook-id>.<webhook-timestamp>.<raw body>"` keyed with the base64-decoded secret. The same headers are what [MCP Events](/guides/mcp-events) deliveries use.

```js Node
import { Webhook } from "standardwebhooks";

const wh = new Webhook(process.env.ALLTERNIT_WEBHOOK_SECRET); // "whsec_…"
const event = wh.verify(rawBody, {
  "webhook-id": req.headers["webhook-id"],
  "webhook-timestamp": req.headers["webhook-timestamp"],
  "webhook-signature": req.headers["webhook-signature"],
}); // throws when the signature or timestamp is bad
```
