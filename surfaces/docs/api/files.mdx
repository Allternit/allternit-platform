## Overview

Files you attach in Allternit are stored in the private R2 bucket `allternit-user-files` at `u/<userId>/<fileId>/<name>`. The cloud API never streams file bytes: it checks your plan, hands you a presigned URL, and verifies the result. All routes need a Clerk session and only ever touch your own files.

## Plan limits

| Plan | Total storage | Largest file |
| --- | --- | --- |
| Free | 100 MB | 10 MB |
| Plus | 2 GB | 100 MB |
| Super and Ultra | 10 GB | 500 MB |

Deleting a file frees its space immediately.

## Upload

```http
POST /api/v1/files/uploads
{ "name": "report.pdf", "contentType": "application/pdf", "bytes": 482113 }
```

Returns `{ fileId, key, putUrl, expiresInSeconds }`. `PUT` the bytes to `putUrl` within 15 minutes. The URL is signed for exactly `bytes`, so a different size is rejected by R2. Then confirm:

```http
POST /api/v1/files/{fileId}/complete
{ "name": "report.pdf", "contentType": "application/pdf", "bytes": 482113 }
```

The server checks the stored size and only then records the file (`201`). A file that never completes leaves no record and uses no quota.

## Download and delete

```http
GET /api/v1/files/{fileId}               # presigned GET, valid 10 minutes
GET /api/v1/files/{fileId}?expires=86400 # 60 seconds to 7 days
DELETE /api/v1/files/{fileId}            # deletes the object, then the record (204)
GET /api/v1/files/usage                  # { plan, usedBytes, totalBytes, maxFileBytes }
```

## Errors

Errors are `{ "code", "message" }`.

| Status | Code | Meaning |
| --- | --- | --- |
| 413 | `file-too-large` | Over your plan's per-file limit |
| 413 | `storage-quota-exceeded` | Would pass your plan's total |
| 507 | `storage-full` | Allternit's shared storage is at its ceiling (9.5 GB of 10 GB). Uploads pause; downloads and deletes still work |
| 409 | `upload-missing`, `size-mismatch` | `complete` found no object, or one of a different size (it is discarded) |
| 404 | `not-found` | Not your file, or already deleted |
| 503 | `storage-unavailable` | Storage is not configured or reachable |

## Custom voice recordings

The consent clip for a custom voice is stored in the same bucket at `voices/<userId>/<voiceId>.wav`, outside your file quota. Revoking the voice deletes the object. The voice service still reads it through the same cloud API route.
