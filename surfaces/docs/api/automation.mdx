## Overview

The Automation API surfaces Gizzi Code's cron/routine/loop runtime through the Allternit platform API. A **goal** is a platform-owned objective that can own **routines** (persistent scheduled jobs) and **loops** (session-scoped recurring jobs). Routines and loops can execute locally or in the cloud via the Gizzi cron daemon.

## Base URL

```
https://api.allternit.com/api/v1/automation
```

For local development:

```
http://127.0.0.1:8013/api/v1/automation
```

## Authentication

All automation routes require a valid bearer token. See [Authentication](/api/authentication).

| `goal_id` | string | Optional parent goal. |
| `agent_id` | string | Bot/agent that runs it. Required for `local` routines. |
| `gizzi_job_id` | string | Daemon job id when cloud scheduled. |
| `name` | string | Routine name. |
| `description` | string | Optional description. |
| `status` | string | `active`, `paused`, etc. |
| `schedule_type` | string | `cron`, `interval`, `manual`, or `once`. |
| `schedule_expression` | string | Cron expression or interval shorthand. |
| `timezone` | string | Optional timezone. |
| `execution_domain` | string | `local` or `cloud`. |
| `config` | object | Routine configuration including `jobType`. |
| `max_runs` | integer | Optional maximum run count. |
| `timeout_seconds` | integer | Optional per-run timeout. |
| `max_retries` | integer | Optional retry count. |
| `metadata` | object | Free-form, plus run bookkeeping the local scheduler maintains (below). |
| `next_run_at` | string | Local scheduler cursor; `null` when paused, manual, or needing a bot. |
| `last_run_at` | string | Start of the last run. |

The local scheduler keeps these keys in `metadata`:

| Key | Meaning |
|-----|---------|
| `lastRunStatus` | `succeeded`, `skipped` (monitor output unchanged) or `failed`. |
| `lastRunError` | Last failure message; removed by a good run. |
| `consecutiveFailures` | Failed runs in a row; removed by a good run. |
| `autoPaused` | `{ at, reason, lastError }` when the routine paused itself after 3 failures in a row. |
| `needsAgent` | `true` for a local routine with no `agent_id`. It is never run until one is assigned. |

## Create a goal

```http
POST /api/v1/automation/goals
```

### Request body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `title` | string | Yes | Goal title. |
| `workspace_id` | string | No | Workspace id. |
| `agent_id` | string | No | Associated agent id. |
| `description` | string | No | Description. |
| `priority` | string | No | Defaults to `medium`. |
| `target_date` | string | No | ISO 8601 date. |
| `metadata` | object | No | Arbitrary metadata. |

### Example request

```bash
curl -X POST https://api.allternit.com/api/v1/automation/goals \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Ship Q3 release",
    "description": "Coordinate release tasks",
    "priority": "high",
    "target_date": "2026-09-01"
  }'
```

## Create a routine


| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Routine name. |
| `schedule_type` | string | Yes | `cron`, `interval`, `manual`, or `once`. |
| `schedule_expression` | string | Yes | Cron expression or interval shorthand (`5m`, `1h`, etc.). |
| `workspace_id` | string | No | Workspace id. |

| `timezone` | string | No | Timezone. |
| `execution_domain` | string | No | `local` or `cloud`; defaults to `local`. |
| `config` | object | No | Routine config; include `jobType` to control daemon job type. |
| `tags` | string[] | No | Tags. |
| `metadata` | object | No | Metadata. |
| `max_runs` | integer | No | Maximum runs. |
| `timeout_seconds` | integer | No | Timeout. |
| `max_retries` | integer | No | Retries. |

```bash
curl -X POST https://api.allternit.com/api/v1/automation/routines \
```

## Routines and bots

A local routine runs as a turn in its bot's chat, so it must have a bot.

- `POST /routines` without `agent_id` for a local routine returns `400` with `{"error": "agent_required", "message": "..."}`. An `agent_id` that names no agent returns `400` `agent_not_found`.
- Local routines that have no bot (created before this rule) are never run. The scheduler sets `metadata.needsAgent = true` and clears `next_run_at`; the Bots UI lists them under **Needs a bot**.

### Assign a routine to a bot

```http
PUT /api/v1/automation/routines/:id
Content-Type: application/json

{ "agent_id": "<bot id>" }
```

Sets the routine's bot, removes `needsAgent`, `consecutiveFailures` and `autoPaused`, and resets `next_run_at` so the scheduler arms the next run from the schedule. Other fields are unchanged. An empty `agent_id` means no change; a routine cannot be unassigned.

### Pause, resume and automatic pause

`PUT` with `{"status": "paused"}` pauses a routine; `{"status": "active"}` resumes it and clears `consecutiveFailures` and `autoPaused`, so it gets 3 more tries. After 3 failed runs in a row the scheduler sets `status` to `paused`, records `metadata.autoPaused`, and appends a `routine.paused` event to the bot's activity ledger (next to the `routine.failed` event for each failed run).

## Trigger a routine

```http
POST /api/v1/automation/routines/:id/run
```

Local routines run at once on this API and answer `{"status": "running", "routineId": "...", "domain": "local"}`; the result lands in the run history and the bot's chat. A local routine with no bot returns `409` `agent_required`; one that is already running returns `409` `already_running`. Cloud routines run through the Gizzi cron daemon.

## List routine runs

```http
GET /api/v1/automation/routines/:id/runs
```

Returns stored runs for the routine, newest first, and for cloud routines attempts to sync the latest history from the Gizzi cron daemon.

A local run's row is written with `status: "running"` when it starts and completed in place when it ends. Its `metadata` holds:

| Field | Meaning |
|-------|---------|
| `sessionId` | The thread the run wrote to. Set as soon as the run has one. |
| `model` | `provider/model` that ran the turn. |
| `apps` | Tools the turn called, first use first, each once. Connector tools (`mcp__<app>__<tool>`) name the app. |
| `steps` | The turn's last todo list: `{content, status}` items. |

`status` is one of `running`, `succeeded`, `failed`, `skipped` or `cancelled` (stopped; a cloud run the daemon reports as `aborted` is stored as `cancelled`). A run left `running` when the API stopped is marked `failed` with `outcome_reason: "runtime_restart"` at the next start.

### Example response

```json
{
  "runs": [
    {
      "id": "run_550e8400",
      "routine_id": "rtn_550e8400",
      "gizzi_run_id": "grun_550e8400",
      "status": "completed",
      "scheduled_at": "2026-08-13T09:00:00Z",
      "started_at": "2026-08-13T09:00:01Z",
      "finished_at": "2026-08-13T09:00:05Z",
      "duration_ms": 4000,
      "output": "Standup summary generated.",
      "error": null,
      "attempt": 1,
      "triggered_by": "schedule"
    }
  ],
  "sync": { "attempted": true, "synced": 1, "error": null }
}
```

## Recent runs in the routine list

```http
GET /api/v1/automation/routines?recent_runs=14
```

Each routine gains `recentRuns`, newest first, for a run-history strip without one request per routine. A local run in progress is listed first with `status: "running"` even before its row is read.

```json
"recentRuns": [
  { "id": "run_9c1", "status": "running" },
  { "id": "run_9b7", "status": "succeeded", "startedAt": "2026-10-23T09:00:01Z", "finishedAt": "2026-10-23T09:00:42Z", "durationMs": 41000, "reason": null, "apps": ["mcp__linear__list_issues", "mcp__slack__post_message"], "model": "provider/model-name" }
]
```

## Watch a run in progress

```http
GET /api/v1/automation/routines/:id/live
```

While a local run is going this reads its thread and answers `{"running": true, "runId", "startedAt", "sessionId", "steps", "apps", "model", "text", "canStop": true}`. `steps` is the turn's todo list so far and `text` is the last 600 characters it has written. For a cloud run it answers `running` with empty `steps` and `apps` (the daemon does not report them). When nothing is running it answers `{"running": false}`. Poll it every few seconds while a run is going.

## Stop a run

```http
POST /api/v1/automation/routines/:id/runs/:run_id/cancel
```

Cancels the run's turn. The run ends with `status: "cancelled"`, `outcome_reason: "stopped"` and the text it had written as `output`. A stopped run does not count toward the automatic pause and opens no "Something needs fixing" item. Answers `{"status": "stopping", "runId"}`. A run that already finished returns `409` `not_running`. For a cloud routine the API asks the Gizzi cron daemon to stop the job's run (`POST /jobs/:id/abort`); a daemon too old to stop runs returns `502` `stop_failed`.

## Create a loop

```http
POST /api/v1/automation/loops
```

Same request shape as a routine, plus an optional `session_id` and `expires_at`.

## List local schedules

```http
GET /api/v1/automation/local-schedules
```

Returns all routines and loops whose `execution_domain` is `local`.

### Example response

```json
{
  "routines": [...],
  "loops": [...]
}
```

## Routines and loops tied to a thread

A routine or loop created from inside a bot thread belongs to that thread. On create, when `metadata.sessionId` (routine) or `sessionId` (loop) is one of a thread's sessions, the server stamps `metadata.sourceThreadId`. When the thread is resolved, archived or paused by its owner, its tied routines and loops are set to `paused` with `metadata.closedWithThread`, and the matching Gizzi cron jobs stop. Reopening the thread sets them back to `active`. See [Threads and subagents](/guides/bot-threads#what-stops-when-a-thread-closes).

## Error codes

| Status | Meaning |
|--------|---------|
| `200 OK` | Success. |
| `201 Created` | Resource created. |
| `204 No Content` | Resource deleted. |
| `400 Bad Request` | `agent_required` (local routine without a bot) or `agent_not_found`. |
| `401 Unauthorized` | Missing or invalid bearer token. |
| `409 Conflict` | Run now on a routine with no bot (`agent_required`) or one already running (`already_running`); Stop on a run that already finished (`not_running`). |
| `502 Bad Gateway` | Stop on a cloud routine when the cron daemon can't stop runs (`stop_failed`). |
| `404 Not Found` | Goal, routine, or loop not found. |
| `500 Internal Server Error` | Database or daemon error. |
