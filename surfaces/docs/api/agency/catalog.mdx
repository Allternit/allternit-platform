The catalog endpoints list what a request can refer to. They are read-only, cursor-paginated and need scope `catalog:read`. They open with the rest of the API, after a run can survive restart, resume, verify, replay and receipt-backed completion.

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/v1/capabilities` | [List capabilities](#list-capabilities) |
| `GET` | `/v1/agents` | [List agents](#list-agents) |
| `GET` | `/v1/models` | [List model classes](#list-model-classes) |
| `GET` | `/v1/authority-profiles` | [List authority profiles](#list-authority-profiles) |
| `GET` | `/v1/completion-criteria` | [List completion criteria](#list-completion-criteria) |

All five take the same query parameters:

| Parameter | In | Type | Description |
|-----------|----|------|-------------|
| `cursor` | query | string | Opaque cursor from a previous page's `next_cursor`. |
| `limit` | query | integer | 1 to 200. Default 50. |

<Note>
The registry entries in the examples on this page (capability IDs, model class IDs, profile contents, semantics text) are illustrative. The real entries are whatever the registries return.
</Note>

## List capabilities

```http
GET /v1/capabilities
```

The capability registry. A capability is a stable semantic ability with an ID starting `cap.`. IDs are independent of whichever backend provides the ability. Use them in `capabilities.allow` and `capabilities.deny` on a [run request](/api/agency/runs#capabilities-tier-b) and in authority grants.

```json
  "next_cursor": null
```

## List agents

```http
GET /v1/agents
```

Logical composite agents. An agent is the external identity you address in `agent` on a request, optionally pinned to a version (`allternit-code@v1`). The default agent is `allternit-code`.

## List model classes

```http
GET /v1/models
```

Logical model classes by trust class and locality. This endpoint returns **classes, not models**. Concrete models are interchangeable components and are never listed. No vendor or model name appears in a default response.

Use class IDs (they start `mc.`) in `models.allow_classes` and `models.deny_classes` on a [run request](/api/agency/runs#models-tier-b). Model or vendor names in those fields are rejected.

{{params:listModelClasses}}

### Responses

```json
      "latency_class": "normal"
    }
  ],
  "has_more": false,
  "next_cursor": null

```

`trust_classes` is the set of data trust classes a class may receive. `locality` is `local`, `fabric` or `remote`.

## List authority profiles

```http
GET /v1/authority-profiles
```

Named authority profiles and the grants each expands to. Three profiles exist: `read-only`, `code-safe` and `code-write`. No bypass equivalent is ever public. Each definition is versioned; a run records the profile as `id@version` in `Run.resolved.authority`.

### Parameters

{{params:listAuthorityProfiles}}

### Responses

{{responses:listAuthorityProfiles}}

[AuthorityProfilePage](/api/agency/schemas#authorityprofilepage) of [AuthorityProfile](/api/agency/schemas#authorityprofile):

{{fields:AuthorityProfile}}

`filesystem_scope` ([FilesystemScope](/api/agency/schemas#filesystemscope)):

{{fields:FilesystemScope}}

`approval_requirements` items ([ApprovalRequirement](/api/agency/schemas#approvalrequirement)):

{{fields:ApprovalRequirement}}

| `mode` | Meaning |
|--------|---------|
| `never_allowed` | The effect is not permitted under this profile. |
| `always_ask` | Every occurrence raises an approval request. |
| `ask_unless_granted` | Raises an approval request unless an explicit grant covers it. |
| `allowed` | Permitted without asking, subject to hard policy. |

`grants` items are [Grant](/api/agency/schemas#grant) objects and `network` is a [NetworkPolicy](/api/agency/schemas#networkpolicy); both are described under [Create a run](/api/agency/runs#authority).

```bash
curl https://api.allternit.com/v1/authority-profiles \
```

```json
      "network": { "default": "deny", "private_ip": "deny", "max_redirects": 3, "redirect_scope": "allowlist", "dns_rebind": "pin_resolution" },

      "approval_requirements": [
        { "effect": "write", "mode": "never_allowed" },
        { "effect": "execute", "mode": "never_allowed" },
        { "effect": "network", "mode": "never_allowed" },
        { "effect": "spend", "mode": "never_allowed" },
```

## List completion criteria

```http
GET /v1/completion-criteria
```

The versioned, extensible completion-criteria registry. Each criterion states, in `verifier_semantics`, exactly what a pass means, and names the kind of verifier that checks it.

Built-in criterion IDs: `tests_pass`, `no_new_regressions`, `build_passes`, `typecheck_passes`, `lint_clean`, `artifact_exists`, `requirement_verified`, `human_review`.

Refer to a criterion in `completion.require` by ID (latest version at resolution time) or as `{id, version}` to pin it. The resolved version is recorded in `Run.resolved.completion`.
