A **Run** is one durable execution of a goal. It is persisted before the create call returns and survives process restart. The alpha opens only after a run can survive restart, resume, verify, replay and receipt-backed completion. For the concepts behind this page see [The kernel](/architecture/kernel).

## The Run object

{{fields:Run}}

Run IDs match `^run_[A-Za-z0-9]+$`.

### Status

| Status | Terminal | Meaning |
|--------|----------|---------|
| `accepted` | no | Persisted. Stays here until `resolved` is recorded. |
| `running` | no | At least one node is executing or verifying. |
| `waiting` | no | Nodes are on a wait gate or a lease reclaim is pending; none is running. |
| `needs_attention` | no | An attention request is open. Includes `budget_exhausted` after spend is halted. |
| `paused` | no | Paused by an operator; leases released at a safe boundary. |
| `cancelling` | no | Cancel receipted; in-flight effects are settling. |
| `completed` | yes | The completion predicate is true. |
| `partial` | yes | Closed with unmet criteria, only when `allow_partial` is `true`. |
| `failed` | yes | Closed after an unrecoverable failure or a budget stop. |
| `cancelled` | yes | Closed after a cancel. |

Precedence when nodes differ: `cancelling` > `paused` > `needs_attention` > `running` > `waiting` > `accepted`.

## Create a run

```http
POST /v1/agency
```

Compiles the request into explicit internal contracts and returns the Run immediately. It never executes an implicit free-form loop. The run is persisted before `202` is returned.

Only `goal` is required. The server resolves workspace, authority, budget and completion from the agent's and profile's versioned defaults and records them on `Run.resolved` before any execution. There are no hidden permissive defaults: if a default cannot be safely resolved the call fails with `422 ERR_DEFAULTS_UNRESOLVABLE` and no run executes. Runs created here always have judge fail-closed and verifier-owned completion enabled; clients cannot disable either.

{{fields:Authority}}

{{fields:Grant}}

{{fields:ExecutionEnvironment}}

#### budget

[Budget](/api/agency/schemas#budget). At least one of `max_seconds` or `max_cost_usd` is required when you supply a budget. On exhaustion the platform first hard-stops all billable and effectful execution, then asks or stops.

{{fields:Budget}}

#### completion

[CompletionCriteria](/api/agency/schemas#completioncriteria). Items in `require` are registry IDs (a string, latest version) or pinned `{id, version}` objects ([CriterionRef](/api/agency/schemas#criterionref)).

{{fields:CompletionCriteria}}

{{fields:CapabilityLimits}}

### Example

```bash
curl -X POST https://api.allternit.com/v1/agency \
  -H "Authorization: Bearer $ALLTERNIT_API_KEY" \
  -H "Idempotency-Key: 3f1c2a9e-7b1d-4c55-9a0e-1d2b3c4d5e6f" \
  -H "Allternit-Version: 2026-09-29" \
  -H "Content-Type: application/json" \
  -d '{
    "agent": "allternit-code",
    "goal": "Fix the failing checkout tests and verify the repair",
    "workspace": {"repo": "repo://acme/store"},
    "authority": {"profile": "code-safe"},
    "budget": {"max_seconds": 900, "max_cost_usd": 2.0},
    "completion": {"require": ["tests_pass", "no_new_regressions"]},
    "stream": true
  }'
```

The `202` response body is a Run with `status: "accepted"`. A full response, including `resolved`, is shown in the [overview](/api/agency/overview#the-minimal-call).

Error example, when defaults cannot be resolved:

```json
{
  "error": {
    "family": "INPUT",
    "code": "ERR_DEFAULTS_UNRESOLVABLE",
    "message": "No default workspace can be resolved for agent allternit-code. Supply workspace.",
    "retryable": false,
    "request_id": "req_8f2c1d",
    "param": "workspace"
  }
}
```

## Submit input

```http
POST /v1/runs/{run_id}/input
```

Answer an attention request, steer the run, or add data. `approval` and `rejection` must carry `attention_id`. An approval only resolves a policy ask; it can never override a hard policy deny (`403 ERR_POLICY_DENIED`). Input is recorded as a receipt before it takes effect.

## Pause a run

```http
POST /v1/runs/{run_id}/pause
```

Asynchronous and idempotent. Nodes stop at the next safe boundary; in-flight effects finish and are receipted; leases are released. Status goes to `paused`. Pausing a paused run is a no-op (`202`, same Run).

{{params:pauseRun}}

{{fields:ControlRequest}}

{{responses:pauseRun}}

## Resume a run

```http
POST /v1/runs/{run_id}/resume
```

Asynchronous and idempotent. Resumes from durable state and receipts, never from a transcript. A node interrupted in the middle of an effect is not blindly re-run: it resumes only if its effect is idempotency-keyed and receipted. Otherwise the run raises an attention request (reason `unsafe_resume`).

### Parameters

{{params:resumeRun}}

### Request body

Optional. [ControlRequest](/api/agency/schemas#controlrequest) (`reason`).

### Responses

{{responses:resumeRun}}

### Example

```bash
curl -X POST https://api.allternit.com/v1/runs/run_01JB2K4Y7MQ8/resume \
  -H "Authorization: Bearer $ALLTERNIT_API_KEY" \
  -H "Idempotency-Key: 5b9f1c22-0d4e-4c7a-b1f3-8a6e9d0c2b17"
```

## Cancel a run

```http
POST /v1/runs/{run_id}/cancel
```

Asynchronous and idempotent. Status goes `cancelling`, then `cancelled`.

- No new node is admitted or leased after the request is receipted.
- Effects already dispatched are not silently abandoned. Each one completes, times out, or is rolled back where the node declares a rollback, and its outcome is receipted. `Run.cancellation.effects_in_flight` lists them until settled.
- Open attention requests are withdrawn.
- Repeating cancel on a `cancelling` or `cancelled` run returns `202` with the current Run.
- Cancelling a run already `completed`, `partial` or `failed` returns `409 ERR_RUN_TERMINAL`.

### Parameters

{{params:cancelRun}}

### Request body
