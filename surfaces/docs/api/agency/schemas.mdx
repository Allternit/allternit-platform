## Reading the tables

- **Required** means the field must be present: in a request body you must send it, and in a response the server always returns it. A field marked `no` may be absent.
- **Disclosure tier** marks fields outside the everyday surface: B is the capability tier, C is the graph tier, D is the runtime tier. See [progressive disclosure](/api/agency/overview#progressive-disclosure).
- Request objects are closed unless the table says otherwise. Unknown request fields are rejected with `ERR_INPUT_UNSUPPORTED`. Clients must ignore unknown response fields and treat unknown enum values as not understood. See [Versioning](/api/agency/versioning).
- Names ending in `V1` in descriptions (for example `AttentionRequestV1`) refer to [kernel contracts](/architecture/kernel-contracts). The API objects are public views of those contracts.

## AgencyRequest

Only `goal` is required. `workspace`, `authority`, `budget` and `completion` are optional; when omitted the server resolves each from the agent's/profile's versioned defaults and returns the resolved values on `Run.resolved` before execution. Supplying a field overrides the default (never widening beyond caller entitlement or hard policy). There are no hidden permissive defaults. `capabilities` and `models` are Level B, `graph` is Level C, `runtime` is Level D. Unknown fields are rejected, including any attempt to disable judge fail-closed or verifier-owned completion. `thread_id` is a correlation ID only.

## Authority

Explicit authority (optional on the request; resolved from the agent's default profile when omitted and returned in `Run.resolved.authority`). A named `profile` (`read-only`, `code-safe`, `code-write`, optionally pinned `name@version`) compiles into capabilities and policy, not magic strings (GET /v1/authority-profiles). `grants` may only add scoped grants within the caller's entitlement; nothing can weaken a hard policy deny. There is no bypass/yolo/auto-approve profile: such names are rejected with `ERR_AUTHORITY_PROFILE_FORBIDDEN` and no executor's native bypass mode is honored.

## CompletionCriteria

Verifier-owned completion. The run reaches `completed` only when the system evaluates: every required criterion has a PASS verification receipt, no blocking failure is unresolved, required artifacts exist, and policy obligations are met. A model saying "done" is a proposal with no authority. INCONCLUSIVE is never PASS. Items in `require` are string ids or `&#123;id, version?&#125;` referring to the versioned registry (GET /v1/completion-criteria); omitted version means latest at resolution time and the resolved version is recorded in `Run.resolved.completion`. `allow_partial` is the only way a run may end `partial`.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `require` | array of [CriterionRef](#criterionref) | yes |  |
| `criteria` | array of [Criterion](#criterion) | no | Custom criteria, referenced from `require` by `id`. |
| `allow_partial` | boolean | no | If true, a run that stops with some criteria unmet ends `partial`. `partial` is only ever produced when this is true, and is never a synonym for failed or unfinished. |

No other properties are accepted.

## Receipt

Append-only, content-addressed, hash-chained per run. `content_hash` = sha256 over the canonical JSON (RFC 8785) of every field except `content_hash` and `signature`. `prev_hash` links to the previous receipt in the run chain (null only at index 0). Corrections append a new receipt with `supersedes`. Signing: per-run previous-hash chain; RFC 8785 JCS canonicalization, SHA-256, Ed25519. The signed material is the JCS-canonical object &#123;`schema_id`, `schema_version`, `domain`, `content_hash`&#125;, so signatures bind schema id, schema version and the domain-separation tag `allternit.receipt.v1`. Verification keys: `/.well-known/jwks.json`.
