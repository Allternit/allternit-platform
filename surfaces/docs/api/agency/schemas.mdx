This page lists all 98 component schemas in the [v0.3 OpenAPI contract](/api/agency/overview#openapi-file), in contract order. The tables are generated from the contract file, so they match it field for field. Nested inline objects are flattened with dotted names (`data.from`, `criteria[].result`).

## Reading the tables

- **Required** means the field must be present: in a request body you must send it, and in a response the server always returns it. A field marked `no` may be absent.
- **Disclosure tier** marks fields outside the everyday surface: B is the capability tier, C is the graph tier, D is the runtime tier. See [progressive disclosure](/api/agency/overview#progressive-disclosure).
- Request objects are closed unless the table says otherwise. Unknown request fields are rejected with `ERR_INPUT_UNSUPPORTED`. Clients must ignore unknown response fields and treat unknown enum values as not understood. See [Versioning](/api/agency/versioning).
- Names ending in `V1` in descriptions (for example `AttentionRequestV1`) refer to [kernel contracts](/core/kernel-contracts). The API objects are public views of those contracts.

## Extensions

Extension pattern. Any closed object may carry properties named `x-<vendor-neutral-name>`. Servers preserve unknown `x-` properties; they never change kernel semantics.

Property names must match `^x-[a-z0-9-]+$`; values are unconstrained.

## AgencyRequest

Only `goal` is required. `workspace`, `authority`, `budget` and `completion` are optional; when omitted the server resolves each from the agent's/profile's versioned defaults and returns the resolved values on `Run.resolved` before execution. Supplying a field overrides the default (never widening beyond caller entitlement or hard policy). There are no hidden permissive defaults. `capabilities` and `models` are Level B, `graph` is Level C, `runtime` is Level D. Unknown fields are rejected, including any attempt to disable judge fail-closed or verifier-owned completion. `thread_id` is a correlation ID only.

## Authority

Explicit authority (optional on the request; resolved from the agent's default profile when omitted and returned in `Run.resolved.authority`). A named `profile` (`read-only`, `code-safe`, `code-write`, optionally pinned `name@version`) compiles into capabilities and policy, not magic strings (GET /v1/authority-profiles). `grants` may only add scoped grants within the caller's entitlement; nothing can weaken a hard policy deny. There is no bypass/yolo/auto-approve profile: such names are rejected with `ERR_AUTHORITY_PROFILE_FORBIDDEN` and no executor's native bypass mode is honored.

|-------|------|----------|-------------|

| `interaction_mode` | string enum | no | `autonomous` still stops at every policy ASK; it only removes discretionary review. One of: `autonomous`, `approval_gated`, `recommend_only`. Default: `"approval_gated"`. |
| `grants` | array of [Grant](#grant) | no |  |
| `network` | [NetworkPolicy](#networkpolicy) | no |  |
| `environment` | [ExecutionEnvironment](#executionenvironment) | no |  |
| `expires_at` | string \| null (date-time) | no | Defaults to run end. Grants never outlive the run. |

No other properties are accepted.

## Budget

On exhaustion the platform first hard-stops ALL further billable/effectful execution, then moves the run to `needs_attention` with attention reason `budget_exhausted`. No spend occurs while waiting; only a human answer can raise the budget.

At least one of `max_seconds`, `max_cost_usd` is required.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `max_seconds` | integer | no | Min: 1. |
| `max_cost_usd` | number | no | Min: 0. |
| `max_steps` | integer | no | Cap on executed work nodes. Min: 1. |
| `max_attention_requests` | integer | no | Min: 0. |
| `on_exhaustion` | string enum | no | `request_attention` (default): hard-stop, then `needs_attention/budget_exhausted`. `stop`: hard-stop then `failed`. A model can never raise its own budget. One of: `request_attention`, `stop`. Default: `"request_attention"`. |

No other properties are accepted.

## CompletionCriteria

Verifier-owned completion. The run reaches `completed` only when the system evaluates: every required criterion has a PASS verification receipt, no blocking failure is unresolved, required artifacts exist, and policy obligations are met. A model saying "done" is a proposal with no authority. INCONCLUSIVE is never PASS. Items in `require` are string ids or `{id, version?}` referring to the versioned registry (GET /v1/completion-criteria); omitted version means latest at resolution time and the resolved version is recorded in `Run.resolved.completion`. `allow_partial` is the only way a run may end `partial`.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `require` | array of [CriterionRef](#criterionref) | yes | Min items: 1. |
| `criteria` | array of [Criterion](#criterion) | no | Custom criteria, referenced from `require` by `id`. |
| `allow_partial` | boolean | no | If true, a run that stops with some criteria unmet ends `partial`. `partial` is only ever produced when this is true, and is never a synonym for failed or unfinished. Default: `false`. |

No other properties are accepted.

## RunStatus

Aggregate of the work-node lifecycle and the run receipt's completion status. When nodes differ, precedence is `cancelling` &gt; `paused` &gt; `needs_attention` &gt; `running` &gt; `waiting` &gt; `accepted`. See [Runs and completion](/core/runs-and-completion#run-status).

| Value | Meaning |
|-------|---------|
| `accepted` | Persisted; node work is declared, admitted or ready. Also the status until `Run.resolved` is recorded. |
| `running` | At least one node is leased, spawned, running, producing output, verifying, continuing or replanning. |
| `waiting` | Active nodes are on a timer, dependency or event wait gate, or a lease reclaim is pending, and none is running. |
| `needs_attention` | A node needs a human (an open AttentionRequest), including `budget_exhausted` after billable and effectful execution has been hard-stopped. |
| `paused` | Operator pause; leases were released at a safe boundary. |
| `cancelling` | The cancel is receipted; in-flight effects are settling. |
| `completed` | Terminal. The completion predicate evaluated true. |
| `partial` | Terminal. The run closed with the predicate false and the completion contract has `allow_partial: true`. Never a synonym for failed or unfinished. |
| `failed` | Terminal. Closed after an unrecoverable failure or a budget stop. |
| `cancelled` | Terminal. Closed after a cancel. |

## Receipt

Append-only, content-addressed, hash-chained per run. `content_hash` = sha256 over the canonical JSON (RFC 8785) of every field except `content_hash` and `signature`. `prev_hash` links to the previous receipt in the run chain (null only at index 0). Corrections append a new receipt with `supersedes`. Signing: per-run previous-hash chain; RFC 8785 JCS canonicalization, SHA-256, Ed25519. The signed material is the JCS-canonical object &#123;`schema_id`, `schema_version`, `domain`, `content_hash`&#125;, so signatures bind schema id, schema version and the domain-separation tag `allternit.receipt.v1`. Verification keys: `/.well-known/jwks.json`.

|-------|------|----------|-------------|

| `index` | integer | yes | Min: 0. |
| `content_hash` | string | yes | Pattern: `^sha256:[0-9a-f]{64}$`. |
| `prev_hash` | string \| null | yes |  |
| `signature` | [ReceiptSignature](#receiptsignature) \| null | no |  |
| `supersedes` | string \| null | no |  |
