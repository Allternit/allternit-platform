Every `4xx` and `5xx` response has the same body: one `error` object.

```json
{
  "error": {
    "family": "POLICY",
    "code": "ERR_POLICY_DENIED",
    "message": "Writing outside the workspace is not permitted by profile code-write@1.",
    "retryable": false,
    "request_id": "req_01J...",
    "run_id": "run_01J...",
    "param": null,
    "policy_reason_codes": ["fs.outside_workspace"],
    "receipt_id": "rcpt_01J...",
    "docs_url": "https://docs.allternit.com/api/agency/errors"
  }
}
```

| Field | Meaning |
|-------|---------|
| `family` | The broad class of error. Branch on this. |
| `code` | The specific `ERR_*` code. Kernel codes pass through unchanged. |
| `message` | Human-readable text. Do not parse it. |
| `retryable` | Whether the same request may succeed if retried. |
| `request_id` | Quote this when you report a problem. |
| `run_id` | The run the error belongs to, if any. |
| `param` | The request field that caused the error, if any. |
| `policy_reason_codes` | Why policy denied or asked, for policy errors. |
| `receipt_id` | The receipt that recorded the denial or failure, if any. |

The full field table is in [Schemas: Error](/api/agency/schemas#error).

## Handling codes you do not recognize

New codes may be added in a minor version. A client that meets an unknown `code` handles it by `family` and `retryable`, the same way it treats unknown enum values: as not understood, never as success.

- `retryable: true`: retry with backoff, reusing the same `Idempotency-Key`. See [Idempotency](/api/agency/idempotency).
- `retryable: false`: do not retry the same request. Fix the input, answer the attention request, or surface the error.

## Errors that are never overridable

- `ERR_POLICY_DENIED` (`403`) is a hard policy deny. It never becomes an approval request, and no answer, grant or score changes it. See [Policy](/architecture/policy).
- `ERR_AUTHORITY_PROFILE_FORBIDDEN` rejects any request that names a bypass-style profile.
- `ERR_DEFAULTS_UNRESOLVABLE` means a safe value could not be resolved for an omitted field. No run executes; the API never falls back to a permissive default.
- `ERR_REPLAY_UNRECORDED` fails one replay step whose external call has no recording. The call is never sent live. See [Replay](/architecture/replay).
