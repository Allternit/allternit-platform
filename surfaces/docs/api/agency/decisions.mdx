<Note>
**Implementation: IMPLEMENTED (E1, E5 flywheel, E6 vendor adapters) · Exposure: PREVIEW.** Served by allternit-api's Agency Kernel Decision Runtime (`cmd/allternit-api/src/agency_api/decisions/`). The local scorer is the sidecar in `domains/decision-runtime/`, managed by Allternit Desktop. Computer use starts calling it in phase E2.
</Note>

A decision picks one option from a list you supply. It never invents an option and never generates text: the local scorer reads the answer straight from a model's next-token distribution in one forward pass. The planner model sets a goal once; every step after that (which element, which op, did it work, is it safe, escalate?) can be a decision.

Three rules hold for every decision:

- **Bounded.** The answer is always one of your option ids, or `null` when it abstains.
- **Pure.** A decision has no side effects. Before you act on one, check that the chosen option is still valid (the screen may have changed).
- **Not authorization.** A decision is never a permission. Policy runs first; a decision can only add caution.

## Create a decision

```http
POST /v1/decisions
POST /v1/systemone        (compatibility alias, same request and response)
```

Authenticated like every Agency API route. Responses carry `Allternit-Request-Id`.

### Request body

| Field | Type | Required | Meaning |
|---|---|---|---|
| `context` | string, or `{ "text": string, "image": string }` | yes | What the decision is about: the goal, the screen's element map, what happened so far. Up to 64 KB. `image` is a `data:image/...` URL under 6 MB (a screenshot crop). |
| `options` | array of `{ "id": string, "text": string }` | yes | 2 to 255 options. Ids are 1–128 characters and unique; text is what the model reads. |
| `kind` | string | no (`choice`) | The decision kind. It picks the confidence threshold and, when `question` is empty, the question. Built in: `choice`, `element`, `op`, `verify`, `safety`, `escalate`, `route`. Any `[A-Za-z0-9_.-]{1,64}` is accepted. |
| `question` | string | no | The question, when the kind's default does not fit. |
| `allow_abstain` | boolean | no (`false`) | Return `choice: null` when no backend reaches the kind's threshold within the budget. |
| `latency_budget_ms` | integer | no (`10000`) | The total time for the decision, escalations included (1–120000). A backend that would start with under 5 ms left is skipped; one that runs past the budget is cut off. |
| `backends` | array of strings | no | Override the configured chain for this decision, for example `["local"]` or `["oracle"]`. |
| `session_id`, `task` | string | no | Stored with the decision, for grouping its outcomes later. |
| `project` (alias `project_id`) | string | no | The project the decision belongs to (1–128 characters). Vendor backends run only for projects enabled for them. |

### Response

| Field | Type | Meaning |
|---|---|---|
| `id` | string | `dec_…`. Use it to report the outcome. |
| `kind` | string | The decision kind. |
| `choice` | string or `null` | The chosen option id. `null` when abstained. |
| `probs` | object | Option id → probability, from the backend that answered. Relative to your option set, not calibrated. |
| `confidence` | number | The top probability (0–1). |
| `abstained` | boolean | No answer reached the threshold and `allow_abstain` was set (or the oracle abstained). |
| `escalated` | boolean | A later backend was tried because an earlier answer was under the threshold. |
| `threshold` | number | The kind's threshold that applied. |
| `calibrated` | boolean | Always `false`: probabilities are relative to the option set. |
| `backend` | string | Which backend answered: a live head (`head.lookup`), `local`, `oracle`, `vendor`, `typesafe`, or `none`. |
| `latency_ms` | number | Server time for the whole decision. |
| `attempts` | array | Every backend tried, in order: its latency, confidence, error, or why it was skipped. |

### Example

```bash
curl -X POST "$ALLTERNIT_API/v1/decisions" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{
    "kind": "element",
    "context": "Goal: compute 7 + 3 in Calculator.\n\nScreen: Calculator. Display shows 7.",
    "question": "Which button comes next?",
    "options": [
      {"id": "btn_plus", "text": "click button +"},
      {"id": "btn_3", "text": "click button 3"},
      {"id": "btn_eq", "text": "click button ="}
    ],
    "allow_abstain": true,
    "latency_budget_ms": 1500
  }'
```

```json
{
  "id": "dec_4f0c…",
  "object": "decision",
  "kind": "element",
  "choice": "btn_plus",
  "probs": { "btn_plus": 0.93, "btn_3": 0.05, "btn_eq": 0.02 },
  "confidence": 0.93,
  "abstained": false,
  "escalated": false,
  "threshold": 0.6,
  "calibrated": false,
  "backend": "local",
  "latency_ms": 133.8,
  "attempts": [{ "backend": "local", "latency_ms": 133.1, "confidence": 0.93, "abstain": false, "detail": { "engine": "mlx", "model": "qwen3.5-4b" } }]
}
```

When no backend answers and `allow_abstain` is false, the response is `503` with `error.code` `ERR_DECISION_UNAVAILABLE` and the attempts in `error.detail`.

## Backends and escalation

The router walks the chain in order (default `head,local,open,vendor,typesafe,oracle`, set with `ALLTERNIT_DECISIONS_CHAIN`). It stops at the first answer at or over the kind's threshold; a later answer replaces an earlier one. Backends that are not configured are left out; backends that cannot see images are skipped for a decision that carries one.

| Backend | What it is | On by default |
|---|---|---|
| `local` | The owned scorer sidecar: one-pass option scoring (ported from open-jev, MIT). MLX on Apple silicon; llama.cpp on Windows, Linux, Intel Macs and cloud hosts. Default model Qwen3.5-4B (Apache-2.0); `ALLTERNIT_DECISIONS_MODEL=gemma-3-4b` switches to Gemma 3 4B (set `HF_TOKEN` if your mirror is gated). Text only. | Yes, wherever Allternit Desktop runs it (`ALLTERNIT_DECISIONS_LOCAL_URL`) |
| `head` | The slot for the decision kind's live flywheel heads (see [The flywheel](#the-flywheel)). Empty until a head earns promotion; a head that has no answer passes the decision on. Text only. | Yes, but empty until a head is live |
| `open` | A self-hosted open-weight decision model over the Jev/SystemOne wire format (`POST /v1/systemone`, one `choice` question, the options as criteria): Liquid d1-3B (the decision sidecar's `systemone` engine, or llama-server), Cloudflare Clef / Clef-flash (SGLang), vLLM-SR d3. Text only. Not metered and not vendor-gated: it is ours. Model: `ALLTERNIT_DECISIONS_OPEN_MODEL` (default `LiquidAI/d1-3B`); optional bearer token `ALLTERNIT_DECISIONS_OPEN_TOKEN`. | No: needs `ALLTERNIT_DECISIONS_OPEN_URL` |
| `vendor` | Adapter for a hosted vendor decisions API (its public beta `POST /v1/decisions`: one `choice` question, the options as choices, text and image input). Metered by the vendor. | No: needs `ALLTERNIT_DECISIONS_VENDOR_KEY` **and** the project enabled |
| `typesafe` | TypeSafe Jev adapter (`POST /v1/systemone`, one `choice` question, the options as criteria). Text only. Metered by the vendor. | No: needs `ALLTERNIT_DECISIONS_TYPESAFE_KEY` **and** the project enabled |
| `oracle` | The planner model through gizzi, like every other model call. Sees images. The escalation path and the source of labels. Model: `ALLTERNIT_DECISIONS_ORACLE_MODEL=provider/model`, else your default model. | Yes (`ALLTERNIT_DECISIONS_ORACLE=0` turns it off) |

### Vendor backends

Both vendor backends are off by default and gated twice: the key has to be configured on the server (it comes from the server's secret environment, is sent only as the vendor's bearer token, and never appears in logs, attempts or errors), and the decision's `project` has to be enabled for that backend in `ALLTERNIT_DECISIONS_VENDOR_PROJECTS`:

```json
{ "vendor": ["proj_a", "proj_b"], "typesafe": ["*"] }
```

`*` enables every decision, with or without a project. A request that names a vendor in `backends` for a project that is not enabled leaves it out of the chain. Endpoint and model can be overridden with `ALLTERNIT_DECISIONS_VENDOR_URL` / `_MODEL` and `ALLTERNIT_DECISIONS_TYPESAFE_URL` / `_MODEL`. Both vendors bill per token; get the spend approved before enabling a project.

To compare backends on the same decisions, run `domains/decision-runtime/bench/compare_backends.py`. It sends each case once per backend through `/v1/decisions` (same adapters as production) and prints a latency and accuracy table. It refuses metered backends unless `--allow-metered` is passed.

Thresholds per kind: `default` 0.6, `verify` 0.8, `safety` 0.9, `escalate` 0.7. Override with a JSON object in `ALLTERNIT_DECISIONS_THRESHOLDS`, for example `{"default": 0.5, "element": 0.55}`.

### Native decision models (`systemone` engine)

The sidecar can also run a native decision model instead of option scoring on a chat model: `python -m allternit_decisions --engine systemone` (model preset `d1-3b`, Liquid d1-3B at a pinned revision, LFM Open License v1.0). It answers `/v1/score` as usual and also serves `POST /v1/systemone`, so the same process can back both `local` and `open`. It needs `transformers>=5.14`, `torch`, `torchvision` and `pillow` (installed on first use) and about 6 GB of weights. Liquid reports 8 ms per decision on an RTX 4090 and 30 ms on an M5 Pro; on a 4-core cloud CPU in float32 it measured about 6.5 s, so give it a GPU or Apple silicon in production.

## Training data (opt-in)

Decisions can become training data for the flywheel's trained heads, but only for organizations that opt in.

- `GET /v1/decisions/training` shows your scope (your organization, or you without one), whether it opted in, and how many examples are stored and labelled.
- `PUT /v1/decisions/training` `{"opted_in": true}` opts in. Organization admins only. `{"opted_in": false}` opts out and **deletes** the scope's stored examples.
- While opted in, each decision stores its context, question and options, DLP-redacted, next to the answer that served it. Labels come from outcomes (`PATCH /v1/decisions/:id` with a `label`, or the served choice on `success`; a `failure` marks it wrong) or, until one arrives, from a confident answer of a teacher backend (`oracle`, `open`, `vendor`, `typesafe`).
- `GET /v1/decisions/datasets/:kind` exports the labelled examples as JSONL in the Jev/SystemOne shape (`state`, `questions`, `answers`), ready for a decision fine-tune. `?scope=mine` (default, organization admins) exports your scope; `?scope=all` pools every opted-in scope with no scope or owner ids in the rows (decisions admins, `ALLTERNIT_DECISIONS_ADMINS`). Trained heads are shared across opted-in organizations.

## Decisions inside agency runs

Agency task types (`GENERAL_TASK`, `THREAD_WORK`, `COMPUTER_USE`, `RESEARCH_DOC`, `TEMPLATE`, `CAMPAIGN`) run a compute graph whose steps sit on tiers: S0 deterministic, S1 decisions, S2 generation, S3 deep solving. A step with `cognitive_role: "S1"` is a live decision: the run calls the Decision Runtime in-process as the run's owner, scoped to the run's `metadata.project_id` for vendor gating, with `session_id` set to the run id and `task` to `<run id>:<node id>`, so the decision shows in `GET /v1/decisions/:id`, `/v1/descent` and, for opted-in organizations, the harvested training data.

The step's decision is declared in the node's `extensions["x-decision"]`:

```json
{ "kind": "verify", "question": "Does the result meet the goal?",
  "options": [{ "id": "pass", "text": "The result meets the goal." },
              { "id": "fail", "text": "The result does not meet the goal." }],
  "pass": ["pass"] }
```

`options_from` takes the options from an earlier step's output instead (a JSON array, or one per line). `min_confidence` raises the bar above the kind's threshold, and `backends` overrides the chain. The chosen option id is written to the step's outputs. `routes` maps an option id to a step the node has an edge to. A routed choice goes to that step. Otherwise a choice in `pass` (default: any option) continues along the normal edge, and any other choice fails the run. An abstention, an answer under the threshold, or no backend answering fails the step over to its ESCALATE edge. In the shipped graphs that edge leads to an S2 twin of the step (`x-twin_of`). Every shipped task type's "review against the goal" step is an S1 `verify` decision.

Runs are deterministic. The runtime takes the argmax over option probabilities and never samples, and a tie goes to the earlier option. The answer is journaled per run and step before the run acts on it, so a re-drive or replay serves the journaled answer and never asks again. When the run completes with verified evidence, its decisions get the `success` outcome with the chosen option as the label. When verification fails, they get `failure`. A decision whose own choice failed the run gets no outcome, because whether that choice was right is unknown. This labelling is best effort. Under the scripted executor (`ALLTERNIT_AGENCY_COGNITION=scripted`), `scripted.json` can name the option per step (`"decide": {"G05": "fail"}`, or `"abstain"`). Without one, the first option is chosen.

## Descent metrics

`GET /v1/descent?days=30` reports whether work is moving down the tiers, over your decisions in the window: per decision kind and in total, how many each tier answered (`head`, `local`, `open`, `vendor`, `oracle`), the `cheap_share` (head + local + open), the `oracle_share`, the `escalation_rate`, the mean latency and the oracle's spend in USD. `daily` gives the cheap share per day; it should rise as heads are trained and promoted.

### The local scorer

The sidecar binds a loopback port at app start and does nothing heavy until the first decision. That decision starts its preparation: it installs its pinned Python packages, downloads the model (about 3 GB) into the app's data folder, and loads it. Until it is ready, decisions escalate past it; its status and download progress are in `GET /health` on the sidecar and in Desktop's `decision-runtime:get-status`. No model weights ship in the app.

To get the most out of it, put what stays the same first in `context` (the goal, the element map) and what changes per step last or in `question`, with blank lines between blocks. The scorer keeps the state at each block boundary, so the next decision over the same screen only reads what changed.

Measured on an M1 Pro (2026-10-09, Qwen3.5-4B 4-bit, machine under load): 19 of 19 obvious Calculator decisions right, p50 154 ms, p95 252 ms; a decision that reuses the screen costs about 130 ms, and one forward pass costs about 110 ms however few tokens it reads. Qwen3.5-2B ran at a 65 ms p50 but got only 9 of 19 right, so 4B stays the default. Newer Apple silicon is faster.

## Report the outcome

```http
PATCH /v1/decisions/{id}
```

| Field | Type | Meaning |
|---|---|---|
| `status` | `success` · `failure` · `error` · `skipped` | What happened when the choice was acted on. |
| `label` | string | The option id that was right, when known (from the oracle, a person or a verifier). |
| `detail` | string | Up to 4000 bytes. |

Returns the stored decision. `GET /v1/decisions/{id}` returns it too. The store keeps the context's sha256, never the context itself, plus the options, choice, probabilities, backend, latency, attempts and outcome. The context text is kept only for organizations that opted in to [training data](#training-data-opt-in), DLP-redacted, and an outcome relabels that example and feeds the flywheel below.

## The flywheel

A **head** is a tiny, fast decider registered for a decision kind. It earns its place on live traffic:

1. **Shadow.** Every decision of the kind runs each registered head after the answer is stored, off the latency path. The head's choice is kept next to the served choice and, once you report it, the outcome.
2. **Promotion.** When a head's accuracy against outcomes reaches the kind's bar over a minimum number of labelled answers, and its confidence is not higher than its accuracy, it goes **live**: it is tried first in the chain (the `head` slot). If it has no answer, or answers under the threshold, the decision escalates as usual.
3. **Demotion.** When a live head's accuracy drops under a lower bar, it goes back to shadow. Metrics count only answers since the last change of state, so every state has to be earned again.

Every change of state, automatic or by hand, is audited with the metrics that caused it. Outcomes count as follows: `success` confirms `label` (or the served choice); `failure` with a different `label` names the right option, otherwise it rules out the served choice; `error` and `skipped` do not count.

| Bar setting | Default | Meaning |
|---|---|---|
| `min_samples` | 200 | Labelled answers needed before promotion. |
| `promote_at` | 0.97 | Accuracy needed to go live. |
| `demote_at` | 0.93 | Live accuracy under this demotes. |
| `min_demote_samples` | 50 | Labelled live answers needed before demotion is judged. |
| `window` | 1000 | Most recent answers the metrics look at. |
| `max_overconfidence` | 0.05 | Mean confidence may exceed accuracy by at most this much. |
| `auto_promote` | `true` (`false` for `safety`) | A `safety` head never goes live by itself. |

Override per kind with JSON in `ALLTERNIT_DECISIONS_FLYWHEEL`, for example `{"default": {"min_samples": 300}, "element": {"promote_at": 0.98}}`.

The first head is **`head.lookup`**: an exact-match lookup over your own past outcomes. Same kind, same context, same question and the same options in the same order: it answers with the option that succeeded there before (one success gives 0.67, five give 0.86; failures count against it). It reads one indexed row and answers in well under 10 ms. It never sees images, it learns from the first outcome of each decision only, and it is per account. With no traffic it stays in shadow.

### List heads

```http
GET /v1/decisions/heads
```

Every head and kind it has seen: `state` (`shadow`, `live` or `retired`), `state_since`, the `bar`, `metrics` since the last change of state (`decisions`, `answered`, `coverage`, `agreement` with the served choice, `labelled`, `accuracy`, `overconfidence`, head `p50_latency_ms` / `p95_latency_ms`), `next` (the change the metrics call for, if any) and the last ten `audit` entries. Counts only: no contexts or options.

### Change a head's state

```http
PUT /v1/decisions/heads/{head}/{kind}
{ "state": "retired", "reason": "drift on the new Settings app" }
```

Head state is server-wide, so only user ids listed in `ALLTERNIT_DECISIONS_ADMINS` (comma separated; `*` for a single-user Desktop) may change it; others get `403`. `retired` takes a head out of shadow and serving until it is set back to `shadow`.

## Compatibility with contract v0.3

The published [v0.3 contract](/api/agency/schemas#decisionrequest) describes a wider decision surface (`operation`, `scale`, `range`, `require_level`, `threshold_action`). The server implements the choice decision above. It accepts the v0.3 names `state` (for `context`), `candidates` (for `options`), `label` (for an option's `text`) and `max_latency_ms` (for `latency_budget_ms`). The other operations and calibration levels are not served yet.
