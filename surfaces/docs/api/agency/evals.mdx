An **eval** applies graders to trajectories. A trajectory is what a run did: the steps it took in order, the effects it performed, what the verifier said, what it cost. Graders are deterministic checks over that trajectory ("did it run the policy check before it wrote the file?"), so an eval needs no model.

Evals are built on [replays](/api/agency/replays). A case can be a **recorded run**, replayed `k` times through the same recorded-only engine as `POST /v1/replays/batch` (optionally with a candidate head, model class or graph as `overrides`), or a **goal fixture** for a task type, walked by the scripted runner (no model, no effect). Every replayed effect is `recorded_only`: the replay asserts zero live effects and fails closed otherwise.

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/v1/evals/suites` | Create or replace one of your suites |
| `GET` | `/v1/evals/suites` | List your suites |
| `GET` | `/v1/evals/suites/{suite_id}` | Get a suite |
| `POST` | `/v1/evals/runs` | [Run suites](#run-an-eval) |
| `GET` | `/v1/evals/runs/{eval_run_id}` | Get an eval run |
| `POST` | `/v1/evals/cases/from-run/{run_id}` | [Promote a run into a regression case](#promote-a-run-into-a-regression-case) |

Suites and eval runs belong to the user who created them. A replayed case only reads runs you own; decisions admins (`ALLTERNIT_DECISIONS_ADMINS`) may also replay other users' runs in their evals. A case whose run you cannot read is skipped with `ERR_NOT_FOUND`, never replayed.

## Suites

A suite is a versioned JSON document:

```json
{
  "schema": "allternit.eval_suite.v1",
  "id": "refunds",
  "name": "Refund flow regressions",
  "cases": [
    {
      "id": "looks_up_before_refunding",
      "source_run_id": "run_01JB2K4Y7MQ8",
      "graders": [
        { "type": "step_order", "steps": ["obs.lookup_order", "mut.refund"] },
        { "type": "effect_count", "max": 1 },
        { "type": "verifier_pass" }
      ],
      "k": 3,
      "pass_rule": "all_of_k",
      "stakes": "high"
    },
    {
      "id": "brief_cites_sources",
      "task_type": "RESEARCH_DOC",
      "goal": "Write a one-page brief on container sandboxes",
      "params": { "writable_resources": ["fs:docs/brief.md"] },
      "script": {},
      "graders": [{ "type": "verifier_pass" }, { "type": "forbidden_step", "steps": ["R04_deep"] }],
      "k": 5,
      "pass_rule": { "n_of_k": 4 }
    }
  ]
}
```

| Case field | Meaning |
|---|---|
| `id` | 1-64 characters of `[A-Za-z0-9_.-]`, unique in the suite. |
| `source_run_id` | A recorded run to replay. Give this or `task_type`. |
| `overrides` | Replayed cases only: replay overrides (`decision_heads`, `model_class`, `graph_version`), as for [replays](/api/agency/replays). |
| `fixture` | Replayed cases only, optional: `{task_type, params, script}`. Used instead of the replay when the recording is not on this server (another server, CI). |
| `task_type`, `goal`, `params`, `script` | A goal fixture for the scripted runner. `script` decides only what a real executor would observe: `fail` (nodes whose attempt fails), `wait` (WAIT gates `open` or `closed`), `withhold` (criteria whose evidence is withheld). |
| `graders` | 1-20 [graders](#graders). An attempt passes when every grader passes. |
| `k` | Attempts, 1-10 (default 1). |
| `pass_rule` | `"all_of_k"` (default) or `{"n_of_k": n}`. |
| `stakes` | `normal` (default) or `high`. A high-stakes case must use `all_of_k`, and any high-stakes failure fails the CI gate. |
| `snapshot`, `title` | Free information, kept with the case. |

## Graders

| Type | Parameters | Passes when |
|---|---|---|
| `step_order` | `steps` | These steps committed in this order (a subsequence; a step id matches a node id or a primitive id). |
| `required_steps` | `steps` | Every one of these steps ran, in any order. |
| `forbidden_step` | `steps` | None of these steps ran. |
| `effect_count` | `min`, `max`, `tool` | The number of committed effects (of `tool`, if given) is within the bounds. |
| `must_cite` | `min` (default 1), `marker` (default `[src:`) | The run's output has at least `min` distinct citations. |
| `verifier_pass` | | The verifier passed and the run completed. |
| `cost_ceiling` | `max_usd`, `max_tokens` | Spend is at or under the ceiling. |
| `latency_ceiling` | `max_ms` | Wall time is at or under the ceiling. |
| `status` | `equals` | The trajectory ended in this status. |
| `stopped_at` | `step` | The trajectory stopped at this step. |
| `missing_evidence` | `equals` | The verifier found exactly these criteria missing. |

For a replayed case the trajectory is the replay's: its node path and outcomes, its verifier verdict and its replay totals (`tokens`, `cost_usd`, `latency_ms` from the replay results). Effects are the source run's effects, served from the recording, for the nodes the replay committed. Text for `must_cite` is the recorded model output and document content.

## Run an eval

```http
POST /v1/evals/runs
```

| Field | Meaning |
|---|---|
| `suite_id` | One of your suites. |
| `suite` | An inline suite (not stored). Give `suite_id` or `suite`, not both. |
| `include_shipped` | Also run every shipped task-type eval set (`task_types/evals/*.v1.json`) as suites. |
| `overrides` | Replay overrides applied to every replayed case, on top of the case's own. This is how a candidate head, model class or graph is tested against a regression suite. |
| `effects` | `recorded_only`, the only allowed value. |
| `seed` | Seed of the bootstrap interval (default fixed). The same results and seed give the same interval. |
| `resamples` | Bootstrap resamples, 100-20000 (default 2000). |

The eval runs in the request unless a case needs live model calls (a `model_class` or `graph_version` override outside scripted mode); then it is accepted with `status: running` and finishes in the background. Live model calls count against the server's daily spending caps exactly like replays: a reached cap stops the case with `ERR_BUDGET_CAP_REACHED` and no further calls.

The eval run (`evr_…`) has one entry per suite in `suites`, each with its `cases` and `metrics`, and `metrics` pooled over all suites. Each case result has `via` (`replay`, `scripted`, or `scripted_fixture`), `attempts` (with `pass`, every grader's `grades`, and for replays the `replay_id`, readable at `/v1/replays/{replay_id}`, and the `verdict`), `passes`, `pass_rate` (passes over `k`) and `pass` (by the case's rule). Skipped cases carry `skip_reason`.

| Metric | Meaning |
|---|---|
| `cases`, `graded`, `skipped`, `passed` | Case counts. |
| `pass_rate` | Passed cases over graded cases. |
| `attempt_pass_rate` | Passing attempts over all attempts. |
| `ci95` | Percentile bootstrap 95% interval of `pass_rate` over the cases: `low`, `high`, `method`, `resamples`, `seed`. |
| `high_stakes_failures` | Ids of failed high-stakes cases. |

```bash
curl -X POST https://api.allternit.com/v1/evals/runs \
  -H "Authorization: Bearer $ALLTERNIT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"suite_id": "regressions", "overrides": {"decision_heads": {"element": "head.lookup"}}}'
```

## Promote a run into a regression case

```http
POST /v1/evals/cases/from-run/{run_id}
```

Owner only, finished runs only (`completed`, `partial`, `failed`). Snapshots the run into a suite as a regression case, typically a run the [trace monitor](/api/agency/runs#get-trace-monitor-findings) flagged. The case keeps ids and fixtures, not content: the run id, task type, graph and template ids, write set, committed path, effect count, verifier verdict, spend, the monitor's finding checks, and a SHA-256 of the goal. It never copies the goal text, model outputs or credentials. Task-type runs also get a scripted `fixture` (their WAIT answers and failed steps) so the case still runs where the recording is not available.

| Field | Meaning |
|---|---|
| `suite_id` | Target suite (default `regressions`, created on first use). |
| `case_id` | Default `reg_<run id>`. The same id replaces the earlier case. |
| `graders`, `k`, `pass_rule`, `stakes`, `overrides` | Override the defaults. Default graders: `verifier_pass`, `effect_count` with the source's count as `max`, `step_order` over the source path when the source verified, and `cost_ceiling` at twice the source's spend. Default stakes: `high` when the run had a high or critical finding. |

The response (`201`) is `{ "object": "eval_case", "suite_id", "case", "suite_case_count" }`.

## The CI regression gate

`scripts/agency-eval-gate.mjs` runs the shipped task-type eval sets and the committed suites (`cmd/allternit-api/src/agency_api/evals/suites/*.v1.json`) offline, with the scripted runner only (no model, no secrets), through the cargo test `agency_api::evals::tests::eval_gate_offline_report`. It compares the report with `evals/baseline.v1.json` and exits non-zero when:

- a suite's pass rate drops more than 2 percentage points below its baseline (`max_drop_pp` in the baseline, or `--max-drop-pp`);
- any high-stakes (all-of-k) case fails;
- a baseline suite is missing from the report or graded nothing.

```bash
node scripts/agency-eval-gate.mjs                    # build, run, compare
node scripts/agency-eval-gate.mjs --report r.json    # compare an existing report
node scripts/agency-eval-gate.mjs --write-baseline   # refresh the baseline (same PR as the change)
```

Exit codes: `0` pass, `1` regression, `2` usage or infrastructure error. The comparison logic is tested by `node --test scripts/agency-eval-gate.test.mjs`. The gate needs a build of `allternit-api`, which takes well over five minutes on a GitHub-hosted runner, so it is a manual workflow (`.github/workflows/agency-eval-gate.yml`, `workflow_dispatch`), not a required check. The same offline report also runs, and is checked against the baseline, in `cargo test -p allternit-api --lib agency_api`.
