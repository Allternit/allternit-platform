## Overview

Artifacts v2 is the one store every Allternit surface reads and writes: Desktop, ai.allternit.com, the phone layout, the m.allternit.com PWA, cloud computers and gizzi. An artifact is something the assistant (or a person) made that you would show someone. Each one has a `kind`, an immutable list of versions, and sharing settings. The design contract is `docs/design/artifacts-v2.md` in allternit-platform.

<Note>
This is a different API from the sectioned [Artifacts API](/api/artifacts) under `/api/v1/artifacts`, which lives on your data-plane node. Artifacts v2 is served by the hosted Cloud API under the separate `/api/v2` prefix.
</Note>

## Base URL

```text
https://api.allternit.com/api/v2
```

## Authentication

Every route except the public link route takes one of:

- a Clerk session JWT (`Authorization: Bearer <jwt>`). This is the only caller that carries an organization, a role and an email;
- an `allternit_*` API token with the `compute` scope (or `*`). A token without it gets `403`;
- a paired device's token (`allternit_runtime_…`, what `gizzi login` stores). It acts as the device's owner, with no organization.

See [Authentication](/api/authentication).

When a create leaves out `body_format`, the kind's default is used. The server also accepts well-formed kinds it doesn't know (lower-case, at most 32 characters) so newer clients keep working. Apps show an unknown kind as a page when the body is HTML and as code otherwise.

`runtime_version` is `2` for current artifacts. `1` marks legacy artifacts imported from the old local stores. A create with `runtime_version: 1` must set `origin.legacy_source`.

## Access

Your access to an artifact is the highest of:

| Source | Access |
| --- | --- |
| You own it | `owner` |
| A share row for your user id, your email (lower-cased) or your organization (a `group` share naming your org id) | the row's `level`: `view`, `comment` or `edit` |
| `visibility: "org"` and you are in the artifact's organization | `view` |
| `visibility: "link"` | `view`, only through the public link route |

If you have no access, every route answers `404`, so it doesn't reveal that the artifact exists. If you can see it but lack the level an action needs, you get `403`.

| Action | Needs |
| --- | --- |
| Read the artifact and its versions | `view` |
| Save a new version, rename, change the icon | `edit` |
| Sharing, `shared_version`, `capabilities`, delete | `owner` |

Viewers and commenters see `shared_version`, or the latest version when it is `null` ("always share latest"). Editors and the owner see every version. An outside email invite counts as accepted the first time its invitee opens the artifact while signed in with that email. From then on it no longer expires.

## List artifacts

```http
GET /api/v2/artifacts?scope=all&kind=page&q=plan&origin=chat&limit=50&cursor=...
```

| Query | Description |
| --- | --- |
| `scope` | `mine`, `shared` (shared with you, or visible to your org), or `all` (default). Link-shared artifacts are never listed for people who don't own them. |
| `kind` | Only this kind. |
| `q` | Case-insensitive title search. |
| `origin` | Only artifacts whose `origin.surface` matches. |
| `limit` | 1–100, default 50. |
| `cursor` | The `next_cursor` from the previous page. |

Returns `{ "items": [ArtifactSummary], "next_cursor": string | null }`, newest `updated_at` first.

## Create an artifact

```http
POST /api/v2/artifacts
{
  "kind": "page",
  "title": "Launch plan",
  "icon": "rocket",
  "body": "<h1>Launch plan</h1>",
  "body_format": "text/html",
  "meta": {},
  "origin": { "surface": "chat", "session_id": "ses_1", "message_id": "msg_9" },
  "capabilities": {}
}
```

Returns `201` with the `Artifact` (version 1). Optional fields: `id`, `icon`, `template_id`, `origin`, `capabilities`, `body_format`, `meta`, `runtime_version`.

- **Idempotent create.** If you send an `id` you already own, you get that artifact back unchanged with `200`. If someone else owns the `id`, you get `409 id_conflict`. Client ids are `art_` followed by letters, digits, `_` or `-`, at most 128 characters. Legacy imports use `art_legacy_<source>_<localId>`.
- **Body limit.** A body can be at most 16 MiB. A larger one gets `413 body_too_large`.
- **Organization.** The artifact belongs to the creator's active Clerk organization, and its sharing follows that organization. If the org has turned artifacts off, the create gets `403 artifacts_disabled`. If the org has turned connectors off, `capabilities.connectors` gets `422 connectors_disabled`.

## Get, update and delete

```http
GET    /api/v2/artifacts/{id}
PATCH  /api/v2/artifacts/{id}   { "title"?, "icon"?, "shared_version"?: number | null, "capabilities"? }
DELETE /api/v2/artifacts/{id}
```

`PATCH` returns the `Artifact`. `title` and `icon` need `edit`. `shared_version` (from 1 to `current_version`, or `null`) and `capabilities` need `owner`. Turning on `ai` or `connectors` for an artifact shared by link gets `422 link_not_allowed`.

`DELETE` is owner-only and **permanent**. There is no trash. Versions, shares and comments are deleted with the artifact. It returns `204`.

## Dashboard body

A `dashboard` artifact's body is JSON with `body_format` `application/vnd.allternit.dashboard+json`. The server stores it like any other body; the apps parse and validate it. A tile that fails validation is skipped and the rest of the dashboard still draws.

```json
{
  "version": 1,
  "refreshSeconds": 300,
  "filters": [
    { "id": "region", "label": "Region", "type": "select",
      "options": [{ "value": "emea", "label": "EMEA" }], "default": "emea" }
  ],
  "tiles": [
    {
      "id": "revenue",
      "title": "Revenue",
      "type": "kpi",
      "layout": { "x": 0, "y": 0, "w": 3, "h": 2 },
      "query": { "tool": "stripe__list_charges", "args": { "region": "{{filters.region}}" } },
      "encoding": { "y": ["total"], "compare": "previous" },
      "format": { "style": "currency", "currency": "USD" }
    }
  ]
}
```

| Field | Meaning |
| --- | --- |
| `version` | Always `1`. A newer number is read as far as possible. |
| `refreshSeconds` | Re-query while the dashboard is open. `0` or missing: only on open. At least 30 when set. |
| `filters[]` | `id` (letters, digits, `_`), `label`, `type` (`select`, `text`, `number`), `options` for `select`, optional `default`. Up to 8. |
| `tiles[]` | Up to 40. |
| `tiles[].type` | `kpi`, `line`, `area`, `bar`, `table`. |
| `tiles[].layout` | A 12-column grid: `x` and `y` (0-based), `w` (1 to 12 columns), `h` (1 to 40 rows of 72 px). Tiles that overlap are laid out in order. Phones stack tiles in one column, in reading order. |
| `tiles[].query.tool` | `<connector>__<tool>`, the name in the user's connector tool list. |
| `tiles[].query.args` | Tool arguments. Strings may contain `{{filters.<id>}}`. |
| `tiles[].query.sql`, `sqlArg` | SQL for a warehouse tool, placed into the argument named by `sqlArg` (default `query`). In SQL a filter becomes a quoted literal, so write `WHERE region = {{filters.region}}`. Only one read-only statement runs. |
| `tiles[].query.rowsPath` | Where the rows sit in the result (for example `data.rows`). Without it, rows are found automatically. |
| `tiles[].encoding` | `x` (column on the x axis), `y` (series columns; for a KPI the first is the number), `compare` (KPI: previous-period column), `columns` (table). |
| `tiles[].format` | `style` (`number`, `compact`, `currency`, `percent`, `text`, `date`), `currency`, `decimals`, `prefix`, `suffix`. |

A tool result is read as a table: an array of objects, `{ "columns": [], "rows": [[]] }`, or JSON or CSV text.

Dashboards run as the viewer: each call goes through the viewer's own connectors, and a tool that is not read-only is refused (a SQL tool is allowed for a single read-only statement). The owner's client sets `capabilities.connectors` to the connectors and tools the tiles call, so `visibility: "link"` is refused for a dashboard (see [Sharing](#sharing)). Dashboards saved before this format, with `application/vnd.allternit.openui`, still open as cards.

Tiles may also use the built-in read tools `allternit__computers_list`, `allternit__computer_get` and `allternit__computer_history`. They read the viewer's own computers and need no connector.

## Ops sheet body

An `ops` artifact's body is JSON with `body_format` `application/vnd.allternit.ops+json`. It watches one running thing. The apps parse it the same forgiving way as a dashboard: a part that fails validation is skipped, and the rest still draws.

```json
{
  "version": 1,
  "refreshSeconds": 30,
  "filters": [],
  "header": {
    "title": "fraud-scorer",
    "query": { "tool": "deploys__get_deployment", "args": {} },
    "fields": { "status": "status", "version": "version", "environment": "environment", "target": "cluster", "startedAt": "started_at" },
    "stepsFrom": "pipeline"
  },
  "actions": [
    { "id": "pause", "label": "Pause", "icon": "pause", "tool": "deploys__pause_rollout", "args": {}, "confirm": "Pause the rollout?", "when": ["running"] }
  ],
  "tabs": [
    { "id": "pipeline", "label": "Pipeline", "panels": [
      { "id": "pipeline", "type": "steps", "query": { "tool": "deploys__list_steps", "args": {} } }
    ] }
  ]
}
```

| Field | Meaning |
| --- | --- |
| `version` | Always `1`. |
| `refreshSeconds` | Re-read while the sheet is open. `0` or missing: only on open. At least 10 when set. |
| `filters[]` | Same as dashboard filters, up to 4. One `select` filter is drawn as a "1 of N" switcher. `{{filters.<id>}}` works in panel and action args. |
| `header.query` | Returns one row: the thing being watched. |
| `header.fields` | Which columns to use for `title`, `id`, `version`, `status`, `environment`, `target`, `progress` (0 to 1 or 0 to 100), `progressLabel` and `startedAt`. Missing names are found by their usual column names. The one exception is `startedAt`, which is read only when named. |
| `header.stepsFrom` | The id of a `steps` panel. The progress bar then has one segment per step. |
| `actions[]` | Up to 4. `label`, `icon` (`pause`, `play`, `rollback`, `restart`, `stop`, `retry`, `promote`, `run`), `tool`, `args`, `confirm` (shown when the viewer approves), `when` (header statuses that show the button), `danger`. `rollback` and `stop` are always drawn as dangerous. |
| `tabs[]` | Up to 8: `id`, `label`, `panels`, optional `countFrom` (a panel id whose row count shows on the tab). |
| `panels[].type` | `steps` (name, status, duration, detail, progress), `logs` (time, level, source, message), `stats` (one row, `fields` with `label`, `format`, `baseline`, `limit`), `fields` (one row, `fields` with `label` and `mono`), `line`, `area`, `bar` (`encoding.x`, `encoding.y`, optional `limit` and `limitLabel`), `table` (`encoding.columns`). Up to 24 panels in all. Ids are unique across the sheet. |
| `panels[].query` | Same as a dashboard tile's query. |

Reads run like dashboard tiles: as the viewer, through the viewer's connectors, and read-only tools only. Action tools run only from their button, and the viewer approves every call. On save the server sets `capabilities.connectors` to every tool the body reads or acts with, so `visibility: "link"` is refused.

## Versions

```http
GET  /api/v2/artifacts/{id}/versions          # { items: [{version, author_id, created_at, size_bytes, meta}] }, newest first
GET  /api/v2/artifacts/{id}/versions/{v}      # {artifact_id, version, body, body_format, meta, size_bytes, sha256, author_id, created_at}
POST /api/v2/artifacts/{id}/versions
{ "base_version": 3, "body": "...", "body_format"?: "...", "meta"?: {}, "author"?: "user" | "assistant" }
```

Appending needs `edit` and returns `201` with the `Artifact`. `body_format` defaults to the previous version's. If `base_version` is not the current version, the server answers:

```json
HTTP/1.1 409 Conflict
{ "error": "stale_version", "code": "stale_version", "message": "...", "current_version": 4 }
```

Fetch version 4, merge your change onto it, and append again with `base_version: 4`. Viewers only see the shared version, so asking them for any other version gets `404`.

## Sharing

```http
GET /api/v2/artifacts/{id}/sharing
PUT /api/v2/artifacts/{id}/sharing
{
  "visibility": "people",
  "shares": [
    { "principal_type": "user",  "principal_id": "user_2abc", "level": "edit" },
    { "principal_type": "email", "principal_id": "pat@example.com", "level": "view" },
    { "principal_type": "group", "principal_id": "org_2xyz", "level": "comment" }
  ]
}
```

Both routes are owner-only. `PUT` replaces the whole share list. Rows you leave out are removed, and rows you keep only change level. Both return a `Sharing` object:

```json
{
  "visibility": "link",
  "shares": [{ "principal_type": "email", "principal_id": "pat@example.com", "level": "view",
               "display": "pat@example.com", "expires_at": "2026-11-07T…Z", "accepted_at": null }],
  "link_url": "https://ai.allternit.com/a/art_01J…",
  "policy": { "link_allowed": true, "outside_invites_allowed": true }
}
```

`link_url` appears only when `visibility` is `link`. `policy.reason` explains why links are not allowed. The server sets the link base from `ARTIFACTS_PUBLIC_BASE_URL` (default `https://ai.allternit.com/a`).

### Sharing rules

All of these failures return `422` with the `code` shown.

| Rule | Code |
| --- | --- |
| `visibility` must be `private`, `people`, `org` or `link`. | `invalid_visibility` |
| `private` carries no shares. Use `people` for specific people. | `private_has_no_shares` |
| `org` needs an artifact that was created in an organization. | `org_required` |
| `link` is refused when `capabilities.ai` or `capabilities.connectors` is set. It is also refused when the org has `external_sharing` off and the artifact isn't in its `allowed_external` list. Personal accounts may use links. | `link_not_allowed` |
| `email` principals are outside invites. They need the org to allow them (personal accounts may always invite). Each invite expires 30 days after it is sent unless it is accepted. | `outside_invites_not_allowed` |
| At most 50 outside invites per artifact. | `too_many_outside_invites` |
| A `doc` can only be shared with `view` or `edit`. | `doc_level_not_allowed` |
| A `doc` can't have `email` principals. | `doc_email_not_allowed` |
| A `doc` can only be shared by link when the org has `external_sharing` on. The per-artifact `allowed_external` list doesn't apply to docs. | `link_not_allowed` |
| `principal_type` must be `user`, `email` or `group`. `level` must be `view`, `comment` or `edit`. | `invalid_share` |

The owner always has access, so a share naming the owner is dropped. If the same principal is listed twice, the higher level is kept.

## Public link

```http
GET /api/v2/public/artifacts/{id}     # no auth
```

This route returns `{id, kind, title, icon, body, body_format, meta, version, updated_at, runtime_version, owner_name}`. It works only while `visibility` is `link` and the policy still allows links. If an org turns off external sharing or artifacts, its links stop working at once. Viewers get `shared_version`, or the latest version when it is `null`. Every other case answers `404`. Responses carry `Cache-Control: private, no-store` and `X-Robots-Tag: noindex`.

## Organization settings

```http
GET /api/v2/org/artifact-settings
PUT /api/v2/org/artifact-settings
{ "external_sharing": true, "allowed_external": ["art_01J…"] }
```

| Field | Default | Effect |
| --- | --- | --- |
| `enabled` | `true` | When off, members can't create artifacts and the org's public links close. |
| `templates` | `{}` | `{kind: bool}`. A missing kind uses the plan default. |
| `external_sharing` | `false` | Allows link sharing. |
| `outside_invites` | `false` | Allows `email` invites to people outside the org. |
| `presence` | `true` | Shows who else is viewing. |
| `connectors` | `true` | When off, artifacts can't declare `capabilities.connectors` and pages can't call connectors. |
| `allowed_external` | `[]` | Artifact ids individually allowed to be shared by link (not docs). |

`GET` returns the settings for your active organization, plus `org_id`, `updated_by`, `updated_at` and `can_edit`. Personal accounts get the defaults with `org_id: null`. `PUT` changes only the fields you send. It needs the Clerk organization role `admin` (or `org:admin`). Everyone else gets `403`.

Admins can list what the org has shared outside with `GET /api/v2/org/artifact-shared-outside`. It returns `{items: [{id, title, kind, owner_id, owner_name, by_link, outside_invites, allowed, updated_at}]}` for artifacts that are public by link or have email invites, and needs the same admin role. `allowed` is whether the artifact is in `allowed_external`.

## Comments

Comments are threaded: a root comment plus replies one level deep. They are stored in `artifact_comments`.

| Method and path | Needs | Body | Returns |
|---|---|---|---|
| `GET /api/v2/artifacts/:id/comments` | view | | `{ items }`, oldest first, at most 500 |
| `POST /api/v2/artifacts/:id/comments` | comment | `{ body, anchor?, parent_id?, version?, agent_name? }` | the comment, `201` |
| `PATCH /api/v2/artifacts/:id/comments/:cid` | edit, or the author | `{ resolved? , body? }` | the comment |
| `DELETE /api/v2/artifacts/:id/comments/:cid` | the author or the owner | | `204`. Deleting a root deletes its replies. |
| `POST /api/v2/artifacts/:id/comments/assistant-reply` | edit | `{ parent_id, body }` | the reply, `201`, with `author_id: "assistant"` |

A comment has `id`, `artifact_id`, `version`, `anchor`, `parent_id`, `author_id`, `author_name`, `author_image_url`, `agent_name`, `body`, `to_assistant`, `resolved_at` and `created_at`. `body` is 1 to 4000 characters. `anchor` is an opaque object up to 16 KB; the app writes `{ kind: "text" | "cell" | "slide" | "element", ... }`. A comment that mentions `@gizzi` or `@allternit` is stored with `to_assistant: true`.

**Comment anchors.** The server stores `anchor` exactly as sent, every field kept, so the app can add fields without a server change. It checks only that it is an object up to 16 KB whose `kind`, when present, is `text`, `cell`, `slide` or `element`. On a Design canvas a comment pinned to a frame or layer uses the `element` kind:

```json
{ "kind": "element", "shapeId": "shape:title", "artboard": "shape:hero", "label": "Title" }
```

- `shapeId` is the layer's shape id, or the artboard's own id when the comment is about the whole frame (`shapeId` equals `artboard`).
- `artboard` is the artboard's shape id and `label` the name shown in the thread. When present, `shapeId`, `artboard` and `label` must be strings of at most 200 characters, otherwise `400`.
- The app draws a numbered pin for each open thread anchored on the canvas, at the layer's top-right corner (or the frame's, for a frame anchor). Resolved threads hide their pin. A reply inherits its root's anchor.
- A comment posted with `agent_name` (an agent's question pinned to a frame) has a smaller limit: its `anchor` is at most 4 KB. Docs have no Commenter level, so a viewer of a doc can't comment.

An agent posts under its own name by sending `agent_name` (gizzi's `artifact_comment` does this). The comment is then stored with `author_id: "assistant"` and that `agent_name`, and `author_name` comes back as the agent name. On every read, `author_name` falls back to `agent_name` when the author has no profile name. `agent_name` is `null` for comments people write.

## Presence

Presence is shared by every Cloud API instance. Each heartbeat upserts one row per artifact and user in `artifact_presence` (migration `086_artifact_presence.sql`); the table holds only the current state and is not a viewing history.

| Method and path | Needs | Body | Returns |
|---|---|---|---|
| `POST /api/v2/artifacts/:id/presence` | view (edit with `agent`) | `{ state: "viewing" \| "editing" \| "left", agent? }` | `204` |
| `GET /api/v2/artifacts/:id/presence` | view | | `{ enabled, users: [{ user_id, name, image_url, state, kind, task, anchor, cost_usd, session_id }] }`, without you |

Send a heartbeat about every 15 seconds. `GET` returns the entries seen in the last 45 seconds, up to 200, ordered by `user_id`. `left` deletes the caller's entry. Entries older than 10 minutes are deleted as a side effect of about one request in 50. When the owner's organization turned presence off, `GET` returns `{ enabled: false, users: [] }` and a person's `POST` does nothing. Agent frame claims still work then (see [frame claims](#frame-claims)).

### Agent presence

An agent working on the artifact for the caller sends `agent: { name, session_id?, task?, anchor?, cost_usd? }` with the heartbeat. This needs edit access. The row is then the agent's own, not the caller's:

- `user_id` is `agent:<session_id or none>:<slug of name>`, and `kind` is `"agent"` (people are `"user"`).
- The row stores `name`, `task` (at most 200 characters), `anchor` (at most 4 KB of JSON), `cost_usd` and `session_id`.
- `state` works as for people. `left` deletes that agent's row.

`anchor` says where the agent is working, in the same location fields a suggestion uses: `{ "kind": "block", "block": 3 }` for a doc block (0-based), `{ "kind": "cell", "sheet": null, "address": "B4" }` for a sheet cell, or `{ "kind": "artboard", "artboard": "shape:hero" }` for a frame of a design canvas. The app draws the agent's cursor or frame tag there. `cost_usd` is the agent session's model cost so far, or absent when unknown. For people, `kind` is `"user"` and the agent fields are `null`.

### Frame claims

On a design canvas, an agent claims an artboard before it changes it, so two agents never change the same frame. A claim is an agent presence heartbeat whose `anchor` has an `artboard` id. There is no separate claims table.

- **Claim.** `POST /presence` with `agent.anchor.artboard` set. If another live agent session holds that artboard, the reply is `409`, and nothing is written:

  ```json
  { "error": "artboard_claimed", "code": "artboard_claimed", "message": "Oki is working on that artboard; pick another one or wait",
    "holder": { "name": "Oki", "session_id": "ses_..." } }
  ```

  "Another live agent session" means an agent row other than the caller's own, seen in the last 45 seconds, whose `session_id` differs (or any other agent row when the caller sends no `session_id`). It can belong to another person's agent on a shared design. Otherwise the heartbeat upserts as usual. The check and the write run under one lock per artboard, so two agents claiming at once can't both win.
- **Keep it.** Each heartbeat from the holder keeps the claim. It lasts as long as the heartbeats do (the 45-second TTL).
- **Release.** A heartbeat with `anchor: null` (or without an artboard), or `state: "left"`, releases it. A claim whose heartbeats stop lapses after 45 seconds.
- An agent row holds one frame at a time: claiming another frame moves the claim.
- **Presence turned off.** Claims hold even when the owner's organization turned presence off, so agents still never change the same frame. The server writes and checks agent claim rows as usual, and a heartbeat that claims nothing deletes the agent's row instead of storing it. `GET /presence` still returns `{ enabled: false, users: [] }`, so nobody sees the claims, but a second agent's claim or artboard suggestion still gets `409 artboard_claimed`.
- Artboard ids compare without tldraw's `shape:` prefix, so `hero` and `shape:hero` are the same frame. `anchor.artboard` must be a string of 1 to 200 characters, otherwise `400`.

## Suggestions

Agents propose edits to doc and sheet artifacts, and frame changes to design canvases, as pending suggestions instead of writing a new version. The user accepts or rejects each one. Suggestions are stored in `artifact_suggestions` (migration `098_artifact_agent_watch.sql`).

| Method and path | Needs | Body | Returns |
|---|---|---|---|
| `POST /api/v2/artifacts/:id/suggestions` | edit | `{ base_version, agent_name, session_id?, cost_usd?, changes: [{ change, reason? }] }` | `{ items }` |
| `GET /api/v2/artifacts/:id/suggestions?status=pending\|all` | view | | `{ items }`, oldest first. `status` defaults to `pending`. |
| `PATCH /api/v2/artifacts/:id/suggestions/:sid` | edit | `{ status: "accepted" \| "rejected" \| "stale" }` | the suggestion. `409 already_resolved` unless it is pending. |
| `POST /api/v2/artifacts/:id/suggestions/resolve` | edit | `{ ids: [...], status }` | `{ items }`, the ones it changed |

A suggestion is `{ id, artifact_id, base_version, agent_name, session_id, change, reason, cost_usd, status, created_at, resolved_at }`. `id` starts with `sug_`. `cost_usd` is a number or `null`. `status` is `pending`, `accepted`, `rejected` or `stale`. Resolving one sets `resolved_by` and `resolved_at`.

`change` is one of four shapes:

| kind | Shape | Meaning |
|---|---|---|
| `text` | `{ "kind": "text", "block": 2, "find": "about 40%", "replace": "38%" }` | Replace the first occurrence of `find` in the plain text of block `block` (0-based index into `doc.blocks`). `block: null` searches the whole document, block by block. |
| `block` | `{ "kind": "block", "op": "replace" \| "insert_after" \| "delete", "block": 4, "markdown": "..." }` | `markdown` becomes blocks the same way the editor converts markdown. `delete` ignores `markdown`. |
| `cell` | `{ "kind": "cell", "sheet": null, "address": "B4", "value": "Nov 10" }` | Set one cell. `sheet` is a sheet name or id; `null` means the first sheet. A `value` starting with `=` is a formula. |
| `artboard` | see below | One agent turn on one frame of a design canvas: the frame's full new layer list, plus what it replaces. |

Which artifact takes which kind:

| Artifact | Change kinds |
|---|---|
| `doc` | `text`, `block` |
| `sheet` | `cell` |
| `design` whose current body format is `application/vnd.allternit.design+json` | `artboard` |

Any other pair, including an HTML design (`text/html`), is `400 unsupported_kind`.

### Artboard changes

```json
{
  "kind": "artboard",
  "artboard": "shape:hero",
  "name": "Hero",
  "frame": { "fill": "#0b0b0f" },
  "layers": [ { "id": "shape:title", "type": "text", "name": "Title", "artboard": "shape:hero",
                "x": 96, "y": 120, "w": 800, "h": 80, "props": { "text": "Plan your week", "color": "white" } } ],
  "before": { "frame": { "fill": "#ffffff" }, "layers": [ { "id": "shape:title", "...": "..." } ] }
}
```

- `artboard` is the artboard's id, and `name` its name (optional, for display).
- `layers` is the artboard's **full** new layer list in stacking order (first at the bottom), as `CanvasLayer` objects from the design body format. Every layer's `artboard` must equal `artboard`, layer ids are unique in the list, and they must not be used by layers on other artboards (`422 layer_id_in_use`). Layers are stored as sent.
- `frame` optionally patches the artboard: `fill` (string), `w` and `h` (1 to 100,000) and `props` (object). Other fields are dropped. Left out, the artboard is unchanged.
- `before` is `{ frame?, layers }`: the artboard as the agent read it. gizzi fills it from the body.
- The artboard must exist in the current body (`422 unknown_artboard`). A body that isn't a v2 canvas yet isn't checked.
- Limits: `layers` and `before` at most 2 MB of JSON each, and at most 2000 layers each, otherwise `400 change_too_large`. A request is at most 16 MB.
- While another live agent session holds the artboard (see [frame claims](#frame-claims)), the `POST` is refused with `409 artboard_claimed` and the same `holder`. The holder's own session, and anyone when no one holds the frame, can suggest.
- `controls` (optional) adds generated sliders to the change; see [controls](#controls).

### Controls

An artboard change can carry `controls`: sliders, colour pickers and selects the user moves on the frame card before keeping the change. An agent sends them when the user is tuning something (spacing, radius, colour, density) instead of guessing one value.

```json
"controls": [
  { "id": "radius", "label": "Corner radius", "type": "range", "layer": "shape:card", "prop": "radius", "min": 0, "max": 32, "step": 1, "value": 12 },
  { "id": "accent", "label": "Accent", "type": "color", "layer": "shape:cta", "prop": "fill", "value": "#6366f1" },
  { "id": "density", "label": "Density", "type": "select", "layer": null, "prop": "frame.padding", "options": ["compact", "cozy"], "value": "cozy" }
]
```

| Field | Rule |
|---|---|
| `id` | 1 to 64 characters, unique in the change |
| `label` | 1 to 200 characters, shown on the card |
| `type` | `range`, `color` or `select` |
| `layer` | the id of a layer in the change's `layers` (with or without `shape:`), or `null` (or left out) for the artboard itself |
| `prop` | a key in the layer's `props`, or `x`, `y`, `w`, `h`. A `frame.` prefix (`frame.padding`) targets the artboard's props and needs `layer: null` |
| `range` | finite numbers `min` less than `max`, optional `step` greater than 0 and at most `max - min`, and a numeric `value` from `min` to `max` |
| `color` | a non-empty colour string `value` (at most 200 characters) |
| `select` | 1 to 50 non-empty string `options`, and a `value` that is one of them |

- At most 12 controls and 64 KB of JSON per change. An empty list stores no controls.
- Any problem is `400` with code `bad_controls` and a message naming the control. Unknown fields are dropped.
- A controls-only change is fine: `layers` equal to `before.layers`, plus `controls`.
- **The client applies controls.** Moving one rewrites the previewed after state live (`applyControl(change, controlId, value)` in the app). **Keep** saves the tweaked state as the new version and records the final values in that version's `meta`. The stored suggestion keeps the values the agent sent.

**Applying is pure and client side.** Remove every layer whose `artboard` is the change's artboard, insert `layers` where the first removed one sat (or at the end when there were none), and patch the artboard with `frame`. The change is **stale** when the artboard no longer exists. While a change is pending the canvas shows the after state, marked "In review". **Keep** saves a version with it and marks it `accepted`; **Undo** restores `before` and marks it `rejected`. A kept change can still be undone for 24 hours if the artboard still matches its `layers`.

Limits: at most 50 changes per `POST`; `find`, `replace`, `markdown` and `value` at most 20,000 characters each; `reason` at most 500. The artifact must be a `doc`, a `sheet` or a design canvas, otherwise `400 unsupported_kind`.

**The client applies accepted changes, not the server.** To accept, the app applies the change to the current body, saves a new version (author the user, with `meta.note`), then sends `PATCH` with `accepted`. When a change no longer applies to the body (the text or cell moved on), the app marks it `stale`. **Accept all** applies the pending suggestions in order, saves one version, and resolves them with one `POST .../resolve`. The server never rewrites a body.

## Library archive

`GET /api/v2/artifacts` accepts `archived=true` for the caller's archive.
Omitted or `false` returns saved work. This filter combines with scope, kind, title search, origin and cursor pagination.
Updated servers include `archive_supported: true` in the list response.

```http
PUT /api/v2/artifacts/:id/library
Content-Type: application/json

{"archived": true}
```

Send `false` to restore. Success returns `204 No Content`; repeated writes are idempotent.
The caller must have at least view access. The server derives the user from authentication and rejects extra request fields.
Missing or inaccessible artifacts return `404`; invalid request bodies return `400`.

Archive is private library metadata per viewer. It does not change the artifact body, versions, updated time, ownership, grants or public link.
Access checks still apply to archived lists. Deleting the artifact also deletes its library metadata.

Deploy the Cloud API with Postgres migration `109_artifact_library_archive.sql` before releasing archive clients.
Clients must not interpret an older server's unfiltered list as an archive.
