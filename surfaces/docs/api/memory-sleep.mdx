---
title: Memory Sleep API
description: "Routes for Allternit Sleep: status, cycles, runtime signals, topic pages, disputes, settings and thresholds. Every stage is off by default; the orchestrator runs cycles once you turn it on."
---

Allternit Sleep is memory consolidation that runs on your own computer while you are
not using it. When a session goes idle, before a conversation is compacted, or when a
session ends, the runtime tells Sleep. Sleep then sorts new memories, keeps
contradicting memories as disputes instead of silently picking one, and builds short
topic pages the model can load at the start of a chat. Every page claim keeps a pointer
back to where it came from. Sleep uses your own model quota, up to a daily cap you set,
and you can undo a cycle.

These routes are served by the Allternit API under `/api/v1`, next to the
[Memory API](/api/memory) and the [Memory Drive API](/api/memory-drive). They use the
normal signed-in session; a request with no user gets `401`.

<Note>
Every stage is off by default. The `orchestrator` stage (cycles from the unit queue)
runs once you turn it on; the other stages are still contract only. Read routes return real empty states, never
`501`. Write routes that need a later stage check their input, then refuse (see
[Refused writes](#refused-writes)). The status column below says which stage makes each
route live.
</Note>

## Routes

| Route | Status | What it does |
| --- | --- | --- |
| `GET /memory/sleep/status` | Live | Master switch, stage flags, debt, last cycle, spend today, manifest, open disputes. |
| `GET /memory/sleep/cycles` | Live (empty until the orchestrator stage runs a cycle) | Recent cycles, newest first. |
| `GET /memory/sleep/cycles/:id` | Live (empty until the orchestrator stage runs a cycle) | One cycle and its report. |
| `POST /memory/sleep/cycles/:id/undo` | Refuses until the orchestrator | Undo a cycle. |
| `POST /memory/sleep/run` | Live with the orchestrator stage on; otherwise refuses | Queue a nap or daydream now. |
| `POST /memory/sleep/signal` | Live with the orchestrator stage on; otherwise refuses | Runtime trigger: idle, pre-compact, session end, resume. |
| `GET /memory/sleep/context` | Live (empty until the router) | What the runtime puts in front of the model at session start. |
| `POST /memory/sleep/pages/load` | Refuses until the router | Load one topic page mid-session. |
| `GET /memory/sleep/pages` | Live (empty until pages) | Page versions. |
| `GET /memory/sleep/pages/:topic` | Live (empty until pages) | One topic's versions and claims with their sources. |
| `GET /memory/disputes` | Live (empty until disputes) | Contradicting memories. |
| `POST /memory/disputes/:id/resolve` | Refuses until disputes | Pick a side. |
| `GET /memory/sleep/settings`, `PUT /memory/sleep/settings` | Live | Master switch, stage flags and the daily spend cap. |
| `GET /memory/sleep/config`, `PUT /memory/sleep/config` | Live | Thresholds, each with its source. |

## Errors

| Status | Meaning |
| --- | --- |
| 400 | Invalid input, for example an unknown stage, an unknown config key, or a value out of range. Nothing is written. |
| 401 | Not signed in. |
| 404 | No such cycle, topic or dispute for you. |
| 409 | A refused write: the stage it needs is off or not built yet. |
| 422 | The JSON body has the wrong shape or an unknown field. |

### Refused writes

`run` (with the orchestrator stage off, or for `deep` and `rem`), `cycles/:id/undo`,
`pages/load` and `disputes/:id/resolve` answer `409`.
`signal` answers `200`, because the runtime sends it on every idle, compaction and
session end, whether Sleep is on or not.

```json
{ "accepted": false, "reason": "sleep_disabled", "stage": "orchestrator",
  "error": "Sleep is off (stage `orchestrator`). Turn it on in Memory settings." }
```

| `reason` | Meaning |
| --- | --- |
| `sleep_disabled` | The master switch or that stage's flag is off. |
| `stage_not_built` | The flags are on, but this version does not have that stage yet. |

## Status

### `GET /memory/sleep/status`

```json
{
  "available": true,
  "enabled": false,
  "stages": {
    "checks": false, "disputes": false, "intentions": false, "labels_live": false,
    "orchestrator": false, "pages": false, "rem": false, "router": false,
    "strengths": false, "track1": false
  },
  "debt": 0,
  "last_cycle": null,
  "spend_today_usd": 0,
  "daily_spend_cap_usd": 0,
  "manifest_id": null,
  "open_disputes": 0,
  "tracks": { "track1": "off", "track2": "off" }
}
```

- `enabled` is the master switch. A stage runs only when `enabled` and its own flag are both `true`.
- `stages` holds each stage's own flag.
- `debt` is sleep debt: memories added since your last finished nap (at most the last 7 days), divided by `debt_scale`. See [How a cycle runs](#how-a-cycle-runs).
- `last_cycle` is the newest cycle row and `spend_today_usd` the sum of today's cycle spend.
- `tracks.track2` (pages) is `on` when `enabled` and `stages.pages` are both on. `tracks.track1` (personal adapters) is the same for `stages.track1`.

## Cycles

### `GET /memory/sleep/cycles?limit=`

`limit` is 1 to 200, default 50.

```json
{ "cycles": [
  { "id": "cyc_1", "trigger": "idle", "kind": "nap", "state": "finished", "stage": null,
    "session_id": "s_123", "spend_usd": 0.04, "manifest_before": "man_0", "manifest_after": "man_1",
    "started_at": "2026-11-20 03:10:00", "finished_at": "2026-11-20 03:12:41", "undone_at": null }
], "count": 1 }
```

| Field | Values |
| --- | --- |
| `trigger` | `idle`, `pre_compact`, `session_end`, `manual`, `clock` |
| `kind` | `daydream`, `nap`, `deep`, `rem` |
| `state` | `running`, `finished`, `stopped`, `failed`, `undone` |
| `stage` | The stage running now, or the last one that ran: `capture`, `consolidation`, `fit`, `dream`, `curation`, `pages`, `checks`, `sign` |

### `GET /memory/sleep/cycles/:id`

`{ "cycle": { ... }, "report": { ... } | null }`, with the same cycle fields as the list.

### `POST /memory/sleep/cycles/:id/undo`

No body. Returns `404` for an unknown cycle. Once live, undo restores the manifest from
before the cycle.

### `POST /memory/sleep/run`

Optional body `{ "kind": "nap" }`, where `kind` is `daydream`, `nap`, `deep` or `rem`.
Leave it out for a `nap`. With the `orchestrator` stage on, a `nap` or `daydream` is
queued and the worker runs it within `worker_poll_s` seconds:

```json
{ "accepted": true, "kind": "nap", "queued": ["<unit id>"] }
```

It answers `202`. `queued` is empty when a manual run of that kind is already waiting
or running. `deep` and `rem` answer `409` with `reason: "stage_not_built"`.

### `POST /memory/sleep/signal`

Sent by the runtime, never by a person.

```json
{ "session_id": "s_123", "event": "idle", "cache_ttl_s": 300 }
```

| `event` | When the runtime sends it |
| --- | --- |
| `idle` | The session has been idle for the provider's cache time, so the prompt cache has already expired. |
| `pre_compact` | Just before the conversation is compacted. |
| `session_end` | The session ended. It only queues work. |
| `resume` | You came back. Any running cycle stops cleanly. |

`session_id` is required. `cache_ttl_s` is optional and must be above 0.

With the `orchestrator` stage on, a signal writes units to the queue and answers:

```json
{ "accepted": true, "event": "idle", "queued": ["<unit id>"], "cancelled": [] }
```

| `event` | What it does |
| --- | --- |
| `idle` | Queues one `nap`. If you raise `nap_after_ttl_multiple` above 1.0 the first idle queues a `daydream` (a light pass) instead. |
| `pre_compact` | Records a `capture` unit (scratch values and unsaved high-attention items must be captured), then queues a `nap`. It answers `200` fast and never blocks compaction; an internal error is logged and answers `queued: []`. |
| `session_end` | Queues a `nap`. No immediate work. |
| `resume` | Cancels this session's `queued` daydream and nap units (`cancelled` lists them). A unit already `leased` gets `stop_requested: true` in its payload, and its cycle stops cleanly after the stage that is running; the rest is held and the session's next signal continues it. |

There is at most one open (`queued` or `leased`) unit per session and kind, so a repeated
signal never queues twice. With the stage off the signal is refused as shown above and
nothing is written. `nap_after_ttl_multiple` (default 1.0) is in the thresholds list.

## How a cycle runs

With `enabled` and `stages.orchestrator` on, one background worker in the Allternit
API takes queued `daydream` and `nap` units one at a time (one per user at once) and
runs each as a cycle. Nothing is scheduled by launchd or cron.

A nap runs these stages in this order. A daydream runs the first two only.

| # | Stage | Runs when | Spends quota |
| --- | --- | --- | --- |
| 1 | `capture` | Always. Marks your queued `capture` units done and records what they asked for. | No |
| 2 | `consolidation` | Always. Merges duplicate memories (the same job as the consolidation clock). | No |
| 2b | `fit` | `stages.strengths` is on. Fits the decay half-life from your labelled recalls. | No |
| 3 | `dream` | Dream is on for your drive and today's Dream has not finished. | Yes |
| 4 | `curation` | A bot's weekly memory curation is due. | Yes |
| 5 | `pages` | Not built yet. Recorded as skipped. | - |
| 6 | `checks` | Not built yet. Recorded as skipped. | - |
| 7 | `sign` | Not built yet. Recorded as skipped. | - |

The cycle's `report` lists each stage with `status` (`done` or `skipped`), a `note`
(for example `not_due`, `spend_cap`, `stage_off: strengths`), `spend_usd` and the job's
own result.

- **Daily spend cap.** A spending stage runs only when `daily_spend_cap_usd` is above 0
  and today's spend plus the stage's estimate (`dream_cost_estimate_usd`,
  `curation_cost_estimate_usd`) fits under it. Otherwise it is skipped with
  `spend_cap`. With the default cap of 0, no stage spends quota and the others still run.
- **Clean stop.** A `resume` signal stops the cycle after the stage that is running. The
  cycle ends `stopped` and the remaining stages wait as a `held` unit; the session's next
  signal queues it again and the next cycle starts from the next stage. The per-cycle stop
  rule (`cycle_max_stages`, `cycle_max_minutes`) stops a cycle the same way.
- **Failures.** A stage error ends the cycle `failed` and counts one attempt. After
  `unit_max_attempts` failures (or expired leases) the unit is `deferred`: it is not
  retried until your next cycle opens, then it gets fresh attempts.
- **Sleep debt.** While `debt` is at or above `debt_pause_threshold`, consolidation
  skips its decay step, so nothing fades while a nap is overdue.
- **The old clocks.** The consolidation tick, the nightly Dream and the weekly bot
  curation still run on their own for users with the orchestrator off, exactly as
  before. With it on, they only queue a `nap` (session `clock`, at most one waiting)
  and the cycle runs the job.

Unit states in `sleep_units`: `queued`, `leased`, `done`, `cancelled`, `deferred`
(failed `unit_max_attempts` times this cycle) and `held` (the rest of a stopped cycle,
with `resume_from_stage` in its payload).

## Context and pages

### `GET /memory/sleep/context?session_id=&model=`

```json
{
  "available": true, "enabled": false,
  "core": null, "index": [], "pages": [],
  "overlay": [], "disputes": [], "intentions": [],
  "budget": { "share": 0.05, "tokens": null },
  "manifest_id": null, "signature": null
}
```

- `enabled` is the router stage.
- `overlay` holds your corrections that are not applied to a page yet. Each one is `{ id, topic_id, claim_id, correction, as_of }`.
- `disputes` holds the open disputes, in the same shape as `GET /memory/disputes`.
- `intentions` holds open reminders: `{ id, content, cue_kind, cue, due_at }`.
- `budget.share` is the share of the model's context window pages may use.

### `POST /memory/sleep/pages/load`

```json
{ "topic_id": "top_42", "session_id": "s_123", "model": "claude-sonnet" }
```

`topic_id` is required. Once live, it returns the page and records a router miss.

### `GET /memory/sleep/pages?limit=`

```json
{ "pages": [
  { "id": "pg_1", "topic_id": "top_42", "version": 3, "sha256": "9f2c…", "manifest_id": "man_1",
    "provenance_tier": "user", "tokens": 410, "created_at": "2026-11-20 03:12:40" }
], "count": 1, "manifest_id": "man_1" }
```

A page's text is stored once per `sha256`. The manifest is signed, and the runtime
checks the hash and the signature every time it loads a page.

### `GET /memory/sleep/pages/:topic`

```json
{
  "topic": { "id": "top_42", "name": "Acme launch", "state": "active" },
  "versions": [ { "id": "pg_1", "version": 3, "sha256": "9f2c…" } ],
  "claims": [
    { "id": "cl_7", "claim": "Launch moved to March 3.", "source_type": "user_said",
      "observation_id": "obs_88", "fact_id": null, "as_of": "2026-11-18", "superseded_by": null }
  ]
}
```

Topic `state` is `active`, `weak`, `gist` or `untethered`. An untethered topic is
left out of the index but can still be loaded directly.

### Source types

Every claim, and every fact Sleep scores, carries a `source_type`:

| `source_type` | Meaning |
| --- | --- |
| `user_said` | You said it. |
| `tool_observed` | A tool or web result showed it. It never goes into a page without your confirmation. |
| `model_inferred` | The model concluded it. |
| `dream_generated` | A Sleep cycle proposed it. It is kept only if it improves a score. |
| `imported` | It came from an import. |

A claim must point back to an observation or a fact. A claim without that pointer is refused.

## Disputes

### `GET /memory/disputes?state=&limit=`

`state` is `open`, `needs_user` or `resolved`. Leave it out to get all of them.

```json
{ "disputes": [
  { "id": "dsp_3", "topic_id": "top_42",
    "side_a": { "kind": "fact", "id": "f_1" }, "side_b": { "kind": "fact", "id": "f_9" },
    "scope": "work", "stakes": 0.8, "margin": 0.05, "pick": null, "reason": null,
    "state": "needs_user", "created_at": "2026-11-20 03:11:02" }
], "count": 1 }
```

`needs_user` means the two sides were close and the stakes were high, so Sleep asks
you instead of picking.

### `POST /memory/disputes/:id/resolve`

```json
{ "choice": "both_scoped", "reason": "Home address vs. office address" }
```

`choice` is `a`, `b`, `both_scoped` (both are true in different scopes) or `neither`.
Returns `404` for an unknown dispute.

## Settings and thresholds

Every value has a default in code. Your own value overrides it. Each value reports its
`source`:

| `source` | Set by |
| --- | --- |
| `default` | The code default. |
| `fitted` | Fitted from your own recall logs. |
| `owner` | You, through `PUT /memory/sleep/settings` or `PUT /memory/sleep/config`. |

### `GET /memory/sleep/settings`

```json
{
  "enabled": false,
  "stages": { "pages": false, "router": false, "...": false },
  "daily_spend_cap_usd": 0,
  "entries": {
    "enabled": { "value": false, "source": "default", "default": false, "updated_at": null,
                 "group": "setting", "about": "Master switch for Sleep." },
    "stage.pages": { "value": false, "source": "default", "...": "..." },
    "daily_spend_cap_usd": { "value": 0, "source": "default", "...": "..." }
  }
}
```

The daily spend cap defaults to `0`, which means Sleep spends nothing.

### `PUT /memory/sleep/settings`

Send only the fields you change. Returns the same object as `GET`.

```json
{ "enabled": true, "stages": { "pages": true }, "daily_spend_cap_usd": 0.5 }
```

Stage names are `labels_live`, `strengths`, `pages`, `router`, `orchestrator`,
`disputes`, `checks`, `intentions`, `rem` and `track1`. An unknown stage or a cap outside
0 to 1000 returns `400`, and nothing is written.

`labels_live` works now. When it and `enabled` are both on, each assistant reply sent to
`POST /memory/retain` labels the session's most recent recall from the last 30 minutes. The
recall's `memory_recall_logs` row gets `label_used`, a JSON array of the result ids the reply
used (every other id in `results` counts as unused), plus `label_source` set to `answer` and
`labeled_at`. A recall is labelled only once. With the flag off, nothing is written.

### `GET /memory/sleep/config`

`{ "values": { "<key>": { "value", "source", "default", "updated_at", "group", "about" } } }`

| Key | Default | Meaning |
| --- | --- | --- |
| `idle_ttl_s` | 300 | Idle seconds before a nap. The runtime sends its real cache time. |
| `nap_after_ttl_multiple` | 1.0 | An idle signal starts a nap once the session has been idle this many times the cache time; below that it starts a daydream. |
| `unit_max_attempts` | 3 | Attempts before a unit of work moves to the next cycle. |
| `unit_lease_s` | 900 | Lease length for a running unit. |
| `worker_poll_s` | 30 | Seconds between the Sleep worker's checks of the queue (global row only). |
| `cycle_max_stages` | 8 | Per-cycle stop rule: most stages one cycle runs. The rest waits for the next signal. |
| `cycle_max_minutes` | 30 | Per-cycle stop rule: no new stage starts after this many minutes. |
| `dream_cost_estimate_usd` | 0.05 | Spend charged against the daily cap for one Dream. |
| `curation_cost_estimate_usd` | 0.05 | Spend charged against the daily cap for one weekly curation. |
| `debt_scale` | 50 | New memories since the last finished nap that make 1.0 of sleep debt. |
| `debt_pause_threshold` | 1.0 | At or above this debt, memory decay pauses until a nap finishes. |
| `page_budget_share` | 0.05 | Share of the model's context window for pages per message. |
| `router_min_confidence` | 0.5 | Below this, the router falls back to embedding search. |
| `pull_cost_multiple_max` | 2 | Most a mid-session page load may cost, as a multiple of a preload. |
| `dispute_ask_margin` | 0.15 | Margin under which a high-stakes dispute asks you. |
| `dispute_ask_stakes` | 0.7 | Stakes at or above which a close dispute asks you. |
| `rem_min_keep_rate` | 0.25 | REM turns itself off under this keep rate. |
| `fit_min_labeled_events` | 200 | Labelled events needed before fitted values replace defaults. |
| `check_router_sample` | 200 | Fixed router sample size in the bounded check. |
| `check_neighbours` | 5 | Neighbours checked for each changed memory. |
| `strength_half_life_days` | 30 | Days for retrieval strength to halve at storage strength 0. |
| `strength_spacing_credit` | 0.2 | Storage strength a fully spaced recall earns. |
| `strength_difficulty_weight` | 1 | Extra credit for a recall made while retrieval strength was low. |
| `strength_min_spacing_days` | 1 | Days since the last recall that earn full spacing credit. |
| `strength_instant_credit_cap` | 0.02 | Most a recall under the minimum spacing can earn. |
| `credence_user_said` | 0.9 | Credence of a fact you said. |
| `credence_tool_observed` | 0.8 | Credence of a fact a tool reported. |
| `credence_imported` | 0.6 | Credence of an imported fact. |
| `credence_model_inferred` | 0.5 | Credence of a fact the model inferred. |
| `credence_dream_generated` | 0.3 | Credence of a fact a dream produced. |
| `attention_base` | 0.1 | Attention every new fact starts with. |
| `attention_w_remember` | 0.35 | Attention added when you flagged the fact ("remember this"). |
| `attention_w_self` | 0.2 | Attention added for a first-person statement about you. |
| `attention_w_repeat` | 0.15 | Attention added when a near-duplicate is already stored. |
| `attention_w_surprise` | 0.2 | Attention added when the fact updates an existing one. |
| `attention_w_stakes` | 0.2 | Attention added for money, health, legal or deadline facts. |
| `attention_repeat_jaccard` | 0.6 | Word overlap at or above which two facts count as a repeat. |

### Write-time scores

When the Sleep master switch is on, every new memory fact is scored as it is written,
with no model call. `attention` (0 to 1) says how much the fact deserves keeping. It
rises for a "remember this" flag, a first-person statement about you, a near-duplicate
already stored, an update to an existing memory, and money, health, legal or deadline
words. `credence` (0 to 1) says how likely the fact is true and comes only from where it
came from: you said it, a tool reported it, it was imported, the model inferred it, or a
dream produced it. `flashbulb` is 1 when you flagged the fact. A flag raises attention
and never credence. `source_type` names the source. With Sleep off these four columns
stay empty. The goal-link signal waits for the `intentions` stage.

### `PUT /memory/sleep/config`

```json
{ "values": { "router_min_confidence": 0.6, "unit_max_attempts": 4 } }
```

Every key must be one of the keys above, and its value must be in range. Whole-number
keys refuse fractions. One bad key returns `400`, and nothing is written.

## Two strengths

With the `strengths` stage on, each memory keeps two numbers. Storage strength says how
well it is learned and only rises. Retrieval strength says how reachable it is now: it
fades with time and a recall resets it to 1. Time never deletes or retires a memory. A
recall raises storage strength by more when it is spaced out and when the memory had
faded. A repeat recall seconds later earns almost nothing. For a user with the stage on,
the old 90-day decay no longer runs. The consolidation pass logs which memories it would
have decayed (`shadow_old_decay`) and changes nothing. With the stage off, nothing here
runs and decay works as before. Recall ranking does not use the strengths yet.

## Fitted decay

Once you have at least `fit_min_labeled_events` recalls with answer-used labels, Sleep can
fit how fast your memories fade from your own history. For each memory shown in a labelled
recall it takes the days since that memory was last recalled and whether the reply used it,
then fits `used chance = a x 0.5^(days / h)` by a grid search. The fitted `h` is saved as
`strength_half_life_days` with source `fitted`. Below the label minimum, or when the labels
show no clear decay, nothing is written and the default stays. A value you set yourself is
never replaced. `strength_spacing_credit` is not fitted: the labels do not show it, so it
keeps its default. Nothing runs this fit on a schedule yet.

## Events

These events go on the memory activity stream. They are declared now and emitted once
the orchestrator and disputes land.

| Event | When |
| --- | --- |
| `sleep.cycle.started` | A cycle begins. |
| `sleep.cycle.stage` | A cycle moves to its next stage. |
| `sleep.cycle.finished` | A cycle ends: finished, stopped or failed. |
| `sleep.dispute.opened` | Two memories contradict each other. |
| `sleep.dispute.needs_user` | A dispute needs you to pick. |
| `sleep.debt.changed` | The amount of waiting consolidation changed. |
