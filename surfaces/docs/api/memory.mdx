## Overview

The `/api/memory` surface gives agents durable memory primitives: documents, events, entities, edges, semantic query, and session-scoped key/value storage. It proxies to the memory service when available and falls back to local SQLite-backed storage when it is not. Session memory powers the model-facing `memory` tool, letting an agent read and write values keyed by session.

<Note>
Long-term agent memory (the facts your agents recall across sessions) is stored in each user's [Memory Drive](/api/memory-drive), a private git repo. `/memory/v2/retain`, `/memory/v2/recall` and `/memory/v2/facts` keep their shapes; writes now commit to the drive and the facts are an index rebuilt from it. See [Memory Drive internals](/core/memory-drive).
</Note>

## Entities

### List entities

```http
GET /api/memory/entities?agentId=:agentId&type=:type&q=:q
```

The response is `{"entities": [...], "pages": [...]}`. `entities` lists the stored entity rows (filtered by `agentId`, `type` and `q`); `pages` lists your [entity pages](#entity-pages) that match `q` (all of them, most mentioned first, when `q` is absent): exact name or alias first, then a name or alias that contains `q`, then a page whose text does.

```json
{
  "entities": [],
  "pages": [
    { "id": "ent_9f2c41d07a3be5c1d2e4f6a8", "name": "Allternit Platform", "kind": "name",
      "aliases": ["AP"], "mention_count": 7, "target_count": 5, "updated_at": "2026-10-13 09:12:44" }
  ]
}
```

### Get an entity page

```http
GET /api/memory/entities/:id
```

Returns `page` (structured), `text` (the page as Markdown) and `mentions` (every fact, observation, document and note that mentions the entity, most mentions first). Another user's page id returns `404`.

### Entity pages

Your memory keeps one page per recurring entity, so agents follow entities instead of searching again (the CorpusMap pattern). Pages are built from your facts, observations, documents (including passages written by memory adapters such as open-notebook) and notes, in the background, with no model calls:

- **Mentions** are capitalized names (`Dana Whitfield`, `Bank of America`, `ACME`), emails, URLs, `@handles`, code identifiers (backticked, `a::b`, `snake_case`) and the names and aliases of your entities (`properties.aliases`), which match in any case.
- **Merging** is exact and explicit: spellings that normalize to the same key (`Acme Corp.`, `ACME corp`, `Acme-Corp`) are one entity, and so are names tied by alias evidence: `Allternit Platform (AP)` when the acronym is the initials, `X aka Y`, or an entity's aliases. Names are never merged by similarity, and never across users.
- **A page** exists for every entity you created and every name mentioned by at least two items. It holds the name, kind, aliases, the top facts and observations, the documents and notes that mention it (each with a one-line snippet) and related entities by co-mention.
- **Updates** are incremental: only items whose text changed are read again, and only the pages whose mentions changed are rewritten. The same memory always gives the same pages.

When an Agency run's goal names an entity, the run's recalled memory starts with that entity's page and the documents that mention it, ahead of the other hits.

### Create an entity

```http
POST /api/memory/entities
```

#### Request body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Entity name. |
| `agentId` / `agent_id` | string | No | Associated agent. |
| `entityId` / `entity_id` | string | No | External entity id (defaults to a new id). |
| `type` / `entity_type` | string | No | Defaults to `General`. |
| `content` | string | No | Free-form content. |
| `vectorId` / `vector_id` | string | No | Vector store reference. |

#### Example response

```json
{
  "success": true,
  "entity": {
    "id": "ent_4d5e6f"
  }
}
```

## Session memory

Session memory stores JSON values keyed by `(user_id, session_id, key)`. It is the backing store for the agent `memory` tool.

### Read a key

```http
GET /api/memory/session?session_id=:session_id&key=:key
```

### Example response

```json
{
  "id": "sm_5e6f7a",
  "user_id": "user_1a2b",
  "session_id": "sess_2f8a9c",
  "key": "mode",
  "value": "fast",
  "created_at": "2026-08-13T10:00:00Z",
  "updated_at": "2026-08-13T10:00:00Z"
}
```

### List keys

```http
GET /api/memory/session/list?session_id=:session_id
```

### Write a key

```http
POST /api/memory/session
```

#### Request body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `session_id` | string | Yes | Session id. |
| `key` | string | Yes | Memory key. |
| `value` | any | Yes | JSON value. |

### Delete a key

```http
DELETE /api/memory/session?session_id=:session_id&key=:key
```

### Example response

```json
{
  "key": "mode",
  "deleted": true
}
```

## Error codes

| Status | Meaning | Typical cause |
|--------|---------|---------------|
| `200 OK` | Success | Request succeeded. |
| `201 Created` | Created | Document, event, or entity created. |
| `400 Bad Request` | Invalid request | Missing `session_id`/`key`, invalid body. |
| `401 Unauthorized` | Unauthorized | Missing or invalid bearer token. |
| `404 Not Found` | Not found | Session memory key or entity page not found. |
| `503 Service Unavailable` | Unavailable | Memory service unreachable during consolidation/query. |
| `500 Internal Server Error` | Server error | Contact support. |
