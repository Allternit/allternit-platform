## Overview

The Usage API aggregates `usage_events` into an on-demand invoice draft for an organization. It is scoped to organization owners and admins and covers a caller-specified billing period.

## Base URL

```
https://api.allternit.com/api/v1/usage/summary
```

All endpoints require a valid Bearer token in the `Authorization` header. See [Authentication](/api/authentication) for details.

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/usage/summary` | Get a usage summary invoice draft. |

## Get usage summary

```bash
GET /api/v1/usage/summary?organization_id=org_abc123&period_start=2026-08-01T00:00:00Z&period_end=2026-09-01T00:00:00Z
```

Query parameters:

| Parameter | Type | Description |
|-----------|------|-------------|
| `organization_id` | string | Organization to query. Must match the active organization. |
| `period_start` | string | ISO 8601 start timestamp (inclusive). |
| `period_end` | string | ISO 8601 end timestamp (exclusive). |
| `group_by` | string | Optional. Comma-separated, 1 to 6 of `surface`, `tier`, `model`, `lane`, `bot`, `day`. When set, the response adds a `ledger` object built from every model call (`llm_usage_events`). An unknown dimension returns `400 invalid_group_by`. |
| `tz_offset_minutes` | integer | Optional. The viewer's UTC offset in minutes (for example `-300` for Chicago in summer), so `day` buckets follow the viewer's calendar. Default `0` (UTC); clamped to ±840. |

Dimensions:

| Dimension | Key value |
| --- | --- |
| `surface` | Where the call came from (`chat`, `bot`, `cowork`, `api`, …). |
| `tier` | `S1`, `S2`, … |
| `model` | `provider/model`, for example `allternit/standard`. The dashboard's **Brain** breakdown is the provider half of this key. |
| `lane` | `api`, `subscription-cli`, `vendor`, `local`. |
| `bot` | The bot (agent id) whose session made the call, read from the session's `agentId` metadata. An empty string means the call came from no bot session. |
| `day` | `YYYY-MM-DD`, shifted by `tz_offset_minutes`. |

With `group_by`, the response also carries:

```json
"ledger": {
  "group_by": ["model", "bot", "day"],
  "groups": [
    {
      "key": { "model": "allternit/standard", "bot": "bot_chief", "day": "2026-10-19" },
      "calls": 12, "prompt_tokens": 48210, "completion_tokens": 3920, "reasoning_tokens": 0,
      "cache_read_tokens": 102400, "cache_write_tokens": 0,
      "cost_microdollars": 731000, "latency_ms_total": 41200, "cache_hit_rate": 0.68
    }
  ],
  "totals": { "calls": 12, "prompt_tokens": 48210, "completion_tokens": 3920, "reasoning_tokens": 0, "cache_read_tokens": 102400, "cache_write_tokens": 0, "cost_microdollars": 731000, "latency_ms_total": 41200 },
  "cache_hit_rate": 0.68,
  "s1": { "decisions": 0, "served_by_s1": 0, "estimated_savings_microdollars": 0 }
}
```

Groups cover every combination of the requested dimensions, so a client can roll them up to any one dimension (or filter to one bot) without asking again. Servers older than `bot`/`day` reject those two with `invalid_group_by`; the web dashboard then retries with the first four.

## Your usage windows

`GET /api/v1/me/usage` (see [Me API](/api/me)) also reports the caller's Allternit Cloud inference spend in three windows, and how fast it is being used. The window fields use snake_case keys. The older weekly fields on the same reply keep their names.

```json
{
  "windows": [
    { "id": "5h", "label": "5-hour", "used_usd": 0.42, "limit_usd": 1.83, "used_ratio": 0.23, "resets_at": "2026-11-26T20:00:00Z", "enforced": true },
    { "id": "7d", "label": "7-day", "used_usd": 3.10, "limit_usd": 7.33, "used_ratio": 0.42, "resets_at": "2026-12-03T15:00:00Z", "enforced": true },
    { "id": "month", "label": "This month", "used_usd": 9.80, "limit_usd": 22.0, "used_ratio": 0.45, "resets_at": "2026-12-01T00:00:00Z", "enforced": false }
  ],
  "pace": { "window_id": "5h", "burn_per_hour": 0.18, "runs_out_at": null, "status": "ok" },
  "carry_past_windows": false
}
```

| Window | What it covers |
| --- | --- |
| `5h` | The last 5 hours, rolling. |
| `7d` | The last 7 days, rolling. |
| `month` | The calendar month, UTC. |

- `used_usd` is Cloud inference spend at the price charged to the user (`cost_usd` in `inference_usage`). Hosted computer time is not counted; it keeps its own hour allowance.
- `limit_usd` and `used_ratio` are `null` when the plan has no limit for that window (for example a no-plan account).
- `enforced` is `true` for the `5h` and `7d` windows on paid plans. The month window shows the plan's credit grant and is not a stop.
- `pace.status` is `ok`, `warn` (at the current burn the window runs out before it resets) or `out` (already used up). `runs_out_at` is `null` unless the window will run out. `burn_per_hour` is the spend per hour over the window so far.

### Limits per plan

The limits are USD of Cloud inference spend. The month limit equals the plan's monthly credit grant.

| Plan | 5-hour | 7-day | Month |
| --- | --- | --- | --- |
| Plus | 1.83 | 7.33 | 22.00 |
| Max | 9.17 | 36.67 | 110.00 |
| Ultra | 18.33 | 73.33 | 220.00 |

A Free account has no plan and no limits.

### When a window is used up

A Cloud request made while an enforced window is used up is refused with HTTP `429`:

```json
{ "error": "usage_window_exhausted", "window": "5h", "resets_at": "2026-11-26T20:00:00Z" }
```

`window` is `5h` or `7d`. `resets_at` is when that window frees up. Clients show a notice with the reset time and never print the raw error. The same check applies to model-router calls billed to the viewer.

The refusal is skipped when the account has turned on `carry_past_windows` and its credit balance is above 0. The request then runs and is billed from the balance. Credits themselves still answer `402 credits_exhausted` at 0.

### Credits carry-over setting

| Method | Path | Body | Reply |
| --- | --- | --- | --- |
| GET | `/api/v1/me/usage/settings` | none | `{ "carry_past_windows": false }` |
| PUT | `/api/v1/me/usage/settings` | `{ "carry_past_windows": true }` | `{ "carry_past_windows": true }` |

`carry_past_windows` is stored on `user_credits` (migration 168) and is `false` until the person turns it on. Off: the 5-hour and 7-day windows are hard stops until they reset. On: work continues past a window and is billed from the credit balance. The Usage page switch saves this value. `PUT` answers `409` ("Add usage credits first.") for an account with no credits row.

## Error codes

| Status | Code | Description |
|--------|------|-------------|
| 200 | — | Success. |
| 401 | `unauthorized` | Missing or invalid authentication. |
| 403 | `inactive_organization` | Requested organization is not the active organization. |
| 403 | `insufficient_role` | Only organization owners/admins may view metered usage. |
| 429 | `usage_window_exhausted` | A Cloud request hit an enforced 5-hour or 7-day window (see above). |
| 500 | `db_error` / `task_join_error` | Database or task error. |
