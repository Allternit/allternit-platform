## Overview

The Workspace Files API exposes filesystem operations on the computer that runs the Allternit runtime. It resolves paths against the home folder (supporting the `~` shorthand), then checks every path against a scope before it reads or writes anything. What a request may reach depends on where it came from: the Desktop app on the same computer, or another device through the relay. See [Path scoping](#path-scoping).

## Base URL

```text
https://api.allternit.com/api
```

For local development:

```text
http://127.0.0.1:8013/api
```

## Authentication

Requests are authorized through the platform auth middleware. The route also accepts a desktop-bootstrap header as a lenient fallback so Electron desktop sessions can operate without requiring the middleware to populate an `AuthUser` extension. Authentication says who is asking; [path scoping](#path-scoping) decides which paths that request can reach.

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/files/list` | List entries in a directory. |
| `GET` | `/files/read` | Read a text file. |
| `GET` | `/files/raw` | Read a file as raw bytes with a MIME type. |
| `GET` | `/files/exists` | Check whether a path exists (JSON response). |
| `HEAD` | `/files/exists` | Check whether a path exists (status only). |
| `POST` | `/files/mkdir` | Create a directory. |
| `DELETE` | `/files/delete` | Delete a file or directory. |
| `POST` | `/files/write` | Write a text file. |

## Path resolution

Paths are resolved against the home folder of the computer running the runtime:

- `~/Allternit/Inbox` resolves to the `Allternit/Inbox` folder in the home folder.
- `/absolute/path` is used as written, then checked against the scope.
- `relative/path` resolves to `relative/path` inside the home folder.

The runtime then makes the path canonical before any check:

- A path with a `..` part is refused, wherever the `..` appears.
- Symbolic links are followed to where they really point. For a file that does not exist yet (a write or `mkdir` target), the deepest folder that does exist is resolved and the rest of the path is added to it. A link that points at nothing is refused.
- `/files/delete` resolves the folder that holds the target but not the target itself, so deleting a link removes the link, never what it points at.
- Folders match whole path parts only: a rule for `~/Allternit` does not cover `~/AllternitX`.
- Responses carry the canonical path, so `path` fields may differ from what you sent (for example, the real letter case of a folder on a case-insensitive disk).

## Path scoping

Every request is either **local** or **relayed**.

- **Local**: the Desktop app on the same computer, reaching the runtime over loopback with no relay or proxy header.
- **Relayed**: any request replayed by the cloud relay (it carries `x-allternit-relayed`), any request with a forwarding header (`x-forwarded-for`, `forwarded`, `x-real-ip` and similar), and any request from a non-loopback address. Requests from ai.allternit.com, the m.allternit.com PWA, and the iOS and Android apps to a computer are relayed.

Both kinds of request are refused for anything outside the home folder, for changes to the home folder itself, and for the secret locations listed below.

### Relayed requests

A relayed request can reach only these paths:

| Path | Access |
|------|--------|
| `~/Allternit` | Read (list) |
| Everything inside `~/Allternit`, including `Inbox`, `Shared`, `Agent Output`, `Downloads`, `Meetings` and `Scans` | Read and write |
| `~/.allternit/plugins`, `~/.agents/plugins`, `~/.codex/plugins` and everything inside them | Read only |
| `~/.allternit/mcps`, `~/.agents/mcps`, `~/.codex/mcps` | List, read the files directly inside, write or delete the `.json` files directly inside |
| `~/.config/allternit-shell/allternit.json`, `~/.config/gizzi/allternit.json`, `~/.config/gizzi-code/allternit.json`, `~/.claude/settings.json`, `~/.codex/config.toml`, `~/.gemini/mcp.json` | Read only (these exact files) |
| `~/agents/AGENT_ID/.allternit/governance/HEARTBEAT.md` | Read and write (this exact file for each agent) |

Anything else answers `403`. The runtime does not create the `~/Allternit` folders; a write inside them creates the parent folders it needs.

### Local requests

A local request can reach the whole home folder except the secret locations below. Paths outside the home folder (such as `/etc` or `/tmp`) are refused. The Desktop app still reads and writes skills, plugins, commands and MCP folders such as `~/.claude/skills`.

### Secret locations

These are refused for every caller, matched without regard to letter case (so `~/.SSH` is refused too):

- SSH, GPG and password stores: `~/.ssh`, `~/.gnupg`, `~/.password-store`
- macOS Keychains: `~/Library/Keychains`
- Cloud and developer credentials: `~/.aws`, `~/.azure`, `~/.kube`, `~/.config/gcloud`, `~/.config/gh`, `~/.config/stripe`, `~/.docker/config.json`, `~/.netrc`, `~/.npmrc`, `~/.pypirc`, `~/.git-credentials`
- Agent CLI sign-ins: `~/.claude/.credentials.json`, `~/.codex/auth.json`, `~/.gizzi/credentials.json`, `~/.local/share/gizzi-code/auth.json`, `~/.local/share/gizzi-code/fabric-lease.key`, `~/.local/share/tailscale`
- Allternit keys and private state: `~/.allternit/phone-gateway.json`, `~/.allternit/subscriptions`, `~/.allternit/incus-client`, `~/.allternit/factory/fabric`, `~/.allternit/factory/registry.json`, `~/.allternit/session-caretaker`, `~/.allternit/system-one`, and any `~/.allternit` entry whose name contains `.env`
- The Allternit data folders: the folder named by `ALLTERNIT_DATA_DIR`, the platform data folder's `allternit` and `@allternit` folders (on macOS, `~/Library/Application Support/allternit` and `~/Library/Application Support/@allternit`)

Recursive listings skip entries in secret locations, and for relayed requests they skip entries outside the allowed paths.

### Computer file transfer

The computer routes that move files to and from a cloud computer or VM (`/computers/COMPUTER_ID/files/upload` and `/computers/COMPUTER_ID/files/download`) check the path on that computer by its text: it must be absolute, must not contain `..`, and must not point into any of the secret locations above (for example `/home/user/.ssh/authorized_keys` or `/root/.aws/credentials`), and `/etc/shadow`, `/etc/gshadow` and `/etc/sudoers` are refused. Both routes go through the same confirmation policy as other computer control actions (`computer.file_read` and `computer.file_write`). Transfer uploads (`/computers/COMPUTER_ID/transfer/file`) always land in a folder the runtime chooses, and are refused if that folder resolves into a secret location.

## List files

```bash
curl "https://api.allternit.com/api/files/list?path=~/Allternit/Shared/app&recursive=false" \
  -H "Authorization: Bearer $ALLTERNIT_API_KEY"
```

### Query parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `path` | string | Directory path to list. |
| `recursive` | string | Set to `true` for a recursive listing. |

### Response

```json
{
  "path": "/home/you/Allternit/Shared/app",
  "entries": [
    {
      "name": "src",
      "path": "/home/you/Allternit/Shared/app/src",
      "type": "directory",
      "size": null,
      "modified_at": "2026-08-13T12:00:00Z"
    },
    {
      "name": "package.json",
      "path": "/home/you/Allternit/Shared/app/package.json",
      "type": "file",
      "size": 1024,
      "modified_at": "2026-08-13T11:00:00Z"
    }
  ]
}
```

Recursive listings are capped at a depth of 8 and a maximum of 1,000 entries. If the directory does not exist, the endpoint returns an empty `entries` array rather than an error.

## Read a text file

```bash
curl "https://api.allternit.com/api/files/read?path=~/Allternit/Shared/app/package.json" \
  -H "Authorization: Bearer $ALLTERNIT_API_KEY"
```

### Response

```json
{
  "content": "{\"name\":\"example\"}"
}
```

## Read a raw file

```bash
curl "https://api.allternit.com/api/files/raw?path=~/Allternit/Shared/app/logo.png" \
  -H "Authorization: Bearer $ALLTERNIT_API_KEY" \
  --output logo.png
```

The response is returned with the detected `Content-Type` header.

## Check existence

JSON variant (always returns 200):

```bash
curl "https://api.allternit.com/api/files/exists?path=~/Allternit/Shared/app/package.json" \
  -H "Authorization: Bearer $ALLTERNIT_API_KEY"
```

### Response

```json
{
  "exists": true
}
```

HEAD variant:

```bash
curl -I "https://api.allternit.com/api/files/exists?path=~/Allternit/Shared/app/package.json" \
  -H "Authorization: Bearer $ALLTERNIT_API_KEY"
```

Returns `200 OK` if the path exists, otherwise `404 Not Found`. Both variants answer `403` for a path outside the caller's scope.

## Create a directory

```bash
curl -X POST "https://api.allternit.com/api/files/mkdir?path=~/Allternit/Shared/app/new-folder" \
  -H "Authorization: Bearer $ALLTERNIT_API_KEY"
```

### Response

```json
{
  "ok": true
}
```

## Delete a file or directory

```bash
curl -X DELETE "https://api.allternit.com/api/files/delete?path=~/Allternit/Shared/app/old-folder" \
  -H "Authorization: Bearer $ALLTERNIT_API_KEY"
```

### Response

```json
{
  "ok": true
}
```

## Write a file

```bash
curl -X POST "https://api.allternit.com/api/files/write?path=~/Allternit/Shared/app/readme.md" \
  -H "Authorization: Bearer $ALLTERNIT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "path": "~/Allternit/Shared/app/readme.md",
    "content": "# Hello Allternit"
  }'
```

The path may be supplied either as a query parameter or in the JSON body. Parent directories are created automatically.

### Response

```json
{
  "ok": true,
  "path": "/home/you/Allternit/Shared/app/readme.md",
  "bytesWritten": 17,
  "operation": "write"
}
```

## Supported MIME types

The `/files/raw` endpoint detects the following common types from the file extension:

| Extension | MIME type |
|-----------|-----------|
| `.png` | `image/png` |
| `.jpg`, `.jpeg` | `image/jpeg` |
| `.gif` | `image/gif` |
| `.webp` | `image/webp` |
| `.svg` | `image/svg+xml` |
| `.pdf` | `application/pdf` |
| `.txt`, `.md` | `text/plain; charset=utf-8` |
| `.html`, `.htm` | `text/html; charset=utf-8` |
| `.css` | `text/css; charset=utf-8` |
| `.js` | `text/javascript; charset=utf-8` |
| `.json` | `application/json` |
| other | `application/octet-stream` |

## Error codes

| HTTP status | Body | Meaning |
|-------------|------|---------|
| 400 | `{"error": "Missing path"}` | Missing `path` on write. |
| 401 | — | Missing or invalid bearer token. |
| 403 | `{"error": "path_not_allowed", "reason": "...", "message": "..."}` | The path is outside the caller's scope. `reason` is one of `parent_dir`, `outside_home`, `protected`, `outside_roots`, `read_only`, `home_itself`, `unresolvable`, `invalid_path`, `no_home`. |
| 404 | `{"error": "Not found"}` | File or directory does not exist. |
| 500 | `{"error": "Cannot read file" \| "Cannot create directory" \| "Cannot delete" \| "Cannot write file"}` | Filesystem failure. |
