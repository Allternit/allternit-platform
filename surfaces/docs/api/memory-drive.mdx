title: Memory Drive API
description: "Routes for the git-backed Memory Drive: files, history, writes, clone tokens, nightly Dreams, shared drives and the questions board."
---

The Memory Drive is each user's agent memory, stored as a private git repo in the
open [Agent Memory Repo](https://github.com/AgentMemoryRepo/agentmemoryrepo) format.
These routes are served by the Allternit API data-plane node under `/api/v1`, next to
the [Memory API](/api/memory) and [hosted brains](/api/brain-git). They use
the normal signed-in session. For the user-facing guide see [Memory Drive](/guides/memory-drive).

The drive is the source of truth. The kernel's `memory_facts` rows are an index
rebuilt from it after every commit, so `/memory/v2/recall` keeps working unchanged.

## Errors

| Status | Meaning |
| --- | --- |
| 400 | Invalid input, for example a bad path, a possible credential, or a memory line without `source`/`added`. |
| 401 | Not signed in. |
| 403 | You don't have access to that drive, or you have read access and tried to write. |
| 404 | No such drive, file or entry. |
| 409 | The drive changed since `expected_revision`. The body has `expected_revision` and `actual_revision`. Re-read and retry. |
| 503 | The commit landed (`committed: true`) but indexing is still pending. The next read repairs it. |

## Choosing a drive

Every route takes an optional `drive`, as a query parameter for `GET` or a body field
for `POST`/`PUT`. The default is `personal`.

| `drive` | Who can open it |
| --- | --- |
| `personal` | You. |
| `team:<workspaceId>` | The workspace owner and members. Members with the `viewer` role can read only. |
| `project:<projectId>` | The project's owner. |
| `bot:<agentId>` | The bot's owner. |
| `swarm:<orchestratorId>` | The swarm's owner. |

Access is checked on every request, so removing someone from a workspace removes their
access at once, including their git tokens for that drive.

### `GET /memory/drive/mounts`

Every drive you can open.

```json
{ "mounts": [
  { "ref": "personal", "kind": "personal", "name": "Personal", "access": "write", "revision": "3f2a…" },
  { "ref": "team:ws_42", "kind": "team", "name": "Acme", "access": "read", "revision": null }
] }
```

`revision` is `null` for a drive that hasn't been created yet; opening it creates it.

## Files and history

### `GET /memory/drive/info`

Creates your personal drive on first call.

```json
{
  "ref": "personal", "kind": "personal", "name": "memory", "brain_id": "9c1e…", "branch": "main",
  "revision": "3f2a…", "indexed_revision": "3f2a…", "index_dirty": false,
  "imported_at": null, "pending_writes": 0, "access": "write",
  "clone_url": "http://127.0.0.1:8013/api/v1/brains/9c1e…/git"
}
```

`clone_url` never contains a credential. `usage` is `{ bytes, files, max_bytes, max_files }`. `pending_writes` counts writes whose commit
failed and will be retried.

| Route | Returns |
| --- | --- |
| `GET /memory/drive/tree?revision=` | `{ revision, files: [{ path, bytes }] }` |
| `GET /memory/drive/file?path=&revision=` | `{ revision, path, content }` |
| `GET /memory/drive/history?path=&limit=` | `{ commits: [{ revision, parents, author, timestamp, message }] }`, newest first, `limit` up to 100 (default 25). |
| `GET /memory/drive/diff?from=&to=&path=` | `{ from, to, path, diff }` as a unified diff. For a drive's first commit use the empty tree `4b825dc642cb6eb9a060e54bf8d69288fbee4904` as `from`. |

## Writing

### `POST /memory/drive/write`

Applies a batch as one commit, only if the drive is still at `expected_revision`.

```json
{
  "expected_revision": "3f2a…",
  "message": "Fix my city",
  "operations": [
    { "UpsertEntry": { "path": "facts.md", "entry": {
      "id": "m-1a2b", "text": "User lives in Saint Paul.", "source": "/?session=s_123",
      "added": "2026-10-06", "metadata": { "memory_type": "fact" } } } },
    { "DeleteEntry": { "id": "m-9f8e" } },
    { "SetFile": { "path": "projects/launch.md", "content": "# Launch\n\n" } },
    { "DeleteFile": { "path": "old.md" } }
  ]
}
```

Returns `{ revision, changed }`. `MEMORY.md`'s `## Index` is regenerated from the topic
files on every write. `twin/` is managed by Allternit and can't be written.

### `POST /memory/drive/remember`

Saves one memory without building an entry yourself.

```json
{ "text": "Prefers short answers.", "memory_type": "preference", "session": "s_123" }
```

The server sets the id and date and picks the topic file from `memory_type` (`facts.md`,
`preferences.md`, `events.md`, `procedures.md`, `people-and-things.md`,
`relationships.md`, `tasks.md`) unless you pass `path`. With `session` the source is that
session's link; without it, a manual save from Settings. Returns
`{ revision, fact_id, path, entry_id }` for the personal drive.

### `POST /memory/drive/import`

Moves memories saved before the drive existed into it.

- `{}` (dry run) returns the plan and changes nothing: `{ dry_run: true, plan: { total, converted, skipped, topic_files, already_imported, rows } }`.
- `{ "apply": true, "expected_revision": "…" }` writes one `Import existing memory` commit. Running it again changes nothing.

Old rows stay visible for 30 days after the import and are then hidden. They are never deleted.

### `POST /memory/drive/import-text`

Imports memories from another assistant. Body `{ text, from, apply?, selected? }`, where `from` is
`chatgpt`, `claude`, `gemini`, `grok`, `copilot`, `perplexity`, `meta`, `kimi`, `mistral`, `mem0` or `other`.
`text` is plain lines, bullets, a numbered list (code fences are ignored), or JSON (an array of
strings, or objects with `content`, `memory` or `text`, also inside `memories`, `results`, `items` or `data`, which covers Mem0's export), up to 500 items and 512 KB.

- Dry run: `{ dry_run: true, plan: { from, path, entries: [text], skipped: [{ text, reason }], remaining } }`.
- `apply: true`: one commit to `path` (for example `imports/gemini.md`), returns `{ dry_run: false, revision, imported }`.
  `selected: [text]` imports only those previewed entries.

Each line's source is `<assistant>:memory-import` (`meta-ai:` for Meta AI, `le-chat:` for Le Chat).
Computers older than this change accept only `chatgpt`, `claude` and `other` and answer
`400 from must be …` for the rest; the app then imports as `other`.

### `GET /memory/drive/import-agents`

Lists agents on the computer that holds the drive whose memory files can be imported:
`{ sources: [{ id, name, files, items }] }`, where `id` is `claude-code`, `codex`, `hermes` or
`openclaw`. Only these fixed paths under the home folder are read:

| Agent | Files |
| --- | --- |
| Claude Code | `~/.claude/CLAUDE.md`; `~/.claude/projects/*/memory/*.md` except `MEMORY.md` (one memory per file, its `description`) |
| Codex | `~/.codex/AGENTS.md`; `~/.codex/memories/*.md` and one folder down |
| Hermes | `~/.hermes/memories/{USER,MEMORY}.md` and `~/.hermes/profiles/*/memories/{USER,MEMORY}.md` (entries split on `§`) |
| OpenClaw | `~/.openclaw/workspace/{USER,MEMORY}.md` |

Markdown files give one item per bullet or paragraph; headings, tables, code blocks and comments
are left out. Files over 512 KB and symlinks are skipped. Older computers answer 404.

### `POST /memory/drive/import-agents`

Body `{ source, apply?, selected? }`. Same plan and result shapes as `import-text`. Items run
through the same checks (too long, looks like a secret, listed twice, already remembered) and each
keeps the file it came from as its source, for example `claude-code:memory/<project>/<file>.md`.
One run takes up to 500 items, newest files first; `plan.remaining` says how many are left for
the next run. The commit goes to `imports/<source>.md`.

### `GET /memory/drive/find-memories`

The model that reads exported chats and the request limits:
`{ model: "provider/model", max_conversations, max_conversation_chars, max_batch_chars }`
(today 20 conversations, 8,000 characters each, 80,000 per request). The model is
`ALLTERNIT_MEMORY_MODEL`, else `ALLTERNIT_GEN_SMALL_MODEL`, else the built-in small default, the same
one that saves memories from chats. Older computers answer 404.

### `POST /memory/drive/find-memories`

Body `{ from, conversations: [{ id, title?, date?, text }] }`, where `text` is the person's own
messages from one conversation. The app reads the export (ChatGPT or Claude `conversations.json`,
Gemini's Takeout `MyActivity`, the Grok archive) in the browser and sends only this. Returns
`{ memories: [{ text, conversation }] }` and saves nothing. Requests run two at a time per computer;
when the model doesn't answer, the reply is `503`.

### `POST /memory/drive/import-chats`

Body `{ from, found: [{ text, conversation }], apply?, selected? }` (up to 5,000 facts). Same plan and
result shapes as `import-text` and the same checks. Each line's source is
`<assistant>:conversation/<id>`; the commit goes to `imports/<assistant>-chats.md`.

### `GET /memory/drive/capture`

The capture switches and per-source counts:
`{ settings: { channels, gizzi, agent_folders }, counts: [{ scheme, memories }], agents: [{ id, name, files, items }], verified_channels: [channel] }`. `verified_channels` lists the channels with a verified owner identity, which channel capture needs.
Switches are stored per user in `runtime_settings` (key `memory_capture`); the defaults are
`channels` and `gizzi` on, `agent_folders` off. `counts` groups personal-drive entries by the part
of `source:` before the colon. Session links and `allternit:` ids aren't listed. Older computers answer 404.

### `PUT /memory/drive/capture`

Body: any of `{ channels, gizzi, agent_folders }`. Returns `{ settings, imported }`. Turning
`agent_folders` on runs one agent-folder import right away. After that the API repeats it every
6 hours for every owner who has it on (`memory_capture::spawn`).

### `POST /memory/drive/capture/turn`

Body `{ source: "gizzi", label: "gizzi:session/<id>", text }`. Gizzi sends the person's message at
the end of each turn. The API records it as a `turn_user` observation with the label as its source
when the `gizzi` switch is on, and runs no extraction, because Gizzi saves memories itself. Returns
`{ recorded }`.

**Channels** are captured where messages arrive. In `channel_transports::accept_events_with` and
in bot email, a message is captured only when its sender matches the account's verified owner
(`channel_auth::Rule::is_owner`). It's recorded with the label `<provider>:chat/<chat>` and
goes through the same model extraction as a web chat turn (`memory_capture::owner_channel_turn`).
Facts and Dream lessons from these turns cite that label.

### `POST /memory/drive/forget-source`

Body `{ scheme }`, for example `chatgpt`, `telegram` or `claude-code`. Removes every
personal-drive entry whose source starts with `<scheme>:` as one commit, up to 2,000 at a time.
Returns `{ revision, removed, more }`.

Incognito sessions are refused by `/memory/v2/retain` and `/memory/v2/observation`, which answer
`{ status: "skipped", reason: "incognito" }`.

### Ledger: `GET /memory/drive/ledger`, `GET /ledger/file`, `POST /ledger/snapshot`, `GET /ledger/download`

The ledger is a bare git repo beside the personal drive (`<drive folder>/ledger.git`).
`ledger::collect` reads the owner's rows from `agents` (bots and agents, not archived),
`bot_templates`, `routines`, `cowork_routines`, `workflows`, open `tasks` and `long_running_tasks`,
`skills`, `cowork_projects`, `cowork_scheduled_tasks`, `loops`, `beta_deployments`, the safe
columns of `connector_connections`, each bot's workspace folder, and the SKILL.md folders in
`~/.allternit/skills`. It writes them as JSON and Markdown files.
Credential columns (`identity_key`, `principal_id`, tokens) are never read. JSON values under
credential-like keys are replaced, `git_remote` loses its userinfo, and any file with a token shape
(or, for copied files, a `password:`/`TOKEN=` style value) is left out and listed in `README.md`.
`ledger::spawn` snapshots every owner hourly. A snapshot commits only when the tree changed.

- `GET /memory/drive/ledger`: `{ revision, files: [{ path, bytes }], history: [{ revision, timestamp, message, changed, paths }] }`.
- `GET /memory/drive/ledger/file?path=&revision=`: `{ path, content }`.
- `PUT /memory/drive/ledger/file`: body `{ path, content }` (up to 1 MB). `ledger_edit.rs` applies the
  edit to the real thing, then saves a snapshot. Returns `{ summary, revision }`.
  - **Record files** update the owner's row: only columns it has, never `id`, `user_id`, timestamps or
    the kind's dropped columns. `[left out…]` values keep the stored value, including nested JSON.
    A credential-keyed value typed into the file is refused.
  - **Bot workspace files** and **files of installed skills** are written to disk after a secret check.
  - `README.md` and `connected-apps.json` are read-only.
  - **A record path not yet in the ledger creates the thing.** It gets a new id (or the given one if
    unused), with credentials refused and `[left out]` values dropped. Scheduled kinds start paused.
    A missing required field answers `Add "<field>"`.
- `DELETE /memory/drive/ledger/file?path=`: bots and agents are archived (`archived_at`), other records
  are deleted, and workspace and skill files are removed (not `SKILL.md`). Then it snapshots. Returns
  `{ summary, revision }`.
- `POST /memory/drive/ledger/snapshot`: `{ changed, revision }`.
- `GET /memory/drive/ledger/download?revision=`: `application/zip` with everything under `ledger/`.

- `POST /memory/drive/ledger/restore`: body `{ files: { "<ledger path>": "<text>" }, apply? }` (up to
  5,000 files, 40 MB). Returns `{ dry_run, plan: { items: [{ kind, path, name, action, reason, needs,
  paused }], files_added, files_kept, reconnect: [{ connector, account }] } }`, where `action` is `add`,
  `already_here` or `skip`. `ledger_restore.rs` keeps each record's id. It writes only the columns the
  table has here, with `user_id` set to the caller. It drops `[left out…]` values and lists them in
  `needs`. It pauses routines, scheduled messages, schedules, loops and scheduled runs. It adds bot
  workspace files and skill folders without overwriting anything. Applying saves a ledger snapshot.

Older computers answer 404.

### Copies: `GET/PUT /memory/drive/copies`, `POST /memory/drive/copies/run`

Copies of the drive and ledger kept elsewhere (`memory_copies.rs`), stored per user in
`runtime_settings` (key `memory_copies`).

- `GET` returns `{ folder: { path, status } | null, git: { url, has_token, status } | null }`, where
  `status` is `{ last_at, last_error }`. The token is never returned.
- `PUT` takes `{ folder_path?, git_url?, git_token? }`. `""` stops that copy; an absent field
  leaves it as it is. The folder must be an existing absolute path. The remote must be HTTPS with
  no credentials in it. The token is sealed with the platform key, and the request is refused if
  sealing isn't available. The ledger is saved and both copies run once before the reply.
- `POST /run` saves the ledger and runs the copies now. They also run after each hourly ledger snapshot.

The folder copy writes `<folder>/Allternit/{memory,ledger}/…` and removes only files listed in its
`.allternit-copy.json` (path → content hash). It never writes through a symlink.

**Two-way.** Before writing, a run compares the copy with what it last wrote. For a folder that's the
manifest hashes; for git it's the commits it last pushed (`last_memory`, `last_ledger`), against a
fetch of the two branches. Changed, added and deleted files go through `memory_copies::apply_inbound`:
- ledger files through `ledger_edit::edit` / `delete`;
- memory files as one checked `memory_drive_scopes::apply_for` batch.

A path that also changed in Allternit since the last copy is a conflict. Allternit's version stays; the
copy's version is written as `<path>.conflict-<time>` in the folder, or its commit is pushed to
`allternit-conflicts/<branch>-<time>`. `status` reports `applied`, `conflicts` and `failed`.
Re-saving the same remote keeps `last_*`, so remote edits are never overwritten unseen. The git copy force-pushes the drive to
`allternit-memory` and the ledger to `allternit-ledger` (force, because "delete forever" rewrites
history). The token goes to git as an `http.extraHeader` through `GIT_CONFIG_*` environment
variables, never on the command line or in the URL. Push errors are reported in plain words and
never include the token.

### `POST /memory/drive/purge`

Permanently removes entries from the drive and its whole history.
Body `{ drive?, expected_revision, entry_ids: [id], confirm: "delete forever" }` (1 to 200 ids;
for lines without an `id`, use the derived `entry-<sha256>` id). Returns `{ revision, purged }`.
Commit messages, authors and dates are kept; stored revisions (index, import, Dreams) are
remapped; Dream reports that quoted a purged memory are replaced with a note. Purged ids and
text are refused from then on, on writes and pushes. Clones made before the purge keep their copy.

### `POST /memory/drive/reindex`, `GET /memory/drive/health`

Rebuild the index from the drive now, and report `{ revision, indexed_revision, index_dirty, imported_at, pending_writes }`.

## Clone tokens

| Route | What it does |
| --- | --- |
| `GET /memory/drive/tokens` | `{ tokens: [{ id, label, access, created_at, last_used_at }] }` for that drive. |
| `POST /memory/drive/tokens` | Body `{ access: "read" \| "write", label? }`. Returns `{ id, token, username, access, clone_url }`. The token is shown once. |
| `DELETE /memory/drive/tokens/:id` | Revokes it at once. |

A token opens exactly one drive. A `read` token can clone and fetch; a `write` token can
also push. Use it as the git password, never in the URL:

```sh
export ALLTERNIT_MEMORY_TOKEN=allternit_git_…
git -c credential.helper= \
  -c 'credential.helper=!f() { echo username=x-access-token; echo "password=$ALLTERNIT_MEMORY_TOKEN"; }; f' \
  clone "$CLONE_URL" memory
```

Every push is checked before the branch moves: only `main`, fast-forward only, at most
200 commits, every file a markdown file in the standard format, no possible credentials,
and no changes to `twin/`. A refused push prints `Memory Drive refused this
push:` and the reason. After an accepted push the index is rebuilt.

## Nightly Dream

| Route | What it does |
| --- | --- |
| `GET /memory/drive/settings` / `PUT` | `{ dreaming_enabled, timezone }`. Dreaming is on by default; `timezone` is an IANA name (e.g. `America/Chicago`) and decides when the Dream runs (02:00–06:00 local). `PUT` takes either field. |
| `GET /memory/drive/dreams?limit=` | `{ dreams: [{ id, date, status, revision, base_revision, report, summary, error, undo_revision, created_at }] }` |
| `POST /memory/drive/dreams/run` | Runs today's Dream now. Once per day; a second call returns today's result. |
| `POST /memory/drive/dreams/:id/undo` | `{ undone: true, revision, dream }`. 409 with `conflicts: [paths]` when you edited a line the Dream changed. |

`status` is `running`, `applied`, `no_changes`, `failed` or `undone`. `summary` counts
`merged`, `resolved`, `lessons`, `pruned`, `proposals` and `skipped`. See
[how Dreaming works](/core/memory-drive#nightly-dream).

## Questions board

For team, project and swarm drives. Questions and answers live in `questions.md`.

| Route | Body | Returns |
| --- | --- | --- |
| `GET /memory/drive/questions?drive=` | | `{ revision, questions: [{ id, text, author, added, status, source, answers: [...] }] }` |
| `POST /memory/drive/questions` | `{ drive, text, source? }` | `{ revision, question }` |
| `POST /memory/drive/questions/:id/answer` | `{ drive, text, source? }` | `{ revision, answer }` |
| `POST /memory/drive/questions/:id/resolve` | `{ drive }` | `{ revision }` |

`status` is `open`, `answered` (at least one answer) or `resolved`. Bots reach the same board
through the MCP tools `memory_questions`, `memory_ask` and `memory_answer` (with `drive`), using
their owner's membership. Concurrent askers and
answerers never overwrite each other: each change is retried on the latest version.
