## Overview

The Sandbox API provides VM-based code execution with configurable resources, network access, and toolchains. Sandboxes run on infrastructure you control. For organization-scoped templates and long-lived instances, see [Cloud Sandboxes](/tools/sandbox).

## Base URL

```text
https://api.allternit.com/sandbox
```

Local development:

```text
http://127.0.0.1:8013/sandbox
```

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/sandbox/` | Service status |
| POST | `/sandbox/execute` | Execute code synchronously |
| POST | `/sandbox/execute/stream` | Execute code with streaming output |
| GET | `/sandbox/capabilities` | Driver capabilities |
| GET | `/sandbox/health` | Driver health |
| GET | `/sandbox/pool` | Warm VM pool status |

### Get capabilities

```bash
curl -X GET http://127.0.0.1:8013/sandbox/capabilities \
  -H "Authorization: Bearer <token>"
```

Response:

```json
{
  "driver_type": "vm",
  "isolation_level": "vm",
  "supported_languages": ["python", "node", "bash", "rust"],
  "available_toolchains": ["python-3.12", "node-22", "rust-stable"],
  "max_concurrent_sessions": 10,
  "supports_snapshots": true,
  "supports_streaming": true
}
```

### Execute code

```bash
curl -X POST http://127.0.0.1:8013/sandbox/execute \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "code": "print('"'"'hello from sandbox'"'"')",
    "language": "python",
    "timeout_secs": 300,
    "network_enabled": false,
    "resources": {
      "cpu_cores": 1,
      "memory_mb": 512
    },
    "toolchains": ["python-3.12"]
  }'
```

Request body:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `code` | string | yes | Code or command to execute |
| `language` | string | yes | `python`, `node`, `bash`, or `rust` |
| `timeout_secs` | integer | no | Timeout in seconds; default 300 |
| `workdir` | string | no | Working directory inside the sandbox |
| `env` | object | no | Environment variables as key/value strings |
| `resources` | object | no | `{ "cpu_cores": number, "memory_mb": integer }` |
| `toolchains` | array | no | Toolchain layers to install |
| `network_enabled` | boolean | no | Whether the sandbox may access the network |

Response:

```json
{
  "exit_code": 0,
  "stdout": "hello from sandbox\n",
  "stderr": "",
  "duration_ms": 142,
  "session_id": "sess_abc123"
}
```

### Streaming execution

```bash
curl -N -X POST http://127.0.0.1:8013/sandbox/execute/stream \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "code": "import time\nfor i in range(3):\n  print(f'step {i}')\n  time.sleep(1)",
    "language": "python"
  }'
```

Response (SSE):

```
data: {"type":"stdout","line":"step 0"}

data: {"type":"stdout","line":"step 1"}

data: {"type":"stdout","line":"step 2"}

data: {"type":"done","exit_code":0}
```

### Health check

```bash
curl -X GET http://127.0.0.1:8013/sandbox/health \
  -H "Authorization: Bearer <token>"
```

Response:

```text
OK
```

## Security

- Buffered `/sandbox/execute` runs on the VM driver; when a warm pool is configured it checks out a health-checked VM and returns it afterwards, and a checkout failure returns 503 rather than falling back to an unsandboxed run.
- `/sandbox/execute/stream` spawns the process directly with a cleared, allow-listed environment and caps the timeout at 300 seconds. It does not use the VM driver.
- `network_enabled` defaults to `false`.
- Execution timeout is enforced by the server.

## Error codes

| HTTP | Code / Message | Meaning |
|------|----------------|---------|
| 200 | — | Execution succeeded; check `exit_code` |
| 503 | `VM driver not available` | No VM driver is initialized |
| 503 | `VM driver not initialized` | Health check failed |
