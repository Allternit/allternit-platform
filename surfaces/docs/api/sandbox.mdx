## Overview

The Sandbox API provides VM-based code execution with configurable resources, network access, and toolchains. Sandboxes run on infrastructure you control. For organization-scoped templates and long-lived instances, see [Cloud Sandboxes](/tools/sandbox).

## Base URL

```text
https://api.allternit.com/sandbox
```

Local development:

```text
http://127.0.0.1:8013/sandbox
```

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/sandbox/` | Service status |
| POST | `/sandbox/execute` | Execute code synchronously |
| POST | `/sandbox/execute/stream` | Execute code with streaming output |
| GET | `/sandbox/capabilities` | Driver capabilities |
| GET | `/sandbox/health` | Driver health |
| GET | `/sandbox/pool` | Warm VM pool status |

### Get capabilities

```bash
curl -X GET http://127.0.0.1:8013/sandbox/capabilities \
  -H "Authorization: Bearer <token>"
```

Response:

```json
{
  "driver_type": "vm",
  "isolation_level": "vm",
  "supported_languages": ["python", "node", "bash", "rust"],
  "available_toolchains": ["python-3.12", "node-22", "rust-stable"],
  "max_concurrent_sessions": 10,
  "supports_snapshots": true,
  "supports_streaming": true
}
```

### Execute code

```bash
curl -X POST http://127.0.0.1:8013/sandbox/execute \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "code": "print('"'"'hello from sandbox'"'"')",
    "language": "python",
    "timeout_secs": 300,
    "network_enabled": false,
    "resources": {
      "cpu_cores": 1,
      "memory_mb": 512
    },
    "toolchains": ["python-3.12"]
  }'
```

Request body:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `code` | string | yes | Code or command to execute |
| `language` | string | yes | `python`, `node`, `bash`, or `rust` |
| `timeout_secs` | integer | no | Timeout in seconds; default 300 |
| `workdir` | string | no | Working directory inside the sandbox |
| `env` | object | no | Environment variables as key/value strings |
| `resources` | object | no | `{ "cpu_cores": number, "memory_mb": integer }` |
| `toolchains` | array | no | Toolchain layers to install |
| `network_enabled` | boolean | no | Whether the sandbox may access the network |
| `files` | array | no | Uploads to stage into the sandbox as `in/<name>`: `[{ "name": "data.csv", "uploadId": "..." }]`. `/sandbox/execute` only. |

Response:

```json
{
  "exit_code": 0,
  "stdout": "hello from sandbox\n",
  "stderr": "",
  "duration_ms": 142,
  "session_id": "sess_abc123"
}
```

### Files in and out

Pass `files` to stage uploads (from `POST /api/v1/uploads`) into the sandbox working folder as `in/<name>`. Whatever the code writes to `out/` comes back in the response as `files`, each stored as an upload you can fetch with `GET /api/v1/uploads/:id`.

```json
{
  "code": "import csv\nopen('out/n.txt','w').write('42')",
  "language": "python",
  "files": [{ "name": "data.csv", "uploadId": "up_123" }]
}
```

Response (extra field):

```json
{
  "exit_code": 0,
  "stdout": "",
  "stderr": "",
  "duration_ms": 180,
  "session_id": "sess_abc123",
  "files": [{ "name": "n.txt", "mediaType": "text/plain", "uploadId": "up_456", "size": 2, "url": "/api/v1/uploads/up_456" }]
}
```

Each output file has `size` (bytes stored) and `url` (where to fetch it). Downloads use the protective headers listed in [Uploads API](/api/uploads#download-upload). `files` is left out of the response when the request staged no files. Input and output are each limited to 20 MB in total. A file name must not be empty or contain `/`, `\`, quotes or control characters. `files` needs the VM sandbox: the plain-subprocess fallback used when no VM driver is configured refuses it, and `/sandbox/execute/stream` rejects it with 400 `files_unsupported`.

### Streaming execution

```bash
curl -N -X POST http://127.0.0.1:8013/sandbox/execute/stream \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "code": "import time\nfor i in range(3):\n  print(f'step {i}')\n  time.sleep(1)",
    "language": "python"
  }'
```

Response (SSE):

```
data: {"type":"stdout","line":"step 0"}

data: {"type":"stdout","line":"step 1"}

data: {"type":"stdout","line":"step 2"}

data: {"type":"done","exit_code":0}
```

### Health check

```bash
curl -X GET http://127.0.0.1:8013/sandbox/health \
  -H "Authorization: Bearer <token>"
```

Response:

```text
OK
```

## Security

- Buffered `/sandbox/execute` (`execute_handler`) runs on the VM driver; when a warm pool is configured it checks out a health-checked VM and returns it afterwards, and a checkout failure returns 503 rather than falling back to an unsandboxed run.
- `/sandbox/execute/stream` does not use the VM driver or the pool. It spawns the process directly on the API host with a cleared, allow-listed environment, supports `python`, `node` and `bash`, and caps the timeout at 300 seconds. Use `/sandbox/execute` when you need VM isolation.
- `network_enabled` defaults to `false`.
- Execution timeout is enforced by the server.

## Error codes

| HTTP | Code / Message | Meaning |
|------|----------------|---------|
| 200 | — | Execution succeeded; check `exit_code` |
| 400 | `files_unsupported` | `files` was sent to `/sandbox/execute/stream` |
| 400 | `invalid file name` | A `files[].name` is empty or has a path or control character |
| 404 | `upload not found` | A `files[].uploadId` does not exist |
| 413 | `files[] is limited to 20MB in total` | Staged files exceed 20 MB |
| 503 | `VM driver not available` | No VM driver is initialized |
| 503 | `VM driver not initialized` | Health check failed |
