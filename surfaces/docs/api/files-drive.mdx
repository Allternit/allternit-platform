The Files drive protocol (`files/2`) is one set of requests that every client uses: the web app, the phone layout, the PWA, Desktop, iOS, Android and Gizzi Code. The contract is in `contracts/files-drive/` in the platform repo: `SPEC.md` says how it behaves, `schema/*.json` holds the message shapes, and `fixtures/` holds examples. The older [Files API](/api/files) covers cloud file storage and attachments and is a different system.

The protocol ships dark behind the per-account flag `files_drive`. A caller without it gets `feature_disabled`.

The routes the runtime (`allternit-api`) answers today, with what this release does not do yet, are listed in the [Files drive runtime API](/api/files-drive-runtime).

## Principles

- Routes take IDs, not paths. The one exception is adding a user folder as a root.
- Browsing never wakes or bills a computer. Only the wake-consent call wakes one.
- A write carries `base_rev`. A stale write becomes a conflict copy, never an overwrite.
- Every read says where it came from, in a `Freshness` object.
- Files in Inbox and shared folders are untrusted data.

## Runtime routes

The computer that owns the files serves these under `/api/v1/files/v2`.

| Method and path | Purpose |
| --- | --- |
| `GET /ping` | Returns `protocol: "files/2"`. |
| `GET /whoami` | Who the caller is and which permissions apply. |
| `GET /roots` | List roots. |
| `POST /roots` | Add a user folder as a root. |
| `PATCH /roots/:root_id` | Change a root's policy. |
| `DELETE /roots/:root_id` | Remove a user-added root. Files stay on disk. |
| `GET /roots/:root_id/list` | List a folder. |
| `GET /items/:item_id` | Stat an item. |
| `GET /items/:item_id/content` | Read bytes. Supports `Range` and `If-None-Match`. |
| `GET /items/:item_id/manifest` | Chunk manifest for a revision. |
| `GET /chunks/:hash` | One chunk's bytes. |
| `PUT /roots/:root_id/content` | Small write, 4 MiB or less. |
| `POST /mkdir`, `/move`, `/copy`, `/delete`, `/restore` | Change the tree. |
| `GET /roots/:root_id/trash` | List trash. |
| `GET /items/:item_id/versions` | List versions. |
| `POST /items/:item_id/versions/restore` | Restore a version. |
| `POST /search` | Search by name, or by content when the computer is awake. |
| `POST /pin` | Pin an item to keep it offline on a device. |
| `GET /roots/:root_id/changes` | Change feed, poll. |
| `GET /subscribe` | Change feed, WebSocket. |
| `GET /jobs/:job_id` | State of a large or cross-computer copy. |
| `GET /storage` | Volumes, free space and bytes per root. |
| `GET /items/:item_id/comments`, `POST /comments` | Comments. |
| `GET /replicas`, `POST /replicas`, `POST /replicas/restore` | Replicas, on the replica host. |

The relay maps any path containing `/files` to the `runtime:files` capability, so no new capability is needed.

### Roots

A root is a named folder with a policy: read, write, shareable, agent_process, protected, offline, replica, versions and `trash_days`. The default roots are `allternit_home` (`~/Allternit`), `inbox`, `shared`, `agent_output`, `downloads`, `meetings`, `scans`, `memory_drive`, `code` and `models`, plus any `user_added` root. `path_hint` is shown to the owner only and is never sent to guests.

`POST /roots` takes `local_path`. The runtime resolves symlinks, requires the folder to be inside the home folder, and refuses the secrets deny-list with `scope_violation`. A root added over the relay starts with `shareable: false` and `agent_process: false`.

A symlink that leads outside its root is not followed. A `protected` root answers `protected_root_locked` until the client sends a device unlock proof in `x-allternit-unlock`.

### Items and revisions

An item ID (`it_` plus an opaque string) comes from the index on the owning computer and survives rename and move. Never parse it.

A revision is `"<meta_version>-<blake3 content hash>"`, or `"<meta_version>-dir"` for a folder. It is the HTTP `ETag`.

### Conflicts

Small writes, upload commits, moves, deletes and version restores carry `base_rev`. When it is stale:

| `on_conflict` | Result |
| --- | --- |
| `keep_both` | The write lands as a conflict copy and the response carries `ConflictInfo`. Default for sync clients. |
| `fail` | `rev_mismatch` (409) with the `current` item. |
| `replace` | Refused while `base_rev` is stale. It only settles name clashes. |

The conflict copy is named `<stem> (conflict <device name> <YYYY-MM-DD HHmm>).<ext>`, for example `Lease (conflict iPhone 2026-11-15 1042).pdf`. If that name exists, ` 2`, ` 3` and so on is added before the closing parenthesis. A create with no `base_rev` whose name exists lands as `<stem> (2).<ext>` with `keep_both`, or returns `already_exists` with `fail`. Move, delete, trash and version restore with a stale `base_rev` always return `rev_mismatch`.

## Chunked upload

A file of 4 MiB or less can use the small write. Larger files, and any file that must resume, use an upload session.

### Chunker

| Parameter | Value |
| --- | --- |
| Algorithm | FastCDC, `v2020` |
| Minimum chunk | 262144 bytes (256 KiB) |
| Average chunk | 1048576 bytes (1 MiB) |
| Maximum chunk | 4194304 bytes (4 MiB) |
| Hash | blake3-256, lower-case hex |

Clients must pass the shared vectors in `contracts/files-drive/vectors/chunker-v1.json`. The schema rejects a chunk bigger than 4 MiB. The relay caps a request body at 5 MiB, and a 4 MiB chunk leaves room for the envelope.

### Flow

1. Chunk the file and compute each chunk hash and the whole-file hash.
2. `POST /chunks/have-need` with the hashes. The response lists what the computer still needs.
3. `POST /uploads` with the target (a new file under `parent_id`, or `item_id` at `base_rev`), the size, the hash and the first chunk refs.
4. `PUT /uploads/:session_id/chunks/:hash` for each needed chunk. For very large files, `POST /uploads/:session_id/chunks` appends more refs.
5. `POST /uploads/:session_id/commit`. The runtime checks every chunk hash and the whole-file hash.

A session survives a dropped connection until `expires_at`. `GET /uploads/:session_id` returns what is still needed, so a client resumes by sending only that. `DELETE /uploads/:session_id` cancels. Chunks are stored once per computer and shared between revisions.

Commit and put errors: `chunk_hash_mismatch` (bytes do not match their hash), `chunk_missing` (a needed chunk was never sent), `manifest_invalid` (a bad manifest, or a whole-file hash that does not match).

Write and upload-create requests can send `utc_offset_minutes` so the conflict name uses the editing device's local time.

## Change feed

Each root has a monotonic change cursor, formatted `c1.` plus an opaque string. Compare cursors only by asking the server.

- Poll: `GET /roots/:root_id/changes?cursor=&limit=&wait_s=`. `wait_s` is at most 25 and holds the request open until something changes.
- Subscribe: open the WebSocket and send a `SubscribeMessage` with a cursor per root. The server sends `changes`, `reset`, `state` and `heartbeat` frames.
- If the cursor is too old, the index was rebuilt or the root was removed, the answer is `reset_required: true` (poll) or a `reset` frame. List from scratch. `410 cursor_expired` is for a cursor that cannot be parsed or that names another root; treat it like a reset.

A held socket or long poll never counts as activity and never keeps a computer awake. When the computer sleeps the server sends `state: asleep` and closes.

## Wake consent

For `/api/v1/files/v2/*`, cloud-api does not call `wake_for_device` and does not touch the activity timer. Legacy `/api/v1/files/*` keeps its current wake behaviour until its callers move to v2.

While a computer sleeps:

- `roots`, `list`, `stat`, `changes` and name search are answered from the asleep snapshot, with `served_by: snapshot` and `computer_state: asleep`.
- `content`, `manifest`, `chunks`, uploads, writes and content search return `wake_consent_required` (409) with a `WakeHint` (`setting`, `consent_path`), unless the request carries a valid wake ticket.

### The consent call

```http
POST /api/v1/computer-files/:computer_id/wake-consent
```

The body is a `WakeConsentRequest` with a `WakeReason`. The computer's wake setting decides the result:

| Setting | Result |
| --- | --- |
| `ask` (default) | The client has already asked the user. The call wakes the computer and returns a ticket. |
| `auto` | Same, with no prompt. |
| `never` | `wake_denied`. |

The response is `{ticket, expires_at, computer_state: waking|awake, estimated_wake_s}`. Send the ticket in `x-allternit-wake-ticket` on later requests. A ticket lives 120 seconds, wakes its computer at most once, and can be sent on any number of requests to that one computer until it expires. The consent call records one activity touch, so the idle sweep does not put the computer back to sleep right after the wake. A transfer that outlasts the idle window asks for a new ticket.

Get and set the setting with `GET` and `PUT /api/v1/computer-files/:computer_id/wake-settings`.

### The snapshot

The runtime writes file names, sizes and revisions, never contents, to the user's own R2 bucket. It writes only while awake: on a sleep notice, and at most every 5 minutes while changes are pending. Names are plain text in v2 (`names_encrypted: false`). Protected roots are left out, and `path_hint` and local paths are never included.

## Transports and where a read comes from

`GET /api/v1/computer-files/:computer_id/endpoints` returns transport candidates sorted by `priority`, lowest first.

| Transport | Used for |
| --- | --- |
| `loopback` | The Desktop app talking to its own runtime. |
| `mesh` | Between the owner's own devices. |
| `relay` | Always available. The baseline. |
| `gateway` | Guests. |

Cloud computers are relay only. A client picks the first source that works: loopback, mesh, relay (awake only), a current replica on another device, the snapshot (metadata only), then the device's own cache.

## Relay

A client posts a `RelayRequest` to `POST /api/v1/runtime-devices/:computer_id/proxy` with `path` set to `/api/v1/files/v2/...`. The request body is `{method, path, headers, body, body_encoding}`. cloud-api accepts `body_encoding` and the older `bodyEncoding`. The relay streams the runtime's raw response back.

The relay passes these request headers through to the runtime:

| Header | Purpose |
| --- | --- |
| `x-allternit-wake-ticket` | The wake ticket from the consent call. |
| `range` | Partial reads of `content`. |
| `if-match` | Revision precondition. |
| `x-allternit-unlock` | Unlock proof for a protected root. |
| `x-allternit-device-id` | Which of the owner's devices is calling. |

The relay caps a request body at 5 MiB, measured as the decoded size. Live change-feed sockets use the existing socket-ticket flow.

The computer ID is the cloud-api `computer_id`.

## Sharing routes

| Method and path | Purpose |
| --- | --- |
| `POST /api/v1/computer-files/:computer_id/shares` | Create a share. |
| `GET /api/v1/computer-files/:computer_id/shares` | List shares. |
| `DELETE /api/v1/computer-files/shares/:share_id` | Revoke. Applies on the guest's next request. |
| `GET /api/v1/computer-files/shares/:share_id/access` | Audit rows. |
| `GET /api/v1/files-gateway/summary` | Public summary for a link. |
| `POST /api/v1/files-gateway/redeem` | Exchange a link and passcode for a guest session. |
| `/api/v1/files-gateway/v2/*` | The guest subset of the runtime routes. |

Guests send `Authorization: Files-Guest` followed by a capability token. See the [sharing guide](/guides/files-sharing).

The guest page at `ai.allternit.com/s/` followed by the link token calls summary first, then redeem with the passcode when `passcode_required` comes back. It sends `Authorization: Files-Guest` on the v2 routes and redeems again about a minute before the token lapses (tokens last one hour), so a long visit does not ask for the passcode twice. Error codes it handles: `passcode_required`, `passcode_invalid`, `rate_limited`, `share_expired`, `share_revoked`, `not_found`, `guest_wake_not_allowed`. The owner's share dialog creates a share with `role`, optional `expires_at`, `passcode`, `invite_emails` and `guest_wake`. The "let an agent process files" switch is not part of the share. It updates the root policy field `agent_process`.

### Capability tokens

Wake tickets and guest tokens share one format: a prefix, the claims as base64url JSON, and an Ed25519 signature, joined by dots. The prefix is `awt1` for a wake ticket and `fgt1` for a guest token. cloud-api signs them. Runtimes fetch public keys from `GET /api/v1/computer-files/token-keys` and verify offline.

Two checks apply to a guest. The gateway checks the token and whether the share is revoked. The runtime then checks scope (computer, root, item, role) on every request. Roles are `view_download`, `upload_only`, `edit` and `comment`. An `upload_only` guest cannot list. A passcode is checked at redeem (`passcode_required`, `passcode_invalid`). A guest never wakes the owner's computer unless the share has `guest_wake: true`.

## Principals

| Principal | Authenticates with | Reaches |
| --- | --- | --- |
| `owner` | The user's session or API token | All roots on their computers. |
| `own_device` | The owner token plus `x-allternit-device-id`, or mesh identity | Same as owner. Pins and caches are per device. |
| `guest` | A capability token | One folder or file, one role. |
| `agent` | The runtime session with an `AgentGrant` | Only the roots and tools in the grant. |

`agent_process` is separate from share roles, and `transfer` is separate from `execute`.

## Events

| Event | When |
| --- | --- |
| `files.changed` | A create, modify, move, rename, delete, trash or restore. |
| `files.inbox.dropped` | A file landed in Inbox. Carries `untrusted` and the task state. |
| `files.task.result` | An Inbox or folder-rule task finished, failed or was rejected. |
| `files.share.accessed` | Every guest access, allowed or denied. |
| `files.conflict` | A write landed as a conflict copy. |

## Versions and trash

Each root keeps versions by count and age. `keep_days` counts from the time a version was replaced, and 0 means no limit. Delete moves to trash unless `permanent` is set. `trash_days: 0` deletes at once. A write whose `base_rev` names a file that is now gone creates it with `keep_both`, and returns `not_found` with `fail` or `replace`.

The web Files tab lists versions per file and trash per root, and restores either. A restore into a taken name returns the item under a new name. There is no route yet to download an old version or to empty the trash.

## Errors

Every error body is `ErrorBody`: `{error, message, code}` plus optional `retry_after_s`, `computer_state`, `wake`, `current` and `missing_chunks`. `error` and `code` both hold the error code.

| HTTP | Codes |
| --- | --- |
| 400 | `invalid_request`, `invalid_name`, `manifest_invalid`, `chunk_hash_mismatch` |
| 401 | `unauthorized`, `passcode_required`, `passcode_invalid` |
| 403 | `forbidden`, `feature_disabled`, `scope_violation`, `protected_root_locked`, `agent_process_denied`, `execute_denied`, `guest_wake_not_allowed`, `wake_denied` |
| 404 | `not_found`, `root_not_found`, `upload_session_not_found` |
| 409 | `already_exists`, `rev_mismatch`, `wake_consent_required`, `chunk_missing` |
| 410 | `share_expired`, `share_revoked`, `upload_session_expired`, `cursor_expired` |
| 413 | `payload_too_large` |
| 422 | `integrity_failed` |
| 429 | `rate_limited` |
| 500 | `internal` |
| 501 | `unsupported` |
| 503 | `asleep`, `waking`, `offline`, `replica_unavailable`, `key_unavailable` |
| 507 | `quota_exceeded` |
