## Overview

The Files drive serves the files on one computer to the owner's other devices. Every request names roots and items by opaque ID, never by path. Writes carry the revision the client last saw, so a stale write becomes a conflict copy instead of an overwrite. Big files move as content-defined chunks that resume after a dropped connection.

The full contract lives in the platform repo at `contracts/files-drive/SPEC.md`, with JSON schemas in `contracts/files-drive/schema/` and generated Rust, TypeScript, Swift and Kotlin types. This page covers the **runtime** side: the routes `allternit-api` answers on the computer that owns the files. The cloud-api routes (wake consent, endpoints, shares and the guest gateway) are documented with their own release.

<Note>
The Files drive ships dark. On the runtime it is off unless the process runs with `ALLTERNIT_FILES_DRIVE=1`. While it is off, every route answers `403 feature_disabled` and nothing is created on disk. The per-user `files_drive` flag is held by cloud-api.
</Note>

## Base URL

```text
http://127.0.0.1:8013/api/v1/files/v2
```

Other devices reach the same routes through the cloud relay: `POST /api/v1/runtime-devices/{computer_id}/proxy` with `path` set to `/api/v1/files/v2/...`.

## Authentication and callers

Requests go through the platform auth middleware like every other runtime route. The runtime then decides the **principal**:

| Principal | When | Reaches |
|---|---|---|
| `owner` | the signed-in user, no device header | every root |
| `own_device` | the owner's token plus `X-Allternit-Device-Id` | every root; pins are per device |

A request replayed by the relay (it carries `x-allternit-relayed`), forwarded by a proxy, or sent from a non-loopback peer is a **relayed caller**. Relayed callers reach registered roots only, which is all v2 exposes, and a folder they add starts with sharing and agent access turned off.

Two more headers matter:

- `X-Allternit-Device-Name` names the device in conflict-copy names when the request does not say.
- `X-Allternit-Unlock` is the proof of a fresh device unlock (Face ID, Windows Hello). Protected roots answer `403 protected_root_locked` without it. Today any non-empty value is accepted; a signed unlock assertion replaces it before the drive leaves the flag.

Files traffic never counts as activity: no v2 request, long poll or socket resets the computer's idle timer or keeps it awake.

## Roots

The first request creates the default roots:

| Kind | Name | Folder | Notes |
|---|---|---|---|
| `allternit_home` | Allternit | `~/Allternit` | parent of the six folders below |
| `inbox` | Inbox | `~/Allternit/Inbox` | shareable; agents may take items as task inputs |
| `shared` | Shared | `~/Allternit/Shared` | shareable |
| `agent_output` | Agent Output | `~/Allternit/Agent Output` | agent results |
| `downloads` | Downloads | `~/Allternit/Downloads` | `provider_ready: false` until downloads land here |
| `meetings` | Meetings | `~/Allternit/Meetings` | `provider_ready: false` until recordings land here |
| `scans` | Scans | `~/Allternit/Scans` | `provider_ready: false` until phone scans land here |
| `memory_drive` | Memory Drive | your Memory Drive | protected; writes become Memory Drive commits |
| `code` | Code | `ALLTERNIT_FILES_CODE_DIR` | `provider_ready: false` while unset; add your code folder with `POST /roots` instead |
| `models` | Models | the local engine's model cache | read-only here; no versions or trash |
| `user_added` | your choice | a folder you pick | see [Adding a folder](#adding-a-folder) |

`path_hint` (for example `~/Allternit/Inbox`) is sent to the owner and own devices only, never for a provider's internal folder.

### Memory Drive

Memory Drive is a git repository, not a folder. The runtime shows its current files as a read view and turns every Files write or delete there into one commit through the Memory Drive write path, so its history and checks stay in force. Only Markdown files can be written. Writes there fail closed: an existing name without `base_rev`, or a stale `base_rev`, is an error, never a conflict copy. Making folders, moving, copying in, uploading and restoring versions are refused with `forbidden`.

### Adding a folder

`POST /roots` takes an `AddRootRequest` with `local_path`. The runtime resolves `~`, refuses `..`, follows symlinks, and requires the real folder to exist inside the home folder. It refuses, with `403 scope_violation`, the home folder itself, the secrets deny-list (`~/.ssh`, `~/.gnupg`, cloud CLI credentials, keychains, agent CLI tokens, `~/.allternit` private state), any folder that contains one of those, and the Allternit data folders. These are the same rules as the [Workspace Files](/api/workspace-files) routes.

A relayed caller may not turn sharing or agent access on, or protection off, with `PATCH /roots/{root_id}`; those changes are made from the computer itself.

## Writing files

A file of 4 MiB or less may use the small write:

```bash
curl -X PUT "http://127.0.0.1:8013/api/v1/files/v2/roots/$ROOT/content?parent_id=$PARENT&name=Lease.pdf&base_rev=$REV&on_conflict=keep_both&device_name=iPhone&utc_offset_minutes=-360" \
  --data-binary @Lease.pdf
```

Anything bigger, or anything that must resume, uses an upload session: `POST /uploads` with the chunk list, `POST /chunks/have-need` or the session's `need` list to skip chunks the computer already has, one `PUT` per needed chunk, then `POST /uploads/{session_id}/commit`. The runtime checks every chunk hash and the whole-file hash at commit (`chunk_hash_mismatch`, `chunk_missing`, `manifest_invalid`).

Body limits: the small write and the chunk `PUT` take at most 4 MiB + 64 KiB; every other v2 route takes 1 MiB. A bigger body returns `413 payload_too_large`.

### Conflicts

With a stale `base_rev` and `on_conflict: keep_both` (the default), the write lands beside the original as `Lease (conflict iPhone 2026-11-15 1042).pdf` and the response carries `ConflictInfo`. The date and time are the writing device's local time, from `utc_offset_minutes` (-840 to 840); without it the runtime uses UTC. The device name comes from `device_name`, then `X-Allternit-Device-Name`, then the principal's name. `on_conflict: fail` returns `409 rev_mismatch` with the item as it is now in `current`.

## Reading files

`GET /items/{item_id}/content` returns the bytes with `ETag: "<rev>"` and `Accept-Ranges: bytes`. Send `If-None-Match: "<rev>"` to get `304` when nothing changed, or `Range: bytes=0-1023` for a `206` partial response. A range past the end returns `416`.

A symlink inside a root that resolves outside it is listed with `read: false`; reading it returns `403 scope_violation`.

## Change feed

Each root has a change cursor. `GET /roots/{root_id}/changes?cursor=<cursor>&wait_s=25` returns the changes after the cursor and a new one; `wait_s` (at most 25) holds the request until something changes. When the cursor is too old the response has `reset_required: true` and the client lists the root again.

`GET /subscribe` opens a WebSocket. The client's first frame is a `SubscribeMessage`:

```json
{"type": "subscribe", "roots": [{"root_id": "rt_…", "cursor": "c1.…"}]}
```

The server sends `changes` frames as files change, `reset` frames when a cursor expires or a root is removed, and a `heartbeat` every 25 seconds. A protected root without the unlock header closes the socket with reason `protected_root_locked`.

## Search and intelligence

The runtime indexes the text of files on the computer that owns them. The index lives in `intel.sqlite` beside the engine database and never leaves the computer.

### Search modes

`POST /search` takes `mode`:

- `name`: the file name contains the query. Always available.
- `full_text`: words inside files and names, ranked by relevance (SQLite FTS5, bm25). Words match any-of, best match first. Put the query in double quotes to match a phrase. Each hit carries a `snippet` of the matching text.
- `semantic`: files closest in meaning to the query, using the local embedding endpoint (`ALLTERNIT_EMBED_URL`, by default the loopback model on port 7719). With no model reachable the route answers `501 unsupported`, and no vectors are made. The hash fallback the memory index uses is not used here, because it carries no meaning.

`index_state` is `building` until the background worker has caught up with the files, then `ready`. Searches only return files in roots the caller may read. A caller that is an agent sees only roots whose policy allows `agent_process`. A guest gets no hits from these routes; guests search inside their share through the sharing gateway. Snippets are file content and are never returned to a guest. A protected root needs the unlock header, as everywhere else.

### What is indexed, and when

- **Text files only.** A file is indexed when it is UTF-8 with no NUL bytes in its first 8 KiB, up to 2 MiB of it. PDF, Office files and audio are not read yet. Images get a thumbnail and no text.
- **Only while the computer is awake (D12).** Indexing, embeddings and previews run on one background thread inside the runtime process. They never wake a computer, never reset its idle timer, and use no company compute. The embedding call goes to the endpoint on the computer.
- **CPU budget.** One thread at low priority (niced on Linux), held to a duty cycle of **25% of one core** by default: after each file it rests three times as long as the file took. At most 8 files per pass. When a pass finds nothing the wait before the next doubles from 30 seconds up to 5 minutes. Set `ALLTERNIT_FILES_INTEL_CPU_PERCENT` (1 to 100), `ALLTERNIT_FILES_INTEL_BATCH` (1 to 200) or `ALLTERNIT_FILES_INTEL=off` to change it. This keeps a 2 CPU, 4 GB cloud computer usable for the user's own work.
- **Protected roots are skipped.** The Memory Drive and any root with `protected: true` are not indexed. The owner can opt a root in with `PUT /intel/roots/{root_id}` and `{"index": true}`, which needs the device unlock and does not work over a relay. Opting out removes what was indexed.

### Routes

| Method | Path | Notes |
|---|---|---|
| `GET` | `/intel/status` | Index progress, models in use, the CPU budget |
| `PUT` | `/intel/roots/{root_id}` | `{"index": bool}`: opt a protected root in or out (owner only) |
| `GET`, `POST` | `/intel/tags` | Tag counts. `POST {item_id, add, remove}` changes an item's tags (needs write access) |
| `GET` | `/intel/tags/{tag}/items` | Items with a tag, readable ones only |
| `POST` | `/intel/provenance` | `{item_id, provenance}`. A change from an agent is always `ai_generated: true` |
| `GET` | `/intel/dedup?root_id=` | Groups of files with the same content hash, with the bytes saved by keeping one |
| `GET`, `POST` | `/intel/collections` | List, or create `{name}` (owner only) |
| `GET`, `POST`, `DELETE` | `/intel/collections/{id}` | Items in it, `POST {item_id, remove?}` to add or remove, delete |
| `GET` | `/items/{item_id}/preview?kind=` | `thumbnail` (PNG, 256 px) or `text` (first 2000 characters). `404` until indexed, never the preview of an older version |
| `POST` | `/intel/actions` | `{item_id, action}`: `summarize` is extractive (sentences picked from the file, no model); `transcribe` returns `501 unsupported` |
| `GET`, `POST` | `/intel/rules` | Folder rules (owner only): `{folder_id, action: "summarize"}` summarizes new and changed files under that folder |
| `DELETE` | `/intel/rules/{id}` | Remove a rule |

Items returned anywhere carry `tags`, `provenance` (shown by clients as an AI-generated label when `ai_generated` is true) and `has_thumbnail` when they exist. Summaries and transcripts are never made on their own: only an explicit action or a folder rule the owner created runs them.

## Errors

Every error is an `ErrorBody`: `{error, code, message}` plus Files fields (`current`, `missing_chunks`, `retry_after_s`, `computer_state`, `wake`). `error` and `code` hold the same code.

| HTTP | Codes |
|---|---|
| 400 | `invalid_request`, `invalid_name`, `manifest_invalid`, `chunk_hash_mismatch` |
| 401 | `unauthorized` |
| 403 | `forbidden`, `feature_disabled`, `scope_violation`, `protected_root_locked` |
| 404 | `not_found`, `root_not_found`, `upload_session_not_found` |
| 409 | `already_exists`, `rev_mismatch`, `chunk_missing` |
| 410 | `upload_session_expired`, `cursor_expired` |
| 413 | `payload_too_large` |
| 422 | `integrity_failed` |
| 501 | `unsupported` |
| 500 | `internal` |
