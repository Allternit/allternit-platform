## Overview

The Voice API provides text-to-speech (TTS), speech-to-text (STT), voice session management, and service introspection. The Rust voice service (`services/voice`) listens on port `8001` (override with the `PORT` environment variable). Both STT and TTS are real and run on [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) inside the binary:

- **STT:** Silero VAD segments the audio, then Moonshine tiny (default) or Parakeet TDT 0.6B v3 (accurate) transcribes each segment. Any sample rate is accepted and resampled to 16 kHz; 8 kHz phone audio (including G.711 μ-law WAV) works.
- **TTS:** Kokoro-82M v1.0 (fp32), 28 English voices (default `af_heart`), 24 kHz output. Kokoro runs in `allternit-tts`, a separate GPL-3.0 program the service starts as a child process.
- **Models download on first use** into `~/.allternit/models/voice/<pack>/` (sha256-verified). The `small` pack (~39 MB: VAD + Moonshine + Smart Turn) downloads on first speech-to-text use, the `tts` pack (~350 MB: Kokoro v1.0) on first text-to-speech use; the `accurate` pack (~487 MB, Parakeet, CC-BY-4.0) downloads on first accurate-STT request. Poll `GET /v1/models` for `missing | downloading | ready | error` state. Override the download base with `ALLTERNIT_VOICE_MODEL_BASE`.
- Inference uses `ALLTERNIT_VOICE_THREADS` threads (default **2**), CPU provider, one model at a time, so voice stays light on a 4-core laptop.

Licences and attributions: `services/voice/THIRD_PARTY_NOTICES.md` (sherpa-onnx Apache-2.0; Moonshine MIT; Kokoro Apache-2.0; Silero VAD MIT; Smart Turn BSD-2-Clause; Parakeet CC-BY-4.0, attribution required; onnxruntime MIT). The voice service contains no GPL code; `allternit-tts` is GPL-3.0-or-later because it links espeak-ng (`services/voice-tts/LICENSE`).

## Base URL

```
http://localhost:8001
```

The voice service binds to `127.0.0.1:8001` by default. When deployed behind the Allternit gateway, it may be exposed under a platform path; consult your deployment's routing table.

## Authentication

The standalone voice service does not require authentication in local development. When exposed through the platform API, standard bearer-token auth applies. See [Authentication](/api/authentication).

### Desktop sidecar token

Allternit Desktop starts the voice service with `ALLTERNIT_VOICE_TOKEN` set to a random secret generated for each app run. The Voice Session WebSocket (`/v1/voice/session?token=…`) accepts that token; without it, the service accepts loopback connections only. The app gets the URL and token from the Desktop preload bridge:

```ts
const endpoint = await window.allternit.voice.getSessionEndpoint();
// { httpUrl: 'http://127.0.0.1:8001', wsUrl: 'ws://127.0.0.1:8001/v1/voice/session', port: 8001, token?: string }
```

`token` is present only when this Desktop run started the service itself; a service that was already running never received this run's token, so the app connects over loopback without one. The token never leaves the machine and is not shown in the UI.

## Text-to-speech

```http
POST /v1/tts
```

Synthesises speech and returns audio bytes (`audio/wav` by default; pass
`format: "pcm16"` for raw s16le mono 24 kHz). The first request downloads
the `small` pack if it is not on disk yet.

### Request body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `text` | string | Yes | Text to synthesize. |
| `voice` | string | No | Kokoro voice id; default `af_heart`. Alias `voice_id` accepted. |
| `language` | string | No | Language hint (reserved). |
| `speed` | number | No | Speech speed multiplier (default 1.0). |
| `format` | string | No | `wav` (default) or `pcm16`. |

### Example request

```bash
curl -X POST http://localhost:8001/v1/tts \
  -H "Content-Type: application/json" \
  -d '{"text": "Hello from Allternit", "voice": "af_heart"}' \
  --output hello.wav
```

### Response

`200 OK`: `audio/wav` bytes (or raw pcm16 with `format: "pcm16"`) with
`X-Duration-Seconds`, `X-Sample-Rate`, and `X-Format` headers. `400` for
empty text, an unknown voice or an unsupported format; `503` if the model
could not be downloaded or loaded. Errors are JSON: `{ "error": "..." }`.

## Streaming text-to-speech

```http
POST /v1/tts/stream
```

Streaming TTS: the text is split into sentences, the first one cut at its
first clause (or about halfway) so the first audio is short, and each piece
is emitted as soon as it is synthesised, so playback starts before the
whole text is done.

### Response

`200 OK` — `application/x-ndjson` stream:

```jsonl
{"type":"audio","index":0,"text":"Hello there.","sample_rate":24000,"format":"pcm16","audio_b64":"<s16le base64>"}
{"type":"audio","index":1,"text":"How can I help?","sample_rate":24000,"format":"pcm16","audio_b64":"<s16le base64>"}
{"type":"done","duration_secs":4.32}
```

A failure mid-stream sends `{"type":"error","error":"..."}` and ends the
stream.

Decode each `audio_b64` to raw s16le mono PCM at `sample_rate`; concatenating
all chunks yields the full utterance.

## Speech-to-text

```http
POST /v1/stt
```

Transcribes uploaded audio passed as multipart form data. Accepts WAV
(PCM 8/16/24/32-bit, float32, G.711 μ-law/A-law; any sample rate; mono or
stereo) or raw 16 kHz s16le PCM. Audio is resampled to 16 kHz and segmented
by Silero VAD; each segment is transcribed with the selected model.

### Request body (multipart)

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `audio` | bytes | Yes | Audio bytes (`.wav` or raw pcm16). |
| `language` | string | No | Language hint (echoed back). |
| `model` | string | No | `moonshine` (default) or `parakeet` (accurate pack). |
| `sample_rate` | integer | No | Only for raw PCM without a WAV header; default 16000. |

### Example request

```bash
curl -X POST http://localhost:8001/v1/stt \
  -F "audio=@recording.wav" \
  -F "language=en"
```

### Example response

```json
{
  "text": "hello world",
  "confidence": 0.9,
  "language": "en",
  "segments": [
    {
      "start_time": 0.0,
      "end_time": 1.4,
      "text": "hello world",
      "confidence": 0.9
    }
  ]
}
```

`segments` carry VAD-derived timestamps. `confidence` is a heuristic —
the offline recognisers do not emit per-word confidence.

### First use: voice pack downloading

If the model pack is not on disk yet, the request starts the download and
returns `503` right away (with a `Retry-After: 5` header) instead of hanging:

```json
{
  "error": "Downloading the voice pack (39 MB)… try again in a moment.",
  "code": "voice_pack_downloading",
  "pack": "small",
  "pct": 0.4,
  "size_bytes": 39181595,
  "retry_after_secs": 5
}
```

Retry after a few seconds, or poll `GET /v1/models`. Desktop dictation shows
the message to the user and a later press transcribes normally.

## Streaming speech-to-text

```http
POST /v1/stt/stream
```

Streaming STT: send raw s16le mono PCM in chunks as you capture it
(`?sample_rate=`, default 16000; `?model=moonshine|parakeet`) and read
`application/x-ndjson` events as speech is segmented:

```jsonl
{"type":"partial","text":"hello wor"}
{"type":"final","text":"hello world","start":0.0,"end":1.4}
{"type":"done","duration_secs":6.1}
```

`partial` is an interim transcript of the speech in progress (each replaces
the last); `final` is a finished segment, sent after 0.3 s of silence, with
times in seconds from the start of the stream. Finish the request body to
flush trailing speech and get `done`. Several streams can run at once.

## Error codes

| Status | Meaning |
|--------|---------|
| `200 OK` | Success. |
| `204 No Content` | Session deleted successfully. |
| `202 Accepted` | Pack download started. |
| `400 Bad Request` | Missing audio, empty text, unknown model/voice/format, or bad `sample_rate`. |
| `404 Not Found` | Voice or session not found. |
| `415 Unsupported Media Type` | Unsupported audio container (e.g. WebM/Opus — decode to WAV client-side). |
| `503 Service Unavailable` | Engine failed to initialise (e.g. model download/verify failure). |

## Voice Session (realtime)

`GET /v1/voice/session` is a WebSocket for live voice conversations. It carries mic audio in, live transcripts and end-of-turn events out, and speaks reply text as it streams in. Barge-in stops the speech when the user talks over it. Implementation IMPLEMENTED (engine traits, state machine, WebSocket route, Smart Turn), with the speech engine wired once the sherpa-onnx engine lands; Exposure INTERNAL (Desktop sidecar). The canonical protocol is [`services/voice/spec/VOICE_SESSION.md`](https://github.com/Gizziio/allternit/blob/main/services/voice/spec/VOICE_SESSION.md).

Voice is input and output only. The app sends each final user turn to the agent as a normal chat message, then streams the agent's reply text back to be spoken.

### Connect

| Where | URL |
|-------|-----|
| Desktop sidecar | `ws://127.0.0.1:<port>/v1/voice/session?token=<sidecar token>` |
| Allternit Cloud | `wss://…/v1/voice/session?ticket=<short-lived ticket>` |

`token` must match the service's `ALLTERNIT_VOICE_TOKEN`. If that variable is unset, only loopback connections are accepted. A failed check returns `401` before the upgrade, with a message that says whether the ticket was invalid or Allternit Cloud could not be reached.

### Cloud tickets and usage

On Allternit Cloud the service redeems each `ticket` against cloud-api before the upgrade. Tickets are single-use. It does this only when both variables are set; otherwise every ticket is refused.

| Variable | Purpose |
| --- | --- |
| `ALLTERNIT_CLOUD_API_URL` | Base URL of cloud-api. |
| `ALLTERNIT_VOICE_WORKER_TOKEN` | Bearer token for `POST /api/v1/voice/tickets/redeem` and `POST /api/v1/voice/usage`. |

A ticket session reports `engine: "cloud"` in `session.ready`. The ticket carries a `maxSeconds` limit. When the session reaches it, the service sends `error` with `code: "session_limit"` and `fatal: true`, then closes the socket.

When the session closes for any reason, the service reports the wall-clock duration (rounded up to whole seconds) to cloud-api as Cloud Voice minutes. It retries in the background for about a minute, and cloud-api ignores duplicates for the same session. Token and loopback sessions, such as the Desktop sidecar and the call worker, report nothing.

### Frames

- **Text frames** are JSON with a `type`.
- **Binary frames** are audio. Client → server is PCM16 LE mono mic audio at `inputSampleRate` (default 16000, 20 ms frames). Server → client is PCM16 LE mono speech at `outputSampleRate` from `session.ready`.

| Client → server | Fields | Meaning |
|-----------------|--------|---------|
| `session.start` | `voice?`, `sttModel?` (`light`/`accurate`), `language?`, `inputSampleRate?`, `bargeIn?` (default `true`), `turn?` {`mode`: `smart`/`vad`, `silenceMs?`} | First frame. The answer is `session.ready` or `error`. |
| `session.update` | any `session.start` field | Change settings mid-session. |
| `speak.delta` | `id`, `text` | Append reply text. It's spoken sentence by sentence. |
| `speak.done` | `id` | No more text for `id`. |
| `speak.cancel` | `id?` | Stop speaking `id` (or the current one). The answer is `speak.ended`. |
| `mic.mute` / `mic.unmute` | | Ignore mic audio while muted. |
| `session.end` | | Close. |

| Server → client | Fields | Meaning |
|-----------------|--------|---------|
| `session.ready` | `protocol` (1), `sessionId`, `engine` (`device`/`cloud`), `outputSampleRate`, `models` {stt, tts, vad, turn}, `voices` | Ready. |
| `speech.started` / `speech.stopped` | `atMs` | VAD start and stop, in ms of mic audio. |
| `transcript.delta` | `segmentId`, `text`, `final: false` | Live caption. |
| `transcript.final` | `segmentId`, `text` | Final text for a segment. |
| `turn.ended` | `text`, `confidence` | The user's turn is over. Send `text` to the agent now. |
| `speak.started` / `speak.ended` | `id` | Brackets the speech audio for `id`. |
| `speak.interrupted` | `id`, `sentMs` | Barge-in. Flush playback now and abort the agent's turn. |
| `error` | `code`, `message`, `fatal` | `fatal: true` closes the socket. |

### Turn detection

- `smart` (default) runs Smart Turn v3.2 at each pause. A score of 0.5 or more ends the turn at once. Below that, the turn ends after `silenceMs` of silence (default 1500).
- `vad` ends the turn after `silenceMs` of silence (default 700).

### Example

```json
→ {"type":"session.start","inputSampleRate":48000,"turn":{"mode":"smart"}}
← {"type":"session.ready","protocol":1,"sessionId":"…","engine":"device","outputSampleRate":24000,"models":{"stt":"moonshine-tiny-en","tts":"kokoro-en-v0_19","vad":"silero-vad","turn":"smart-turn-v3.2"},"voices":["af","…"]}
→ (binary mic frames)
← {"type":"speech.started","atMs":1180}
← {"type":"transcript.delta","segmentId":"seg-1","text":"what time","final":false}
← {"type":"turn.ended","text":"What time is it?","confidence":0.93}
→ {"type":"speak.delta","id":"r1","text":"It's noon. "}
→ {"type":"speak.done","id":"r1"}
← {"type":"speak.started","id":"r1"}
← (binary speech frames)
← {"type":"speak.ended","id":"r1"}
```

To try it from a terminal, run `cargo run -p voice-service --example voice_session_client -- --wav question.wav --say "It is noon." --out reply.wav`.

## Custom voices (cloud-api)

Custom voices live in the Allternit Cloud API, not the voice service. All routes need a signed-in user, except the two worker routes, which need the voice worker token. See the [Custom voices guide](/guides/custom-voices).

| Method and path | Purpose |
|---|---|
| `GET /api/v1/voice/custom-voices/consent-text` | The current consent statement, its `version`, and the allowed clip length (`minSeconds`, `maxSeconds`). |
| `POST /api/v1/voice/custom-voices` | Record consent and create a voice. Body: `name`, `speakerName`, `relationship` (`self` or `authorized`), `consentVersion`, `consentAccepted` (must be `true`), `clipBase64` (a 16-bit mono PCM WAV, 8–24 s, under 1.6 MB). Returns `201` with `id`, `voiceId` (`custom:<id>`) and `clipSha256`. |
| `GET /api/v1/voice/custom-voices` | List your active voices. |
| `DELETE /api/v1/voice/custom-voices/{id}` | Revoke: deletes the clip, ends consent, resets bots using the voice to `allternit-default`. Idempotent (`204`). |
| `GET /api/v1/voice/custom-voices/{id}/consent` | Worker only: whether consent is on file, with the clip hash. |
| `GET /api/v1/voice/custom-voices/{id}/clip` | Worker only: the reference clip. |

Errors carry `{ "code", "message" }`: `consent-required` (422), `consent-text-changed` (409), `bad-clip` (422), `clip-too-large` (413), `too-many-voices` (409).

The voice service checks consent through the worker routes before it speaks a `custom:` voice, and refuses with the realtime error code `custom_voice_refused` if consent is missing or revoked. If it can't reach the cloud to check, it reports the voice as unavailable rather than speaking. The voice's engine is Pocket TTS, from the `voices` model pack.
