# Service Accounts

<Note>
These endpoints are served by the Allternit runtime (the Desktop app, or a paired or hosted computer), not by `api.allternit.com`. On Allternit Cloud the console hides this page.
</Note>


Service accounts are machine identities that receive scoped credentials. They are useful for CI/CD pipelines, background workers, and integrations that should not use a personal user token.

Each service account has a `client_id` and `client_secret`. The secret is returned only on creation and rotation; at all other times only its SHA-256 hash is stored.

## Base URL

```text
http://127.0.0.1:8013/api/v1/admin/service-accounts
```

The base URL is the Allternit runtime's (Desktop app, or a paired or hosted computer), not `api.allternit.com`.

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/api/v1/admin/service-accounts` | Create a service account |
| `GET` | `/api/v1/admin/service-accounts` | List service accounts |
| `GET` | `/api/v1/admin/service-accounts/:id` | Get a service account |
| `PATCH` | `/api/v1/admin/service-accounts/:id` | Update a service account |
| `DELETE` | `/api/v1/admin/service-accounts/:id` | Delete a service account |
| `POST` | `/api/v1/admin/service-accounts/:id/rotate` | Rotate the client secret |

## Scopes

Scopes are passed as a comma-separated string on creation or update and returned as an array. Typical scopes include:

- `gateway:read`
- `gateway:write`
- `admin`

## Create a service account

```bash
curl -X POST http://127.0.0.1:8013/api/v1/admin/service-accounts \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Pipeline CI",
    "scopes": "gateway:read,gateway:write"
  }'
```

### Request body

```json
{
  "name": "Pipeline CI",
  "scopes": "gateway:read,gateway:write"
}
```

### Response

```json
{
  "id": "sa_01hqx8x7x7x7x7x7x7x7x7x",
  "org_id": "org_01hqx8x7x7x7x7x7x7x7x7x",
  "name": "Pipeline CI",
  "client_id": "sa-550e8400e29b41d4a716446655440000",
  "client_secret": "sasec-dGhpcyBpcyBhIHNlY3JldA",
  "scopes": ["gateway:read", "gateway:write"],
  "created_at": "2026-08-13T18:00:00Z",
  "last_rotated_at": "2026-08-13T18:00:00Z"
}
```

<Warning>
  Save the `client_secret` immediately. It cannot be retrieved later.
</Warning>

## Update a service account

```bash
curl -X PATCH http://127.0.0.1:8013/api/v1/admin/service-accounts/sa_01hqx8x7x7x7x7x7x7x7x7x \
  -H "Authorization: Bearer $ADMIN_TOKEN" \

  }'
```

## Rotate a client secret

```bash
curl -X POST http://127.0.0.1:8013/api/v1/admin/service-accounts/sa_01hqx8x7x7x7x7x7x7x7x7x/rotate \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

### Response

```json
{
  "id": "sa_01hqx8x7x7x7x7x7x7x7x7x",
  "client_id": "sa-550e8400e29b41d4a716446655440000",
  "client_secret": "sasec-bmV3IHNlY3JldCB2YWx1ZQ",
  "last_rotated_at": "2026-08-13T18:05:00Z"
}
```

Rotation invalidates the previous secret immediately.

## Authenticate with a service account

Use the `client_id` and `client_secret` as a Bearer token or exchange them for an access token according to your organization's auth flow. Pass the resulting token in the `Authorization` header:

```bash
curl -X GET http://127.0.0.1:8013/api/v1/admin/workspaces \
  -H "Authorization: Bearer $SERVICE_ACCOUNT_TOKEN"
```

## Error codes

| Status | Code | Description |
|--------|------|-------------|
| `400` | `invalid_name` | Name must be 1–128 characters. |
| `403` | `organization_required` | Caller is not associated with an organization. |
| `403` | `insufficient_role` | Caller is not an organization owner or admin. |
| `404` | `account_not_found` | Service account does not exist. |
