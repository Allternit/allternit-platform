# Spend Limits

<Note>
These endpoints are served by the Allternit runtime (the Desktop app, or a paired or hosted computer), not by `api.allternit.com`. On Allternit Cloud the console hides this page. On Cloud, set the monthly spend cap per project in the Platform API: see [Billing and spend caps](/api/platform/billing#spend-cap). The console shows it on the Project billing page.
</Note>


Spend limits protect against runaway usage by capping monthly organization spend in USD cents. Organization owners and admins can view the current cap and spend, request an increase, and approve or reject pending increase requests.

## Base URL

```text
/api/v1/admin/spend-limits
```

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/v1/admin/spend-limits` | Current limits, usage, and pending request |
| `POST` | `/api/v1/admin/spend-limits/increase-request` | Request a limit increase |
| `POST` | `/api/v1/admin/spend-limits/approve` | Approve a pending increase request |
| `POST` | `/api/v1/admin/spend-limits/reject` | Reject a pending increase request |
| `GET` | `/api/v1/users/me/balance` | Available and total balance for the caller |

## Get spend limit

```bash
curl -X GET http://127.0.0.1:8013/api/v1/admin/spend-limits \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

### Response

```json
{
  "org_id": "org_01hqx8x7x7x7x7x7x7x7x7x",
  "monthly_usd_cap": 100000,
  "current_month_spend": 42350,
  "increase_request_status": null,
  "increase_request_amount": null,
  "increase_request_reason": null,
  "increase_request_created_at": null,
  "increase_request_updated_at": null,
  "created_at": "2026-01-01T00:00:00Z",
  "updated_at": "2026-08-13T18:00:00Z"
}
```

All monetary values are in USD cents. In this example, the cap is `$1,000.00` and the current spend is `$423.50`.

## Request a spend-limit increase

```bash
curl -X POST http://127.0.0.1:8013/api/v1/admin/spend-limits/increase-request \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 50000,
    "reason": "Growth campaign launching next month"
  }'
```

### Request body

```json
{
  "amount": 50000,
  "reason": "Growth campaign launching next month"
}
```

### Response

```json
{
  "org_id": "org_01hqx8x7x7x7x7x7x7x7x7x",
  "monthly_usd_cap": 100000,
  "current_month_spend": 42350,
  "increase_request_status": "pending",
  "increase_request_amount": 50000,
  "increase_request_reason": "Growth campaign launching next month",
  "increase_request_created_at": "2026-08-13T18:00:00Z",
  "increase_request_updated_at": "2026-08-13T18:00:00Z",
  "created_at": "2026-01-01T00:00:00Z",
  "updated_at": "2026-08-13T18:00:00Z"
}
```

The `amount` must be greater than `0` USD cents.

## Approve an increase request

```bash
curl -X POST http://127.0.0.1:8013/api/v1/admin/spend-limits/approve \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"amount": 50000}'
```

### Request body

```json
{
  "amount": 50000
}
```

If `amount` is omitted, the pending request amount is used. The organization's `monthly_usd_cap` is increased by the approved amount and the request status becomes `approved`.

### Response

```json
{
  "org_id": "org_01hqx8x7x7x7x7x7x7x7x7x",
  "monthly_usd_cap": 150000,
  "current_month_spend": 42350,
  "increase_request_status": "approved",
  "increase_request_amount": 50000,
  "increase_request_reason": "Growth campaign launching next month",
  "increase_request_created_at": "2026-08-13T18:00:00Z",
  "increase_request_updated_at": "2026-08-13T18:05:00Z",
  "created_at": "2026-01-01T00:00:00Z",
  "updated_at": "2026-08-13T18:05:00Z"
}
```

## Reject an increase request

```bash
curl -X POST http://127.0.0.1:8013/api/v1/admin/spend-limits/reject \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

### Response

```json
{
  "org_id": "org_01hqx8x7x7x7x7x7x7x7x7x",
  "monthly_usd_cap": 100000,
  "current_month_spend": 42350,
  "increase_request_status": "rejected",
  "increase_request_amount": 50000,
  "increase_request_reason": "Growth campaign launching next month",
  "increase_request_created_at": "2026-08-13T18:00:00Z",
  "increase_request_updated_at": "2026-08-13T18:10:00Z",
  "created_at": "2026-01-01T00:00:00Z",
  "updated_at": "2026-08-13T18:10:00Z"
}
```

Rejection requires a pending request. The monthly cap is unchanged.

## Check balance

```bash
curl -X GET http://127.0.0.1:8013/api/v1/users/me/balance \
  -H "Authorization: Bearer $TOKEN"
```

### Response

```json
{
  "object": "balance",
  "available_balance": 57650,
  "total_balance": 100000,
  "currency": "USD"
}
```

`available_balance` is `total_balance - current_month_spend`.

## Behavior when the cap is reached

When `current_month_spend` reaches `monthly_usd_cap`, the gateway rejects new requests with `429 Too Many Requests` and a `budget_exceeded` detail. In-flight runs are allowed to finish.

## Error codes

| Status | Code | Description |
|--------|------|-------------|
| `400` | `invalid_amount` | Amount must be greater than `0` USD cents. |
| `400` | `no_pending_request` | No pending increase request to approve or reject. |
| `403` | `organization_required` | Caller is not associated with an organization. |
| `403` | `insufficient_role` | Caller is not an organization owner or admin. |
| `429` | `budget_exceeded` | Monthly spend cap has been reached. |
