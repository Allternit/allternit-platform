The card lives in `allternit-ai/src/components/bots/meet/`. One build serves Allternit Desktop, ai.allternit.com (desktop and phone layouts) and the m.allternit.com PWA. User guide: [Meet your bots](/guides/meet-your-bots).

| Entry | Mounted by | Steps |
|---|---|---|
| `setup` | `FirstRunSetup.tsx` at the `mainbot` step (desktop, phone layout, `PhoneOnboardingFlow`) | start · team · main · routines · job · done |
| `botmode` | `BotLaunchpadView.tsx` through `MeetYourBotsOverlay` (desktop and the phone `BotsScreen`) when a main bot exists and the intro hasn't been seen | start · team · routines · job · done |

With no main bot, `BotModeRail` still opens **Set up your main bot** first; the card follows once there is one.

## Finishing

Nothing is created before **Start the job**. `runFinish()` then runs in order, recording each item as `ok`, `skipped` or `failed` with the reason:

1. **Main bot**: `setUpPrimaryBot` (A://, dressed with the picked look) or the vendor bot the picker connected, then `setMainBot`.
2. **Team bots**: each template through the same apply path as the template gallery, skipping templates already on the account (`config.templateId`). Each wears its template's `look` (`castAvatarConfig`). `skipRoutines` stops the template from installing its own routines.
3. **Routines**: each kept draft with its edited cron and on/off state.
4. **Thread #1**: the bot's main chat, with the edited job text sent once as the user's message.

A failure never stops later items. **Retry what didn't finish** reruns only failed items. Bots added afterwards from **Works well with your team** (template `handoffs` not on the team) are created with their routines paused.

## Seen flag

`src/lib/bots/bots-intro.ts`: one flag for both entries, Clerk `user.unsafeMetadata.botsIntroSeenAt`. Web and the PWA read and write it with the Clerk client. Desktop has no Clerk client, only a session JWT, so it reads it once from `GET /api/v1/me/flags` on the cloud API (waiting up to 3 s before deciding) and writes it with `PUT` (see [Me API](/api/me)). If this device saw the card before the account knew, it tells the account. localStorage `allternit-bots-intro-seen` is the cache, and the fallback when signed out, offline, or the endpoint answers 404/503. Set on finish and on skip. `requestBotsIntroReplay()` (Bots rail **⋯** → **Replay intro**, the Bots header on a phone) reopens it in `botmode`.

## Routines scheduler

`src/components/bots/schedule/` is shared by the card and Bot Mode → Routines → Calendar (`views/bots/home/BotRoutinesSchedule.tsx`):

- `routine-rule.ts`: `RoutineRule` (`daily` · `weekdays` · `weekly` · `monthly` · `interval` with a window), `ruleFromCron` / `ruleFromSchedule` / `ruleToCron` (round-trips every built-in template cron), `ruleLabel`, `moveRule`, `ruleForSlot`. Intervals are limited to the editor's choices (30 min, 1–4 h); anything else stays off the calendar and is listed under it.
- `RoutineScheduler.tsx`: controlled Day (default) / Week hour grids from 6 AM to 10 PM and a Month view. Empty-slot click → `onRequestNew(day, minute)`; chip click → `onRequestEdit(id)`; vertical drag → `onMove(id, minute)` in 15-minute steps. Interval routines draw as one striped band.
- `RoutineEditor.tsx`: dialog (bottom sheet on phones), portalled to `document.body`, Escape in the capture phase.
- Bot Mode saves through `bot-routine.service.ts`: `createBotRoutineOnCron`, `updateBotRoutine` (PUT `/api/v1/automation/routines/:id` with `schedule_type: cron`; metadata is merged onto the stored row because the server replaces it whole) and `deleteBotRoutineById`. The API resets `next_run_at` on a schedule change.
