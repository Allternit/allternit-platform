Every responsibility in the system has exactly one owner. The architecture groups owners into eight **planes**. New kernel code belongs to exactly one plane.

## Architecture contract

| # | Plane | Owns | Machine |
|---|-------|------|---------|
| 1 | Experience / API | The single external agent identity, API and SDK surface, event streams, threads, artifacts. The [Agency API](/api/agency/overview) lives here. | Neither; the surface over both |
| 2 | Agent | [TaskIR and AgentState](/architecture/state), the [Agent ISA](/architecture/graphs), capability semantics | Shared |
| 3 | Work Orchestration | The compute graph, node lifecycle, node outputs, leases, heartbeat and reclaim, admission, campaigns, wait and wake, idempotency, replay hooks | [Work Machine](/architecture/work-machine) |
| 4 | Cognition | [S0–S3](/architecture/cognition-levels), the decision runtime, the judge runtime, verification cognition | [Cognitive Machine](/architecture/cognitive-machine) |
| 5 | Context + State | The [context compiler](/architecture/context), chunk store, memory, cognitive state | Cognitive Machine |
| 6 | Execution / Model | The [router and model pool](/architecture/routing), tool runtimes, fabric placement | Cognitive Machine |
| 7 | Governance + Observability | [Policy](/architecture/policy), [receipts](/architecture/receipts), [replay](/architecture/replay), evaluations, provenance, budgets | Under both |
| 8 | Product Operations | [Attention](/architecture/work-runtime/attention), human approvals, channels, remote control, quiet hours and caps, pause, resume and kill, the needs-you queue, audit views | Work Machine |

Two ownership decisions are fixed:

- **The work runtime ledger owns lifecycle.** No other store is the truth for where a node is.
- **ComputeGraphIR is authoritative.** The work-item view that existing tools use is a one-way, disposable projection of it.

Product Operations is not a second agent runtime. It presents and routes; it does not decide or execute.

Why planes: when two components both think they own a responsibility (for example, two places that can close a task), the system has no single truth. Assigning one owner per responsibility is what lets each part be replaced without breaking the rest.

## Current implementation

The ownership map is recorded in the repository structure guide and is used to place new kernel code. The table below lists what exists in each plane on main.

## Developer relevance

When you contribute, find the plane first. A change that makes one plane decide something another plane owns (a tool that closes its own node, a surface that runs agent logic) will not be accepted.
