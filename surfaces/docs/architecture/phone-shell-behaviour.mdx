The phone layout (`allternit-ai`, `src/fabric-session/phone/`) and the iPhone app follow one contract. This page is for developers. For the user view, see [Composer](/guides/chat-composer#on-a-phone) and [Code session list](/guides/code-session-list).

## Contract

| Id | Rule |
| --- | --- |
| C1 | The composer rests as one line (+, the line, send) and grows on focus. Tools (Agent mode, Plugins, Artifacts) sit behind the sliders button, not in a band under the card. There is no Output control. |
| C2 | The permission pill is removed. **+** shows Permission and a page with Auto, Ask, Read-only, from the same store. |
| C3 | The mic sits left of the voice button and toggles dictation. A failure shows one calm line. |
| C4 | The computer chip sits above the composer in Chat, Bots and Code. **✕** shrinks it to a dot on **+**. |
| C5 | No status number or code in UI text. |
| C6 | Code status order: Archived, Needs input, Working, Ready for review, Done. |
| C7 | An account row is a person or one of their orgs. Tapping an org switches with Clerk `setActive`. Tapping a remembered person signs out and opens sign-in with that email filled in. |
| C8 | **☰** only opens the drawer; it has no hold. Press the mode orb and slide to switch mode in one move; lift to pick. Hold still for 450 ms to open the Shelves hub, or tap the drawer's mode icon, which fires `allternit:open-mode-hub`. A tap opens the pill. A lens follows the finger (see Motion); with reduced motion it does not swell, stretch or magnify. The hub rises from the bottom edge. |

## Composer rest and Tools

The composer is one line at rest and opens on focus. The focus ring draws only for keyboard focus (`src/lib/input-modality.ts` sets `data-modality` on the html element). The mode orb and the New orb sit at the composer's top corners. The New orb shows only when a session is open, and logic for the new item lives in `src/shell/new-item.ts`. Hosts with no composer, such as Settings, open the hub through the `allternit:open-mode-hub` event.

## Code status signals (C6)

The node owns the signals, in `cmd/allternit-api/src/code_session_status.rs`. They are session metadata keys that clients cannot write: `needsInput`, `needsInputAt`, `needsInputKind` (`permission` or `question`), `readyForReview`, `readyForReviewAt`. Absent means false.

- `needsInput` is set when a permission or question is asked, and cleared when no ask is pending, on error, on idle and on run start.
- `readyForReview` is set on idle when the run sent `file.edited` or finished an edit, write, patch or artifact tool. It clears on run start or on `PATCH { markReviewed: true }`.
- Clients send `markReviewed` when a session is opened. The web does so only while the Code screen is visible: `markSessionReviewed(id)`, `registerCodeViewOpen()`, `sessionApi.markReviewed(id)`.
- An always-on watcher reads the gizzi `/v1/global/event` stream, so flags update with no client connected. Open clients get `session_flags` events on `/agent-sessions/sync`. The sync stream closes when the gizzi stream ends so clients reconnect.
- Web helpers: `codeSessionFilterStatus`, `isNeedsInput`, `needsInputKind`, `isReadyForReview` in `src/lib/code-session-status.ts`. Filters live in `components/session-overview/code-session-filter.ts`.
- Known limits: events while the node is disconnected are missed, and a thread placed on another server takes its flags from that server.

## Shelves hub

`src/shell/mode-hub/contract.ts` holds the sections for each mode, the timings (`HOLD_MS` 450, `HOVER_INTENT_MS` 120), the haptic map and the event names. `ModeHubHost` is mounted once in the phone shell and once in the desktop shell. After a pick it fires `allternit:mode-arrive` with `{ from, to }`. With reduced motion, states change at once. The old menu hold fan and Bots shelf (`menu-hold.ts`) are removed.

## Titles, intros and arrivals

The motion numbers (dock distance, springs, intro unlock, arrival timeline, drawer push) live in `src/design/polish/contract.ts` and `dock-math.ts`. Swift and Kotlin copy them. Arrivals and mode intros trigger on a change in the shell mode store, and also on `allternit:mode-arrive`, so pill taps, rail buttons and deep links count. With reduced motion, titles and arrivals fade. Haptics do nothing on Desktop and iOS Safari. For users, see [Phone titles, intros and arrivals](/guides/phone-titles-and-intros).

First-visit intros store their seen state in the account flags `intro*SeenAt` (see [Account flags](/api/me#account-flags)). Each client keeps a local cache so an intro shows once even when offline.

## Calm errors

`src/lib/errors/plain-error.ts` exports `plainErrorText(err, fallback)`, `stripStatusText`, `statusSentence` and `isComputeGateRefusal`. Use `plainErrorText` for any text shown to a person. A 409 `compute_required` or 428 on a read shows no error: the list shows its empty state and the chip shows. On an action the compute gate sheet opens as before. Chip state comes from `useComputerChip()` in `PhoneNoComputer.tsx`.

## Haptics and accounts

`src/lib/haptics.ts` exports `light`, `medium`, `soft`, `selection`, `setHapticsEnabled` and `isHapticsEnabled`; the setting key is `allternit.haptics`. `src/lib/accounts/switch-account.ts` holds `switchAccount` and `switchAccountCleanup`. Clerk single-session mode is still on for the instance, so there are no session rows. Switching person is done with remembered accounts instead (below).

## Remembered accounts

Accounts used on a device are remembered under one key on both platforms: `allternit-remembered-accounts-v1`. On the web and PWA it is in `localStorage`. On iOS it is in `UserDefaults`. The value holds, for up to 8 accounts, a user id, name, email, avatar, plan label and last-used time. It never holds a password or a token. It is not in the per-person key list, so the person cleanup and sign-out keep it.

- **Web:** `rememberAccount` runs on every Clerk-confirmed sign-in. Helpers: `listRememberedAccounts`, `forgetRememberedAccount`, `setRememberedAccountPlan`, `switchToRememberedAccount`, `addAnotherAccount`, `signInUrlFor`, `readSignInEmail`, `useRememberedAccounts`. A switch runs the person cleanup, then `signOut({ redirectUrl })` to `/sign-in?email=`. The PWA reads `?email=` in `fabric-session/App.tsx`. Electron hides the section.
- **iOS:** `RememberedAccounts.*`, `PersonSwitchOrder.run` and `AccountSwitch.switchPerson(email:authManager:)`. The email is passed to Clerk's `AuthView.initialIdentifier(_:)` through `AuthManager.pendingSignInEmail`. A person change also runs `AccountSwitchCleanup.resetLocalState(reason:)`. Device credentials are keyed per Clerk user (`RuntimeCredentialKeys`).
