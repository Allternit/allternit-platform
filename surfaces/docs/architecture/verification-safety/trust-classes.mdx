Two labels travel with content. Trust says how far to believe it. Sensitivity says who may see it.

## Architecture contract

| Trust class | Use |
|-------------|-----|
| `PUBLIC`, `INTERNAL`, `RESTRICTED`, `SECRET` | Ordered by how tightly the content is held |
| `UNTRUSTED` | Content from outside the run, such as web pages, files a user did not author and predecessor output |

Sensitivity uses `PUBLIC`, `INTERNAL`, `RESTRICTED`, `SECRET`. Eligibility is a policy function applied before utility, so a component that may not see a chunk never has it ranked. Untrusted content is fenced and compiled, never concatenated into control instructions.

## Current implementation

On main, untrusted text passed between nodes is wrapped in a fence with a random per-render nonce. The compiler-level enforcement across all context is not on main.

## Trust labels on bot input

Every input that reaches a bot thread carries one of seven labels, most trusted first: `owner`, `team`, `contact`, `vendor_bot`, `tool_output`, `web`, `stranger`. "Tainted" means below `team`.

- **Where it is set.** Channel inbound maps the owner's handle to `owner`, a person the twin knows to `contact` and everyone else to `stranger`. Inbound email does the same. A thread made by the owner is `owner`; one made by a bot or the coordinator is `team`.
- **What is recorded.** `content_provenance` stores the label, source, scanner score and flags, and a hash of the excerpt. `bot_threads.trust_floor` holds the lowest label seen and only ever goes down.
- **The scanner.** `injection_score` and `scan_text` flag a message and mark a tainted one down to `stranger`. They never block on their own.
- **What the label gates.** A tainted thread asks before every send, its write and send tools are set to ask, and the approval carries `provenance_json` (`trust`, `sourceKind`, `sourceRef`, `excerpt`, `flags`). Outside text reaches the model in a nonce fence. See [Prompt injection defense](/guides/injection-defense).
