## What was done

- **Allternit USB Agent** (name chosen by Eoj): a bot operates a real iPhone through a small ESP32-S3 board in the phone's USB-C port. The board is the hands (USB mouse + keyboard, with iOS AssistiveTouch showing the pointer); the phone's AirPlay mirror to Desktop is the eyes. Nothing is installed on the phone, and it needs no Mac-only Mirroring and no Apple developer account. Bots use the same `phone.*` tools as the Android lane.
- **Firmware** (`hardware/usb-agent/`, public, MIT notice for the parts adapted from esp32-iphone-agent): USBA/1 protocol, provisioning over USB serial, arm button, lease, auto-disarm.
- **Desktop main** (`surfaces/allternit-desktop/src/main/phone-usb-agent*.ts`, `phone-airplay.ts`, `phone-usb-agent-firmware.ts`): authenticated TCP link, UxPlay receiver, calibration and aiming, USB serial setup, bundled firmware + verification, Web Serial permission for Espressif boards only.
- **UI** (allternit-ai `src/components/computers/UsbAgentSection.tsx`, `PhoneLiveView.tsx`, `src/lib/usb-agent-flash.ts`): iPhone rows (status, View, Calibrate, Stop, Forget, Update available) and a five-step Connect an iPhone wizard whose single **Set up** button installs the firmware (esptool-js over Web Serial), then writes Wi-Fi and a new key.
- **Fixes found along the way:** the phone MCP shim only passed PNG screenshots, so iPhone JPEGs reached the bot as text; opening Settings downloaded adb even with no Android phone; the tool gateway needed adb to start; `spawnSidecar` couldn't pass extra fds; allternit-ai main didn't typecheck (`IdentityStepProps` deleted in d4cb1068, restored in #540).

## How it works

- **USBA/1:** the board dials Desktop on port 7300; mDNS `_allternit-usba._tcp` is the fallback when the saved address fails. The handshake is a mutual HMAC proof with the per-board 32-byte key, and each connection gets a fresh session key. Every command is HMAC-tagged and carries a strictly increasing sequence number. A lost answer is reported `uncertain`, never ok.
- **Safety:**
  - The board boots disarmed, and only its BOOT button arms it. The button also stops a command part-way. Desktop's Stop can disarm but never arm.
  - It releases every key and button after 10 s without authenticated traffic.
  - It disarms itself after 30 min idle, or 1 min with no Desktop.
  - Every command is bounded.
  - The key is written over USB only.
  - AirPlay is PIN-protected with its own trust register, so nobody else on the Wi-Fi can feed fake screens.
- **Firmware delivery:** Desktop ships `resources/phone/usb-agent/usb-agent-firmware.bin` with `firmware.json` (version, size, SHA-256, core), built reproducibly by `hardware/usb-agent/build-firmware.sh`. A test fails if the image and the source version disagree.
- **Licensing:** UxPlay (GPL-3.0) runs as a separate program and is never bundled. The arduino-esp32 core (LGPL) is covered because the firmware source is public and the image is rebuildable (Eoj approved publishing).

- **macOS firewall prompts.** The first setup will ask to allow incoming connections for Allternit and `uxplay`. This is documented but unverified on a signed build.
- **Known firmware limit** (documented in `hardware/usb-agent/README.md`): the Wi-Fi password and key are not encrypted in flash unless ESP32 flash encryption is turned on, which burns eFuses irreversibly. Left to whoever builds production boards.
- **Not done:** Windows support (UxPlay is Unix-only), texts and calls through the USB Agent, and plain-English tasks on iPhone.
- **Toolchain on this machine:** arduino-cli and the esp32 core (~6 GB in `~/Library/Arduino15`) were installed to build the firmware. Keep them for rebuilding the image; delete them if space is needed.
