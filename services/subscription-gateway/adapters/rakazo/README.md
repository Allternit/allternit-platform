# Rakazo native bot adapter

This adapter calls the pinned Rakazo product RPC directly. Configure `SUBS_GATEWAY_RAKAZO_URL` as the exact HTTPS origin for the user's Rakazo server (HTTP is accepted only for loopback); no public host or port is guessed. Set `SUBS_GATEWAY_RAKAZO_SPACE_ID`, or store a credential JSON object `{ "token": "<BetterAuth bearer session>", "spaceId": "<selected space id>" }` per account. A plain session token is accepted when the selected space ID is configured separately. The session token is never persisted by this adapter.

Pinned upstream `elie222/rakazo` commit `0394e92c820994ec9978b046f652c3ab4ca85fa5`: `packages/auth/src/index.ts` enables Better Auth's `bearer()` plugin; `packages/contracts/src/rpc.ts` defines `bots.list`, `threads.head`, `threads.send`, and `threads.subscribe`; `packages/contracts/src/domain.ts` defines bot `id`, `spaceId`, `threadId`, and archive state; `packages/contracts/src/events.ts` defines `ProductEvent`; `apps/api/src/app.ts` mounts oRPC at `/rpc/*`, obtains its auth session, and uses `x-rakazo-space-id` to resolve membership; `apps/api/src/router.ts` implements thread operations; `apps/api/src/thread-target.ts` creates the user message and run, returns `runId`, and emits native terminal events.

The adapter selects an active bot only within the chosen space, uses that bot's existing shared native thread, and submits `threads.send` with the Allternit correlation ID as `clientNonce`. It consumes the pinned oRPC JSON/SSE envelope and accepts only assistant text events followed by `run.completed` for the exact returned `runId` and bot thread. Native history remains in Rakazo. This adapter does not create a generic model proxy or a private thread; context resumption through a detached Allternit context is unsupported.

The wire format is from the upstream lockfile's `@orpc/client` 1.15.0 and published package source: POST `/rpc/<procedure path>` with `{json: input}`, output `{json: result}`; subscribe returns `text/event-stream` whose `data:` frames contain the same JSON envelope. The package is not added as a gateway dependency; the adapter uses native `fetch` for this verified narrow contract.
