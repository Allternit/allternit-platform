# OpenMuse CopilotKit adapter

Primary source: https://github.com/CopilotKit/openmuse/tree/1ac68f3909f2478ab6280883f1ab5ea65eb5719d
Pinned upstream uses `@copilotkit/runtime` 1.70.1 and `@ag-ui/client` 0.0.59. The adapter speaks AG-UI through the gateway's own HTTP/SSE client (`adapters/_shared/ag-ui.ts`, shared with the generic `ag-ui` adapter); it does not use CopilotKit IntelligenceAgent, which speaks a separate websocket `/connect` and `/run` receipt protocol.

Configure `SUBS_GATEWAY_OPENMUSE_COPILOTKIT_URL` (default `http://127.0.0.1:8787`, from pinned `apps/server/src/config.ts`) and provide the user's `OPENMUSE_ACCESS_KEY` through the sealed account credential. The adapter rejects keys shorter than 24 characters, exchanges the key at `POST /api/session` for a session bearer, then sends the bearer only to the configured loopback host. OpenMuse must run in live mode; source requires `OPENMUSE_ACCESS_KEY` (24+ characters), `TOKEN_ENCRYPTION_KEY`, and `CPK_INTELLIGENCE_API_KEY`. A live agent also needs a configured model and provider key, or `AGENT_BACKEND=agui` with `AGENT_URL` (and optional `AGENT_TOKEN`).

Pinned `apps/server/src/app.ts` exposes `GET /api/health` with `mode` and `agentConfigured`; `apps/server/src/agent.ts` defines when the default agent is configured and mounts the CopilotKit handler at `/api/copilotkit/*`. The shared AG-UI client posts a `RunAgentInput` to `POST /api/copilotkit/agent/default/run` as JSON and consumes AG-UI SSE. The adapter sends a generated isolated `threadId`, unique `runId`, and user message ID, guards those IDs in the outbound body, and requires matching RUN_STARTED and successful RUN_FINISHED events before accepting the assistant messages that run streamed (assembled per `messageId`, or taken from a `MESSAGES_SNAPSHOT`). It retains local history per context for subsequent turns.

OpenMuse does not expose a supported agent roster, thread creation/read route, or durable transcript resumption. The adapter therefore advertises one configured default agent, `resume:false`, local isolated contexts, and best-effort completion attribution. Context history and event receipts last only in this gateway process. Uncertain sends are not retried automatically; context close detaches without cancelling the vendor run. No tools, approvals, tasks, memory, or computer control are claimed.
