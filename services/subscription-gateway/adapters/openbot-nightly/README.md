# Nightly OpenBot adapter

Connects to the Nightly Labs OpenBot desktop host through its authenticated loopback Team API. Set `SUBS_GATEWAY_OPENBOT_NIGHTLY_URL` to the exact loopback origin and runtime-assigned port reported by the host. There is no default port. Set `SUBS_GATEWAY_OPENBOT_NIGHTLY_TOKEN` to a host session token; this is the Nightly Team API credential, not a model API key.

Nightly's pinned API supports `POST /v1/auth/login` with `{ "username": "…", "password": "…" }`; its response contains `sessionToken`. Obtain it through the host's documented local login flow and place that token in the sealed credential. The adapter sends it only as `Authorization: Bearer …`. It negotiates Team API protocol v5 and identifies itself as `Allternit/0.1.0` by default; the host checks that this header is present and at most 64 characters, without requiring a Nightly version format. Set `SUBS_GATEWAY_OPENBOT_NIGHTLY_APP_VERSION` to override the client identifier when needed. The adapter does not store account passwords.

The adapter discovers `GET /v1/agents`, reads `GET /v1/agents/:id/conversation`, and sends `POST /v1/agents/:id/messages` with a fresh `clientMessageId`. These endpoints return ordinary JSON; the roster response is a top-level array. The adapter treats the returned `messageId` as the exact user receipt, verifies its exact text, follows that message's `turnId`, and returns only completed assistant messages from that turn once the snapshot no longer identifies the turn as active. The local completion event is produced only after that check.

Contexts are shared with the selected OpenBot account and conversation. This adapter provides best-effort polling and completed replies. Streaming, steering, interrupt/cancel, approvals, tools, memory, files, tasks, and computer control are unavailable. Closing a context detaches Allternit and does not stop host work. If a send times out or its outcome is uncertain, inspect the conversation and retry only with the same send ID.
