# Any AG-UI agent adapter

Protocol source: https://docs.ag-ui.com (event names and fields as in `@ag-ui/core` 0.0.59). The adapter speaks AG-UI through the gateway's own HTTP/SSE client (`adapters/_shared/ag-ui.ts`, shared with OpenMuse); it adds no npm dependency.

The user supplies the agent's run URL and, optionally, a bearer token in Settings → Connections → Any AG-UI agent. The wizard seals them as the account credential, JSON `{"url":"https://agent.example.com/run","token":"…"}`; an optional `"headers":{"X-Api-Key":"…"}` object (up to 20 single-line values; `host`, `content-type`, `accept`, hop-by-hop headers, and `authorization` when a token is set are refused) can be added for agents that authenticate another way. `SUBS_GATEWAY_AG_UI_CREDENTIAL` provides the same JSON for a gateway without accounts.

URL rules: `http` or `https` to loopback (`127.0.0.1`, `::1`, `localhost`), or `https` to a public host. Userinfo and `#fragment` are refused. For a public host the adapter resolves every DNS answer and refuses the URL if any answer is private, loopback, link-local (including `169.254.169.254` metadata), CGNAT `100.64.0.0/10`, ULA `fc00::/7`, IPv4-mapped/NAT64/6to4/Teredo, documentation, multicast or reserved. It then connects through `node:http(s)` with a fixed `lookup`, so the socket goes to the address it checked while TLS still verifies the certificate for the hostname (DNS rebinding between check and connect cannot redirect it). Redirects are never followed. Limits: the check runs again on every send, but a host whose public address forwards traffic inward (a reverse proxy the user controls) is outside what an address check can see; loopback URLs are trusted as "this computer", where the gateway runs.

Each connection exposes one agent, `ag-ui:<host[:port]>`, named after the host. `agent.list` validates the URL and sends a `GET` with the credential: 401/403 is `AUTH_REVOKED`, 429 `RATE_LIMITED`, 3xx `POLICY_DENIED`, 5xx or no answer `VENDOR_UNAVAILABLE`; other answers (most AG-UI routes return 405 to GET) count as reachable. A send POSTs a `RunAgentInput` (`threadId`, `runId`, `state`, `messages`, empty `tools`/`context`/`forwardedProps`) with `accept: text/event-stream`, a 120 s timeout and an 8 MiB stream cap. A reply is accepted only after `RUN_STARTED` and a successful `RUN_FINISHED` for the submitted thread and run; assistant text is assembled per `messageId` (`TEXT_MESSAGE_*`, `TEXT_MESSAGE_CHUNK`) or taken from `MESSAGES_SNAPSHOT`. `RUN_ERROR` is `VENDOR_UNAVAILABLE`, foreign run events or an invalid stream are `ADAPTER_DRIFT`, an `interrupt` outcome is `UNSUPPORTED`. Unknown event types are ignored.

The adapter keeps local history per context for later turns and sends it as `messages`. AG-UI defines no roster, thread listing or durable transcript route, so contexts are isolated, `resume:false`, best-effort, and last only in this gateway process. Uncertain sends are never retried; context close detaches without cancelling the agent's run. No tools, approvals, tasks, memory or computer control are claimed.
