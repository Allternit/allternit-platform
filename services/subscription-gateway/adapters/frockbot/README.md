# FrockBot deployment-admin connector

This is an opt-in, limited administrative connector to the native FrockBot deployment debug API. It does not impersonate each user's FrockBot session. The upstream `/api/debug/*` surface is guarded by deployment `DEBUG_TOKEN`; native turn submission additionally requires the configured FrockBot `userId` to be a deployment admin. FrockBot's ordinary Better Auth cookie/session flow is not used by this adapter.

Enable explicitly with `SUBS_GATEWAY_FROCKBOT_DEBUG_ENABLED=1`. Configure the exact FrockBot origin in `SUBS_GATEWAY_FROCKBOT_URL` (HTTPS required except loopback HTTP) and `SUBS_GATEWAY_FROCKBOT_ADMIN_USER_ID` with a deployment-admin account ID. Every account binding must supply its own sealed credential as JSON in `credential.apiKey`, for example `{"token":"<DEBUG_TOKEN>","userId":"<admin-user-id>"}`. The credential's `userId` takes precedence; the configured admin ID is only its fallback. `SUBS_GATEWAY_FROCKBOT_DEBUG_TOKEN` is accepted only for an unscoped operator/health call and is never a fallback when an account binding exists. Missing configuration leaves the auto-registered adapter inert. Before sending any configured token, it probes `GET /api/debug/users` without credentials and requires 401 or 403; a successful unauthenticated response rejects the instance. Redirects are refused.

Bot discovery uses the native debug bot list scoped to the credential's selected user. Context ownership includes the AAI account binding and selected FrockBot user ID; one binding cannot adopt another binding's context. Sends use `POST /api/debug/users/{userId}/bots/{botId}/turns`; completion polls `GET /api/debug/bots/{botId}/runs/{runId}?userId={userId}` and checks both that ID and the exact submitted input before accepting a completed `responseText`. Vendor failure text is never returned to Allternit. Context and event cursors are process-local. No cancellation, approval forwarding, streaming, durable resume, or general user account isolation is claimed. The configured identity must be the deployment admin and may be able to inspect other accounts through deployment-level debug routes; use a dedicated FrockBot deployment and admin account for this integration.
