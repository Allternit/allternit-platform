Create or update GIZZI.md at the project root. It is the canonical instruction file that coding agents read before working in this repository.

Capture only what an agent cannot learn by listing files or reading the obvious:
- Build, lint, typecheck and test commands, including how to run a single test.
- Conventions the code actually follows (imports, naming, error handling, formatting) where they differ from defaults.
- Gotchas: required environment, generated files, ordering constraints, things that look removable but are not.
- Existing rules from .cursor/rules, .cursorrules, .github/copilot-instructions.md or AGENTS.md: fold them in.

Leave out directory listings, file-by-file descriptions and generic advice such as "write clean code". Verify each command before you write it down. Aim for about 100 lines, shorter if the repository is simple.

If GIZZI.md already exists (or AGENTS.md in ${path}), improve it instead of starting over. Keep what is still true, fix what is stale.
