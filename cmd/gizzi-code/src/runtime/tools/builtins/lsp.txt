Interact with Language Server Protocol (LSP) servers to get code intelligence features.

Prefer this tool over grep/text search whenever the question is about code
structure rather than text: finding where a symbol is defined, finding every
real reference to a symbol (not just textual matches of its name), listing
the symbols in a file, or searching for a symbol by name across the
workspace. LSP results are semantically accurate (they follow imports,
resolve aliases, and skip comments/strings that merely mention the name);
grep only pattern-matches text and will miss or over-match in those cases.
Prefer grep instead when searching for arbitrary text/log strings, or in
files with no configured language server.

Supported operations:
- goToDefinition: Find where a symbol is defined
- findReferences: Find all references to a symbol
- hover: Get hover information (documentation, type info) for a symbol
- documentSymbol: Get all symbols (functions, classes, variables) in a document
- workspaceSymbol: Search for symbols by name across the entire workspace (requires query)
- goToImplementation: Find implementations of an interface or abstract method
- prepareCallHierarchy: Get call hierarchy item at a position (functions/methods)
- incomingCalls: Find all functions/methods that call the function at a position
- outgoingCalls: Find all functions/methods called by the function at a position
- rename: Rename the symbol at a position everywhere the language server knows it is used (every file in the project), then apply the edits. Requires newName.

All operations require:
- filePath: The file to operate on
- line: The line number (1-based, as shown in editors)
- character: The character offset (1-based, as shown in editors)

workspaceSymbol also accepts:
- query: The symbol name (or substring) to search for across the workspace

rename also requires:
- newName: The new name for the symbol at line/character (point at the symbol's name, e.g. its declaration or any use)

About rename:
- Prefer rename over edit/multiedit/grep-and-replace whenever you rename a function, class, method, variable, type or parameter that is used anywhere else. It follows imports and skips unrelated text that happens to match the name.
- The edits are applied for you (the user is asked to approve the edit of every file listed). The result lists each changed file with its number of edits, plus any new errors.
- File moves or renames the server proposes are not applied; they are listed so you can do them by hand.
- If no language server handles the file, rename returns a message instead; then use the edit tool for each occurrence.
- To replace a whole function or class body, use symbol_edit; for small changes inside a function, use edit.

Note: LSP servers must be configured for the file type. If no server is available, an error is returned (rename returns a message suggesting the edit tool instead).
