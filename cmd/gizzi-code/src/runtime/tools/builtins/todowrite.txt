Keep a task list for the current session. Each call sends the whole list.

Use it for work with 3 or more steps, when the user gives several tasks, or when asked. Skip it for a single simple task or a question. Searching, reading and linting are not items; they are how you do an item.

Rules:
- Write outcomes, not activities: "Login rejects expired tokens", not "Look at login".
- Keep one item in_progress at a time. Mark it completed right away when it is done; do not batch.
- Give an in-progress item an activeForm, the present-continuous label shown while it runs ("Fixing token expiry").
- The last item verifies the work (run the check, read the result).
- Every item has a stable id (one is assigned if you omit it). A blocked item names its blocker in blockedBy by id. Unknown ids and cycles are refused.
- Status is pending, in_progress, completed, cancelled (dropped on purpose) or interrupted (stopped before it finished).
- If a step fails or turns out wrong, keep it in_progress or add a new item; never mark it completed on partial work.
