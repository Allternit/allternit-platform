Launch a new agent to handle complex, multistep tasks autonomously.

Available agent types and the tools they have access to:
{agents}

When using the Task tool, you must specify a subagent_type parameter to select which agent type to use.

When to use the Task tool:
- When you are instructed to execute custom slash commands. Use the Task tool with the slash command invocation as the entire prompt. The slash command can take arguments. For example: Task(description="Check the file", prompt="/check-file path/to/file.py")

When NOT to use the Task tool:
- If you want to read a specific file path, use the Read or Glob tool instead of the Task tool, to find the match more quickly
- If you are searching for a specific class definition like "class Foo", use the Glob tool instead, to find the match more quickly
- If you are searching for code within a specific file or set of 2-3 files, use the Read tool instead of the Task tool, to find the match more quickly
- Other tasks that are not related to the agent descriptions above


Usage notes:
1. Launch several agents at once only for truly independent tracks, in a single message with multiple tool uses. Do not send an agent to re-verify what you can check yourself.
2. When the agent is done, it will return a single message back to you. The result returned by the agent is not visible to the user. To show the user the result, you should send a text message back to the user with a concise summary of the result. The output includes a task_id you can reuse later to continue the same subagent session.
3. Each agent invocation starts with a fresh context unless you provide task_id to resume the same subagent session (which continues with its previous messages and tool outputs). A fresh agent has not seen this conversation or its attachments, so pass file paths or quote what it needs. Brief it like a colleague who just walked in: the goal and why, what you know or ruled out, the files and lines to look at, the scope, and exactly what its one final report should contain. Do the synthesis yourself; never write "based on your findings, fix it".
4. An agent's report is a claim. Read the real diff or run the check before telling the user the work is done.
5. Clearly tell the agent whether you expect it to write code or just to do research (search, file reads, web fetches, etc.), since it is not aware of the user's intent. Tell it how to verify its work if possible (e.g., relevant test commands).
6. Run in the foreground (the default) when you need the result before your next step. Set run_in_background only when you have independent work to do meanwhile; you are notified when it finishes, so do not sleep or poll. Once you delegate a piece of work, do not also do it yourself.
7. Never predict or invent a pending agent's result. If asked early, say it is still running. If you have task_output and task_stop, check or stop a background agent with them instead of guessing its state.
8. Name tasks you will want to address later: name="tests" gives the child a path such as /root/tests (a child of a named child gets /root/build/tests, at most 3 levels). Pass that path, or the plain name relative to you, as task_id to resume it; a taken name gets -2.
9. Pick the model class for the work: small is haiku-class (lookups, searches, checks), standard is sonnet-class (normal building), deep is opus-class. Use deep only for risky work: many files, migrations, auth, billing, or a bug with no known cause. effort (low, medium, high) sets how hard that model thinks.
10. fork="all" hands the child a copy of this conversation up to your last finished message, so you need not restate context: tell it only what to do and what is out of scope. It runs on your own model, so it takes no model or effort. Use it when the child needs what you already know; leave fork unset (none) for a fresh child with only your prompt, which is cheaper and the right default.
11. If the agent description mentions that it should be used proactively, then you should try your best to use it without the user having to ask for it first. Use your judgement.
