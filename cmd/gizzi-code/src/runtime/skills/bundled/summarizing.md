# Summarizing

Use this for summaries, notes and handoffs from transcripts, logs, diffs or documents. (This replaces the old `scribe` subagent.)

1. Read the whole source before you write. Don't summarize from the first part only.
2. Write the shortest summary that keeps every decision, every open item, every owner and every file path.
3. For a handoff, use this order: current state, what is done, what is open (all of it, not just the top items), next steps, and where things live (repos, branches, PRs, files).
4. Write dates as absolute dates (2026-10-27), not "yesterday" or "next week".
5. Don't add facts that are not in the source. If something is unclear in the source, say it is unclear.

When the source is too large for your context (for example a long transcript), give it to `explorer` to extract the decisions and open items. Then write the summary yourself.
