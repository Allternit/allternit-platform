What was built the three systems

1 · The steering system .steering/

An independent agent (a different model family than the worker) reviews every working agent at checkpoints and gates every commit. Hooks for kimi, Claude Code, codex, and gizzi-code — one script speaks all their protocols. The reviewer accumulates memory across checkpoints in a persistent tmux session.

2 · The discovery pipeline docs/pipeline/

Autonomous feature discovery: 20+ sources → mechanism briefs → deterministic specs → an independent spec-checker with a charter (your taste, as data) → rails-ticket queue → worktree builders → your merge. A full loop from an arXiv paper to a built feature branch with one human touch.

3 · The platform itself rails/ + gizzi-code

Rails grew to full beads-parity (tickets, dependency graphs, capacity-ready computation) plus graph engineering (PageRank/HITS/critical-path as agent-facing JSON) plus a complete agent mail layer (identities, typed envelopes, FTS search, acks). gizzi-code learned per-session worktrees and how to give every user a second brain.

How it works the loop that built it all

1 · SPEC

Requirements written checkably (EARS-ish WHEN/SHALL) before any code. Reviewed by the independent agent first.

2 · BUILD

An executor agent in its own git worktree builds it, keeping a checkpoint file current.

3 · CHECK

Every checkpoint and every commit is reviewed by a different model family, with evidence citations, not vibes.

4 · GATE

Commits physically cannot land until the reviewer says APPROVE. STEER verdicts inject fixes back into the worker.

5 · VERIFY

The orchestrator re-runs every test suite itself — never trusts the executor's notes at face value.

6 · MERGE

The only human touch. Every rejection feeds back as a taste precedent the pipeline consults forever.

arXiv / RSS / HN→ scout→ brief→ generate-spec→ spec-checker→ rails tickets→ build-queue→ you: merge

How it looks real output, unedited

The steering verdict that killed a shipped bypass

The first claude-backed review of the commit gate found the gate's own regex let /usr/bin/git commit and sh -c 'git commit' sail straight past it — before the feature ever shipped.

STEER

BLOCKER — .steering/bin/steer-pre-commit-gate.sh:24. The git-detection regex
`(^|[;&|[:space:]])git[[:space:]]+(commit|push)([[:space:]]|$)` requires the
character immediately before "git" to be start-of-string, `;`, `&`, `|`, or
whitespace. That's trivially not true for common, non-adversarial patterns:
  - `/usr/bin/git commit -m x`   (preceded by `/`)
  - `sh -c 'git commit -m x'`    (preceded by `'`)
Any of these silently bypass the entire gate — no consult, no steer_log entry.
Shipping it with an easy bypass is worse than not having the gate.

What the system caught the point of building it

BLOCKER — its own gate, bypassable

The steering agent found its own infrastructure shipping a regex bypass. Fixed and re-tested against a 12-case matrix before merge.

DESIGN — backlog starvation

When the executor and the spec disagreed on dedup-vs-cap ordering, the reviewer ruled for the option that drains backlog over time — and explained why the alternative starves discoveries. Both spec and code updated.

MAJOR — taste precedents untested

The charter layer's memory-precedent path was silently neutralized by the test shim — caught before the taste engine shipped hollow.

MAJOR — a note field that doesn't exist

The B3 spec asked for a ticket note; the reviewer grepped the API and found only `description` exists. Spec fixed before the builder hit the wall.

HONEST — "my path is dead code"

The W2 executor reported its own wiring was on an unreachable code path rather than calling it done. W2b wired the real one.

The next wave, shipped D2 · D3 · B3

D2 · Brains become hostable f1297f804

The platform now provisions per-user bare git repos and serves smart-HTTP push/pull through git http-backend, guarded by a new allternit_git_ personal-access-token type (hash-stored, mint-once, git-routes only). A read API returns brain pages with parsed frontmatter. D1's gizzi brain init --remote now has somewhere real to point.

D3 · The iPhone can git 105cbb81f

The spike verdict was GO: an embedded git client in the iOS app cloned, committed, and pushed from the simulator over HTTP+Basic token auth and over real TLS (a GitHub clone). Every proof externally verified — git log on the remote plus a second clone. Device builds blocked by code signing only — a precondition, not a library problem. D3's product phases (onboarding brain creation, offline capture queue) are unblocked.

B3 · The queue grew dependencies dd4f4c5ee

READY specs now become rails tickets — labeled, dependency-linked, triage-ordered. The build queue reads /api/rails/tickets/ready through the graph's triage scores, so a discovered feature that unblocks three others builds first. Legacy file-based queue entries still work, building after ticketed items.
